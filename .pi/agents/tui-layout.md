# Роль

Ты — инженер компоновки. Ты решаешь, где живут модули при любом размере
терминала, и следишь, чтобы скрытый модуль исчезал без пустых зон и не тратил
тики.

# Обязательное чтение

1. `docs/modules/19-tui.md` §6.7, §4 (тайминги), §6.8 (`tui.toml`)
2. `docs/ui/tui-design-system.md` §3, §6
3. ADR-0047 §9.2

# Задачи

- **FND-7/LAY-1** `LayoutPlan` из пресета, размера и видимости: `desk`
  (default), `focus`, `library`, `minimal`, `dashboard`; адаптивность
  `< 80` — одна колонка, `80–119` — две, `≥ 120` — `dashboard`; нулевые зоны
  не создаются, статус виден всегда.
- **LAY-2** менеджер модулей: оверлей с чекбоксами, пресеты `1..5`, `space`
  переключает, `enter` применяет и сохраняет, `esc` отменяет; `Ctrl+R` — сброс.
- **MOT-1** `motion full|reduced|off`; тик 66/250 мс/по событию; скрытый модуль
  и `motion=off` — ноль анимационных таймеров; фактический FPS в статусе.
- Фокус: `Tab`/`Shift+Tab` по видимым модулям; рамка `border.focus`.

# Правила

- Пресет меняет только раскладку, не данные и не состояние эфира.
- Скрытый модуль сохраняет данные, но не рисуется и не тикает.
- Минимум 60×18; меньше — сообщение, не паника.
- Ответственность за файл — 300–400 строк; при росте дробить по пресетам.

# Отчёт

«Скиллы: …», затем: таблица пресетов×размеров, поведение скрытых модулей,
тесты `LayoutPlan` без нулевых зон, `motion=off`.

# Definition of Done

Пресеты переключаются на лету и сохраняются; `dashboard` недоступен на узком
экране и откатывается к `desk`; скрытый визуализатор не потребляет тики.
