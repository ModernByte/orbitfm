## 1. Архитектура системы и жизненный цикл (Single-Daemon IPC)

OrbitFM проектируется по архитектуре **«Единый фоновый сервис + Легковесный графический GUI-клиент»**.

```text
┌────────────────────────────────────────────────────────┐
│                   Noctalia Bar / Shell                 │
│  [ 📻 OrbitFM Icon ] ── (по клику) ─────────────────┐  │
└─────────────────────────────────────────────────────┼──┘
                                                      │
                                          IPC (Unix Domain Socket)
                                                      │
┌─────────────────────────────────────────────────────▼──┐
│              OrbitFM App (Single Instance)             │
│ ┌────────────────────────────────────────────────────┐ │
│ │  Core Services (same process)                      │ │
│ │  - MPV Engine Session Owner                        │ │
│ │  - MPRIS v2 Interface                              │ │
│ │  - Radio Browser API Client & Cache                │ │
│ └─────────────────────────┬──────────────────────────┘ │
│                           │                            │
│ ┌─────────────────────────▼──────────────────────────┐ │
│ │  GUI Layer (egui + wgpu Custom Render Pass)        │ │
│ │  - 3D Globe Scene & R-Tree Spatial Raycaster       │ │
│ │  - Station List & Player Controls                  │ │
│ └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

### 1.1. Модель жизненного цикла процесса
1. **Единый процесс (`orbitfm`):** Владеет аудиосессией (`libmpv`), IPC-сервером и GUI. Отдельного демона `orbitfmd` нет (ADR-0005).
2. **Графическое окно (GUI):** Создается в рамках того же процесса. При закрытии окна (нажатие `[X]`, а в overlay-режиме — клик мимо) окно **скрывается** (Hide to Tray/Background), а аудиосессия продолжает играть.
3. **Повторный запуск (`orbitfm` CLI):** При вызове бинарника проверяется наличие активного сокета. Если процесс уже запущен, команда отправляется существующему экземпляру, а текущий бинарник завершается. Без аргументов отправляется `toggle`; при отсутствии экземпляра запускается GUI.

## 2. Утвержденный технологический стек (Tech Stack)

| Модуль | Технология / Crate | Назначение и обоснование |
| :--- | :--- | :--- |

| **GUI Framework** | `eframe` / `egui` | Реактивный кроссплатформенный UI с поддержкой прозрачности |

## 3. Детальные спецификации подсистем

### 3.1. 3D-Рендеринг и Spatial Raycasting Engine

#### Рендер-пайплайн (`egui-wgpu` Integration)
* **Сцена:** 3D-сфера с UV-разверткой, матовой PBR-текстурой континентов и процедурным Fresnel-шейдером свечения атмосферы.
* **Рендеринг:** Осуществляется через `egui_wgpu::PaintCallback`. `wgpu` создаёт изолированный Pipeline State и рендерит 3D-сферу непосредственно в целевой `TextureView` UI-контекста.

#### Математика Raycasting & R-Tree Поиска
1. **Пересечение луча со сферой:** При клике ЛКМ вычисляется луч $R(t) = O + tD$ из координат курсора через обратную матрицу видовой проецирующей камеры $(M_{proj} \times M_{view})^{-1}$.
2. **Координатное преобразование:** Точка пересечения сферы $(x, y, z)$ переводится в географические координаты:
   $$\phi = \arcsin\left(\frac{y}{R}\right), \quad \lambda = \arctan2(x, z)$$
3. **R-Tree spatial lookup:** Координата $(\phi, \lambda)$ передается в `rstar::RTree` индекс прямоугольных рамок (Bounding Boxes) стран.
4. **Точная проверка (Point-in-Polygon):** Для отфильтрованных кандидатов из R-Tree запускается проверка `geo::contains` по точным `MultiPolygon` границам из датасета *Natural Earth 110m*.
5. **Обработка антимеридиана:** Используется датасет Natural Earth, в котором полигоны уже разделены по $\pm180^\circ$; дополнительная нормализация не требуется.

#### Маркеры станций
* Поиск дополнительно запрашивает станции с известными координатами
  (`has_geo_info=true`, до 60) и строит маркеры на глобусе. Ошибка гео-запроса не
  влияет на список результатов.
* Координаты `geo_lat`/`geo_long` считаются пригодными, если они конечны, лежат в
  допустимых диапазонах и не равны `(0, 0)`. Станции с координатами, округлёнными до
  2 знаков (≈1 км), объединяются в один маркер с количеством; дубликаты по UUID
  отбрасываются.
* Маркеры проецируются через view-projection камеры, точки задней полусферы
  отсекаются, рисуются egui-оверлеем поверх wgpu-паспорта. Наведение показывает
  подпись, клик по маркеру приоритетнее выбора страны, текущая станция подсвечена.
  Решение — ADR-0012. Этап 8 добавляет вес маркера (votes/bitrate) и до 200
  маркеров в режиме глобального жанра (ADR-0015).

### 3.2. Подсистема работы с Radio Browser API

1. **DNS Server Discovery:**
   * Перед первым запросом выполняется DNS-разрешение `all.api.radio-browser.info`
     (лениво; при старте пул прогревается фоновой задачей).
   * IP-адреса дедуплицируются, пул обходится со случайного смещения; TLS-соединение
     сохраняет имя хоста (SNI), несмотря на подключение к конкретному IP.
2. **HTTP Контракт:**
   * Каждый HTTP-запрос содержит обязательный заголовок:  
     `User-Agent: OrbitFM/1.0 (ModernByte; Linux; Rust)`
   * Таймаут запроса — 5 секунд.
3. **Fallback & Retry Policy:**
   * При сетевой ошибке, таймауте, HTTP `5xx`, `429` или `408` клиент переключается на
     следующее доступное зеркало из пула.
   * После исчерпания пула выполняется повторный discovery и один повтор запроса;
     прочие `4xx` возвращаются сразу.
4. **Данные и клики:**
   * Поиск — `/json/stations/search`, станция по UUID — `/json/stations/byuuid`,
     click-tracking — GET `/json/url/<uuid>` при старте воспроизведения.
   * Для воспроизведения используется `url_resolved`; найденные станции кэшируются
     in-memory (до 512 записей).
   * Для маркеров поддерживается фильтр `has_geo_info=true`; поля `geo_lat` и
     `geo_long` необязательны (`null`, если каталог не знает координат).

### 3.3. Аудиобэкенд и экспериментальный FFT

* **Основное воспроизведение:** Реализовано через безопасную обёртку `libmpv2` над `libmpv`
  C-API. Все вызовы выполняются в выделенном потоке; `LC_NUMERIC` принудительно равен `C`.
  Движок из коробки обрабатывает сетевые лаги, динамический битрейт и кодеки.
* **FFT-визуализатор и полосы (Экспериментальный):**
  PCM не перехватывается, второй декодер не создаётся. К активной сессии mpv
  подключаются два размеченных `lavfi`-фильтра: `@level` с `aspectralstats` и
  `astats` отдаёт агрегированные метрики (centroid, spread, rolloff, flatness, flux,
  RMS), а `@spectrum` через `acrossover`/`amerge`/`pan` — RMS трёх полос
  Bass/Mid/High (20–150, 150–2000, 2000–20000 Гц) без изменения звука. Аудио-поток
  опрашивает `af-metadata` примерно раз в 50 мс. Раскладка каналов выбирает
  stereo- или mono-граф; неизвестная раскладка и отказ `@spectrum` деградируют до
  `@level` (`bands = None`). GUI строит сглаженную огибающую и не блокирует цикл
  рендеринга. Визуализатор включён по умолчанию; отказ анализа не прерывает
  воспроизведение. Пока окно скрыто, анализ снимается и возвращается при показе,
  поэтому припаркованный эфир не платит за невидимую визуализацию. Полосы спектра
  по бинам не предоставляются. Решения и ограничения — ADR-0010, ADR-0027.

### 3.4. Избранное и история станций

* **Хранилище:** Модуль `library` хранит снимки `Station` (включая `url_resolved`),
  поэтому сохранённую станцию можно запустить без сети.
* **Расположение:** `$XDG_DATA_HOME/orbitfm/library.json`; если переменная не задана
  или относительна — `$HOME/.local/share/orbitfm/library.json`.
* **Формат:** JSON `{ "favorites": [...], "history": [...] }`; отсутствующий файл —
  пустая библиотека, повреждённый JSON — ошибка загрузки.
* **Правила:** уникальность по `stationuuid`; избранное — порядок добавления без
  лимита; история — 20 последних станций, повторный запуск перемещает станцию в
  начало. При загрузке дубликаты удаляются, история обрезается до лимита.
* **Запись:** атомарная (`library.json.tmp` + `rename`), синхронная и только по
  действию пользователя. Ошибки записи не прерывают воспроизведение.
* **Отказоустойчивость:** при ошибке загрузки используется эфемерная библиотека без
  файла; её сохранения — no-op, поэтому повреждённый файл не перезаписывается.
* **Интерфейс:** вкладки «Результаты / Избранное / История», звезда у строки и
  текущей станции, очистка истории. История пополняется при успешном запуске
  станции. Новых IPC-команд нет; `Next`/`Previous` MPRIS по-прежнему не действуют,
  так как история не является очередью. Решение — ADR-0013.

### 3.5. Темы и кастомизация интерфейса

* **Хранилище:** Модуль `settings` хранит выбранную тему и акцент в JSON
  `{ "theme": "...", "accent": "..." }`.
* **Расположение:** `$XDG_CONFIG_HOME/orbitfm/settings.json`; если переменная не
  задана или относительна — `$HOME/.config/orbitfm/settings.json`.
* **Тема:** `system` (по умолчанию), `dark`, `light`; отображается на
  `egui::ThemePreference`. `system` следует системной теме, которую сообщает eframe.
* **Акцент:** шесть пресетов — `blue` (по умолчанию), `green`, `amber`, `violet`,
  `rose`, `cyan`. Произвольный выбор цвета не поддерживается, чтобы не писать файл
  на каждое движение мыши.
* **Применение:** акцент задаёт цвет выделения, гиперссылок, вкладок и обычных
  маркеров глобуса; палитра карточки и текста выводится из активной темы. Активный
  маркер сохраняет тёплый янтарный цвет.
* **Запись:** атомарная (`settings.json.tmp` + `rename`), только при изменении
  настройки. Ошибка записи показывается в карточке и не прерывает воспроизведение.
* **Отказоустойчивость:** отсутствующий файл — значения по умолчанию; повреждённый
  JSON — ошибка загрузки и эфемерные настройки, файл не перезаписывается.
* **Интерфейс:** drawer настроек шириной `SETTINGS_WIDTH = 380` px
  (`src/ui/settings_panel.rs`). Строка настройки собирается `controls::row`
  (`src/ui/controls.rs`): подпись слева, контрол в фиксированном слоте справа,
  приглушённая подсказка под подписью. Тема, число полос, язык, реактивность,
  стиль движения и режим окна — `controls::dropdown` (`egui::ComboBox` в стиле
  чипа со своим шевроном), булевые настройки — `controls::checkbox` (18×18,
  галка из двух штрихов, зона нажатия вместе с подписью), палитра акцента —
  шесть плашек, «Скрыть окно» и «Выход» — `widgets::quiet_button` в футере.
  Новых IPC-команд нет. Решение — ADR-0014, интерфейс — ADR-0031.

### 3.6. UX «Orbital Desk» (Этап 8, реализовано в 0.8.0-rc.1)

* **Композиция:** глобус доминирует в Focus-кадре; сверху тонкий HUD, справа
  выезжающая панель станций, снизу транспорт. Геометрия зон задаётся `DeskLayout`,
  раскладка full-bleed. Постоянные подсказки заменены tooltip/первым запуском.
* **Режимы поиска:** `SearchMode { Country, GlobalGenre }`. Маркер приоритетен в
  обоих режимах; клик по стране выбирает страну только в `Country`, в `GlobalGenre`
  клик мимо маркера — no-op.
* **Страна:** `countrycode`-запрос (до 100), локальные фильтры по имени, жанру и
  штату, сортировка votes/bitrate/name; контур и heatmap-заливка по числу
  загруженных станций; поиск страны по названию или ISO-коду в HUD; выбор мягко
  доворачивает камеру.
* **Жанр:** tag-запрос (до 200, маркеры только с `has_geo_info=true`); маркеры
  одного размера и цвета, битрейт/кодек и голоса показываются в подписи при
  наведении; при загрузке сбрасываются подсветка страны и старые маркеры.
* **Roulette:** случайная станция через `order=random` с координатами, перелёт
  камеры `fly_to`, автостарт и toast; до трёх повторов при пустом URL.
* **Визуализация:** синтетический cava-визуализатор на 16/24/32 столбца (ADR-0022);
  в Focus за планетой — круговое орбитальное аудиокольцо (корона из 120 столбцов,
  аврора, комета, искры на onset; ADR-0029), оно гаснет без эфира и при выключенном
  визуализаторе; планета деформируется от эфира (spring-squash, рябь, onset/beat,
  шесть стилей и Auto; ADR-0028) с настройками Motion Off/Low/Normal/High,
  Motion style и Reduce motion, деформация общая для меша, маркеров, стран и
  hit-test; flash усиливает Fresnel-обод на onset; музыкальная качка камеры
  уступает drag/zoom/fly, а перевороты-roll включаются настройкой `allow_flips`
  (по умолчанию выключены, только Focus, простой ≥2 с, кулдаун 12 с); через 4 с
  без взаимодействия глобус медленно вращается (разгон 2 с).
* **Режимы окна:** `WindowMode { Focus, Overlay, Listening }` (ADR-0021), IPC-глагол
  `mode`, режимные размеры и заголовки; Overlay — HUD-строка, мини-глобус и
  избранное, Listening — now-playing с пульсом.
* **Доступность:** focus-ring, роли и подписи контролов, клавиатурный шаг
  громкости, навигация ↑/↓ по списку станций, Space/Enter запускают станцию.
* **MPRIS:** artist из страны/штата, fallback на теги; artUrl — favicon.
* **Данные:** `Station` дополняется `votes`, `country`, `state` с `serde(default)`;
  формат `library.json` не меняется.
* **UI-код:** `src/ui/` (`hud`, `station_panel`, `transport`, `globe_view`,
  `capsule`, `palette`); оркестрация и состояние — в Application Core
  `src/session/` (`Session`), `src/app.rs` остаётся presentation-слоем и живёт ровно
  один прогон окна (ADR-0018).
* **Системный трей:** `src/tray/` — иконка SNI (`ksni`) с меню и колесом громкости;
  третий источник команд наравне с IPC и MPRIS, работает и при закрытом окне
  (ADR-0020).
* **Вне MVP:** favicon-карточки, глобальный aggregate heatmap. Целевой UX —
  `docs/ui/design-vision.md`, фазы и контракты —
  `docs/ui/implementation-plan.md`, решение — ADR-0015 (уточнено ADR-0018–0023).

### 3.7. Безопасность favicon (UGC, ADR-0025)

* **Источник:** favicon приходит по URL из каталога Radio Browser и считается
  недоверенным; файлы не сохраняются на диск, оригинальные байты не покидают память.
* **Форматы:** только PNG, JPEG и WebP по сигнатуре; SVG, GIF и ICO отклоняются.
* **Лимиты:** тело ответа ≤ 512 КиБ (потоково), сторона исходника ≤ 512 px,
  аллокации декодера ≤ 8 МиБ; EXIF/IPTC/XMP отбрасываются при декодировании в RGBA.
* **HTTP:** только `http`/`https`, таймаут 6 с, не более 3 редиректов; при наличии
  `Content-Type` допускаются `image/png`, `image/jpeg`, `image/webp` и
  `application/octet-stream`.
* **Устойчивость:** паника декодера перехватывается и не блокирует очередь; ошибка
  иконки показывает инициал станции без повторных запросов.
* **Неприменимо:** серверное перекодирование, отдельный CDN, CSP/`nosniff`,
  антивирус и sandbox — у клиента нет бэкенда, файлового хранилища и веб-вью.
  Защита от SSRF/приватных адресов — отдельное будущее решение.

## 4. Контракты интеграций и правила окон

### 4.1. Манифест плагина Noctalia v5 (`orbitfm/plugin.toml`)

```toml
id           = "modernbyte/orbitfm"
name         = "OrbitFM"
version      = "1.0.0"
plugin_api   = 3
author       = "ModernByte"
license      = "MIT"
icon         = "radio"
description  = "3D Interactive Global Radio Player"
tags         = ["bar", "audio", "music"]
dependencies = ["orbitfm"]

[[widget]]
id    = "launcher"
entry = "plugin.luau"
```

`id` обязан иметь формат `<author>/<plugin>`; app-id окна остаётся
`org.modernbyte.OrbitFM`. Имя каталога плагина совпадает с частью id после `/`
— это требование каталога Noctalia. Теги выбираются только из официального
списка, а внешняя команда `orbitfm` объявлена в `dependencies`.

### 4.2. Luau Адаптер для Noctalia v5 (`orbitfm/plugin.luau`)

```luau
--!nonstrict

barWidget.setGlyph("radio")
barWidget.setText(noctalia.tr("widget.label"))
barWidget.setTooltip(noctalia.tr("widget.tooltip"))

function onClick()
    local started = noctalia.runAsync("orbitfm panel")

    if not started then
        noctalia.notify(noctalia.tr("widget.error_title"), noctalia.tr("widget.error_body"))
    end
end
```

Плагин не держит состояние и не содержит бизнес-логики: он только отправляет
IPC-команду `panel` — переключатель выпадающей панели (открытая панель
скрывается, другой режим переключается на Panel и показывается) — через CLI.
Форма `runAsync` с колбэком не используется: Noctalia ограничивает такую
команду таймаутом 5 с и убивает группу процессов, поэтому GUI запускается без
callback. Капсула Overlay остаётся CLI-командой `overlay` — виджет её не зовёт;
полный стол Focus тоже не в плагине, а в ярлыке приложения (`orbitfm mode
focus`). Развод точек входа поэтому живёт в командах (ADR-0033, ред. 2026-10-28).
Строки интерфейса — в `translations/en.json` и
`translations/ru.json`; ключи вложены по сегментам (`widget.label`), плоские
ключи с точками каталог не принимает.

### 4.3. Каталог плагинов Noctalia (`catalog.toml`)

* `catalog.toml` в корне репозитория индексирует плагин для git-источника
  `ModernByte/orbitfm`: `id`, `name`, `version`, `author`, `license`, `icon`,
  `description`, `deprecated`, `plugin_api`, `tags`, `dependencies`.
* Каталог плагина расположен в `orbitfm/`: `plugin.toml`, `plugin.luau`,
  `README.md`, `thumbnail.webp` (960×540 WebP, до 512 КиБ) и
  `translations/en.json`.
* Подключение как пользовательского источника:
  `noctalia msg plugins source add orbitfm git https://github.com/ModernByte/orbitfm`,
  затем `noctalia msg plugins enable modernbyte/orbitfm`.
* Внешняя публикация в `noctalia-dev/community-plugins` не выполняется: плагин
  распространяется как git-источник `ModernByte/orbitfm`. Если решение изменится,
  потребуется отдельный PR; в общем магазине `catalog.toml` генерируется CI и
  вручную не редактируется.
* Проверки: `noctalia plugins lint orbitfm` и официальный community-валидатор
  манифеста, README, миниатюры и переводов.

### 4.4. Оконные правила Niri 25.01+ (`wm-configs/orbitfm-niri.kdl`)

Соответствует официальной спецификации Niri (v25.01+):

```kdl
window-rule {
    match app-id="org.modernbyte.OrbitFM" title=r"^OrbitFM$"
    open-floating true
    default-column-width { fixed 1100; }
    default-window-height { fixed 800; }
    default-floating-position x=60 y=48 relative-to="top-right"
    draw-border-with-background false
}
```

Плавающие окна Niri центрирует по умолчанию, поэтому правило задаёт якорь само:
`default-floating-position x=60 y=48 relative-to="top-right"` ставит Focus под
правую секцию бара Noctalia, где стоит виджет; `x` подбирается вручную. Размер
привязан к заголовку (`title=r"^OrbitFM$"`), а не к app-id: у каждого режима свой
заголовок, поэтому правила не пересекаются и порядок их применения не важен.
Правила не-Focus режимов (`Overlay`, `Listening`, `Panel`) по их заголовкам
дополнительно выключают `border` и `shadow`: рамка и тень остаются только у Focus,
который один живёт как обычное окно (`WindowMode::is_borderless`).

### 4.5. Оконные правила Hyprland (`wm-configs/orbitfm-hyprland.conf`)

```ini
windowrulev2 = float, class:^(org\.modernbyte\.OrbitFM)$
windowrulev2 = center, class:^(org\.modernbyte\.OrbitFM)$
windowrulev2 = stayfocused, class:^(org\.modernbyte\.OrbitFM)$
windowrulev2 = size 1100 800, title:^OrbitFM$
```

`size` ключуется по заголовку (`title:^OrbitFM$` — только Focus), а не по классу:
правило по классу навязало бы 1100×800 всем остальным режимам окон.

`windowrulev2` работает в Hyprland 0.52 и совместимом режиме 0.53+; в 0.53+
синтаксис помечен deprecated, новый формат — блок `windowrule { ... }`.
