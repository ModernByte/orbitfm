# Модуль: Настройки оформления

**Путь в коде:** `src/settings/mod.rs`  
**Ответственность:** Хранение темы, акцентного цвета, параметров визуализатора и аудио-движения, локальная персистентность.  
**Зависимости:** serde, serde_json, thiserror

---

## 1. Назначение

Единственная точка работы с пользовательскими предпочтениями оформления.  
Модуль не зависит от egui и GUI: он хранит перечисления `ThemeMode`,
`AccentColor`, `MotionReactivity` и `MotionStyle`, а Application Core применяет
их к стилям, палитре и движению глобуса. Решения — ADR-0014, ADR-0019,
ADR-0028.

## 2. Состав модуля

| Файл | Назначение |
|------|------------|
| `mod.rs` | `SettingsStore`, `Settings`, `ThemeMode`, `AccentColor`, `MotionReactivity`, `MotionStyle`, `VIZ_BAR_CHOICES`, `default_path` |

## 3. Данные

| Поле | Значения | По умолчанию |
|------|----------|--------------|
| `theme` | `system`, `dark`, `light` | `system` |
| `accent` | `blue`, `green`, `amber`, `violet`, `rose`, `cyan` | `blue` |
| `viz_bars` | 16, 24, 32 (иное притягивается к ближайшему) | 24 |
| `help_seen` | `true` после первого показа карточки управления | `false` |
| `motion` | `off`, `low`, `normal`, `high` | `normal` |
| `motion_style` | `auto`, `soft-pulse`, `groove-sway`, `bass-drop`, `ambient-drift`, `sparkle-twitch`, `beat-march` | `auto` |
| `allow_flips` | перевороты камеры на onset (Phase 3) | `false` |
| `reduce_motion` | отключает геометрию и качку, эфир продолжается | `false` |

Акценты — пресеты с фиксированными RGB-компонентами (`AccentColor::rgb`).
Произвольный цвет отложен: перетаскивание color picker приводило бы к записи
файла несколько раз в секунду.

`MotionReactivity` задаёт пределы `squash_limit` (1,0/2,0/3,5 % для
Low/Normal/High), `ripple_limit` (0,15/0,25/0,40 %) и `idle_amplitude`
(0,35/0,35/0,50 %); `capped` ограничивает режим окна. `MotionStyle::Auto`
оставлен значением по умолчанию для будущего выбора по сигналу (Phase 2).

## 4. Персистентность

```
$XDG_CONFIG_HOME/orbitfm/settings.json
$HOME/.config/orbitfm/settings.json   (если XDG_CONFIG_HOME не задан/относителен)
```

- Формат — JSON `{ "theme": "...", "accent": "..." }`, читаемый вручную.
- Запись атомарная: `settings.json.tmp` + `rename`; каталог создаётся при
  необходимости.
- Запись синхронная и только при изменении значения; повторная установка того же
  значения не пишет файл.
- Отсутствующий файл — значения по умолчанию, не ошибка.
- Повреждённый JSON — `SettingsError::Parse`; Application Core создаёт
  `SettingsStore::ephemeral()`, которая не пишет файл, поэтому повреждённые данные
  не теряются.
- Ошибки записи не прерывают воспроизведение; GUI показывает их тостом.

## 5. Применение в GUI

- `configure_style(ctx, settings)` вызывается при старте и после каждого
  изменения: `Context::set_theme` получает `System`/`Dark`/`Light`,
  для обеих тем настраиваются прозрачные `panel_fill`/`window_fill`.
- `selection.bg_fill` и `hyperlink_color` используют акцент; цвет текста на
  выделении выбирается по яркости акцента.
- `Palette::for_ui(theme, accent)` вычисляет цвета панелей, приглушённого текста,
  ошибок, подложек и маркеров. В светлой теме акцент для текста затемняется,
  маркеры остаются яркими.
- Маркеры глобуса используют один цвет `palette.marker` (ADR-0012, обновление
  Этапа 9); качества и рейтинга в цвете больше нет.
- Меню «Настройки» в HUD содержит выбор темы и шесть акцентных образцов;
  ошибки хранилища показываются тостом.
- Секция `Motion` в HUD: чипы `Off`/`Low`/`Normal`/`High` и чекбокс
  `Reduce motion`; изменения применяются сразу и сохраняются. При
  `reduce_motion` эффективная реактивность — `Off`, но настройка `motion`
  не перезаписывается.
- Число столбцов визуализатора (`viz_bars`) меняется в меню «Настройки» и
  применяется к следующему кадру.

## 6. Ограничения

- Нет произвольного цвета, градиентов и пользовательских файлов тем.
- `System` следует теме, которую eframe получает от окружения; если оконный
  менеджер её не сообщает, egui использует тёмную тему.
- Настройки не синхронизируются между машинами и не доступны через IPC.
- Светлая палитра требует отдельной проверки контраста при добавлении новых
  элементов.

## 7. Тестирование

Unit-тесты в `src/settings/mod.rs` покрывают XDG-пути и fallback на `HOME`,
значения по умолчанию, roundtrip темы и акцента, недостающие поля, повреждённый
файл и эфемерное хранилище. В `app.rs` проверяются маппинг режима темы, выбор
контрастного текста и затемнение акцента в светлой палитре.

Живой тест: изолированные `XDG_CONFIG_HOME`/`XDG_DATA_HOME`, переключение
«Системная/Тёмная/Светлая» и акцентов, проверка `settings.json`, перезапуск и
сохранение выбора.
