# Модуль: Локальная статистика прослушивания

**Путь в коде:** `src/stats/mod.rs`  
**Ответственность:** Хранение и накопление счётчиков прослушанного времени на
устройстве: файл `stats.json` схемы 1, пределы списков, атомарная запись, сводки
для UI, CLI и IPC.  
**Зависимости:** serde, serde_json, thiserror, `services::Station`,
`storage::write_atomic`, std  
**Решение:** ADR-0049 «Локальная статистика прослушивания», контракт файла и
команд — `docs/interfaces/17-stats.md`

---

## 1. Назначение и границы приватности

Единственная точка работы с цифрами прослушанного. Модуль отвечает на вопросы
«сколько я слушаю», «какие станции, страны и жанры» без аккаунта, сервера и
синхронизации. Счётчики живут **только на устройстве**: в коде нет адресов
телеметрии, статистика никуда не отправляется и не читается из другого процесса
в обход IPC (README §(г), ADR-0049).

Модуль не знает про egui, GUI, IPC, `Session` и `settings`: он хранит счётчики,
считает сводки и пишет файл. Решение «какая станция сейчас активна», «сколько
секунд прошло» и «разрешён ли учёт» принимает Application Core
(`docs/interfaces/10-session.md` § 3.2).

## 2. Состав модуля

| Файл | Назначение |
|------|------------|
| `mod.rs` | `StatsStore`, `StationStat`, `StatsSnapshot`, `StatsError`, `default_path`, лимиты, сводки по странам/тегам/дням |

Отрисовка раздела настроек — не здесь: она живёт в `src/ui/stats_view.rs`
(`docs/modules/14-ui-settings.md`), модуль не содержит UI-типов.

## 3. Данные и инварианты

```rust
/// Версия формата файла и ответа (`docs/interfaces/17-stats.md`).
pub const SCHEMA: u32 = 1;
/// Потолок записей по станциям: при переполнении выбывает наименьшая по `seconds`.
pub const STATION_LIMIT: usize = 500;
/// Потолок дат глобального бакета `days`; старые даты выбрасываются первыми.
pub const DAY_LIMIT: usize = 730;
/// Сколько накопленных секунд требует записи на диск.
pub const FLUSH_SECS: u64 = 30;
```

- Счётчики хранятся **только по станциям**; сводки по странам, тегам и дням
  считаются при чтении и в файл не пишутся (интерфейс 17 § 2).
- `seconds` — накопленное время в состоянии `Playing`; `sessions` — число
  запусков станции, а не секунд: он отличает «слушал фоном один вечер» от
  «включал десять раз по минуте».
- `name`, `countrycode`, `tags` пишутся при первой встрече и обновляются, если
  каталог дал более полные данные; при этом `seconds` и `sessions` не
  сбрасываются. `tags` усекаются до 128 байт по границе тега.
- Запись станции внешнего потока без каталожного UUID получает ключ
  `external:<fnv1a64(url)>` — 16 шестнадцатеричных разрядов FNV-1a 64-бит, без
  новых зависимостей; адрес в файл не пишется — только имя потока
  (ADR-0025, ADR-0040).
- `days` — глобальные секунды по UTC-датам `YYYY-MM-DD`: лексикографический
  порядок ключа совпадает с хронологическим, поэтому вытеснение старых дат —
  отсечение начала порядка. Своего часового пояса в приложении нет, дата
  считается civil-from-days от unix-секунд.
- Порядок в файле: станции — от больших `seconds` к меньшим, пустой список —
  валидное состояние.

## 4. Персистентность

```
$XDG_DATA_HOME/orbitfm/stats.json
$HOME/.local/share/orbitfm/stats.json   (если XDG_DATA_HOME не задан/относителен)
```

- Формат — JSON `{ "schema": 1, "updated_at": …, "stations": […], "days": {…} }`
  в том виде, что показывает интерфейс 17 § 2: файл читается и правится вручную.
- Запись атомарная: `stats.json.tmp` → `rename` через общий
  `storage::write_atomic` (`src/storage.rs`); каталог создаётся при
  необходимости, при неудаче временный файл удаляется.
- Отсутствующий файл — пустая статистика, а не ошибка.
- Неразбираемый или нечитаемый файл — статистика начинается с нуля, исходник не
  перезаписывается до первой успешной записи (тот же подход, что у
  `StationLibrary`); Application Core показывает тост, воспроизведение от ошибки
  не зависит.
- Ошибка записи возвращается вызывающему: счётчики остаются в памяти, GUI
  показывает существующий тост `NoticeKey::SettingNotSaved` (ADR-0049 § 7).
- Пока накопленное не изменилось, записи нет: фоновой записи по таймеру модуль не
  ведёт.
- Файл содержит приватные данные и живёт в каталоге данных пользователя;
  наружу он не отдаётся и никуда не копируется (§ 1, ADR-0049).

## 5. Накопление и сброс на диск

Контракт семантики — ADR-0049 § 1, § 4 и `docs/interfaces/17-stats.md` § 3:

| Событие | Реакция |
|---------|---------|
| Секунда состояния `Playing` | `record` добавляет время активной станции и текущему дню |
| Запуск станции | `note_start` увеличивает `sessions`, включая перезапуск того же потока после реконнекта |
| `FLUSH_SECS = 30` накопленных секунд | `flush` пишет файл одной атомарной записью |
| Уход из `Playing`, смена станции, `stats clear`, выключение `stats_enabled`, завершение процесса | внеочередной `flush` |
| `stats_enabled = false` | Core перестывает звать `record` и `flush`; накопленное сбрасывается, файл остаётся |

Счётчики переживают закрытие окна вместе с `Session`; при аварийном завершении
процесса теряется максимум `FLUSH_SECS` секунд — это принято осознанно.

## 6. Публичный API и потребители

```rust
pub struct StatsStore { /* path: Option<PathBuf>, data: StatsData, pending: u64 */ }

impl StatsStore {
    pub fn load_default() -> Result<Self, StatsError>;
    pub fn load(path: PathBuf) -> Result<Self, StatsError>;
    pub fn ephemeral() -> Self;
    pub fn path(&self) -> Option<&Path>;
    /// Секунды, накопленные с последней успешной записи.
    pub fn pending(&self) -> u64;
    /// Добавляет секунды активной станции и текущему дню; обновляет метаданные.
    pub fn record(&mut self, station: &Station, seconds: u64, now: u64);
    /// `sessions += 1` для запуска станции.
    pub fn note_start(&mut self, station: &Station, now: u64);
    /// Пишет файл, если `pending > 0`; без накопленного — no-op.
    pub fn flush(&mut self) -> Result<(), StatsError>;
    /// Сбрасывает счётчики и пишет пустую схему 1; идемпотентен.
    pub fn clear(&mut self) -> Result<(), StatsError>;
    /// Сводка для UI, `stats` и `stats --json`.
    pub fn snapshot(&self) -> StatsSnapshot;
}

pub struct StatsSnapshot { /* total, week, month, станции, страны, теги, дни */ }
```

| Потребитель | Что берёт |
|-------------|-----------|
| `Session` (`src/session/`) | `record`, `note_start`, `flush`, `clear`, `pending` — единственные пути изменения счётчиков; гейт `stats_enabled` держит Core, модуль про настройку не знает |
| Окно настроек (`src/ui/stats_view.rs`) | `snapshot()` — суммарные минуты, минуты за 7 и 30 дней, топ-10 станций, стран и тегов |
| IPC и CLI (`stats`, `stats --json`) | `snapshot()` плюс `clear()`; JSON-конверт собирается в Core, модуль схемы ответа не сериализует |
| `park()` | тот же `record`/`flush`: накопление не зависит от видимости окна |

Списки снимка после построения не растут, поэтому держат `Box<[…]>`, а не `Vec`
(`docs/AGENTS.md` § 5.1). Сводки считаются один раз по запросу, а не на каждый
кадр: горячий путь UI их не пересобирает.

## 7. Границы

- **Не трогать `library.json`.** Избранное и история — отдельный переносимый
  контракт (ADR-0013, ADR-0046, интерфейс 15); приватные счётчики в него не
  попадают и экспорт схемы 1 от этого не растёт.
- **Не ходить в сеть.** У статистики нет ни одного сетевого пути, при любом
  профиле сети (ADR-0048) включая `offline-first`.
- **Не менять `status --json`.** Поле статистики в схему 1 статуса не
  добавляется (ADR-0037, ADR-0049 § 6).
- **Не обслуживать browser native host.** Команды `stats` вне белого списка
  ADR-0038.
- **Не знать про egui и язык.** Строки раздела даёт каталог `i18n`
  (`docs/interfaces/12-i18n.md`), ошибки — `NoticeKey::SettingNotSaved`.
- **Не синхронизироваться между процессами** — единственность экземпляра
  обеспечивает single-instance (ADR-0005).

## 8. Ограничения и открытые вопросы

- Статистика не переживает чистку каталога данных и не переносится между
  устройствами: экспорт — вне объёма ADR-0049 § 8, позже только аддитивная схема
  и только по явному желанию пользователя.
- `days` считается по UTC-дате: у слушателя восточнее UTC вечерние секунды
  попадают в бакет «завтра».
- Станции, переименованные каталогом, сохраняют имя из первой записи до
  обновления метаданных.
- Время, сыгранное до внедрения счётчиков, не восстанавливается: история
  длительности не хранит.
- Ключ внешнего потока — FNV-1a 64-бит, дата `days` — civil-from-days от
  unix-секунд. Оба считаются своими ~15 строками в модуле: `sha2` и `ring`
  прямыми зависимостями не являются, `chrono`/`time` в дереве нет, а
  `docs/AGENTS.md` § 1 запрещает добавлять зависимости без обоснования (ADR-0049 § 3).

## 9. Тестирование

Unit-тесты в `src/stats/mod.rs` (временные каталоги — dev-зависимость `tempfile`,
реальный `$HOME` не используется):

| Случай | Что проверяется |
|--------|-----------------|
| `default_path_prefers_absolute_xdg_data_home`, `default_path_falls_back_to_home_for_relative_xdg` | путь файла по XDG, как у библиотеки |
| `missing_file_loads_empty_stats` | отсутствие файла — пустая статистика, не ошибка |
| `corrupt_file_starts_from_zero_and_keeps_original` | неразбираемый JSON даёт ноль, файл не перезаписан до первой успешной записи |
| `roundtrip_persists_seconds_sessions_and_days` | запись и чтение сохраняют счётчики и `updated_at` |
| `station_eviction_drops_the_smallest_seconds` | 501-я станция вытесняет запись с наименьшим `seconds`, лимит `STATION_LIMIT` держится |
| `day_eviction_drops_the_oldest_dates` | `DAY_LIMIT` и отсечение старых дат по порядку ключа |
| `metadata_refresh_keeps_counters` | более полные `name`/`countrycode`/`tags` обновляются без сброса `seconds` и `sessions` |
| `tags_are_clipped_to_128_bytes_on_tag_boundary` | усечение не разрывает тег посередине |
| `external_key_hides_the_url` | ключ `external:<fnv1a64(url)>`, в файле нет адреса |
| `flush_writes_once_per_threshold` | ниже `FLUSH_SECS` записи нет, на пороге — одна атомарная запись, `.tmp` не остаётся |
| `clear_is_idempotent_and_writes_empty_schema` | `clear` при нулевых счётчиках тоже пишет пустую схему 1 |
| `snapshot_ranks_top_ten_and_windows` | топ-10 станций/стран/тегов, `week`/`month` по 7 и 30 датам, `days` — не больше 30 последних, новые первыми |
| `ephemeral_store_keeps_counters_without_file` | хранилище в памяти не создаёт файла |

Сторона `Session` (накопление только в `Playing`, сброс при уходе из эфира,
смене станции, выключении `stats_enabled`, `stats clear` и завершении процесса)
фиксируется тестами `src/session/` — `docs/interfaces/10-session.md` § 10.
