# Модуль: IPC и Single-instance

**Путь в коде:** `src/ipc/`  
**Ответственность:** Обеспечение единственного экземпляра процесса, приём и маршрутизация команд.  
**Зависимости:** tokio (Unix socket и Windows named pipe)

---

## 1. Назначение

- Гарантировать single-instance
- Принимать команды от CLI, Noctalia и других клиентов
- Передавать запросы в Application Layer и возвращать клиенту фактический результат

Модуль не содержит бизнес-логики: он разбирает протокол, ставит запрос в очередь и ждёт
ответа Application Core.

## 2. Состав модуля

| Файл | Назначение |
|------|------------|
| `mod.rs` | Публичный фасад (`IpcServer`, `IpcCommand`, `IpcError`, `IpcRequest`, `WakeFn`) |
| `protocol.rs` | Разбор/сериализация команд, лимиты, ошибки |
| `client.rs` | Одноразовый клиент: подключение, отправка, чтение ответа |
| `socket.rs` | Unix-транспорт: путь сокета, bind, проверка «зомби», права `0600`, удаление при Drop |
| `pipe.rs` | Windows-транспорт: named pipe `\\.\pipe\orbitfm`, первый экземпляр и accept-loop |
| `server.rs` | Accept-loop, очередь запросов, ответы через oneshot |

## 3. Публичный интерфейс

```rust
pub type WakeFn = Arc<dyn Fn() + Send + Sync>;

pub struct IpcRequest { /* ... */ }

impl IpcRequest {
    pub fn command(&self) -> &IpcCommand;
    /// Возвращает `false`, если клиент уже отключился.
    pub fn try_respond(self, response: impl Into<String>) -> bool;
}

pub struct IpcServer { /* ... */ }

impl IpcServer {
    /// Занимает сокет. Err(AlreadyRunning), если живой экземпляр уже есть.
    pub async fn try_bind() -> Result<Self, IpcError>;

    /// Забирает очередь запросов. Вызывается один раз при старте App.
    pub fn commands(&mut self) -> mpsc::Receiver<IpcRequest>;

    /// Отправляет команду уже работающему экземпляру.
    pub async fn send_to_existing(command: &str) -> Result<String, IpcError>;

    /// Принимает соединения до сигнала shutdown, затем дожидается ответов.
    pub async fn run(self, wake: WakeFn, shutdown: tokio::sync::oneshot::Receiver<()>);
}

#[derive(Debug, Clone, PartialEq)]
pub enum IpcCommand {
    Toggle,
    Show,
    Hide,
    Play { station_uuid: String },
    Stop,
    Status,
    Quit,
    Volume { level: f64 },
    Raw(String),                     // для расширяемости протокола
}
```

`IpcServer` — конкретная структура, а не трейт: в тестах используется внутренний
`try_bind_at(path)`, позволяющий занять временный сокет или pipe.

## 4. Транспорт

| Платформа | Механизм              | Адрес | Статус |
|-----------|-----------------------|-------|--------|
| Linux     | Unix Domain Socket    | `$XDG_RUNTIME_DIR/orbitfm.sock` | Реализовано |
| macOS     | Unix Domain Socket    | `$TMPDIR/orbitfm.sock` (fallback) | Реализовано, CI-тесты |
| Windows   | Named Pipe            | `\\.\pipe\orbitfm` | Реализовано, CI-компиляция |

Требования к сокету:

- `XDG_RUNTIME_DIR` обязателен на Linux, должен быть абсолютным каталогом с правами `0700`;
  при нарушении — `IpcError::SocketPath`
- права на сокет `0600` выставляются сразу после bind
- рядом создаётся lock-файл `orbitfm.lock`; эксклюзивная блокировка удерживается на время
  жизни процесса и сериализует проверку/очистку сокета между одновременными запусками
- при `AddrInUse` выполняется пробное подключение (500 мс):
  - живой сокет → `AlreadyRunning`
  - `ConnectionRefused`/`NotFound` → «зомби» удаляется, bind повторяется
  - таймаут или иная ошибка → `AlreadyRunning` (файл не удаляется)
- путь, существующий и не являющийся Unix-сокетом, не удаляется (`SocketPath`)
- `SocketGuard` удаляет сокет при завершении сервера, удерживая lock

## 5. Протокол

Текстовый, одна команда = одна строка `\n`, максимум 4096 байт.

```
toggle
show
hide
play <stationuuid>
stop
status
quit
volume <0.0..=1.0>
```

- Ответ: `ok`, `error <сообщение>` или многострочный `status`
- `status` возвращает `status <state>`, при наличии станции — `stationuuid <uuid>` и
  `name <name>`, затем `volume <0.00>` и `window visible|hidden`;
  состояние — `stopped|playing|paused|buffering|reconnecting|error`
- `play <uuid>` ищет станцию в результатах последнего поиска, затем в каталоге Radio
  Browser (таймаут 8 с), запускает `url_resolved` и отправляет click; ошибки каталога
  возвращаются как `error <сообщение>`
- `stop` и `volume` управляют аудио-ядром; `stop` не сбрасывает последний URL, поэтому
  MPRIS `Play` может перезапустить поток
- Завершение ответа — EOF; сервер пишет финальный `\n` и закрывает соединение
- Пустой ответ и неизвестная команда (`Raw`) обрабатываются как ошибки на стороне App
- Лишние аргументы и невалидный `volume` отклоняются на этапе разбора
- Входное чтение ограничено `MAX_COMMAND_BYTES + 2` байтами, поэтому длина строки не
  может вызвать неограниченную аллокацию; невалидный UTF-8 отклоняется с ошибкой
- Размер ответа, принимаемого клиентом, ограничен 64 КиБ

Полная спецификация команд и ответов — `docs/interfaces/05-ipc.md`.

## 6. Таймауты

| Этап | Таймаут |
|------|---------|
| Подключение клиента | 1 с |
| Чтение команды сервером | 2 с |
| Постановка в очередь | 1 с |
| Ожидание ответа App | 10 с |
| Ожидание ответа клиентом | 12 с |
| Дренаж соединений при shutdown | 1 с |

Дополнительно одновременно обслуживается не более 64 соединений; лишние отклоняются.
Таймауты защищают от зависшего клиента и от блокировки accept-loop. Каждое соединение
обрабатывается отдельной задачей, поэтому медленный клиент не мешает остальным.

## 7. Жизненный цикл

1. `main` пытается отправить команду существующему экземпляру.
2. Если сокета нет:
   - `toggle`/`show` → запуск GUI;
   - остальные команды → ошибка `OrbitFM не запущен`.
3. При запуске вызывается `IpcServer::try_bind()`.
4. Если пришёл `AlreadyRunning` (гонка) — команда повторно отправляется живому процессу.
5. `commands()` передаёт очередь в `OrbitApp`, `run(wake)` поднимает accept-loop.
6. `wake()` вызывает `egui::Context::request_repaint()`, чтобы скрытое окно обработало
   команду даже без пользовательского ввода.
7. `quit` → App отвечает `ok`, затем `ViewportCommand::Close`; main посылает shutdown,
   сервер прекращает accept и ждёт активные соединения до 1 с, после чего `SocketGuard`
   удаляет сокет. Это гарантирует доставку ответа на `quit`.

Закрытие окна пользователем — Hide, а не завершение процесса (ADR-0005).

## 8. Тесты

Покрыто в `src/ipc/`:

- разбор всех команд, `play`, `volume`, отказ невалидных значений и лишних аргументов;
- сохранение неизвестных команд как `Raw` и round-trip через wire-формат;
- запрос → очередь → `try_respond` → ответ клиенту + вызов `wake`;
- `AlreadyRunning` для живого сокета;
- замена «зомби»-сокета;
- права `0600`;
- `NotRunning` при отсутствии сокета;
- удаление сокета после завершения сервера;
- отказ от переразмерной команды и невалидного UTF-8 без постановки в очередь;
- доставка ответа после сигнала shutdown (дренаж).
