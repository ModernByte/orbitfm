# OrbitFM TUI — карта версий и дорожная карта

**Организация:** ModernByte  
**Дата:** 2026-11-21  
**Статус:** спроектировано, код не начат; версии TUI независимы от версий ядра  
**Связано:** [хаб TUI](README.md) · [язык дизайна](../ui/tui-design-system.md) ·
[план трека](../../.agents/plans/tui-modern-design-and-delivery.md) ·
[ADR-0047](../adr/0047-tui-ratatui.md) · [интерфейс 16](../interfaces/16-tui.md) ·
[модуль 19](../modules/19-tui.md)

Карта отвечает на вопросы: **какая версия TUI что даёт, в каком порядке это
делать, что важнее и сколько это стоит**. Версия ядра и версия TUI
развиваются независимо; совместимость определяется конвертом `ev: 1` и
`status.schema: 1`.

`events --spectrum` — обязателен для 0.2.0 (`CRX-1` = P0); поставка — и
source-only (`cargo install`), и отдельный релизный артефакт (`PKG-1`
закрыт). Android возобновляется отдельным решением.

## 2. Milestones и критерии готовности

### 2.1. TUI 0.1.0 «Spark» — рабочий MVP

**Цель:** терминальный клиент, которым реально можно слушать и управлять.

Критерии (совпадают с `docs/ROADMAP.md` «Трек TUI»):

- [ ] При живом `orbitfm` видно now playing; громкость меняется из TUI.
- [ ] Играют станции из Favorites, History и Search; `library.json` не читается.
- [ ] `q` не останавливает эфир; `Q` + подтверждение останавливает ядро.
- [ ] Понятная ошибка без ядра; GUI не поднимается.
- [ ] Нет паники при resize и пустых списках; терминал восстановлен после
      выхода, ошибки и паники.
- [ ] `schema`/`ev` несовпадение — понятная ошибка совместимости без частичного
      управления.
- [ ] Компонентный кит и токены соответствуют
      [`docs/ui/tui-design-system.md`](../ui/tui-design-system.md).

### 2.2. TUI 0.2.0 «Orbit» — собственное лицо

**Цель:** визуализаторы и btop-подобные компоновки, отличающие TUI от CLI.

- [ ] `v` циклит `bars`/`ring`/`scope`/`pulse`; `V` скрывает; выбор сохраняется
      в `tui.toml`.
- [ ] Пресеты `desk`/`focus`/`library`/`minimal` переключаются на лету;
      `dashboard` доступен на `≥ 120` колонок и не ломает меньший экран.
- [ ] `m` включает/выключает модули без пустых зон; скрытый модуль не тикает.
- [ ] `motion=off` и `NO_COLOR` дают статичный читаемый экран; фактический FPS
      виден в статусе.
- [ ] `events --spectrum` реализован в ядре и питает reactive-режим
      (P0 по решению владельца); `viz procedural` — только честный fallback
      для ядра без флага, не целевой режим; скрытый визуализатор не тикает.
- [ ] Help, быстрый таймер сна, строка статуса, тесты и live-приёмка.

### 2.3. TUI 0.3.0 «Deep Field»

- [ ] `stars`/`heat`.
- [ ] Прямой сокет-клиент за тем же `CoreClient` (UI не меняется).
- [ ] Мышь; image protocol для favicon (только fun, не must).

### 2.4. TUI 1.0.0 «Polaris»

- [ ] Контракт `tui.toml` и UI-модулей заморожен.
- [ ] Проверены нагрузка, память длинной сессии, отсутствие утечек процессов.
- [ ] Решение владельца о поставке принято и реализовано (source-only или
      артефакт).
- [ ] Локализация — только если владелец решит (`LOC-1`).

**S** ≈ 1 день, **M** ≈ 2–3 дня, **L** ≈ 4–6 дней, **XL** > недели.

## 4. Критический путь

```
DSN-0 → ADR-R3 → FND-1 → FND-2 → FND-6 → CLC-1 → CLC-2 → SCR-1
      → SCR-2/3/4 → QAT-3 → MVP 0.1.0
      → VIZ-1 → VIZ-2..5 → LAY-1/2 → MOT-1 → 0.2.0
      → CRX-1 (спектр, можно параллельно, не блокирует procedural)
      → T6-1..4 → 0.3.0 → STB-1 → 1.0.0
```

Блокеры: **ADR-R3** (публичные поля `tui.toml`) и **решение владельца о старте
кода**. Headless-трек (`HLR-1`) разблокирует сценарий чистого SSH, но не
блокирует 0.1.0–0.2.0.

## 5. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Нет headless — чистый SSH не работает | Высокое | Честная ошибка в v1; отдельный ADR `HLR-1` |
| `library` отдаёт только 20+20 | Среднее | Документированный лимит; later аддитивная пагинация IPC |
| Задержки CLI-ребёнка | Среднее | Долгоживущий `events`; worker + таймаут 15 с; later сокет |
| Терминальная инъекция из каталога | Высокое | Санитизация C0/C1/DEL/ESC/bidi + `unicode-width` |
| Visualizer жжёт CPU/батарею | Среднее | Opt-in `spectrum`, ≤ 15 FPS, `motion=off`, скрытый модуль не тикает |
| `q` путают с остановкой эфира | Высокое | Подвал `q quit TUI · daemon still running`, `Q` + confirm |
| Procedural-анимация выдаётся за спектр | Среднее | Статус `viz procedural`; запрет в ADR |
| Расползание scope (мышь, темы, локализация) | Среднее | Мышь/image/l10n — 0.3.0+/Later, не раньше 0.2.0 |
| Сдвоенный процесс / второе аудио | Критично | Жёсткий инвариант: TUI без libmpv; ревью `SEC-1` |
| Расхождение версий TUI/ядра | Среднее | Гейты `schema`/`ev`; Help показывает обе версии |

## 6. Явно отложено

- Мышь, image protocol (Kitty/sixel), favicon.
- Полный список избранного > 20 записей.
- `play-url`, `library-export`/`library-import` в TUI.
- Локализация UI TUI.
- Динамический заголовок окна, OSC 8.
- Пятый релизный артефакт без решения владельца.
- Headless-ядро — отдельный трек, не часть 0.1.0–0.2.0.

## 7. Связь с картами версий ядра и решения по приоритету

**Решения владельца от 2026-11-21:** Android Companion поставлен на паузу и не
конкурирует за время; трек TUI поднят в приоритете, но по-прежнему не меняет
контракты ядра, кроме аддитивного `events --spectrum`. Поставка TUI — сразу два
канала: source-only и отдельный релизный артефакт (формат выбирает `tui-lead`).
Android возобновляется отдельным решением и не блокируется TUI.


TUI появляется как отдельная строка в `docs/VERSIONMAP.md` только когда есть
релизуемое содержимое; до этого трек отслеживается в `docs/ROADMAP.md` и этой
карте. Версия TUI не входит в основной релизный ряд ядра и не влияет на его
схемы: `status.schema` и `ev` остаются `1`, `spectrum` — аддитивный кадр.
