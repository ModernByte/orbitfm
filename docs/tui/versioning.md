# OrbitFM TUI — версионирование

**Организация:** ModernByte  
**Дата:** 2026-11-21  
**Статус:** действует для `crates/orbitfm-tui`  
**Связано:** [хаб TUI](README.md) · [карта версий](roadmap.md) ·
[ADR-0047](../adr/0047-tui-ratatui.md) §8 · `crates/orbitfm-tui/build.rs`

Версия TUI **динамическая**: базовое число semver живёт в манифесте, а точное
происхождение сборки (коммит, грязь, дата) вшивается на этапе сборки и всегда
видно в `--version`. Руками строку версии никто не правит и не «забывает
поднять» — это исключено конструкцией.

---

## 1. Из чего складывается версия

```
        Cargo.toml version            ORBITFM_TUI_VERSION (релиз)
                  │                              │
                  └──────────────┬───────────────┘
                                 ▼
                     base semver  (0.1.0)
                                 │
        build.rs  ──►  git sha + dirty, дата сборки (SOURCE_DATE_EPOCH)
                                 ▼
        orbitfm-tui 0.1.0+abc1234def0-dirty
```

| Компонент | Источник | Пример |
|-----------|----------|--------|
| Базовая версия | `[package].version` в `crates/orbitfm-tui/Cargo.toml` | `0.1.0` |
| Переопределение на релизе | env `ORBITFM_TUI_VERSION` (ставит CI по тегу) | `0.2.0` |
| git-состояние | `git rev-parse --short=12 HEAD` + `git status --porcelain` | `abc1234def0`, `abc1234def0-dirty` |
| Дата сборки | `SOURCE_DATE_EPOCH` (воспроизводимость) или текущее UTC | `2026-11-21` |

Раскрывается в `src/version.rs`:

- `VERSION` — база (`0.1.0`);
- `GIT` — `sha`, `sha-dirty` или `unknown`;
- `BUILD_DATE` — `ГГГГ-ММ-ДД`;
- `semver()` — `0.1.0+abc1234def0-dirty` (build-метаданные semver);
- `long()` — многострочная строка для `--version`.

---

## 2. Где видно

| Поверхность | Что показывает |
|-------------|----------------|
| `orbitfm-tui --version` / `-V` | полная строка: semver, git, дата, совместимость ядра |
| `orbitfm-tui --help` / `-h` | короткий semver в заголовке справки |
| Header в TUI | `v{VERSION}` (короткая форма) |
| Строка статуса | тема/конфиг (версия ядра появится в волне 2) |

Пример:

```text
$ orbitfm-tui --version
orbitfm-tui 0.1.0+abc1234def0-dirty
git abc1234def0-dirty · build 2026-11-21 · working tree dirty
core >= 0.18.0-rc.1 (ev 1, status schema 1)
```

`-dirty` — честный сигнал: бинарь собран из дерева с незакоммиченными
изменениями, и его поведение может отличаться от тега.

---

## 3. Совместимость с ядром

Версия TUI **независима** от версии ядра (ADR-0047 §8). Совместимость
определяется контрактом, а не числами:

- `ev: 1` — конверт потока событий;
- `status.schema: 1` — схема `status --json`;
- целевое ядро `>= 0.18.0-rc.1`.

Эти константы — в `src/version.rs` (`EV`, `STATUS_SCHEMA`, `CORE_MIN`) и
печатаются в `--version`. При `ev: 2`/`schema: 2` TUI показывает ошибку
совместимости и не отправляет команд (интерфейс 16 §9).

---

## 4. Политика подъёма версии

TUI следует [SemVer](https://semver.org/lang/ru/):

| Изменение | Версия |
|-----------|--------|
| Исправление поведения без смены UX | PATCH (`0.1.0 → 0.1.1`) |
| Новая возможность/экран/визуализатор | MINOR (`0.1.0 → 0.2.0`) |
| Ломающее изменение UX или `tui.toml` вне аддитивности | MAJOR (`0.x.0 → 1.0.0`) |

Практика трека: MINOR-версия совпадает с milestone
([карта версий](roadmap.md)); базовая строка в манифесте поднимается **в том
же коммите**, что и сама возможность, а не отдельным «release»-коммитом.

---

## 5. Релизный тег

- Тег TUI — `tui-vX.Y.Z` (отдельно от тегов ядра `vX.Y.Z-rc.N`).
- CI-задача TUI выставляет `ORBITFM_TUI_VERSION` из тега перед сборкой
  артефакта, поэтому `--version` релизного бинаря показывает ровно тег без
  суффикса `-dirty`.
- Source-only установка `cargo install --path crates/orbitfm-tui` версию не
  подменяет: на чистом дереве выходит `X.Y.Z+sha`, на грязном — `X.Y.Z+sha-dirty`.

---

## 6. Воспроизводимость

- `SOURCE_DATE_EPOCH` фиксирует дату сборки (hermetic/reproducible builds).
- `build.rs` ставит `rerun-if-changed` на `build.rs`, `.git/HEAD`, `.git/index`,
  `.git/refs` и `rerun-if-env-changed` на `ORBITFM_TUI_VERSION`/
  `SOURCE_DATE_EPOCH`, поэтому версия не «залипает» между сборками.
- Если git недоступен (сборка из архива crates.io), `GIT = unknown`, и версия
  выводится как `X.Y.Z` без метаданных — без паники и без выдумки.

---

## 7. Чего не делаем

- Не пишем версию строкой в коде или в документации как источник истины.
- Не добавляем дату в semver-число (только в build-метаданные/`--version`).
- Не путаем версию TUI с версией ядра и не заставляем их совпадать.
- Не считаем `-dirty` ошибкой: это честная маркировка локальной сборки.
- Не тянем `chrono`/`time` в build-зависимости ради даты: UTC считается
  встроенным алгоритмом `civil_from_days`.
