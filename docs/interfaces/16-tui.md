# Интерфейс: TUI ↔ ядро OrbitFM

**Статус:** принят к реализации (ADR-0047, 2026-11-03; ревизия 2 —
визуализаторы); кода TUI ещё нет  
**Клиент:** `orbitfm-tui`  
**Ядро:** `orbitfm` `>= 0.18.0-rc.1`; `spectrum`-кадры — будущее аддитивное
расширение  
**Транспорт:** публичный CLI/IPC; прямой сокет в v1 не используется

## 1. Назначение

Контракт описывает, как терминальный клиент `orbitfm-tui` получает состояние
и управляет уже работающим ядром. TUI не является вторым плеером: он не
содержит libmpv, не создаёт MPRIS-агента, не читает `library.json` и не
обращается к Radio Browser.

Схема взаимодействия:

```
┌──────────────────┐   Command + args   ┌──────────────────┐   IPC    ┌─────────────┐
│   orbitfm-tui    │ ─────────────────► │ orbitfm CLI      │ ───────► │ orbitfm core│
│ ratatui + crossterm                  │ (адаптер)        │          │ libmpv +    │
│                  │ ◄──── stdout ───── │                  │ ◄─────── │ session     │
│                  │ ◄──── events ───── │ orbitfm events   │ ◄─────── │ StatusFeed  │
└──────────────────┘   NDJSON           └──────────────────┘   IPC    └─────────────┘
```

Граница `CoreClient` изолирует UI от способа доставки. В v1 используется
`CliCoreClient`; будущий прямой клиент сокета обязан реализовать тот же
контракт и не менять UI.

## 2. Планируемый Rust-контракт

```rust
pub trait CoreClient: Send {
    /// Запускает долгоживущую подписку `orbitfm events`.
    /// `spectrum` запрашивает аддитивные кадры визуализатора (§4.1).
    fn start_events(&mut self, spectrum: bool) -> Result<EventStream, CoreError>;

    /// Выполняет one-shot команду в worker-потоке.
    fn execute(&mut self, command: CoreCommand) -> Result<CoreReply, CoreError>;
}

pub type EventStream = std::sync::mpsc::Receiver<CoreEvent>;

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum CoreCommand {
    PlayResult(String),
    Play(String),
    PlayLibrary(String),
    PlayPause,
    Stop,
    Next,
    Previous,
    Roulette,
    VolumeUp,
    VolumeDown,
    Favorite(Option<String>),
    Search(String),
    Library,
    Sleep(u16),
    ClearSleep,
    Quit,
}

#[derive(Debug, Clone, PartialEq)]
pub enum CoreReply {
    Ok { text: String },
    Search { id: u64 },
    Favorite { favorite: bool },
    Library(LibraryPayload),
}

#[derive(Debug, Clone, PartialEq)]
pub enum CoreEvent {
    State(StatusSnapshot),
    Search(SearchFrame),
    Spectrum(SpectrumFrame),
    Keepalive,
    Disconnected { message: String },
}

/// Нормированный кадр для визуализатора; поля аддитивны к `ev: 1`.
#[derive(Debug, Clone, Copy, PartialEq, Default)]
pub struct SpectrumFrame {
    pub seq: u64,
    pub level: f32,
    pub centroid_hz: f32,
    pub spread_hz: f32,
    pub flatness: f32,
    pub flux: f32,
    pub bands: Option<SpectrumBands>,
}

#[derive(Debug, Clone, Copy, PartialEq, Default)]
pub struct SpectrumBands {
    pub bass: f32,
    pub mid: f32,
    pub high: f32,
}

#[derive(Debug, thiserror::Error)]
pub enum CoreError {
    #[error("OrbitFM не запущен")]
    NotRunning,
    #[error("команда отклонена: {0}")]
    Command(String),
    #[error("некорректный ответ ядра: {0}")]
    Protocol(String),
    #[error("таймаут команды")]
    Timeout,
    #[error("не удалось запустить orbitfm: {0}")]
    Io(String),
}
```

`CoreError::NotRunning` определяется по коду возврата 1 и строке
`OrbitFM не запущен` в stderr дочернего процесса.

## 3. Команды

| Действие TUI | Команда CLI | Ответ | Примечание |
|--------------|-------------|-------|------------|
| Подписка на состояние | `orbitfm events` | NDJSON до EOF | долгоживущий процесс |
| Подписка со спектром | `orbitfm events --spectrum` | NDJSON до EOF | планируемый флаг; кадры `spectrum` |
| Играть из выдачи | `orbitfm play-result <uuid>` | `ok` | только последняя выдача |
| Играть из библиотеки | `orbitfm play-library <uuid>` | `ok` | без каталога |
| Играть по UUID | `orbitfm play <uuid>` | `ok` | резерв после ошибки `play-result` |
| Play/pause | `orbitfm playpause` | `ok` | |
| Stop | `orbitfm stop` | `ok` | |
| Next/previous | `orbitfm next` / `orbitfm previous` | `ok` | |
| Roulette | `orbitfm roulette` | `ok` | |
| Громкость | `orbitfm volume-up` / `orbitfm volume-down` | `ok` | шаг ±0.1 задаёт ядро |
| Избранное | `orbitfm favorite [uuid]` | `favorite true\|false` | UUID обязателен для списков |
| Поиск | `orbitfm search <запрос>` | `search <id>` | результаты — кадром `search` |
| Библиотека | `orbitfm library` | JSON ≤ 64 КиБ | по 20 записей на список |
| Таймер сна | `orbitfm sleep <1..=720>` | `ok sleep <n>` | |
| Снять таймер | `orbitfm sleep clear` | `ok` | |
| Выйти из ядра | `orbitfm quit` | `ok` | только после подтверждения `Q` |

Правила:

- аргументы передаются в `std::process::Command` без shell;
- одновременно выполняется не более одной one-shot команды — worker-поток
  сериализует запросы;
- `play-result` при ошибке `неизвестная станция`/`станция не найдена`
  повторяется один раз как `play <uuid>`; другие ошибки не повторяются;
- громкость меняется только относительными командами; абсолютный `volume`
  в v1 не используется, чтобы не гонять состояние между клиентами;
- `favorite` без UUID применяется к текущей станции; с UUID — к выбранной
  строке списка или выдачи;
- `sleep` принимает только целое `1..=720`; TUI проверяет диапазон до
  отправки;
- `library-export`/`library-import` в TUI v1 не используются;
- `events --spectrum` запускается только когда визуализатор включён и
  `motion != "off"`; при отказе ядра (неизвестный аргумент) TUI один раз
  перезапускает `events` без флага и помечает визуализатор procedural.
  Повторных попыток с флагом в этой сессии нет.

## 4. Поток `events`

Формат кадра — `docs/interfaces/13-events.md`, конверт `ev: 1`.

| Кадр | Поведение TUI |
|------|----------------|
| `snapshot` | заменить состояние, снять баннер «подключение», обновить Now Playing |
| `state` | заменить состояние; перерисовать только при изменении |
| `keepalive` | отметить соединение живым, ничего не рисовать |
| `search` | сопоставить `id` с ожидающим поиском, показать результаты или ошибку |
| `spectrum` | обновить модель визуализатора; не влияет на Now Playing и таймауты |
| неизвестный `type` | игнорировать |
| невалидная строка JSON | учесть ошибку; после 5 подряд — переподключиться |
| EOF | `Disconnected`, баннер, переподключение с backoff |

Требования:

- первый кадр после подключения обязан быть `snapshot`; до него экран
  показывает «подключение к OrbitFM»;
- `status.schema` обязан быть `1`, `status.app` — `orbitfm`; иначе TUI
  показывает ошибку совместимости и не отправляет управляющих команд;
- `ev` обязан быть `1`; кадры с другим `ev` не интерпретируются;
- если 45 секунд не пришло ни одного кадра (три keepalive), соединение
  считается мёртвым и переподключается;
- backoff переподключения: 1, 2, 4, 8, 16, 30 секунд, далее 30;
- `R` в TUI сбрасывает backoff и переподключается немедленно;
- TUI не запускает ядро и не вызывает `show`/`toggle`, чтобы «разбудить»
  экземпляр: `events` не входит в cold-start allowlist.

### 4.1. Кадр `spectrum`

Планируемое аддитивное расширение `ev: 1` (ADR-0047 ревизия 2). Кадр
приходит только подписчику `events --spectrum` и только при `state=playing`:

```json
{"ev":1,"type":"spectrum","seq":42,"level":0.63,
 "centroid_hz":1720.0,"spread_hz":1600.0,"flatness":0.42,
 "flux":0.0018,"bands":{"bass":0.70,"mid":0.55,"high":0.30}}
```

| Поле | Тип | Диапазон | Смысл |
|------|-----|----------|-------|
| `seq` | u64 | монотонный | пропуски означают потерю кадров, не ошибку |
| `level` | f32 | 0..=1 | нормированный RMS |
| `centroid_hz` | f32 | 30..=20000 | спектральный центроид |
| `spread_hz` | f32 | ≥ 0 | спектральный разброс |
| `flatness` | f32 | 0..=1 | шумовой/тональный характер |
| `flux` | f32 | ≥ 0 | скорость изменения спектра |
| `bands` | object/null | 0..=1 | bass/mid/high; `null` — полосы недоступны |

Правила:

- частота публикации — не более 30 Hz, latest-wins; очередь не хранится;
- при `paused`/`stopped`/`error` кадры не публикуются, TUI гасит сцену;
- `keepalive` продолжает приходить по общему правилу 15 с;
- кадр не является частью `status`, не влияет на `snapshot`/`state` и не
  требует `schema: 2`;
- поля с `NaN`/`inf` или вне диапазона игнорируются целиком;
- TUI использует `seq` только для диагностики, не для повторной сборки;
- без флага (ядро 0.18) TUI работает в procedural-режиме и маркирует это в
  статусной строке.

## 5. Состояние

TUI использует подмножество `status --json` схемы 1:

| Поле | Использование |
|------|---------------|
| `schema`, `app`, `version` | проверка совместимости, версия ядра в Help |
| `state` | индикатор `playing/paused/stopped/buffering/reconnecting/error` |
| `station.uuid` | выбор станции, `favorite` |
| `station.name` | заголовок Now Playing и строки списков |
| `station.country`, `countrycode` | подпись станции |
| `station.bitrate`, `codec` | качество в Now Playing |
| `station.source` | метка `radio`/`stream` |
| `station.favorite` | индикатор текущей станции |
| `volume` | полоса громкости |
| `can.previous`, `can.next` | доступность `[`/`]` |
| `sleep` | остаток таймера сна |

Поля `window`, `theme`, `accent`, `language`, `ui` в v1 игнорируются.
`station` может быть `null`; TUI обязан корректно рисовать пустой экран и
не паниковать на пустых строках.

### 5.1. Библиотека

Ответ `orbitfm library`:

```json
{
  "favorites": [
    {
      "uuid": "…",
      "name": "…",
      "country": "…",
      "countrycode": "DE",
      "tags": "…",
      "bitrate": 128,
      "source": "radio"
    }
  ],
  "history": []
}
```

- каждый список содержит не более 20 компактных записей;
- полей `url`, `url_resolved`, `favicon`, `homepage` нет;
- TUI не достраивает отсутствующие поля и не ходит в каталог;
- `source` неизвестного значения отображается как есть, но не влияет на
  запуск: запуск идёт по `uuid`;
- ответ больше 64 КиБ считается ошибкой протокола;
- списки перезапрашиваются при открытии экрана, после `favorite` и после
  успешного запуска станции (история меняется).

### 5.2. Поиск

1. TUI отправляет `search <query>` (после `trim`, непустой, ≤128 символов).
2. Ядро отвечает `search <id>`; TUI запоминает `id` как ожидающий.
3. Кадр `search` с этим `id` приносит до 20 результатов или `error`.
4. Кадры с другим `id` игнорируются.
5. Если кадр пришёл раньше ответа `search <id>`, TUI буферизует его и
   сопоставляет после получения `id`.
6. Таймаут ожидания кадра — 15 секунд; по истечении показывается ошибка,
   ожидание сбрасывается, повторного запроса без действия пользователя нет.
7. Новый запрос отменяет предыдущий: старый `id` перестаёт приниматься.

Результаты поиска — компактные станции того же вида, что `library`:
`uuid`, `name`, `country`, `countrycode`, `tags`, `bitrate`, `source`.
Запуск — `play-result <uuid>`; при ошибке — однократный `play <uuid>`.

### 5.3. Визуализатор и компоновка

Визуализатор не добавляет полей в `status` и не требует команд core.
Единственный источник данных сверх состояния — кадры `spectrum` (§4.1);
без них TUI рисует procedural-анимацию от `state`, `volume` и времени.
Выбор визуализатора, пресета компоновки, набор модулей, `motion`, `glyphs`
и `accent` — локальный конфиг TUI
(`$XDG_CONFIG_HOME/orbitfm/tui.toml`), core его не читает и не валидирует.
Ошибка конфига не блокирует управление: TUI берёт значения по умолчанию и
показывает предупреждение в статусе.

## 6. Ошибки и таймауты

| Ситуация | Поведение TUI |
|----------|----------------|
| Ядро не запущено | экран «OrbitFM не запущен», подсказка запустить ядро; автоповтор с backoff |
| `events` завершился с ошибкой | баннер с последней строкой stderr, переподключение |
| Команда вернула `error …` | строка статуса на 5 секунд, состояние не меняется |
| Команда не ответила за 15 секунд | процесс завершается, `CoreError::Timeout`, строка статуса |
| `library` вернул невалидный JSON | ошибка протокола, списки не обновляются |
| Неизвестная команда ядра | ошибка `Command`, без паники |
| `schema`/`ev` не 1 | ошибка совместимости, управление блокируется |
| Терминал меньше 60×18 | экран «терминал слишком мал», без паники |

Таймаут дочернего процесса — 15 секунд: он больше CLI-таймаута 12 секунд и
покрывает `play` с резолвом каталога. По истечении процесс убивается.

## 7. Выход

- `q` и Ctrl-C восстанавливают терминал и завершают только `orbitfm-tui`.
- `Q` открывает подтверждение «Остановить эфир и выйти из OrbitFM?».
- `y` отправляет `quit`; после `ok` TUI закрывается.
- Если `quit` вернул `OrbitFM не запущен`, TUI закрывается как после
  успешного выхода: ядро уже не работает.
- Любая другая ошибка `quit` показывается, TUI остаётся открытым.
- При выходе дочерний `orbitfm events` завершается и дожидается
  (`kill` + `wait`), чтобы не оставлять сироту.
- Паника и сигнал завершения обязаны восстановить терминал через guard и
  panic hook.

## 8. Безопасность

- TUI не открывает сетевых портов и не подписывается на удалённые адреса.
- TUI не читает `library.json`, `settings.json`, кэш обложек и не пишет
  пользовательские файлы.
- TUI не вызывает Radio Browser и не загружает favicon/homepage.
- Все строки от ядра перед выводом очищаются от C0/C1, `DEL`, `ESC` и
  bidi-переопределений; переводы строк и табы заменяются пробелом. Это
  defense-in-depth поверх санитизации ядра.
- Ширина строк считается по `unicode-width`; длинные значения обрезаются с
  многоточием, чтобы не ломать рамки.
- `ORBITFM_BIN` — доверенная переменная локального пользователя; значение
  не интерпретируется через shell.
- `Q` требует подтверждения; `q` не влияет на эфир.
- TUI не устанавливает динамический заголовок терминала и не печатает OSC 8
  hyperlinks.

## 9. Совместимость

- Целевое ядро — `>= 0.18.0-rc.1`; более старые версии могут работать
  частично, но не поддерживаются.
- TUI требует `ev: 1` и `status.schema: 1`. При `schema: 2` или `ev: 2`
  показывается ошибка «обновите TUI»; частичное управление запрещено.
- Неизвестные поля `status`, `library` и `search` игнорируются.
- Отсутствующий `sleep` (старое ядро) скрывает таймер, не ломая остальное.
- `spectrum` — аддитивный тип кадра; ядро без флага не ломает TUI, а TUI без
  поддержки кадра просто его игнорирует. Смена формы кадра — `ev: 2`.
- Версия TUI независима от версии ядра; Help показывает обе.
- Контракт может расширяться аддитивно: новые кадры `events`, поля
  `status` и команды не требуют смены `ev`/`schema`, пока не меняют
  семантику существующих полей.

## 10. Headless

TUI v1 не запускает ядро. `events`, `search` и остальные команды не входят
в cold-start allowlist; `orbitfm` стартует через `run_window` и требует
дисплея. Поэтому:

- в tmux/терминале на машине с уже работающим ядром TUI работает сразу;
- на чистом SSH без графической сессии нужен будущий headless-режим
  (`--headless` или `ORBITFM_HEADLESS=1`), проектируемый отдельным ADR;
- TUI не вызывает `show`/`toggle` как обходной путь: это подняло бы GUI
  там, где его нет.

## 11. Тесты

Модульные и интеграционные тесты `orbitfm-tui` без реального аудио и сети:

- разбор `snapshot`/`state`/`keepalive`/`search`, неизвестных кадров и
  невалидных строк;
- проверка `schema`/`app`/`ev` и ошибка совместимости;
- сопоставление `search <id>` и кадра `search`, включая обратный порядок и
  чужой `id`;
- таймаут поиска, отмена старым запросом, ошибка кадра;
- разбор `library`, лимит 20, превышение 64 КиБ, невалидный JSON;
- разбор `favorite true|false`, `ok sleep n`, `error …`;
- разбор `spectrum`, отбрасывание NaN/out-of-range, отсутствие влияния на
  состояние; fallback `events --spectrum` → `events` без флага;
- переключение визуализаторов, пресетов и модулей; сохранение и чтение
  `tui.toml`, повреждённый конфиг → defaults;
- `motion=off`/`NO_COLOR`/`glyphs=ascii` дают статичный читаемый кадр;
- `play-result` → fallback `play` только при ошибке поиска станции;
- очистка C0/C1/ESC/bidi и обрезка по `unicode-width`;
- подтверждение `Q`, `q` без команды, ошибка `quit`;
- backoff переподключения и сброс по `R`;
- минимальный размер терминала и пустые списки без паники;
- fake `CoreClient` для UI-тестов; CLI-адаптер проверяется на подменяемом
  runner без запуска настоящего `orbitfm`.

Live-приёмка (после реализации): состояние и громкость при живом ядре,
запуск из избранного и поиска, `q`/`Q`, рестарт ядра с переподключением,
отсутствие паники при resize и пустом поиске, переключение визуализаторов и
модулей на живом эфире без роста CPU выше оговорённого тика.
