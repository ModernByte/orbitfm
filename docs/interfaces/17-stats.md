# Интерфейс: локальная статистика прослушивания (схема 1)

**Организация:** ModernByte  
**Дата:** 2026-11-03  
**Статус:** Контракт схемы 1 (ADR-0049)

Счётчики прослушанного времени, которые живут **только на устройстве**.
Формат версионируется полем `schema`; ломающие изменения требуют `schema: 2`
и нового раздела здесь.

## 1. Назначение и границы приватности

- ответить «сколько и чего я слушаю» без аккаунта, сервера и синхронизации;
- дать CLI, интеграциям и будущему TUI стабильный контракт на чтение;
- не смешивать приватные счётчики с переносимым экспортом библиотеки
  (интерфейс 15) — статистика в него не попадает;
- сохранить обещание README §(г): в коде нет адресов телеметрии, статистика
  никуда не отправляется и не читается из другого процесса в обход IPC.

Единственная операция с файлом — локальное чтение и атомарная запись. Сетевых
запросов у статистики нет ни при каком профиле сети (ADR-0048).

## 2. Файл

`$XDG_DATA_HOME/orbitfm/stats.json` (на Windows — каталог данных приложения).
Временный файл `stats.json.tmp` + `rename`. Отсутствующий файл — пустая
статистика, а не ошибка. Неразбираемый файл — пустая статистика при чтении,
исходник не перезаписывается до первой успешной записи.

```json
{
  "schema": 1,
  "updated_at": 1762156800,
  "stations": [
    {
      "uuid": "c685c086-b716-4edd-b313-d4a7baf1084c",
      "name": "Radio Swiss Pop",
      "countrycode": "CH",
      "tags": "pop,rock",
      "seconds": 5400,
      "sessions": 12,
      "last_at": 1762150000
    }
  ],
  "days": { "2026-11-03": 1800 }
}
```

| Поле | Тип | Обязательность | Смысл |
|------|-----|----------------|-------|
| `schema` | integer | да | Версия формата; пишется только `1` |
| `updated_at` | integer | да | Unix-время последней записи в секундах |
| `stations` | array | нет | Счётчики по станциям, большие первыми |
| `days` | object | нет | Глобальные секунды по датам в UTC, `YYYY-MM-DD` |

Станция:

| Поле | Тип | Смысл |
|------|-----|-------|
| `uuid` | string | `stationuuid` каталога или `external:<fnv1a64(url)>` (16 шестнадцатеричных разрядов) для внешнего потока (ADR-0025) |
| `name` | string | Отображаемое имя из каталога или метаданных потока |
| `countrycode` | string | Двухбуквенный код страны, пустая строка если неизвестен |
| `tags` | string | Сырые теги каталога через запятую, не длиннее 128 байт по границе тега |
| `seconds` | integer | Накопленное время в состоянии `Playing` |
| `sessions` | integer | Число запусков станции |
| `last_at` | integer | Unix-время последней секунды прослушивания |

Пределы и порядок:

- `stations` — не больше `STATION_LIMIT = 500` записей; при переполнении
  выбывает запись с наименьшим `seconds`;
- `days` — не больше `DAY_LIMIT = 730` дат; при переполнении выбрасываются
  самые старые;
- `uuid` внешнего потока не раскрывает адрес: в файл не пишутся URL,
  только имя потока. Ключ — FNV-1a 64-бит от строки `url`, напечатанный шестью
  шестнадцатеричными разрядами: детерминирован между запусками и не требует
  новых зависимостей (`sha2`/`ring` в `Cargo.toml` прямыми не являются);
- дата бакета `days` берётся из UTC по стандартному civil-from-days: своего
  расчёта часового пояса в приложении нет, а `chrono`/`time` не зависят.
  Для слушателя восточнее UTC вечерние секунды попадают в бакет «завтра»;
- метаданные станции обновляются, если каталог дал более полные `name`,
  `countrycode` или `tags`; `seconds` и `sessions` при этом не сбрасываются.

## 3. Накопление

Контракт семантики — ADR-0046 и интерфейс 10:

- считаются только секунды активного состояния `Playing`;
- станция-владелец секунд — активная станция (`status`, MPRIS, панель);
- пауза, загрузка, реконнект, ошибка и стоп не добавляют времени;
- `sessions` увеличивается при каждом запуске станции, включая перезапуск
  после реконнекта того же потока;
- запись на диск: каждые `FLUSH_SECS = 30` накопленных секунд, при уходе из
  `Playing`, при смене станции, при `stats clear`, при выключении
  `stats_enabled` и при завершении процесса;
- `stats_enabled = false` (интерфейс 09) останавливает накопление и запись;
  файл остаётся, новые счётчики не создаются.

Просьба учесть: секунды, наработанные до внедрения счётчиков, не
восстанавливаются — история длительности не хранит.

## 4. Чтение и команды

| Команда | Действие | Ответ |
|---------|----------|-------|
| `stats` | Человекочитаемая сводка | `stats total <seconds>`, `stats enabled <bool>` и топ-5 списки (формат строк — интерфейс 05) |
| `stats --json` | Сводка в JSON схемы 1 | объект §5 |
| `stats clear` | Сбросить счётчики | `ok stats cleared` |

Команды обслуживает **уже запущенный** экземпляр (как `sleep`): новый процесс
они не запускают, без запущенного — `error`. Браузерный native host их не
получает: allowlist ADR-0038 отвечает `forbidden`.

`status --json` остаётся прежним — поле статистики в схему 1 не добавляется.

## 5. Ответ `stats --json`

```json
{
  "schema": 1,
  "app": "orbitfm",
  "version": "0.20.0-rc.2",
  "enabled": true,
  "total_seconds": 246000,
  "week_seconds": 3600,
  "month_seconds": 21600,
  "stations": [
    { "uuid": "c685c086-…", "name": "Radio Swiss Pop", "seconds": 5400,
      "sessions": 12, "last_at": 1762150000 }
  ],
  "countries": [ { "code": "CH", "seconds": 9000 } ],
  "tags": [ { "tag": "pop", "seconds": 42000 } ],
  "days": [ { "date": "2026-11-03", "seconds": 1800 } ],
  "ui": { "total": "Total", "stations": "Stations", "countries": "Countries",
          "tags": "Tags", "clear": "Clear" }
}
```

| Поле | Тип | Смысл |
|------|-----|-------|
| `schema` | integer | Версия ответа; `1` |
| `app` / `version` | string | Как в `status --json` (ADR-0037) |
| `enabled` | bool | Значение `stats_enabled` |
| `total_seconds` | integer | Все накопленные секунды |
| `week_seconds` / `month_seconds` | integer | Секунды за последние 7 и 30 UTC-дат |
| `stations` | array | Топ-10 по `seconds`, большие первыми |
| `countries` | array | Топ-10 сводок по `countrycode` |
| `tags` | array | Топ-10 сводок по грубым тегам |
| `days` | array | Не больше 30 последних дат, новые первыми |
| `ui` | object | Подписи на языке приложения (интерфейс 12) |

Сводные массивы считаются приложением из `stations` и `days`; потребитель не
должен пересобирать их сам. Ответ аддитивный: новые поля не ломают
существующих читателей, как в `status --json`.

## 6. Ошибки

| Случай | Поведение |
|--------|-----------|
| Запущенного экземпляра нет | `error OrbitFM не запущен` (`IpcError::NotRunning`) |
| Файл не читается | Пустая статистика + тост; воспроизведение не страдает |
| Ошибка записи файла | Тост `SettingNotSaved`, счётчики остаются в памяти |
| `stats clear` при нулевых счётчиках | `ok stats cleared` — идемпотентно |
