# Интерфейс: поток событий состояния (`events`)

**Версия конверта:** `ev: 1`  
**Статус:** принят (ADR-0039, 2026-10-31)  
**Транспорт:** тот же IPC-сокет, что у остальных команд (ADR-0005)

## 1. Назначение

`events` — долгоживущая read-only подписка на состояние OrbitFM. Вместо
опроса `status --json` клиент один раз открывает соединение и получает поток
NDJSON-кадров:

- `snapshot` — полный снимок сразу после подключения;
- `state` — полный снимок при каждом изменении;
- `keepalive` — маркер тишины, если состояние не менялось 15 секунд.

Поток не является журналом: промежуточные состояния при медленном чтении
схлопываются, история не хранится. Каждый кадр самодостаточен.

Браузерная панель получает тот же поток через native host (ADR-0038,
интерфейс 14); конверт `ev: 1` при этом не меняется.

## 2. Установка соединения

1. Подключиться к IPC-сокету (тот же путь, что у `status --json`;
   Linux — `$XDG_RUNTIME_DIR/orbitfm.sock`).
2. Записать одну строку `events\n`.
3. Закрыть свою половину соединения (на Unix) или прекратить запись.
4. Читать строки до EOF.

Сервер не читает команды из этого соединения после подписки. Отправлять
`events` повторно в то же соединение не нужно.

При незапущенном экземпляре клиент получает `OrbitFM не запущен`, код
возврата 1. `events` **не** поднимает GUI: команда отсутствует в cold-start
allowlist (ADR-0037 п. 4).

## 3. Формат кадра

Кодировка — UTF-8, один кадр — одна строка, завершённая `\n`. Пробелы внутри
JSON не нормируются. Порядок полей не гарантирован.

### 3.1. Снимок

Первая строка после подписки:

```json
{"ev":1,"type":"snapshot","status":{"schema":1,"app":"orbitfm","version":"0.14.0-rc.1","state":"playing","station":{"uuid":"…","name":"…","country":"Германия","countrycode":"de","tags":"…","favicon":"https://…","homepage":"https://…","bitrate":128,"codec":"MP3"},"volume":0.75,"window":{"visible":true,"mode":"focus"},"theme":"dark","language":"ru","can":{"previous":true,"next":true},"ui":{"play_pause":"Пуск/Пауза","stop":"Стоп","previous":"Предыдущая","next":"Следующая","radio_roulette":"Радиорулетка","settings":"Настройки","show_window":"Показать окно","hide_window":"Скрыть окно","nothing_playing":"Ничего не играет","volume_up":"Громче","volume_down":"Тише"}}}
```

`status` — ровно объект `status --json` схемы 1 (ADR-0037,
`docs/interfaces/05-ipc.md` §4). Поля, их типы и правило совместимости
(`schema` растёт только при удалении/переименовании) те же.

### 3.2. Изменение

```json
{"ev":1,"type":"state","status":{ … }}
```

Полный кадр, без дельт. Приходит после изменения воспроизведения, станции,
громкости, темы, языка, видимости/режима окна или доступности skip-команд.
Одинаковые кадры не публикуются.

### 3.3. Тишина

```json
{"ev":1,"type":"keepalive"}
```

Приходит, если 15 секунд не было `state`. Состояния не несёт. Клиент,
получающий keepalive, продолжает ждать; клиент, не получающий ничего дольше
своего таймаута, переподключается.

## 4. Семантика и гарантии

| Свойство | Гарантия |
|----------|----------|
| Первый кадр | `snapshot`, всегда |
| Полнота | Каждый `snapshot`/`state` содержит полный `status` |
| Порядок | Строки приходят в порядке публикации; промежуточные `state` могут быть пропущены |
| Coalescing | Медленный клиент видит последнее состояние, а не очередь |
| Дубликаты | Кадры с тем же содержимым не публикуются |
| Keepalive | Не реже одного кадра каждые 15 с при молчащем состоянии |
| Скрытое окно | Публикация продолжается; `window.visible` равен `false` |
| Скрытое окно на macOS | `window.visible` отражает `mark_hidden` (ADR-0026) |
| Команды | На соединении не принимаются |
| Завершение | EOF после остановки сервера или при исчерпании бюджета |

### 4.1. Переподключение

После EOF или ошибки чтения клиент открывает новое соединение и снова
получает `snapshot`. Номеров последовательности и replay нет: пропущенные
состояния не восстанавливаются, последнее известно из нового снапшота.

## 5. Бюджеты и ошибки

| Ситуация | Ответ сервера |
|----------|----------------|
| Подписок уже 16 | `error слишком много подписок на события`, затем EOF |
| Первый кадр ещё не опубликован | Сервер ждёт публикацию; ошибки нет |
| Команда `events` с лишними аргументами | `error лишний аргумент: …`, EOF |
| Сервер остановлен | EOF |
| Соединение закрыто клиентом | Соединение освобождает слот; сервер продолжает работу |

Общий потолок IPC-соединений — 64, из них подписок — не более 16. Остальные
слоты гарантированно доступны one-shot командам.

## 6. Совместимость

- `ev` версионирует конверт, `status.schema` — снимок. Они независимы.
- Добавление полей в конверт или `status` не меняет ни `ev`, ни `schema`.
- Удаление или переименование поля `status` — `schema: 2`; смена формы
  конверта — `ev: 2`. Клиент обязан обновляться вместе с ними.
- Клиент обязан игнорировать неизвестные поля и неизвестные `type`, не падать
  на `station: null` и пустом `ui`, а также переподключаться при ошибке
  разбора строки.

## 7. Безопасность

- Тот же сокет с правами `0600`: подписка доступна только владельцу сессии.
- Поток раскрывает те же метаданные станции, что `status --json`; новых
  сетевых целей нет.
- Keepalive не содержит идентификаторов и времени.
- Подписка не принимает управляющих команд и не может изменить состояние.

## 8. Пример клиента (псевдокод)

```text
connect(socket)
write("events\n"); shutdown_write()
for line in read_lines():
    frame = json(line)
    if frame.ev != 1: continue
    match frame.type:
        "snapshot", "state" -> render(frame.status)
        "keepalive" -> touch()
        _ -> ignore
```

## 9. Отношение к `status --json`

| | `status --json` | `events` |
|--|-----------------|----------|
| Соединение | Короткое, one-shot | Долгоживущее |
| Ответ | Одна строка `status` | Поток кадров |
| Задержка | До интервала опроса | Сразу после изменения |
| Скрытое окно | Отвечает по запросу | Публикует сам |
| Cold-start | Нет | Нет |

Опрос `status --json` остаётся поддерживаемым резервным путём для простых
скриптов и для проверки, что приложение живо.
