# План: глобус выбранной страны — слой карты, кластеры и порядок загрузки каталога

| Поле | Значение |
|---|---|
| **Статус** | Принято 2026-11-13 (§ 8); ADR-0065/0066 — «Принято»; реализация — волны 1–5
| **Дата** | 2026-11-13 |
| **База** | `0.22.0-rc.3`, ветка `main` |
| **Связанные ADR** | ADR-0012 (маркеры), ADR-0036 (согласованность списка и глобуса), ADR-0035 (снимок мира), ADR-0043 (офлайн), ADR-0048 (профиль сети), ADR-0059 (бюджет рендера), ADR-0060 (управление камерой), ADR-0064 (политика перерисовки) |
| **ADR** | [ADR-0065](../adr/0065-слой-карты-страны-и-кластеры-маркеров.md) «Слой карты страны и кластеры маркеров»; [ADR-0066](../adr/0066-порядок-загрузки-каталога.md) «Порядок загрузки каталога» — оба **Принято** |
| **Целевой релиз** | следующий минор после `0.22.0`; версия — по решению владельца |

**Коротко.** Сейчас выбор страны наполняет глобус только загруженной страницей
списка (100 строк, из них ~⅓ с координатами, после группировки ~1 км остаётся
~9 точек). Проект: (1) глобус рисует **всю выбранную страну** отдельным слоем
карты, (2) близкие маркеры **кластеризуются**, а наведение на кластер открывает
**веер станций** с выбором, (3) порядок загрузки каталога выносится в настройку
и продумывается до мелочей. Требование «в списке — то и на глобусе» переходит в
«строка списка всегда имеет маркер, а маркер всегда называет свои станции».

---

## 1. Задача

Владелец (2026-11-13): при выборе страны в списке 100 станций, а маркеров
«совсем чуток, явно не сто». Нужно:

1. **Вариант B**: глобус показывает всю выбранную страну, а не первую страницу.
2. Если маркер агрегирует несколько станций — при наведении показывать
   **всплывающий список** этих станций (креативно, не просто список), с
   возможностью **выбрать станцию**.
3. При выборе страны первую пачку брать **по рейтингу**, остальное — по
   требованию; порядок загрузки (рейтинг / качество / стиль / жанр / музыкальные
   или разговорные) продумать и, возможно, вынести в настройки.

Требование процесса: продумать до мелочей **до** реализации; значимые решения —
через ADR (AGENTS.md § 1.4, § 6.1).

## 2. Диагноз: почему маркеров «чуток»

Замер по живому API (`/json/stations/search?countrycode=US&order=votes&reverse=true&hidebroken=true&limit=100`),
сверен с приложением (`0.22.0-rc.3`, панель «Country · United States of America»):

| Шаг | Число | Где в коде |
|---|---|---|
| Строк в первой странице списка | **100** | `COUNTRY_RESULT_LIMIT` (`src/session/search.rs`) |
| Из них с валидными координатами | **33** | `markers::station_geo()` отбрасывает `null` и заглушку `(0,0)` |
| Маркеров после группировки 0.01° (≈1 км) | **9** | `GROUP_SCALE = 100.0` (`src/session/markers.rs`) |

Значит расхождение дают две вещи, обе — по спецификации, а не баг:

- **нет координат у ~⅔ строк** — так устроена база Radio Browser (в ADR-0036
  зафиксировано ≈13 % записей с гео; на топе по голосам доля выше, ~33 %);
- **группировка ~1 км** (ADR-0012 § 3) схлопывает совпадающие точки: 17 SomaFM
  (California) → 1 маркер, 6 Radio Paradise → 1, 4 нью-йоркские → 1.

Дополнительно маркеры строятся только из **загруженных** строк
(`SearchState::poll_search` → `build_markers(self.search.results.clone())`), то
есть глобус зависит от пагинации списка, а не от страны.

**Побочное расхождение.** Подпись «На карте: 33 станции» считает
`sum(marker.count)` (`src/app.rs` → `Frame::markers_total`), тогда как ADR-0036
§ 4 называет этот счётчик «маркеры». Рисуется 9 точек, подпись говорит 33
«станций». Число в подписи верно (станций на карте 33), но не совпадает с числом
точек — это и создаёт ощущение «явно не сто».

## 3. Целевая модель

### 3.1. Два независимых представления вместо одного ответа

| Слой | Что показывает | Источник | Кратность |
|---|---|---|---|
| **Список** (панель) | полные строки страны, пагинация «X из M» | `/json/stations/search` без гео-фильтра | по требованию |
| **Карта** (глобус) | все гео-станции страны | отдельный запрос `has_geo_info=true` | все сразу, с потолком |

Связь по ADR-0036 § 2–3 сохраняется в ослабленном виде:

- каждая строка, **попавшая на карту**, имеет маркер;
- маркер с одной станцией ведёт себя как раньше (клик = выбор + эфир + прокрутка
  строки, если строка загружена);
- **маркер-кластер** при наведении раскрывает список станций (§ 3.3), выбор из
  которого выбирает и запускает станцию;
- станция слоя карты может ещё не быть в загруженной странице: тогда
  `reveal_station` не расходуется (прокручивать нечего), но станция выбирается и
  играет — это осознанный размен, его нужно записать в ADR.

Для режима «Глобальный жанр» слой карты строится тем же механизмом (`tag` +
`has_geo_info=true`). Для поиска по имени (без контекста) карта остаётся по
загруженным строкам: у «поиска по имени» нет пространственной границы.

### 3.2. Слой карты: данные

Новые параметры запроса (расширение `SearchParams`, интерфейс 02):

```rust
struct MapLayerParams {
    country_code: Option<String>,   // ISO alpha-2, взаимоисключимо с tag
    tag: Option<String>,
    order: CatalogOrder,            // см. § 3.4
    limit: u32,                     // MAP_MARKER_LIMIT
    offset: u32,                    // 0; потолок — один запрос
    bitrate_max: Option<u32>,       // профиль Metered, ADR-0048
}
```

Запрос всегда `has_geo_info=true&hidebroken=true&reverse=true`. Значения
`order` — строго из официального списка Radio Browser: `votes`, `clickcount`,
`clicktrend`, `bitrate`, `name`, `random`.

Потолок `MAP_MARKER_LIMIT = 800` станций на страну — **потолок API-слоя после
гео-склейки и до экранной кластеризации**, а не обещание нарисовать 800 дисков
(решение владельца 2026-11-13, § 8.4). Если страна отдала ровно лимит, подпись
честно говорит «первые N»; способы уточнить M — в § 4.4.

Состояние в `Session`:

```rust
pub(crate) markers: Vec<GlobeMarker>,        // теперь слой карты, не строки
pub(crate) map_layer: MapLayerState,         // поколение, отпечаток запроса, офлайн-флаг
```

`SearchState::poll_search` больше **не** вызывает `build_markers(results)`; маркеры
обновляет только слой карты. Это снимает связь «маркеры зависят от пагинации».

Перезапуск слоя карты: смена страны, смена жанра, смена `CatalogOrder` в
настройках, смена профиля сети (иначе `bitrateMax` устареет).

Офлайн (ADR-0043): если сеть отказала, слой карты собирается из мирового
снимка (`WorldBaseline`) теми же правилами, что строки, и помечается
`offline` — подпись «на карте» молчит о полном M, как и панель.

### 3.3. Кластеры и веер станций

**Двухступенчатая агрегация** (новая, заменяет одиночную сетку 0.01°):

1. **Гео-склейка** (как сейчас): совпадающие координаты с точностью 0.01°
   (~1 км) → один маркер. Обоснование: 17 станций одного города — это «одно
   место».
2. **Экранная склейка** (новая): маркеры, чьи проекции на экране ближе
   `CLUSTER_PIXEL_RADIUS = 16 px`, объединяются в кластер на время кадра.

Экранная ступень даёт главное: на дальнем зуме страна читается как десятки
кластеров (а не сотни слипшихся точек), при приближении кластеры расходятся на
отдельные маркеры. Это одновременно UX и бюджет кадра (§ 3.5).

- Кластеры пересобираются каждый кадр, пока камера движется; в покое
  кэшируются по ревизии сцены (поколение слоя + матрица камеры).
- Порядок членов кластера — по активному `CatalogOrder`; это же число видит
  веер.
- Скрытые (за горизонтом, вне viewport) маркеры в кластер не входят.

**Вид маркера** по числу станций: `1` — прежняя точка; `2..=4` — точка + тонкое
внешнее кольцо; `>=5` — точка + кольцо + счётчик (число в миниатюре). Радиус и
цвет остаются общими (ADR-0012 ред. «Этап 9»), меняется только «вес».

**Веер станций (popup кластера).** Креативная раскладка — полукруг, как просил
владелец:

- Наведение на кластер с `count >= 2` дольше `CLUSTER_DWELL = 200 мс` →
  открывается веер. Одиночный маркер сохраняет прежнюю подпись-плашку.
- Веер разворачивается **в сторону от центра планеты**, дугой радиуса
  `CLUSTER_ARC_RADIUS = 52 px`, шаг угла `CLUSTER_ARC_STEP = 22°`, максимум
  `CLUSTER_FAN_MAX = 7` слотов.
- Слот — круглый чип с инициалами/иконкой жанра; над ближайшим к курсору слотом
  всплывает строка «имя · kbps · голоса». Клик по чипу — выбор и эфир.
- Если станций больше 7, последний слот — «+N»: клик раскрывает **карточку
  списка** (переиспользуем каналы callout, ТЗ § 1.2) со скроллом, все члены
  кластера, строки кликабельны, сверху — «Играть лучшую».
- Веер живёт, пока курсор над маркером **или** веером; уход — закрытие через
  `CLUSTER_GRACE = 300 мс`.
- Клавиатура: `←/→` — по слотам, `Enter` — играть, `Esc` — закрыть. Веер
  получает фокус и объявляет станции для screen-reader (доступные имена).
- `reduce_motion`: веер появляется без вылета/затухания (ADR-0032).
- Пока веер открыт — 30 fps (`RepaintReason::Interaction`), как у callout.

Веер и карточка списка — **отдельный канал callout тем же паттерном**, что
карточка страны (`CalloutState`/`paint_callout_channel`), и не переиспользуют
`country_callout`/`station_callout`, чтобы не спорить за карточку. Обход
прямоугольников страна → станция → кластер сохраняется.

Клик по кластеру (не наведение) — «закрепить» веер: он не закрывается при уходе
курсора до `Esc` или выбора. Клик по одиночному маркеру — прежнее поведение
(ADR-0036).

### 3.4. Порядок загрузки каталога

Сегодня сортировка списка — **локальная** для панели (`station_filter::StationSort`,
Popularity / Bitrate / Name), а сервер всегда отдаёт `order=votes`. Значит
«первая пачка по рейтингу, дальше по требованию» уже почти есть, но выбор не
влияет на то, **что придёт первым**, и не переживает перезапуск.

Предлагается вынести порядок в настройку и применять его к запросу:

| Пункт UI | `order` Radio Browser | Смысл |
|---|---|---|
| По рейтингу (по умолчанию) | `votes` | как сейчас |
| По популярности | `clickcount` | по числу прослушиваний |
| По тренду | `clicktrend` | растёт в последнее время |
| По качеству | `bitrate` | выше битрейт — выше в списке |
| По имени | `name` | алфавит |
| Случайно | `random` | для «открытий»; **пагинация нестабильна** (см. § 5) |

Правила:

- Новый `settings.catalog_order: CatalogOrder` (по умолчанию `Rating`),
  сериализуется `kebab-case`, аддитивно к схеме `settings.json`.
- **Одна точка правды.** Локальный `StationSort` панели и настройка
  объединяются в один `CatalogOrder`; контрол в панели и в настройках меняет
  одно и то же поле. Смена порядка **перезапускает контекстный запрос с
  `offset = 0`** — иначе уже загруженные страницы упорядочены по старому
  порядку, и «первая пачка» перестаёт быть первой.
- Порядок применяется к списку **и** к слою карты (одно поле), поэтому
  «первая пачка» и «первые маркеры» согласованы.
- Случайный порядок отключает пагинацию: `has_more = false` после первой
  страницы, кнопка «Загрузить ещё» скрывается, в подписи — «N случайных».

### 3.5. Бюджет кадра

ADR-0059 § 4: оптимизация только по замеру. Что известно (план
`render-frame-budget.md`, волна 4):

| Нарисованных маркеров | tessellate p95 |
|---|---|
| 100 | 0,13 мс |
| 500 | 2,28 мс |
| 1000 | 4,48 мс |

При `MAP_MARKER_LIMIT = 800` и «3 формы на маркер» тесселяция выходит за
внутренний порог 1 мс / 500 (к тому же 800 — это список, видимых меньше).
Порог приёмки: p95 тесселяции на типичном зуме ≤ ~1–1,5 мс; если он не
достигается — снижаем лимит или усиливаем экранную склейку (16 px), а не
рисуем 800 дисков. Поэтому в объём входит **обязательная** правка из плана
кадров (волна 4.3):

- для неиграющих и невыбранных маркеров убрать внешнее гало → **1–2 формы**
  вместо 3;
- кластеры рисовать одной формой с числом (не тремя);
- замерить повторно `cargo test --release marker_paint_budget -- --ignored`
  **до и после**, числа внести в план кадров; без числа правка не принимается
  (ADR-0059 § 4).

Экранная кластеризация снижает число **нарисованных** форм: на дальнем зуме
сотни станций схлопываются в десятки чипов.

### 4.3. Счётчики (честность подписей)

- Панель: «загружено X из M» — как сейчас (M из `/json/countrycodes`).
- Глобус: «на карте: A станций, B маркеров» — **два** числа, потому что именно
  их расхождение сбивало с толку. При потолке — «на карте: A из M (гео)».
- `markers_total` перестаёт быть `sum(count)` без пояснения.

### 4.4. Как узнать число гео-станций страны

У Radio Browser нет счётчика с гео-фильтром (проверено: `/json/countrycodes`
даёт все станции). Варианты: (а) не показывать M, писать «на карте: A станций»;
(б) считать локально по ходу слоя карты; (в) отдельный «пробный» запрос с
`has_geo_info=true&limit=1` — счётчика всё равно нет. Рекомендация — (а) для
первой итерации, M только когда укладываемся в потолок.

## 5. Крайние случаи

- **Потолок достигнут** (`page_len == MAP_MARKER_LIMIT`): подпись честно говорит
  «показаны первые N», продолжения нет.
- **Станция слоя карты не загружена в список**: голосовать/выбирать можно,
  прокрутка строки — no-op, тоста нет.
- **Смена страны/жанра/порядка/профиля сети** — перезапуск слоя карты с новым
  поколением; старый ответ отбрасывается по `generation` (как в поиске).
- **Офлайн**: слой карты из снимка, с флагом `offline`.
- **Кластер из одной станции** (все соседи скрыты за горизонтом): веер не
  открывается, работает обычная подпись.
- **`random`**: пагинация скрыта, дубликаты по UUID между «обновлениями»
  возможны — фиксируем выборку до явного обновления.
- **Reduce motion / Asleep**: веер без анимации, кадры не запрашиваются лишний раз.
- **Производительность**: 800 станций × склейка — один проход по решётке;
  проверить, что кадр не аллоцирует `Vec` каждый кадр (переиспользуемые буферы,
  AGENTS.md § 5.6).

   перезапускает контекстную выборку с `offset = 0`; `Random` гасит пагинацию;
   локальная пересортировка списка снята; категория «Каталог» (9-я).
   Тесты: `roundtrip_persists_catalog_order`,
   `station_order_maps_to_api_tokens_and_reverse`, `filters_keep_the_server_order`.
3. **Волна 2 — слой карты.** Отдельный запрос, состояние, счётчики, офлайн.
4. **Волна 3 — кластеризация.** Гео + экранная, форма маркера, бюджет тесселяции
   (замер до/после).
5. **Волна 4 — веер станций.** Раскладка, выбор, клавиатура, callout-канал,
   i18n, тесты взаимодействия.
6. **Волна 5 — приёмка.** Живой прогон на niri, скриншоты, числа fps/тесселяции,
   документация и CHANGELOG.

## 8. Решения владельца (приняты 2026-11-13)

| # | Решение |
|---|---|
| 1 | **Триггер веера:** hover ≥ 200 мс + закрепление кликом. `Esc` и клик в пустоту снимают `pin`. `reduce_motion` — без анимации раскрытия, веер появляется сразу после порога или клика |
| 2 | **Размер веера:** ≤ 7 слотов на дуге + «+N» → прокручиваемая карточка тем же callout-паттерном, что карточка страны, в порядке `catalog_order` |
| 3 | **«Музыкальные / разговорные» — вне объёма.** Эвристика по тегам врёт; отдельная фича с явной пометкой «приблизительно», не блокер слоя карты и кластеров |
| 4 | **`MAP_MARKER_LIMIT = 800`** — потолок API-слоя **после** гео-склейки и **до** экранной кластеризации. Обязательны: гало только у playing/selected, кластер одной формой, повторный замер `marker_paint_budget` до/после. Если p95 на типичном зуме > ~1–1,5 мс — снизить лимит или усилить экранную склейку (16 px) |
| 5 | **Жанр/стиль — только фильтр**, не `order`. Radio Browser не сортирует по тегу; в UI жанр не подписывается как пункт `catalog_order` |

Дополнительно владелец просил явно развести счётчики «станций на карте»
(`sum(count)`) и «точек/кластеров» (`markers.len()`) — это закрывает
неоднозначность ADR-0036 § 4 и внесено в § 3.2/§ 4.3 и ADR-0065 § 4.

Открытым остаётся только **место настройки**: рекомендована новая категория
«Каталог» (девятая). Если владелец предпочтёт другую категорию — правится без
влияния на контракты.

## 9. Что не входит в объём

- Смена GUI-стека, второго audio engine, облака (product non-goals).
- Полный 3D-глобус на Android.
- Геокодирование станций без координат (вне Radio Browser).
- Разделение станций на музыкальные / разговорные (у Radio Browser нет признака
  контента; отдельное решение, см. § 8.3 и ADR-0066 § 5).
- LOD-скрытие станций по зyму как отдельная UX-настройка — только экранная
  склейка в объёме; явный LOD с приоритетом по votes — при желании отдельным ADR.
- «Карта года» из локальной статистики (трек ADR-0049, не сюда).
