# ADR-0048: Профиль сети — metered и offline-first

**Статус:** Принято  
**Дата:** 2026-11-03  
**Участники решения:** ModernByte Architecture

## Контекст

К 0.18.0-rc.1 desktop всегда ведёт себя одинаково по отношению к сети:

- при старте сессии фоном загружается мировой снимок — число станций по
  странам и выборка `WORLD_SAMPLE_LIMIT = 1000` для карты;
- поиск, жанры, страны и Roulette не ограничивают битрейт;
- `FaviconCache` держит до восьми одновременных сетевых запросов обложек;
- офлайн-снимок ADR-0043 уже даёт карту и поиск без сети, но приложение всё
  равно само инициирует фоновые загрузки.

На лимитированном соединении это лишний трафик: мировой снимок и обложки
загружаются без запроса пользователя, а поиск может вернуть станции с
битрейтом выше разумного для мобильного канала. Аудит
`docs/audit/OrbitFM-future-features.md` §2.4 относит профиль сети к приоритету
B и волне 2; Android Companion (ADR-0045) будет читать системный metered flag
и передавать тот же смысл профиля.

Нужен явный пользовательский выбор, который не ослабляет SSRF/publishable
политику ADR-0025, не ломает адаптивное аудио ADR-0043 и не превращает
офлайн-режим в запрет сети.

## Решение

### 1. Три профиля

`settings::NetworkProfile` — `unlimited` (по умолчанию), `metered`,
`offline-first`. Значение хранится в `settings.json` полем
`network_profile`, сериализуется в kebab-case. Старые файлы читаются как
`unlimited` благодаря `#[serde(default)]`.

Профиль меняет только **фоновое** поведение и параметры discovery. Он не
запрещает воспроизведение и не подменяет политику URL или адаптивный
битрейт.

### 2. Unlimited

Текущее поведение без изменений: мировой снимок из 1000 станций, до восьми
параллельных favicon-запросов, discovery без ограничения битрейта.

### 3. Metered

- Все пользовательские запросы каталога — поиск, жанры, страны, «показать
  ещё», Roulette — получают серверный фильтр `bitrateMax=128`. Станции с
  неизвестным битрейтом (`0`) сохраняются: каталог не всегда его знает.
- Мировой снимок уменьшается до 250 станций; число станций по странам
  запрашивается как раньше — это компактный ответ.
- `FaviconCache` держит не больше двух запросов в полёте.
- Уже выбранная станция, избранное, история и внешний поток играют без
  ограничения: cap — свойство каталога, а не плеера. Пользователь вправе
  слушать станцию с высоким битрейтом, выбрав её вручную.
- Экономический fallback ADR-0043 не меняется: при переподключении он может
  выбрать поток легче текущего; это про непрерывность эфира, а не про
  discovery.
- Периодического обновления мира в текущей архитектуре нет: снимок
  загружается один раз за сессию. «Реже world refresh» из аудита здесь
  реализуется уменьшением выборки, а не таймером.

### 4. Offline-first

- Фоновый мировой запрос не стартует: карта и поиск используют снимок
  ADR-0043. Если снимка нет, карта остаётся пустой без сетевого запроса.
- При переключении в этот профиль уже летящий мировой запрос отбрасывается;
  загруженный ранее снимок сохраняется.
- Сетевые favicon-запросы не начинаются. Готовые текстуры из кэша
  показываются, остальные станции получают процедурную обложку ADR-0044.
  Запросы, начатые до переключения, могут завершиться и попасть в кэш; новые
  не планируются.
- Действия пользователя по-прежнему ходят в сеть без ограничения битрейта:
  поиск, «показать ещё», Roulette, запуск станции. Профиль не имитирует
  офлайн-плеер и не скрывает сетевые ошибки.
- Возврат в `unlimited`/`metered` запускает мировой запрос со следующим
  `tick()`, если снимок ещё не загружен.

### 5. IPC и статус

- Новая команда `network <unlimited|metered|offline-first>`. Неизвестный
  профиль — ошибка аргумента; команда доступна desktop-клиенту, но не входит
  в белый список браузерного native host ADR-0038.
- `status --json` схемы 1 получает аддитивное поле
  `"network": "unlimited" | "metered" | "offline-first"`. Текстовый `status`
  не меняется, схема остаётся 1.
- Изменение профиля сохраняется сразу, как `queue_wrap`, и не требует
  перезапуска.

### 6. Интерфейс

Категория «Аудио» окна настроек получает третью карточку — выпадающий список
профилей и подсказку, зависящую от выбора. Подписи входят во все 16 языков и
`System` через `i18n::labels`; ошибка записи показывается существующим тостом
`NoticeKey::SettingNotSaved`.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Клиентская фильтрация битрейта | Тратит трафик на станции, которые всё равно отброшены, и уменьшает полезную выдачу |
| Жёсткий офлайн-режим без любых запросов | Ломает поиск и Roulette — явные действия пользователя |
| Отдельный тумблер на каждую фоновую загрузку | Три профиля покрывают сценарии без комбинаторики настроек |
| Периодический world refresh с интервалом | В текущей архитектуре снимок одноразовый; таймер — отдельное решение |
| Хранить профиль только в памяти | Профиль должен переживать перезапуск, как `queue_wrap` |
| Android metered flag внутри этого ADR | Мобильный клиент живёт по ADR-0045 и читает ОС отдельно |

## Последствия

**Положительные:**

- на лимитированном канале фон не тянет мировой снимок и лишние обложки;
- discovery в metered возвращает станции, посильные для мобильного канала;
- offline-first честно опирается на снимок ADR-0043, сохраняя поиск по
  действию пользователя;
- контракты остаются аддитивными, старые настройки и клиенты не ломаются.

**Отрицательные / Риски:**

- профиль не отменяет сетевой трафик уже играющей станции — это осознанно;
- `bitrateMax` зависит от поддержки параметра каталогом Radio Browser;
- metered не делает периодическое обновление мира «реже», потому что его нет:
  документация обязана говорить об уменьшении выборки, а не о таймере;
- при переключении в offline-first начатые favicon-запросы могут завершиться.
