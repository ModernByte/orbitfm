# ADR-0015: UX-редизайн «Orbital Desk»

**Статус:** Принято  
**Дата:** 2026-10-23  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Целевой UX зафиксирован в `docs/ui/design-vision.md` и референс-макете
`docs/ui/OrbitFM_ Радио Земли в неоне.png`: глобус доминирует в кадре, HUD тонкий,
список станций — выезжающая панель, а не постоянная колонка. Требуются два режима
поиска (страна и глобальный жанр), hover/контур страны, фильтры и сортировка списка,
Radio Roulette с перелётом камеры и визуализация эфира на глобусе.

Текущий код уже содержит камеру с инерцией и zoom limits, raycast страны, маркеры
станций, избранное/историю, темы, FFT-метрики и MPRIS. Однако:

- весь UI собран в `src/app.rs` (1638 строк) — выше мягкого лимита `docs/AGENTS.md`;
- нет `SearchMode`: клик по стране и свободный поиск смешаны, глобального жанра нет;
- `Station` не содержит `votes`, `country`, `state`; сортировать по популярности и
  показывать страну в карточке нечем;
- `GeoService` не отдаёт геометрию страны, поэтому нет hover-контура и заливки;
- нет fly-to камеры, Roulette и pulse-визуализации в шейдере;
- MPRIS уже публикует title/artist/artUrl, но artist — только теги.

Ограничения:

- GUI-стек не меняется (eframe/egui/egui-wgpu, ADR-0002);
- `render` не знает доменных типов; `geo` не знает UI и станций;
- Linux First, без новых зависимостей в MVP;
- формат `library.json`/`settings.json` не ломается;
- существующие темы, избранное, история, IPC и Noctalia продолжают работать.

## Решение

1. **UI выносится в `src/ui/`.** `OrbitApp` остаётся оркестратором состояния и
   побочных эффектов. Модули `hud`, `station_panel`, `transport`, `globe_view`,
   `palette` рисуют виджеты и возвращают `UiAction`; они не вызывают аудио, сеть и
   запись файлов. Это уменьшает `app.rs`, сохраняет однонаправленный поток данных и
   позволяет менять раскладку без доменной логики. Целевой размер `app.rs` — ниже
   мягкого лимита 400 строк для UI-кода; состояние поиска и подсистем остаётся в App.

2. **`SearchMode` — явное состояние.** `SearchMode { Country, GlobalGenre }`
   переключается в верхнем HUD и сбрасывает несовместимое состояние:
   - Country: выбранная страна, её контур/заливка, список страны;
   - GlobalGenre: выбранный тег, маркеры жанра, подсветка страны снята.

   Маркер приоритетен в обоих режимах: клик по нему запускает станцию. Клик по
   стране выбирает страну только в `Country`; в `GlobalGenre` клик мимо маркера —
   no-op. Это соответствует макету и не смешивает модели.

3. **Режим «Страна» работает на локальной выборке.** Один запрос
   `countrycode=<ISO alpha-2>`, `limit=100`, `hide_broken=true`, сортировка API по
   votes. Текстовый фильтр, чипы жанров и сортировка (votes/bitrate/name)
   применяются в клиенте и не порождают сетевых запросов. Для этого `Station`
   дополняется `votes: u32`, `country: String`, `state: String` с
   `#[serde(default)]` — старые `library.json` читаются без миграции. Город в API
   отсутствует; карточка показывает `state`/`country`.

4. **Режим «Жанр» использует tag-поиск Radio Browser.** Основной запрос:
   `tag=<жанр>`, `limit=100`; маркеры: `tag=<жанр>`, `has_geo_info=true`,
   `limit=200`. Запросы выполняются параллельно, ошибка гео-запроса не ломает
   список. Маркеры группируются как в ADR-0012; визуальный вес (размер/свечение)
   вычисляется из `votes` и `bitrate` в Application Core и передаётся в
   `render` готовым числом. Старые маркеры очищаются при старте нового поиска,
   устаревшие ответы отбрасываются по номеру поколения запроса.

5. **Геометрия страны отдаётся из `geo`, рисуется в `render`.** `GeoService`
   получает методы поиска страны по названию и получения колец контура
   (`lon, lat`) для ISO-кода. Application Core проецирует точки через
   `project_on_sphere` и передаёт в `render/countries.rs` экранные пути без
   доменных типов. Контур рисуется egui-painter поверх глобуса; точки задней
   полусферы разрывают путь. Hover страны в режиме Country подсвечивает контур,
   выбранная страна — контур и мягкую заливку. Заливка интенсивностью по count
   использует уже загруженную выборку, без запросов на кадр.

6. **Roulette и fly-to.** `RadioBrowserClient::random_station()` использует
   `order=random&limit=1&has_geo_info=true&hidebroken=true` (значение `random`
   поддерживается официальным API; проверено живым запросом 2026-10-23). Станция
   без `url_resolved` или координат отбрасывается, до трёх попыток. Камера получает
   `fly_to(lat, lon, duration)`: кратчайший путь по yaw, ease-out, отмена при
   drag. После ответа станция запускается, камера летит к координатам, HUD/toast
   показывает название и страну. Новых IPC-команд для Roulette нет.

7. **Pulse-визуализация — часть GPU-пайплайна глобуса.** В uniform камеры
   добавляются позиция камеры и сигнал (0..1), вычисленный из сглаженных FFT-метрик
   (`rms_db`/`flux`). Фрагментный шейдер добавляет Fresnel-обод атмосферы,
   яркость которого зависит от сигнала. `render` по-прежнему не знает об
   `AudioEngine`: App передаёт готовое число в `paint_globe`. Полоса
   `SpectrumOverlay` остаётся опцией, а не единственным визуализатором.

8. **MPRIS обогащается, но не дублирует UI.** `PlaybackInfo` уже содержит
   title/artist/art_url; App формирует artist из страны/штата, при отсутствии —
   из тегов. artUrl остаётся favicon. Никаких системных уведомлений и новых
   зависимостей: уведомления и статус-бар — потребители MPRIS. `Next/Previous`
   остаются неактивными, пока нет модели очереди.

9. **Данные пользователя не мигрируют.** Избранное и история остаются в
   `library.json` (ADR-0013), настройки — в `settings.json` (ADR-0014). SQLite,
   TOML и новая схема в этот редизайн не входят.

10. **Работа идёт фазами.** MVP: UI-каркас, режимы Country/Genre, фильтры,
    Roulette и fly-to. Затем — pulse/heatmap, WindowMode (Overlay/Listening) и
    favicon-карточки. Фазы и критерии приёмки — `docs/ui/implementation-plan.md`.
    WindowMode требует отдельного решения по IPC и не входит в текущий контракт.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Оставить один `app.rs` и добавить режимы внутрь `draw` | Файл уже 1638 строк; смешение UI, состояния и эффектов, риск регрессий |
| Новый GUI-фреймворк или web-view | Ломает ADR-0002, стоимость портирования глобуса и интеграций |
| Отдельный API-запрос на каждое изменение фильтра | Лишняя нагрузка и задержки; выборка страны/жанра достаточно мала для локальной фильтрации |
| Глобальный heatmap по всем странам сразу | Нужен aggregate-эндпоинт/кэш и отдельная модель данных; в MVP достаточно выбранной/наведённой страны |
| Собственный слой favicon-загрузчика в MVP | Новые зависимости и кэш; не блокирует UX-каркас и принимается отдельно |
| SQLite для избранного | Действует ADR-0013; объём данных мал, JSON проще для диагностики |
| Новые IPC-команды для Roulette/WindowMode | Roulette доступен из HUD; WindowMode требует отдельного контракта и решения |

## Последствия

**Положительные:**

- Глобус доминирует, список и фильтры не съедают сцену;
- Country/Genre — явные, тестируемые состояния вместо смешанного поиска;
- `render` и `geo` сохраняют границы: наружу отдаются экранные примитивы и
  геометрия, а не доменные типы;
- фильтры и сортировка не создают сетевой трафик;
- Roulette и fly-to переиспользуют существующую камеру и API;
- старые `library.json` остаются совместимыми.

**Отрицательные / Риски:**

- контур и заливка на сфере без depth buffer требуют аккуратного разрыва путей на
  задней полусфере и проверки на антимеридиане;
- hover-страна добавляет raycast+Point-in-Polygon на движение мыши — нужен кэш
  последней точки/страны;
- маркеры жанра до 200 увеличивают нагрузку egui-оверлея; N ≫ 500 остаётся вне
  скоупа до LOD/кластеризации;
- fly-to может конфликтовать с инерцией и drag — анимация отменяется вводом;
- favicon-карточки и WindowMode откладываются, поэтому макет будет реализован не
  на 100% в первом релизе;
- случайная станция может оказаться нестабильной; это смягчается `hidebroken` и
  повторами, но не устраняется.
