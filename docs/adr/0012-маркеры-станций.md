# ADR-0012: Маркеры станций на глобусе

**Статус:** Принято  
**Дата:** 2026-10-22  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Следующий пункт ROADMAP — показать станции на 3D-глобусе и дать возможность запускать
их кликом по маркеру. Radio Browser отдаёт необязательные координаты `geo_lat` и
`geo_long` (число или `null`) и поддерживает фильтр `has_geo_info` в
`/json/stations/search`. Обычный поиск по стране содержит мало станций с координатами:
живая проверка для `countrycode=DE` дала 4 из 30, тогда как запрос с
`has_geo_info=true` — 30 из 30.

Текущий глобус рисуется wgpu-пайплайном через `egui_wgpu::Callback` без depth buffer.
Модуль `render` не должен зависеть от доменных типов (`Station`), а интерактив
(наведение, клик) уже реализуется средствами egui поверх области глобуса.

## Решение

1. **Два запроса на каждый поиск.** Основной запрос сохраняет текущее поведение и
   наполняет список станций. Параллельно выполняется гео-запрос с теми же фильтрами,
   `has_geo_info=true` и `limit=60`; его результат используется только для маркеров.
   Ошибка гео-запроса не прерывает поиск: маркеры пустеют, в лог пишется предупреждение.
2. **Модель данных.** `Station` получает `geo_lat: Option<f64>` и
   `geo_long: Option<f64>`, `SearchParams` — `has_geo_info: bool`. Координаты
   считаются пригодными, если они конечны, лежат в `[-90, 90]` / `[-180, 180]` и не
   равны одновременно нулю (частая заглушка «координаты неизвестны»).
3. **Группировка.** Станции с одинаковыми координатами, округлёнными до двух знаков
   после запятой (≈1 км), объединяются в один маркер. Представитель группы — первая
   станция в выдаче (сортировка по голосам), на маркере показывается количество.
   Дубликаты по UUID отбрасываются.
4. **Отрисовка.** Новый модуль `render/markers.rs` не создаёт GPU-ресурсов и не знает
   о `Station`: Application Core проецирует точки сферы через
   `GlobeCamera::project_on_sphere` и передаёт экранные `MarkerVisual` в
   `paint_markers`. Маркеры рисуются egui-painter поверх wgpu-callback глобуса.
   Точки на обратной полусфере и за пределами viewport отсекаются.
5. **Взаимодействие.** Наведение в радиусе 10 px показывает подпись станции. Клик по
   маркеру приоритетнее выбора страны: запускается представитель группы. Текущая
   станция подсвечивается. Список результатов остаётся основным способом выбора.
6. Маркеры отражают только последний выполненный поиск, не опрашиваются в фоне и
   очищаются при старте нового поиска. Новых зависимостей и IPC-команд нет.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Использовать только координаты из основного списка | Покрытие ~13% на живой проверке, маркеров почти нет |
| Отдельный wgpu-пайплайн инстансированных маркеров | Нужны depth-тест и новая GPU-обвязка; интерактив всё равно через egui |
| Предзагружать все гео-станции мира | Тяжёлый и устаревающий запрос, лишний трафик без запроса пользователя |
| Кластеризация и «spiderfy» | Вне первого объёма; группировка одинаковых координат решает основной случай |

## Последствия

**Положительные:**

- Маркеры не загрязняют список станций и не требуют новых зависимостей
- Границы модулей сохранены: render не знает доменных типов
- Одна дополнительная сетевая операция на поиск, без фонового polling

**Отрицательные / Риски:**

- Гео-запрос увеличивает нагрузку на Radio Browser вдвое
- Показываются максимум 60 станций на запрос; близкие, но не совпадающие координаты
  могут визуально перекрываться
- Точность координат зависит от данных Radio Browser
