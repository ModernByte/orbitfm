# ADR-0056: Плавное затухание звука перед сном

**Статус:** Принято  
**Дата:** 2026-11-06  
**Участники решения:** ModernByte Architecture, владелец продукта

## Контекст

Таймер сна останавливает эфир резко: на последней секунде звук обрывается.
Владелец потребовал «очень плавное затухание громкости». Это не косметика:
резкий обрыв будит, если человек ещё не уснул, а слишком ранний фейд делает
таймер бессмысленным — звук исчезает, а счётчик ещё идёт.

Ограничения:

- громкостью владеет аудио-воркер (`src/audio/worker.rs`); UI-пассов в
  парковке нет вообще, поэтому «считать фейд в `tick()`» невозможно;
- mpv-свойство `volume` — линейный процент усиления (`apply_volume`), а не
  дБ, поэтому линейный по проценту фейд звучит неровно;
- ручная громкость пользователя должна оставаться главной;
- `Settings.volume` не переписывается фейдом (commit-on-release, ADR-0031).

## Решение

### 1. Фейд живёт в аудио-воркере

Состояние:

```
Fade { started_at, duration, start_pct }
```

Команды:

- `AudioCommand::StartFade { duration_ms }` — старт от текущей громкости;
- `AudioCommand::CancelFade { restore_volume }` — остановить; `true` —
  вернуть громкость до фейда, `false` — оставить как есть.

Шаг выполняется в том же drain-цикле, где уже крутится `mpv.wait_event(0.05)`
(~20 Hz). Нового потока и нового таймера нет. По завершении — один шаг в 0 и
`stop_playback` по общему порядку ADR-0055.

### 2. Кривая — линейно в дБ

`pct(t) = pct0 · 10^(−(D/20)·(t/T))`, где `D = 45` дБ — глубина фейда,
`T` — длительность из настроек.

- При `T = 300 с` это −9 дБ/мин; ощутимая громкость падает вдвое каждые
  ~66 с; шаг на 20 Hz — 0,0075 дБ, zipper-noise нет.
- При `t ≥ T` — один шаг в 0.
- `fade_seconds = 0` — сегодняшнее поведение: стоп сразу, без фейда.

Отвергнуто с числами:

| Кривая | Почему нет |
|--------|-----------|
| Линейно в процентах | к половине окна всего −6 дБ, последние 30 с дают −20 дБ — «рывком» |
| Квадратичная амплитуда | −30 дБ к 63 % окна: звук «пропал», а таймер ещё считает |
| Линейно в дБ с D=60 | к концу слышно на пределе, но первые 4 минуты почти без изменений |

### 3. Настройка

`sleep_fade_seconds` (u16, по умолчанию `300`), ряд
`SLEEP_FADE_CHOICES = [0, 60, 120, 180, 300]`, sanitize по образцу
`nearest_viz_bars`: ручное значение 9999 при загрузке превращается в
ближайший допустимый вариант. IPC: `sleep fade <0|60|120|180|300>`.

### 4. Конфликты и владение

- Явный `SetVolume` от пользователя **отменяет фейд без восстановления**:
  воля пользователя выше автоматики.
- Сброс/перестановка таймера ⇒ `CancelFade { restore_volume: fade_pre_volume }`.
- `Settings.volume` фейдом не пишется; после отмены громкость возвращается к
  значению до фейда, а не к сохранённому.
- Фейд не запускается, если эфир уже остановлен или на паузе.

## Последствия

**Положительные:**

- исчезновение звука не будит и не «щёлкает»;
- фейд одинаково работает при открытом окне и в парковке;
- кривая объяснена числами и покрывается юнит-тестом монотонности.

**Отрицательные / риски:**

- 20 Hz — компромисс между плавностью и нагрузкой; при 300 с этого достаточно;
- фейд занимает аудио-воркер, но тот и так обслуживает mpv;
- при `fade_seconds > sleep_remaining` фейд начинается сразу после установки
  таймера — это ожидаемо, но требует подсказки в UI.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Считать фейд в `Session::tick` | в парковке UI-пассов нет, фейд бы замирал |
| Отдельный поток фейда | второй таймер и синхронизация с mpv |
| `afade`/`volume` фильтр mpv | зависимость от lavfi-графа и поведения потока, сложнее тестировать |
| Линейно в процентах | см. таблицу выше |
| Писать `Settings.volume` по завершении | нарушает commit-on-release (ADR-0031) |
