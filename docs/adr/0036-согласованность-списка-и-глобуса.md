# ADR-0036: Согласованность списка станций, маркеров и счётчиков стран

**Статус:** Принято, ред. 2026-10-28 (2) — полная выдача страны с пагинацией,
маркеры как подмножество строк  
**Дата:** 2026-10-28  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич

## Контекст

Приёмка главного окна 2026-10-28 выявила расхождения между тем, что обещает
интерфейс, и тем, что он показывает:

1. Поле поиска в HUD не использовало остаток строки: ширина ограничивалась
   номиналом 240/150 px, хотя справа оставалось свободное место.
2. Карточка управления глобусом была скрыта по умолчанию: одноразовый
   `Settings::help_seen` гасил её после первого запуска станции или выбора
   страны, и вернуть карточку можно было только вручную.
3. Легенда карты стартовала в режиме «Плотность», хотя пользователь ждёт чистый
   глобус без заливки.
4. Список станций и маркеры глобуса строились из **двух разных выдач**
   (ADR-0012: основной запрос и параллельный гео-запрос). Следствия: выделение в
   списке не отражалось на глобусе, клик по маркеру не подсвечивал и не
   прокручивал строку, а набор станций на глобусе не совпадал со списком.
5. Выбор страны давал маркеров меньше, чем строк в панели, — ровно из-за
   двух выдач: в гео-выдачу попадали только станции с координатами.
6. Подсказка над страной всегда писала «0 stations»: число считалось как сумма
   видимых маркеров страны, а если в текущей выборке их не было, получался
   честный, но ложный ноль. Глобальные счётчики Radio Browser при этом уже
   лежали в `session::world::WorldBaseline` (ADR-0035), но UI их не читал.

Факты, проверенные на живом API (2026-10-27, ADR-0035):

- `/json/countrycodes` отдаёт число станций **каждой** страны одним запросом
  (245 строк, ≈8 КБ). Обход «страна → запрос» стоил бы до 245 запросов на одно
  наведение.
- `Session::new` уже запускает прогрев снимка мира: одна фоновая задача с
  `tokio::join!(country_counts(), top_stations(1000))`, до трёх попыток, без
  блокировки окна.
- `has_geo_info=true` сужает выдачу до станций с координатами: живая проверка
  ADR-0012 для `countrycode=DE` дала 4 из 30 без фильтра и 30 из 30 с фильтром,
  то есть координаты есть примерно у 13 % записей базы.

Ограничения проекта неизменны: Linux First, один процесс, Core не знает про
egui, публичные подсказки локализованы во всех десяти каталогах (ADR-0030).

## Решение

1. **Один гео-полный запрос на поиск.** `Session::begin_search` принудительно
   выставляет `SearchParams::has_geo_info = true` и спавнит один
   `radio.search(params)`. Ответ наполняет и список, и маркеры:
   `search.results = stations`, `markers = build_markers(stations.clone())`.
   Гео-запрос и `geo_limit` из ADR-0012 § 1 удалены, двойные лимиты 100/200
   больше не поддерживаются. Список и глобус становятся одним множеством по
   построению, а не по совпадению. Цена — выдача по имени и стране содержит
   только станции с координатами (≈13 % базы); это осознанный размен: требование
   «что в списке — то на глобусе» сильнее полноты списка. Лимиты прежние:
   `SEARCH_RESULT_LIMIT = 100`, `COUNTRY_RESULT_LIMIT = 100`,
   `GENRE_RESULT_LIMIT = 200`.

2. **Выделенная станция — одна на два представления.** В `Session` появляется
   `selected_station: Option<String>` (UUID). Поле ставится при каждом успешном
   `start_station` (строка списка, hotkey, MPRIS, IPC — все пути идут через
   него) и при клике по маркеру. Presentation читает его напрямую:
   - строка списка получает плашку, accent-рамку и accent-имя, если она играет
     **или** выбрана; эквалайзер рисуется только у играющей;
   - маркер получает белое кольцо вокруг группы
     (`SELECTED_RING_GAP = 6.5`, `SELECTED_RING_WIDTH = 1.8`,
     `SELECTED_RING_ALPHA = 230`), кольцо-пульс эфира остаётся отдельным слоем.
   Остановка эфира выбор не сбрасывает: выбор — это «что я смотрю», эфир — «что
   звучит».

3. **Клик по маркеру выбирает строку и прокручивает список.** Маркер больше не
   отправляет `UiAction::Play`, а отправляет `UiAction::SelectStation(Station)`.
   `apply_action` вызывает `Session::select_station`, затем тот же
   `play_station`, что и строка списка. `select_station`:
   1. ставит `selected_station`;
   2. взводит разовый `reveal_station`;
   3. переключает вкладку панели на `Results` — иначе строки не существует.

   `OrbitApp::draw_layers` в начале кадра забирает просьбу
   (`Session::take_station_reveal()`) и передаёт UUID в `PanelState`; строка с
   этим UUID вызывает `Response::scroll_to_me(Some(Align::Center))`. Если строка
   первая или последняя, egui прижимает прокрутку к границам содержимого — она
   всё равно оказывается видимой, что и просил пользователь. Клавиатурный фокус
   (`gained_focus`) прокручивает строку тем же способом.

4. **Счётчики стран — прогретый мировой снимок, без fan-out.** Подсказка
   страны и её подсветка читают `WorldBaseline::counts()`, который грузится
   одним `/json/countrycodes` при старте `Session` (ADR-0035). Отдельного кэша
   по странам нет: снимок — это и есть кэш на всю базу, а ключ актуальности —
   `WorldBaseline::revision`. Хелпер
   `ui::globe_view::country_station_count` разрешает число так:

   | Состояние | Источник | Результат |
   |-----------|----------|-----------|
   | Снимок пришёл | `counts[ISO]` | `Some(число)`; неизвестный ISO — `None` |
   | Снимок пуст (сеть/старт) | сумма видимых маркеров страны | `Some(>0)` или `None` |

   `country_card` пишет `1 station` / `N stations` для `Some` и **не выводит
   строку вовсе** для `None`. Ложный ноль запрещён: подсказка обязана молчать,
   если счётчик неизвестен. Серверные счётчики описывают всю базу Radio Browser,
   а не текущую выборку, — это то, что пользователь просил у «всех станций».

5. **Карточка управления глобусом включена по умолчанию.** Одноразовый
   `Settings::help_seen` заменён на `Settings::help_visible: bool` (по
   умолчанию `true`). `Session::new` инициализирует `show_help` из него; `?` в
   HUD и тумблер в окне настроек переключают и сохраняют выбор; `Esc` скрывает
   карточку и сохраняет `false`. Первый запуск станции или выбор страны больше
   её не гасят. Старый ключ `help_seen` игнорируется (`serde` не падает на
   неизвестных полях), поэтому после обновления карточка снова видна — это
   ожидаемое поведение нового контракта, а не миграционная ошибка. Ошибка записи
   возвращается как `Result` и показывается тостом `SettingNotSaved` (ADR-0030).

6. **Легенда по умолчанию — «Без карты».** `CountryMetric::Off` помечен
   `#[default]`; текстура тепловой карты не собирается, пока пользователь явно
   не выберет метрику. Выбор метрики по-прежнему не персистится: это режим
   просмотра, а не настройка (ADR-0035 § 7).

7. **Поле поиска HUD занимает остаток строки.** Ширина считается как
   `(available − right_block_width − spacing).max(MIN_SEARCH_WIDTH)`: номиналы
   240/150 px убраны, резерв правого блока (сеть, тема, бейдж эфира, ×) и пол
   120 px сохранены, потому что `Layout::main_wrap == false` не переносит
   контролы на новую строку. Шапка панели уже выделяла поле на всю ширину;
   теперь обе поверхности ведут себя одинаково.

## Последствия

**Положительные:**

- любая строка списка имеет маркер, а любой маркер имеет строку — скрытого
  несоответствия нет;
- выделение одно на два представления: клик в списке подсвечивает маркер, клик
  по маркеру подсвечивает и прокручивает строку в центр;
- подсказка страны показывает реальные числа сразу после прогрева, без 245
  запросов на наведение и без отдельного действия пользователя;
- снимок мира уже существовал для тепловой карты: дополнительного сетевого
  трафика и новых зависимостей нет;
- поведение help-карточки предсказуемо и управляется пользователем, выбор
  переживает перезапуск;
- глобус стартует чистым, заливка появляется только по запросу;
- поле поиска не оставляет пустого места в строке.

**Отрицательные / Риски:**

- `has_geo_info=true` уменьшает выдачу поиска по имени и стране: станции без
  координат в список не попадают (≈13 % записей базы имеют координаты). Если
  полнота списка станет важнее согласованности, решение пересматривается новым
  ADR: например, строки без координат показываются в списке отдельной пометкой;
- при отказе сети `WorldBaseline` пуст: подсказка падает на сумму маркеров или
  молчит, пока не сработает одна из трёх попыток; офлайн реальных чисел нет;
- счётчик подсказки — по всей базе, а не по текущей выборке: «N stations»
  означает «столько станций страны в Radio Browser», а не «столько в фильтре»;
- кольцо выбора видно и на паузе: выбор не равен эфиру;
- при смене вкладки `reveal` расходуется в том же кадре: `select_station`
  принудительно ставит `Results`, иначе просьба была бы потеряна;
- `help_visible = true` по умолчанию вернёт карточку тем, кто её когда-то
  скрыл: это заявленное поведение «по умолчанию включена», отключается один раз
  и сохраняется.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Оставить два запроса ADR-0012 и синхронизировать их постфактум | Список и маркеры различаются по построению — это и есть наблюдаемый баг |
| Обойти каждую страну запросом `countrycode` при наведении | До 245 запросов на одно наведение, троттлинг Radio Browser и задержка первого ответа |
| Локальный кэш «страна → число» с прогревом по наведению | Первое наведение всё равно даёт ноль, а кэш нужно чем-то наполнять; агрегированный эндпоинт — один запрос на всё |
| Писать «0 stations», пока снимок не пришёл | Ложная информация; лучше промолчать (`None`) |
| Хранить выбранную станцию в `settings.json` | Выбор — состояние сессии, а не предпочтение; лишняя запись файла |
| Оставить одноразовый `help_seen` | Пользователь требует «по умолчанию включена» и управляемый выбор |
| Оставить `Density` по умолчанию | Пользователь ждёт чистый глобус до явного выбора карты |
| Вернуть номинальную ширину поиска 240/150 px | Требование «на всю доступную ширину»; место в строке простаивало |

## Обновление (2026-10-28, второе)

Приёмка пагинации показала цену решения 1: страна отдавала только гео-станции
(66 из 387 для Украины), «догружать ещё» было нечего, а обещанное «100 из 1244»
недостижимо. Владелец явно требует полный список страны с догрузкой страниц,
поэтому принудительный `has_geo_info=true` снят:

1. **`begin_search` больше не выставляет `has_geo_info`.** Страна, поиск по
   имени и глобальный жанр возвращают полную выдачу Radio Browser;
   `hide_broken=true` остаётся. Цена решения 1 (≈13 % базы) отменена: полнота
   списка важнее прежнего равенства множеств.
2. **Связь «маркер → строка» вместо равенства.** Список и маркеры по-прежнему
   строятся из одного ответа, но `build_markers` отбрасывает станции без
   координат. Каждый маркер имеет строку в панели; строка без координат маркера
   не имеет и не подсвечивается на глобусе. Клик по маркеру, выделение и
   прокрутка строки работают как в решении 2–3.
3. **Пагинация списка страны.** Первая страница — `COUNTRY_RESULT_LIMIT = 100`;
   подпись «загружено из всего» берёт всего из мирового снимка (ADR-0035), а
   кнопка «Загрузить ещё» просит следующий `offset`. При известном счётчике
   пагинация идёт до него, даже если сервер вернул страницу короче лимита
   (`hide_broken`); пустая страница закрывает выборку. Без счётчика продолжение
   обещает только полная страница. Дубликаты UUID отбрасываются, ошибка
   догрузки не стирает уже показанный список (тост `LoadMoreFailed`).
4. **Счётчик `on_map` шапки — это маркеры, а не вся база.** Подсказка страны
   по-прежнему читает мировой счётчик всех станций; «N из M» в панели означает
   загруженные строки из M станций страны.

Компромисс зафиксирован: равенство «список = маркеры» заменено вложением
«маркеры ⊆ строки». Станции без координат остаются в списке, но не на глобусе —
это ожидаемое поведение, а не рассинхронизация.
