# ADR-0046: Ритуалы слушания — таймер сна, очередь и перенос библиотеки

**Статус:** Принято  
**Дата:** 2026-11-03  
**Ревизия:** 2026-11-03 — быстрый доступ к таймеру во всех интерфейсах  
**Участники решения:** ModernByte Architecture

## Контекст

К 0.17 desktop умеет играть, искать, строить маршруты и переживать плохую
сеть, но у ежедневных ритуалов нет явных контрактов:

- нет способа остановить эфир по времени — пользователь засыпает под радио;
- `next`/`previous` ходят по видимому списку, однако край очереди и пустой
  список не описаны в интерфейсах, а MPRIS/статус всегда сообщали
  «можно вперёд/назад» при непустом списке;
- библиотека живёт только в `library.json` desktop и не переносится на
  будущий Android Companion;
- у `status --json` нет поля таймера, поэтому бар-виджеты не могут показать
  обратный отсчёт.

Аудит `docs/audit/OrbitFM-future-features.md` относит эти пункты к приоритету
B и волне 1. Нужны минимальные расширения без ломки схемы 1 и IPC.

## Решение

### 1. Таймер сна

- Длительность — целое число минут `1..=720`; UI предлагает
  15/30/45/60/90 и «выключен», IPC принимает любое значение диапазона.
- Ряд пресетов задан один раз — `settings::SLEEP_CHOICES = [0, 15, 30, 45, 60,
  90]`; настройки, шапки desktop, трей и расширения показывают один и тот же
  список, `0` означает «выключен».
- По истечении дедлайна выполняется **stop**, а не pause: эфир освобождает
  сеть и аудио-устройство. Плавное затухание громкости в v1 не делается.
- Дедлайн хранится в `Session` (`SleepTimer`), переживает закрытие окна и
  проверяется в `tick()` при открытом окне и отдельной веткой `park()` в
  простое. Выход процесса таймер не переживает — это осознанно.
- IPC: `sleep <minutes>` и `sleep clear`. Повторный `sleep <minutes>` заменяет
  дедлайн; `sleep clear` без активного таймера — no-op.
- По срабатывании показывается уведомление `NoticeKey::SleepExpired`.
- `status --json` получает аддитивное поле
  `sleep: { "minutes": 45, "remaining_secs": 2700 }` или `null`. Схема
  остаётся 1: поле только добавлено.
- Окно просит перерисовку к дедлайну, поэтому таймер срабатывает без
  пользовательских событий.

#### Быстрый доступ (ревизия 2026-11-03)

Таймер — действие «на ночь», поэтому он не должен требовать открытия окна
настроек. Одна и та же иконка часов появляется во всех основных витринах:

- **desktop**: кнопка `Icon::Clock` в правом блоке HUD (Focus), в капсуле
  Overlay и в строке Listening; в шапке панели бар-виджета — тот же
  `ui::sleep_picker`. Активный таймер подсвечен акцентом, подсказка показывает
  выбранные минуты. Выбор даёт `UiAction::SetSleepTimer`, исполняет `App`
  через `Session::set_sleep`/`clear_sleep`.
- **трей**: подменю `sleep_timer` после громкости; `TraySnapshot` несёт
  `sleep_minutes`, клик шлёт `TrayCommand::SetSleep` (SNI и macOS).
- **браузерный попап**: кнопка часов в шапке открывает всплывающий список;
  состояние читается из `status.sleep`, команды `sleep <n>`/`sleep clear` уже
  разрешены native host (ADR-0038).
- **GNOME Shell**: подменю таймера с отметкой активного варианта; статус
  опрашивается тем же `status --json`.
- **Noctalia**: отдельная кнопка не нужна — виджет открывает панель, а её
  шапка уже содержит часы; панель и попап используют один контракт статуса.

Попапы и подменю закрываются по клику вне и по `Escape`, неактивный таймер
показывает пункт «выключен» выбранным. Офлайн-состояние расширений гасит
кнопку/подменю целиком.

### 2. Очередь и края списка

- Видимая очередь — та же, что показывает активная вкладка панели: избранное,
  история или результаты поиска с действующим фильтром.
- Настройка `queue_wrap` (по умолчанию `true`): `next` после последней станции
  возвращается к первой, `previous` с первой — к последней.
- При `queue_wrap = false` шаг за край списка — no-op; кнопки, MPRIS
  `CanGoNext/CanGoPrevious` и поля `can` в `status --json` отражают
  доступность шага.
- Если текущей станции нет в видимой очереди, оба шага разрешены и ведут к
  первой/последней станции списка.
- Семантика `next`/`previous` фиксируется в `docs/interfaces/05-ipc.md` и
  `docs/interfaces/10-session.md`; отдельных новых IPC-команд нет.
- `queue_wrap` живёт в `settings.json`, меняется тумблером в категории
  «Аудио» и сохраняется сразу.

### 3. Экспорт и импорт библиотеки

- Формат — JSON схемы 1, спецификация `docs/interfaces/15-library-export.md`.
  Поля: `schema`, `app`, `exported_at`, `favorites`, `history`; станция
  сериализуется теми же полями, что `library.json`, без локальных путей.
- IPC: `library-export <path>` и `library-import <path>`; путь — остаток
  строки, абсолютный или относительно текущего каталога процесса. Браузерный
  native host эти команды не получает.
- Экспорт пишется атомарно (`storage::write_atomic`) и на Unix получает права
  `0600`: файл содержит stream URL пользователя.
- Импорт — слияние, а не замена: совпадение по `stationuuid` оставляет
  локальную запись, новые добавляются, история нормализуется и обрезается до
  `HISTORY_LIMIT`.
- Недоверенный файл проходит те же проверки, что станция из сети:
  - размер ≤ 2 МиБ, станций ≤ 5000;
  - `schema` строго 1; `app` — пусто или `orbitfm`;
  - строки санитизируются (`single_line`, потолки длины);
  - `url` и `url_resolved` — публичный `http(s)` без userinfo (ADR-0025);
  - координаты вне диапазона отбрасываются, а не отклоняют станцию;
  - некорректные станции пропускаются и попадают в `skipped`.
- Файл сохраняется только при наличии добавлений.

### 4. Локализация

Новые строки входят во все 16 каталогов и `System`: подписи таймера, подсказки
очереди и уведомление о срабатывании. Тест полноты каталога
(`src/i18n/mod.rs`) обязателен. Быстрый доступ не добавляет строк: desktop,
трей, браузер и GNOME используют `settings.sleep_timer`, `settings.sleep_off`
и шаблон `settings.sleep_minutes` с `{minutes}`; три поля продублированы в
`status.ui` для расширений (ADR-0037, схема 1).

### 5. Совместимость

- `status --json` остаётся схемой 1; добавлено только поле `sleep`, а в
  `status.ui` — аддитивные подписи `sleep_timer`, `sleep_off`, `sleep_minutes`.
- Текстовый `status` не меняется.
- Старые `settings.json` читаются с `queue_wrap = true` благодаря
  `#[serde(default)]`.
- Старые `library.json` не мигрируют: экспорт строится из текущего формата.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Пауза по таймеру вместо stop | Держит сеть и аудио-устройство; для сна хуже |
| Fade последние 2 минуты | Требует отдельной кривой громкости и таймера в аудио-ядре; отложено |
| Таймер в аудио-ядре | Не переживает закрытие окна и не виден статусу |
| Новые IPC-команды `queue-*` | Настройка и существующие `next`/`previous` покрывают сценарий |
| Импорт с заменой библиотеки | Риск потерять локальное избранное; слияние безопаснее |
| Разрешить импорт любых URL | Нарушает ADR-0025 и тянет приватные адреса в эфир |
| Отдельный бинарный формат экспорта | Android и desktop проще читают JSON; схема уже версионирована |

## Последствия

**Положительные:**

- эфир останавливается по расписанию и в открытом окне, и в простое;
- таймер включается одним кликом из desktop, трея, попапа и GNOME, не требуя
  окна настроек;
- поведение краёв очереди предсказуемо и видно MPRIS/статусу/кнопкам;
- библиотека переносится на Android без сервера и аккаунта;
- контракты остаются аддитивными, старые клиенты не ломаются.

**Отрицательные / Риски:**

- таймер не переживает выход процесса — это может удивить; фиксируется в
  документации;
- `sleep` в статусе требует обновления бар-виджетов, которые строго
  валидируют JSON (схема 1 разрешает добавление);
- импорт доверяет UUID как ключу слияния; станции без UUID пропускаются;
- экспорт содержит stream URL, поэтому права `0600` обязательны на Unix, а на
  Windows защита определяется ACL каталога пользователя.
