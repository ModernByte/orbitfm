# ADR-0027: Трёхполосный анализ эфира без PCM-tap

**Статус:** Принято  
**Дата:** 2026-10-24  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Для аудио-реактивной планеты нужны отдельные уровни Bass / Mid / High:
20–150 Гц, 150–2000 Гц и 2000–20000 Гц (см.
[`docs/ui/audio-reactive-globe.md`](../ui/audio-reactive-globe.md)).

Сегодняшний контракт [ADR-0010](0010-fft-визуализатор.md) даёт только шесть
агрегатов — centroid, spread, rolloff, flatness, flux и RMS. Полос в нём нет:
`aspectralstats` считает статистику по всему спектру, а не по диапазонам.
ADR-0010 прямо говорит, что для полос нужен PCM-tap и отдельное решение.

Ограничения:

- аудиотракт libmpv не перехватывается и не меняется: звук должен остаться
  бит-в-бит тем же;
- второй декодер/процесс запрещён — это дублирует сеть, рассинхронизируется
  с плеером и противоречит ADR-0003/ADR-0010;
- новые зависимости архитектурного уровня не добавляются;
- анализ должен работать на Linux (Wayland), Windows и macOS, а при
  недоступности фильтров — деградировать, не ломая воспроизведение.

## Решение

1. **Полосы считаются копией сигнала внутри одного lavfi-графа.** Основной
   аудиопоток проходит через `asplit`, анализ идёт по второй ветке, а на выход
   возвращается исходная ветка через `pan`. `acrossover` делит копию на три
   полосы, `amerge` складывает их в один многоканальный поток, `astats`
   измеряет RMS по каналам, `pan` выбирает из общего потока каналы основного
   сигнала. Проверено: сумма полос `acrossover` плоская, а выходной PCM
   совпадает с исходным (md5 одинаковый для stereo и mono).

2. **Два независимых `af`-фильтра с разными метками.**

   ```text
   @level:lavfi=[
     aspectralstats=measure=centroid+spread+flatness+flux+rolloff:win_size=2048,
     astats=metadata=1:reset=1
   ],
   @spectrum:lavfi=[
     asplit=2[main][analysis];
     [analysis]highpass=f=20,acrossover=split=150 2000:order=8th[lo][mi][hi];
     [lo][mi][hi]amerge=inputs=3[bands];
     [main][bands]amerge=inputs=2,
     astats=metadata=1:reset=1:measure_perchannel=RMS_level:measure_overall=none,
     pan=stereo|c0=c0|c1=c1
   ]
   ```

   `@level` сохраняет текущие шесть метрик и их ключи
   `af-metadata/level/lavfi.aspectralstats.1.*` и
   `af-metadata/level/lavfi.astats.Overall.RMS_level`.
   `@spectrum` отдаёт только полосы, поэтому старые ключи и визуализатор
   не меняются.

3. **Карта каналов `@spectrum` фиксирована.**

   | Каналы | Что это |
   |--------|---------|
   | 1–2 | основной сигнал L/R (для контроля, в полосы не входят) |
   | 3–4 | Bass L/R, <150 Гц |
   | 5–6 | Mid L/R, 150–2000 Гц |
   | 7–8 | High L/R, >2000 Гц |

   `astats` в этой ветке вызывается с `measure_overall=none`: общий RMS по
   восьми каналам смешал бы полосы с основным сигналом. Уровень полосы —
   среднее по мощности L/R, а не среднее двух значений в дБ.

4. **Mono поддерживается отдельным графом.** При моно-потоке анализ
   дублирует канал в стерео на входе и возвращает моно на выходе:

   ```text
   [in]pan=stereo|c0=c0|c1=c0,asplit=2[main][analysis];
   ...
   [main][bands]amerge=inputs=2,
   astats=metadata=1:reset=1:measure_perchannel=RMS_level:measure_overall=none,
   pan=mono|c0=0.5*c0+0.5*c1
   ```

   Карта каналов 3–8 при этом не меняется. Проверено: выходной PCM
   совпадает с исходным моно-файлом побитово. Для других раскладок
   (5.1 и т.п.) полосы отключаются, остаётся только `@level`.

5. **Раскладка выбирается после загрузки файла.** Аудио-поток читает
   `audio-params/channel-count` при `FileLoaded` и при включении анализа,
   после чего ставит нужный вариант `af`. Неизвестная раскладка — fallback
   на `@level` без полос. Это исключает попытку применить стерео-граф к
   моно-станции.

6. **Контракт данных расширяется опционально.**

   ```rust
   pub struct BandLevels {
       pub bass_db: f32,
       pub mid_db: f32,
       pub high_db: f32,
   }

   pub struct SpectrumFrame {
       // существующие поля
       pub bands: Option<BandLevels>,
   }
   ```

   `None` означает «полосы недоступны» (старый mpv/ffmpeg, нестандартная
   раскладка, ошибка графа). UI обязан работать в этом режиме: движения
   планеты переходят на полный RMS+flux, а не исчезают.

7. **Санитизация полос.** `astats` может отдать `-inf` для полностью
   подавленной полосы (тишина в диапазоне) и `NaN` при сбое. Для полос
   значения ограничиваются снизу `BAND_FLOOR_DB = -90.0`; `NaN` и
   нечисловые значения трактуются как `None` для всей тройки, чтобы не
   показывать ложный «бас». Базовые шесть метрик сохраняют текущую строгую
   проверку.

8. **Опрос остаётся 20 Гц.** На каждом тике читаются шесть ключей `@level`
   и шесть ключей `@spectrum`; при недоступности `@spectrum` — только
   базовые. Количество обращений растёт с 6 до 12 на тик; это проверяется
   замером CPU в фазе 0 плана.

9. **Fallback при отказе фильтра.** Если `set_property("af", ...)` с двумя
   фильтрами возвращает ошибку, поток повторяет установку только с
   `@level`, пишет `warn!` и продолжает воспроизведение. Полосы в этом
   сеансе недоступны. Это сохраняет инвариант ADR-0010: отказ анализа не
   ломает эфир.

10. **Честная граница возможностей.** Это три огибающие полос, а не
    покадровый спектр по бинам. Cava-визуализатор по-прежнему синтетический
    (ADR-0022), а `showspectrum`/PCM-tap не используются. Если позже
    понадобится полный спектр по бинам, это будет отдельное решение, как и
    написано в ADR-0010.

## Проверка

Проведена 2026-10-24 на локальном окружении (mpv 0.41.0, FFmpeg n9.0.2,
Linux):

- полный граф `@level` + `@spectrum` через `ffmpeg -af` даёт побитово
  одинаковый PCM с исходным сигналом (md5 `528f…4c98` для stereo и
  `cdf4…2720` для mono);
- живой mpv с двумя метками отдаёт `af-metadata/level/*` и
  `af-metadata/spectrum/*` раздельно; для тона 100 Гц + 1000 Гц каналы
  3/6 показывают сильные полосы, 4/5 — подавленные, 7/8 — высокочастотную
  утечку;
- моно-граф с дублированием в стерео и обратным `pan=mono` также сохраняет
  PCM и даёт ту же карту каналов;
- `-inf` в тихой полосе воспроизводится и требует санитизации (п. 7);
- замер CPU на 60-секундном stereo-WAV (`ffmpeg -benchmark`): `@level` —
  около 1,49 с CPU, полный граф — около 4,25 с CPU, то есть примерно 7 %
  одного ядра в реальном времени; вклад полос — около 4,6 п.п. Понижение
  порядка `acrossover` до 4-го пока не требуется.

## Уточнение приёмки (2026-10-24)

Живой замер на niri 26.04 (MP3 128 kbps, 44,1 кГц, GTX 1050 Ti): полный граф
добавляет около 15 п.п. одного ядра поверх декодирования mpv (decode-only —
1–2 %), то есть больше синтетических 7 % из `ffmpeg -benchmark`; вклад даёт
реальный аудиопоток mpv и опрос 12 свойств. Порядок 8th сохранён: качество
полос важнее, а скрытая стоимость устранена на уровне Session — пока окно
закрыто, `analysis_needed` ложно и `settle_analysis` снимает анализ; при
показе граф возвращается. Скрытый эфир: 19–23 % → 2 % одного ядра.

Живой моно-поток (локальный mp3, один канал) прогнан через ignored-тест
`produces_fft_metrics_for_live_stream`: полосы появились, значит моно-граф с
`pan` принят mpv. Реконнект проверен ignored-тестом
`reconnects_after_live_stream_drop`: обрыв и перезапуск локального HTTP-потока
дают `Reconnecting` → `Started` без потери управления. Побитовая проверка PCM
и unit-тесты раскладок остаются в силе.

## Уточнение: чтение `af-metadata` на libmpv 0.37 (2026-11-01)

Официальный AppImage 0.17.0-rc.1 собран на Ubuntu 24.04 с libmpv 0.37.0 и
FFmpeg 6. На этой связке периодическое чтение вложенного ключа
`af-metadata/<label>/<metric>` роняет процесс SIGSEGV внутри
`mpv_get_property`; gdb показывает путь `read_metric` → `read_spectrum` →
`poll_spectrum`. Падение воспроизводится и на одном `astats`, поэтому
причина — не `aspectralstats`, а сам обход ключей свойства.

Проверено вручную: libmpv 0.40.0 + FFmpeg 7.1 и libmpv 0.41.0 + FFmpeg 8
вложенные ключи отдают без падения; libmpv 0.37.0 + FFmpeg 6 падает. При
этом чтение карты целиком — `af-metadata/level` и `af-metadata/spectrum`
как одна строка JSON — на 0.37 стабильно (две минуты опроса каждые 50 мс,
SIGSEGV нет) и тем же вызовом работает на 0.40/0.41.

Решение: воркер больше не читает отдельные ключи. Обе карты забираются
целиком через `get_property::<String>("af-metadata/<label>")`, разбираются
`serde_json` и индексируются по именам метрик. Путь, падающий в 0.37, не
используется; версия libmpv для анализа больше не важна, визуализатор
включается на всех поддерживаемых сборках. Эфир, реконнект и профиль
буфера не затрагиваются. Отказ только анализа соответствует инварианту
ADR-0010 и п. 9 этого ADR.

Эмпирическая приёмка: `src/audio/worker.rs` с картами проверен на связке
0.37.0 + FFmpeg 6 из официального AppImage и на системном 0.41.0;
`bands=true`, падений нет.

## Последствия

**Положительные:**

- появляются настоящие уровни Bass/Mid/High без PCM-tap, второго декодера
  и новых зависимостей;
- основной аудиопоток остаётся прежним, громкость и маршрут libmpv не
  меняются;
- старые шесть метрик и визуализатор не ломаются: они живут в `@level`;
- fallback позволяет работать на сборках mpv без `acrossover`/`amerge`;
- тот же механизм пригодится другим визуальным эффектам, которым нужны
  полосы.

**Отрицательные / Риски:**

- граф тяжелее текущего: `acrossover` 8-го порядка, `amerge`, `astats` и
  `pan` работают в аудиопотоке; нужен замер и, при необходимости,
  понижение порядка до 4-го;
- анализатор добавляет задержку/групповую задержку в тракт визуализации;
  на слух она не влияет, но синхронизация с MPRIS/видео не гарантируется;
- `astats`/`aspectralstats` и `acrossover` должны присутствовать в сборке
  libavfilter; Flatpak/Windows/macOS-сборки проверяются отдельно;
- моно-путь меняет внутреннюю раскладку на стерео и обратно; это проверено
  побитово, но остаётся хрупким местом при смене FFmpeg;
- две карты JSON (`af-metadata/level` и `af-metadata/spectrum`) на тик:
  разбор нескольких килобайт каждые 50 мс — небольшая, но постоянная
  нагрузка при включённом анализе;
- полосы — огибающие, а не бины; для «настоящей» cava-спектрограммы этого
  недостаточно.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| PCM-tap через `ao=pcm` и собственный вывод | Меняет аудиотракт, дублирует ответственность libmpv, требует пересмотра ADR-0003 |
| Второй mpv/ffmpeg-процесс | Двойная сеть, рассинхронизация, лишний процесс; запрещено ADR-0010 |
| Три последовательных `lavfi`-фильтра с полосовыми фильтрами | Каждый фильтр изменил бы звук; последовательная цепь не даёт копию |
| `azmq`/внешний side-channel | Новая зависимость libzmq, сложная кросс-платформенная доставка |
| Разбор лога `astats` | Хрупко, зависит от loglevel и формата, не является контрактом |
| Только `aspectralstats` и эвристика полос из centroid/spread | Не даёт реальных уровней Bass/Mid/High; целевой пайплайн — полосы |
| `acrossover` + `amerge` + `astats` (выбрано) | Сохраняет звук, использует штатный metadata-контракт mpv, без новых зависимостей |
