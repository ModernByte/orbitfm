# ADR-0005: Single-instance и IPC

**Статус:** Принято, ред. 2 (2026-10-31) — каталог сокета проверяется на
владельца и права на всех Unix, macOS получил `$TMPDIR/orbitfm-<uid>`, Windows —
персональное имя pipe; ранее — базовый single-instance и IPC  
**Дата:** 2026-10-21  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

OrbitFM должен работать как единый процесс:

- Аудиосессия продолжает играть при закрытии окна
- Повторный запуск бинарника не создаёт второй экземпляр, а отправляет команду существующему
- Noctalia и другие клиенты управляют окном через простые команды (`toggle`, `show`, `hide`, `play` и т.д.)

## Решение

### Модель процесса

1. **Единый процесс** владеет:
   - libmpv-сессией
   - IPC-сервером
   - GUI (когда окно видимо)

2. **При запуске**:
   - Проверяется наличие сокета (`$XDG_RUNTIME_DIR/orbitfm.sock` на Linux)
   - Если сокет жив — отправляется команда и процесс завершается
   - Если сокета нет — процесс становится демоном + поднимает GUI (или ждёт команды)

3. **Закрытие окна** = Hide (окно скрывается, процесс продолжает жить)

### Транспорт IPC

| Платформа | Транспорт              | Путь / имя                     |
|-----------|------------------------|--------------------------------|
| Linux     | Unix Domain Socket     | `$XDG_RUNTIME_DIR/orbitfm.sock` |
| Windows   | Named Pipe             | `\\.\pipe\orbitfm-<fnv1a64 хеш профиля>` |
| macOS     | Unix Domain Socket     | `$TMPDIR/orbitfm-<uid>/orbitfm.sock` |

*С ред. 2:* каталог сокета — часть контракта, а не удобство. На Linux
`XDG_RUNTIME_DIR` обязан быть абсолютным, принадлежать эффективному UID и иметь
права `0700`; на прочих Unix каталог `$TMPDIR/orbitfm-<uid>` создаётся с `0700`
и проверяется теми же правилами; сам сокет — `0600`. Bind отказывается при
несоответствии, а не понижает права молча. На Windows имя pipe включает хеш
`USERPROFILE`/`USERNAME`, поэтому сессии разных пользователей не сталкиваются;
`first_pipe_instance` исключает захват имени вторым экземпляром,
`reject_remote_clients` закрывает сетевые подключения. DACL по умолчанию не
переопределяется — риск и причина описаны в `SECURITY.md`.

### Протокол команд (текстовый, построчный)

Примеры:
```
toggle
show
hide
play <stationuuid>
stop
status
quit
```

Ответы — простой текст или JSON (решим в спецификации модуля).

### Альтернативы

| Вариант                  | Причина отклонения |
|--------------------------|--------------------|
| D-Bus только             | Хуже кроссплатформенность, избыточно для простых команд |
| Отдельный демон + GUI-процесс | Усложняет lifetime аудиосессии и shared state |
| HTTP localhost           | Лишний overhead и поверхность атаки |

## Последствия

**Положительные:**
- Один процесс — проще управление ресурсами и аудио
- Простой и понятный IPC для Noctalia и скриптов
- Естественная поддержка «скрыть в фон»

**Отрицательные / Риски:**
- Нужна аккуратная обработка «зомби»-сокетов
- На Windows named pipe имеет свои особенности безопасности: собственный DACL
  не выставляется, действует дефолтный (остаточный риск — `SECURITY.md`)
