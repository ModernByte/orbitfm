# ADR-0008: Геопространственный поиск (Raycasting + Point-in-Polygon)

**Статус:** Принято  
**Дата:** 2026-10-21  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

При клике по 3D-глобусу нужно определить, в какую страну попал луч.  
Требования:

- Работа offline
- Достаточная точность для выбора страны
- Приемлемая скорость (клик должен ощущаться мгновенным)

## Решение

Стек:

- **geo** + **geojson** — парсинг и геометрические операции
- **rstar** — R-Tree индекс по bounding box стран
- Датасет границ: Natural Earth 110m (или эквивалент) в формате GeoJSON, поставляется offline в `assets/geojson/`

### Алгоритм (по SRS)

1. Луч из координат курсора через обратную матрицу камеры пересекает сферу.
2. Точка пересечения переводится в географические координаты (φ, λ).
3. По R-Tree быстро отфильтровываются страны-кандидаты по bounding box.
4. Для кандидатов выполняется точная проверка `geo::contains` (Point-in-Polygon).
5. Полигоны, пересекающие антимеридиан (±180°), нормализуются заранее.

### Почему именно этот стек

- `geo` — стандарт де-факто в Rust-геоэкосистеме (GeoRust)
- `rstar` — эффективный R-Tree, хорошо подходит для предварительной фильтрации
- Offline-first — не зависит от сетевых геокодеров

### Альтернативы

| Вариант                    | Причина отклонения |
|----------------------------|--------------------|
| Только `geo::contains` без индекса | Слишком медленно на полном наборе стран |
| Внешний сервис геокодинга  | Нарушает offline-требование |
| Упрощённые прямоугольники стран | Неприемлемая точность |

## Последствия

**Положительные:**
- Полностью offline
- Хорошая скорость за счёт двухэтапного поиска
- Использование зрелых библиотек

**Отрицательные / Риски:**
- Нужно аккуратно подготовить и нормализовать GeoJSON (антимеридиан, валидность полигонов)
- Размер ассета 110m приемлем, более детальные датасеты (50m/10m) могут быть избыточны
