# ADR-0016: Асинхронный favicon-загрузчик

**Статус:** Принято, ред. 2 (2026-10-29) — исходящий fetch переезжает в `src/services/artwork.rs`,
п. 1–4 и 7 уточнены; ранее — только дополнено форматами и лимитами ADR-0025  
**Дата:** 2026-10-23  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

**Причина ред. 2 (0.13.0-rc.2).** Два дефекта, найденных аудитом: п. 3 в прежней
формулировке прямо противоречил слоистости — сетевая политика не могла жить в
App-оркестраторе, потому что тем же путём приватные адреса уходили в MPRIS
(SEC-02); п. 2/4 описывали границы как ориентир, а не инвариант, из-за чего
кэш мог превысить `MAX_CACHED` и потерять слот `in_flight` (SEC-01).

## Контекст

Референс-макет `docs/ui/OrbitFM_ Радио Земли в неоне.png` показывает круглые
лого станций (favicon) в three зонах: карточка now-playing в верхнем HUD,
аватары в строках панели станций и обложка в нижнем transport. ADR-0015 отложил
favicon-слой как «отдельное решение по зависимости» (фаза 6
`docs/ui/implementation-plan.md`).

Факты на момент решения:

- `Station.favicon: Option<String>` уже приходит из Radio Browser и публикуется
  в MPRIS как `artUrl` (`src/services/`, `src/app.rs::sync_media`);
- в зависимостях уже есть `reqwest` (rustls) и `image` 0.25 с feature `jpeg`
  (`Cargo.toml`);
- egui/eframe 0.37 умеет загружать текстуры из CPU-пикселей через
  `Context::load_texture` без дополнительных crate'ов;
- `egui_extras` с image-loader тянул бы формат-декодеры и свой кэш, дублируя
  уже имеющиеся `reqwest`/`image`.

Ограничения:

- UI-модули не выполняют сеть и не блокируют GUI-поток (ADR-0015, п. 1);
- `render` не знает доменных типов; загрузчик относится к presentation-слою;
- Linux First; без тяжёлых runtime-зависимостей.

## Решение

1. **Новых crate'ов нет.** Декодирование — существующий `image`; к `features`
   добавляются `png` и `ico` (favicon Radio Browser — преимущественно PNG/ICO/JPEG).
   HTTP — существующий `reqwest` с User-Agent из ADR-0004.
   *С ред. 2:* `ico` удалена из `features`, добавлена `webp` — allowlist
   форматов сужен до PNG/JPEG/WebP по сигнатуре файла (ADR-0025, п. 1).
   `reqwest` остаётся единственной HTTP-зависимостью.

2. **`FaviconCache` живёт в `src/ui/images.rs` (presentation-слой).**
   Состояние на URL: `Loading`, `Ready(TextureId)`, `Failed`. Ключ — сам URL
   (`favicon` станции). Кэш ограниченный: записи `Ready` хранятся до
   `MAX_CACHED` (256), при переполнении вытесняются давно невидевшиеся кадры;
   `Failed` кэшируется, чтобы не долбить сервер повторно.
   *С ред. 2:* состояний четыре — `Queued`, `Loading`, `Ready(TextureHandle)`,
   `Failed`, и каждая запись несёт номер поколения; `MAX_CACHED` — жёсткий
   инвариант: при исчерпанном потолке вставка новой записи **отказывается**, а
   не превышается, вытеснение ступенчатое (`Failed` → давно не видевшаяся
   `Ready` → `Queued` → `Loading`) (ADR-0025, п. 13).

3. **Загрузка — одна фоновая задача на favicon через `runtime` App.**
   UI-модуль в кадре вызывает `request(url)`: кэш помечает `Loading`, считает
   in-flight и возвращает `None`; App-оркестратор (единственная точка побочных
   эффектов) спавнит `reqwest::get` с таймаутом, декодирует `image`,
   нормализует в RGBA и загружает текстуру `ctx.load_texture` с
   `TextureOptions::LINEAR`. Ответ приходит в канал; App применяет его к кэшу и
   делает `request_repaint`. GUI-поток не блокируется никогда.
   *С ред. 2:* точка входа одна — `texture(url)`: она возвращает готовую
   текстуру либо ставит URL в очередь. Сетевой путь переезжает в
   `src/services/artwork.rs` (`ArtworkFetcher::fetch`): политика цели, хопп-цикл
   и лимит тела относятся к слою исходящей сети (AGENTS.md §4.2) и нужны не
   только UI — тем же путём гейтятся метаданные MPRIS (ADR-0025, п. 8, 12).
   App спавнит `fetch`, декодирует (`ui::images::decode_favicon`) и передаёт
   результат в кэш; `ctx.load_texture` вызывает сам кэш в `poll(&ctx)` на
   следующем кадре — аллокация текстуры происходит на UI-потоке, а сеть и
   декод нет.

4. **Лимит одновременных загрузок — 8.** Лишние заявки остаются в очереди
   `Loading` и стартуют по мере освобождения слотов. Это защищает от шквала из
   100–200 строк панели.
   *С ред. 2:* отдельной неограниченной коллекции очереди нет — заявка живёт
   в той же карте записей как `Queued`, поэтому граница очереди следует из
   границы записей. Canal результатов ограничен тем же числом слотов, задачи
   шлют `try_send` (не `send().await`), а слот страхуется RAII-объектом:
   паника, `?` и ранний выход освобождают `in_flight` ровно один раз
   (ADR-0025, п. 13).

5. **Placeholder — инициалы.** Пока favicon не готов или ошибка — рисуется
   круг с первой буквой названия станции (отрисовка в `ui/widgets.rs`).
   Текстовая информация в строке от этого не зависит.

6. **Размер и память.** Изображение ресамплируется до 64×64 RGBA (4 KiB на
   текстуру; 256 кэшей ≤ ~1 MiB GPU/CPU). Аллокации — вне горячего пути
   загрузки; в кадре только хэш-поиск.

7. **Границы.** `images.rs` не импортирует `AudioEngine`, `RadioBrowserClient`,
   `GeoService`; доменные типы станций в кэш не попадают — только URL и
   `TextureId`. Сетевой клиент и `runtime` передаёт App.
   *С ред. 2:* правило усилено — `ui` не делает сеть вообще: ни `reqwest`, ни
   политику цели, ни таймауты. Из `presentation` в `services` уходит только
   ссылка-строка и возвращается только декодированная текстура. Обратной
   зависимости нет: `services` не знает ни `egui`, ни пикселей.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| `egui_extras` + image-loader | Дублирует `reqwest`/`image`, свой кэш и lifecycle; больше зависимостей ради того же результата |
| Синхронная загрузка в кадре | Блокирует GUI — прямой запрет ADR-0015 |
| Кэш на диске | Favicon дёшевы, HTTP-кэша reqwest достаточно; диск — лишняя сложность и мусорные файлы |
| SVG-фавиконы через `resvg` | Radio Browser отдаёт растр; SVG в выборках почти нет, лишний тяжёлый декодер |
| Отдельная подсистема `library` для картинок | Это presentation-кэш, а не данные пользователя; в `library` хранить нечего |

## Последствия

**Положительные:**

- UI достигает 100% макета: лого станций в списке и transport (с ред. 2026-10-28
  карточка now-playing из верхнего HUD убрана — ADR-0015, `● LIVE` остался);
- ни одной новой crate'овой зависимости — только features у `image`;
- кэш ограниченный, предсказуемый по памяти; ошибки не долбят сервер.

**Отрицательные / Риски:**

- favicon-хосты Radio Browser бывают медленными/мёртвыми — смягчается
  таймаутом, `Failed`-кэшем и placeholder-инициалами;
- 64×64 достаточно для круглых аватаров 20–44 px, но логотип на retina-масштабе
  может выглядеть мягко; при необходимости размер выносится в константу;
- `TextureId` валиден только живого `Context` — кэш не переживает пересоздание
  окна (для single-instance процесса это не сценарий).
