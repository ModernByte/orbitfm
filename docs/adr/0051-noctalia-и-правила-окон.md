# ADR-0051: Noctalia и правила окон как цели интеграции

**Статус:** Принято  
**Дата:** 2026-11-03  
**Участники решения:** ModernByte Architecture

## Контекст

Установщик интеграций (ADR-0037) и страница «Интеграции» (ADR-0042) покрывают
14 целей: бары и панели, окружения, браузеры. Самой ходовой оболочки проекта в
списке нет: плагин Noctalia распространяется как git-источник (ADR-0006,
ADR-0007, `catalog.toml` в корне), а правила окон лежат в `wm-configs/` и, по
модулю 08 §2, «копируются пользователем».

То есть установка на реально используемой машине требует ручных шагов:

```bash
noctalia msg plugins source add orbitfm git https://github.com/ModernByte/orbitfm
noctalia msg plugins enable modernbyte/orbitfm
cp wm-configs/orbitfm-niri.kdl ~/.config/niri/cfg/orbitfm.kdl   # + строка include
```

Владелец потребовал: плагин Noctalia и настройки окон должны ставиться одной
кнопкой на той же странице «Интеграции», а не по инструкции из README.

Отдельная боль — обнаружение. После `integration uninstall` каталоги, которые
создал установщик, остаются пустыми, и `target_detected` по такому каталогу
считает цель обнаруженной: обнаружение кормится собственным следом. Решение
должно это исключить, иначе новые цели унаследуют дефект.

## Решение

### 1. Три новые цели

| Цель | Группа | Что даёт |
|------|--------|----------|
| `noctalia` | Окружения | бар-виджет OrbitFM для Noctalia |
| `niri` | Правила окон | KDL-правила из `wm-configs/orbitfm-niri.kdl` |
| `hyprland` | Правила окон | правила из `wm-configs/orbitfm-hyprland.conf` |

Собственные имена целей не переводятся — как имена оболочек в
`wm::Desktop::name`. Новая группа получает подпись `group_windows` во всех 16
каталогах i18n; порядок групп: бары, окружения, правила окон, браузеры.

### 2. Что делает кнопка «Установить»

**`noctalia`.** Цель не копирует файлы плагина, а регистрирует официальный
источник проекта средствами самой Noctalia — фиксированным набором аргументов:

```
noctalia msg plugins source add orbitfm git https://github.com/ModernByte/orbitfm
noctalia msg plugins enable modernbyte/orbitfm
```

Проверено на живой оболочке (Noctalia 5.4.0): `source add <имя> path <каталог>`
тоже работает, но плагин с тем же `id` из другого источника перекрывается —
`plugins list` начинает показывать наш источник, а после `source remove` виджет
остаётся **выключенным**, хотя git-источник никуда не делся. Копия файлов в
каталоге установщика ломает канал обновлений (`noctalia msg plugins update
orbitfm` перестаёт быть про наш виджет) и требует ручного восстановления.
Поэтому канал один — git-источник Noctalia, а установщик ничего не копирует и
ничего не скачивает сам: загрузку делает оболочка.

- Перед включением цель читает `noctalia msg plugins list` и запоминает, был ли
  виджет включён; в квитанцию ложатся `source_added` (источник добавили мы) и
  `was_enabled`.
- Если источник `orbitfm` уже зарегистрирован, `source add` не выполняется —
  кнопка становится идемпотентной и на машине владельца просто включает виджет.
- Снятие: `disable modernbyte/orbitfm` и `source remove orbitfm` — только если
  источник добавляли мы. После снятия состояние включённости восстанавливается,
  если плагин всё ещё доступен из чужого источника: удаление нашей записи не
  должно выключать виджет, который пользователь включал сам.
- Если `noctalia` нет в PATH или оболочка не отвечает, установка возвращает
  причину в `detail` и ничего не пишет: без оболочки регистрировать нечего.

**`niri`.** Пишет `~/.config/niri/cfg/orbitfm.kdl` (содержимое —
`wm::NIRI_SNIPPET`) и добавляет в `~/.config/niri/config.kdl` ровно одну строку
`include "./cfg/orbitfm.kdl"`, если такой строки там ещё нет. Перед первой
правкой создаётся копия `config.kdl.orbitfm.bak` — тот же приём, что правка
Waybar в ADR-0042 §2. Снятие удаляет ровно свою строку (сравнение целой строки,
не подстроки), затем файл правил. niri 26.04+ перечитывает конфиг сам,
отдельной команды нет.

**`hyprland`.** Пишет `~/.config/hypr/orbitfm.conf` (содержимое —
`wm::HYPRLAND_SNIPPET`) и применяет правила на текущий сеанс через
`hyprctl keyword windowrulev2 …` — тот же фиксированный список из 14 правил,
что в шаге мастера (ADR-0041). Строку `include` в чужой конфиг установщик **не
пишет**: ветка Hyprland переводит конфиг на Lua, и синтаксис include, на который
можно сослаться как на верный, на момент решения не верифицирован. Вместо этого
GUI печатает готовую строку и путь файла — как это делают цели-бары.

### 3. Обнаружение

| Цель | Считается обнаруженной, если |
|------|------------------------------|
| `noctalia` | `noctalia` в PATH или `~/.local/state/noctalia` — каталог |
| `niri` | `niri` в PATH или `~/.config/niri/config.kdl` — файл |
| `hyprland` | `hyprland`/`hyprctl` в PATH или `~/.config/hypr` — каталог |

Запрет на самоподдерживающееся обнаружение: цель не может стать обнаруженной из-за
пути, который создал установщик. Отсюда два правила — файлы правил пишутся
только в каталоги, принадлежащие оболочке (`~/.config/niri`, `~/.config/hypr`),
а `noctalia` вообще не создаёт файлов: её след живёт в состоянии оболочки. Пустые
каталоги, созданные установщиком, снимаются при `uninstall` (п. 4), и старые
цели (`omarchy`, `gnome`, `plasma6`) перестают врать после удаления.

### 4. Квитанция

Схема остаётся `1`, поля аддитивны и читаются со `#[serde(default)]`:

- `dirs[]` — каталоги, созданные установщиком; при снятии удаляется только
  пустой каталог, непустой остаётся;
- `lines[]` — пары «файл + точная строка», добавленные в чужой конфиг; снятие
  убирает ровно эти строки и больше ничего;
- `source_added` и `was_enabled` — признаки цели `noctalia`: добавляли ли мы
  источник и был ли виджет включён до установки. Снятие опирается на них, чтобы
  не выключить чужой виджет и не удалить чужой источник.

### 5. Границы

- Одна цель за один вызов, `--force` для изменённых файлов — без изменений
  (ADR-0037, п. 5).
- Внешние команды — только фиксированный список argv без подстановки
  пользовательских строк: `noctalia msg plugins {list, source add, source
  remove, enable, disable}`, `hyprctl keyword windowrulev2 <правило из кода>`.
  Загрузку плагина делает сама Noctalia; установщик не качает ничего.
- Правка чужого конфига одна и только одна: строка `include` у niri, с бэкапом
  и удалением по квитанции. Это распространение ADR-0042 §2 на новый формат, а
  не разрешение редактора конфигов.
- Браузерный native host команды интеграций не получает (ADR-0038).
- `status --json` и поток `events` схему не меняют: состояния целей остаются в
  `orbitfm integration status` и на странице настроек.

## Альтернативы

- **Оставить плагин только как git-источник.** Требует сети, двух команд и
  ручной кнопки в оболочке; против запроса владельца на одну кнопку.
- **Ставить плагин копией файлов через `path`-источник.** Проверено и отклонено:
  перекрывает канал обновлений Noctalia, а `source remove` оставляет виджет
  выключенным — удаление нашей кнопки ломало бы чужую настройку.
- **Править конфиг Hyprland include-строкой.** Отклонено: верифицированного
  синтаксиса для текущей ветки нет, а ошибка в чужом конфиге дороже недостающей
  кнопки.
- **Сделать «Noctalia + окна» одной целью.** Отклонено: разное обнаружение,
  разное снятие и разная природа файлов; массовая установка против ADR-0037.
- **Редактировать конфиг через GUI-редактор целиком.** Отклонено: установщик не
  должен понимать язык конфиков оболочек, кроме точечной строки include.

## Последствия

- Целей стало 17: растут `Target`, `TargetGroup`, `HELP`, `TARGET_LIST`,
  `parse()` и справочник CLI в README и wiki.
- Ритуал локальной выкатки ставит обнаруженные цели — на машине приёмки это
  `chrome`, `firefox`, `noctalia`, `niri`; `hyprland` остаётся «не обнаружено».
- Модуль 08 §2 больше не может утверждать, что правила «только копируются
  пользователем»: для niri и Hyprland есть кнопка.
- Побочный эффект пустых каталогов закрыт на будущее, старые цели после снятия
  перестают считаться обнаруженными.

## Дополнение (2026-11-10): правила матчат пару «app-id + заголовок»

Правило само по себе ничего не значит, если окно не отдаёт матчерам нужные
поля. На niri `match app-id="org.modernbyte.OrbitFM" title=...` требует
ОБА поля, а `float`/`center`/`stayfocused` в сниппете Hyprland — классовые.
Отсюда инвариант: любое новое окно OrbitFM обязано выставлять
`app_id = org.modernbyte.OrbitFM` тем же билдером, что и заголовок
(корневые прогоны — `main.rs::run_window`, дочерние immediate-вьюпорты —
билдеры в `src/app.rs`). Для окон настроек и предупреждения сна это
исправлено в 0.21.0-rc.4 (ADR-0053 и ADR-0058, «Уточнение (2026-11-10)»).

Проверка при правке правил: `niri msg --json windows` должен показывать у
каждого окна OrbitFM `App ID: "org.modernbyte.OrbitFM"`. Пустой (`null`)
app-id — окно не получит ни размера, ни плавающего режима.
