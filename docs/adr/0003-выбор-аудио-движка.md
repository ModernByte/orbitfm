# ADR-0003: Выбор аудио-движка

**Статус:** Принято  
**Дата:** 2026-10-21  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

OrbitFM должен надёжно воспроизводить интернет-радиостанции (HLS, AAC, MP3, OGG и др.), обрабатывать сетевые обрывы и переподключения, а также (в перспективе) отдавать PCM-данные для FFT-визуализатора.

Требования:
- Высокая устойчивость к нестабильным потокам
- Минимальная задержка старта
- Кроссплатформенность
- Возможность интеграции с MPRIS / системными медиа-контролами

## Решение

Используем **libmpv** (C API) через безопасную Rust-обёртку.

- Низкоуровневый доступ: `libmpv-sys` или собственный bindgen
- Высокоуровневая обёртка: собственный модуль `audio::mpv_engine` (или существующий crate `libmpv`, если он актуален)

### Обоснование

libmpv — проверенный временем движок (основа mpv). Официальный C API (`client.h`) предоставляет:

- `mpv_create` / `mpv_initialize`
- Команды и свойства
- Обработку сетевых стримов «из коробки»
- Возможность получения PCM через audio-filter / IPC

Источник: официальная документация mpv (`DOCS/man/libmpv.rst`, `include/mpv/client.h`).

## Альтернативы

| Вариант              | Причина отклонения |
|----------------------|--------------------|
| rodio + symphonia    | Слабее поддержка сетевых HLS/AAC-потоков и реконнекта |
| gstreamer            | Значительно тяжелее, сложнее встраивание |
| cpal + ручной декодер| Слишком низкий уровень, много собственной работы |
| miniaudio            | Меньше готовой поддержки радио-стримов |

## Последствия

**Положительные:**
- Отличная устойчивость к сетевым проблемам
- Широкая поддержка форматов
- Возможность FFT через audio-filter

**Отрицательные / Риски:**
- Зависимость от системной библиотеки `libmpv` (или статическая линковка)
- Необходимо следить за `LC_NUMERIC=C`
- FFI — нужна аккуратная безопасная обёртка
