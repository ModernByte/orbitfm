# ADR-0043: Офлайн-снимок станций и адаптивное аудио

**Статус:** Принято  
**Дата:** 2026-11-01  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич

## Контекст

OrbitFM зависит от Radio Browser: без сети глобус остаётся геометрической
моделью без заливки, маркеры пустеют, а выбор страны заканчивается карточкой
ошибки. ADR-0004 определяет кэш станций на 512 записей, но он живёт только в
памяти процесса и не переживает перезапуск. При этом в приложении уже есть
мировой снимок (ADR-0035): 1000 станций и счётчики стран, которые приходят
одним запросом после старта.

Вторая проблема — качество сети. `ReconnectPolicy` (ADR-0003) повторяет тот же
URL пять раз с растущей паузой. Если ссылка 320 kbps не тянет, повтор не
помогает: нужен более лёгкий поток. Radio Browser не предоставляет отдельный
API альтернатив, но в каталоге обычно есть дубли одной станции с меньшим
битрейтом.

Ограничения:

- политика SSRF и `publishable` (ADR-0025, ADR-0040) не ослабляются;
- snapshot не должен расти бесконечно и не должен читаться как доверенный
  конфиг;
- запись — атомарная и durable, как у библиотеки и настроек;
- новые сетевые запросы допустимы только после сбоя, а не на каждом кадре;
- MPRIS, IPC-схема и настройки сохраняют обратную совместимость.

## Решение

### 1. Файл снимка

`$XDG_DATA_HOME/orbitfm/cache/stations-snapshot.json` (`~/.local/share/...`
по умолчанию), схема 1:

```json
{
  "schema": 1,
  "saved_at": 1770000000,
  "stations": [
    {
      "uuid": "…",
      "name": "…",
      "url": "https://…",
      "countrycode": "DE",
      "country": "Germany",
      "state": "Berlin",
      "tags": "jazz",
      "bitrate": 128,
      "codec": "MP3",
      "votes": 421,
      "lat": 52.52,
      "lon": 13.40
    }
  ]
}
```

- не более **500** станций, только записи с координатами, публичным
  `url_resolved` и голосами `> 0`;
- компактный JSON (без pretty-print), жёсткий потолок **512 КиБ**;
- `saved_at` — Unix-время; снимок старше 24 часов помечается «устаревшим»,
  но остаётся пригодным для показа;
- файл не является конфигом: любая ошибка чтения/схемы игнорируется, снимок
  перезаписывается при следующем успешном ответе.

Запись выполняет `storage::write_atomic`, поэтому оборванный JSON не появляется.
Снимок сохраняется после каждого успешного мирового снимка; сетевой запрос при
этом не добавляется.

### 2. Старт и деградация

`WorldBaseline` загружает снимок **до** первого сетевого запроса. Пока сеть не
ответила, карта закрашивается по счётчикам снимка, а не остаётся пустой.
Когда `/json/countrycodes` и мировой топ приходят, живые данные заменяют
снимок и снимок обновляется. Если оба запроса не удались:

- загруженный снимок остаётся активным, `WorldBaseline::offline() == true`;
- маркеры строятся из снимка;
- выбор страны/жанра, поиск по имени и повтор рулетки при сетевой ошибке
  получают локальную выборку из снимка (страна — по `countrycode`, жанр — по
  вхождению тега, имя — по подстроке); в панели показывается пометка
  «офлайн-снимок», а не пустая ошибка;
- `resolve_station` ищет UUID сначала в текущей выдаче, затем в снимке;
- воспроизведение из снимка по-прежнему требует сети, но UI остаётся живым и
  объясняет причину отказа.

Счётчики стран в офлайн-режиме — это количество станций снимка, а не всей базы;
это осознанная деградация, подписанная в легенде карты как «снимок».

### 3. Адаптивный буфер

`AudioCommand` получает `SetCacheProfile { economy: bool }`. В обычном режиме
действуют значения libmpv по умолчанию; в экономичном worker увеличивает
`demuxer-max-bytes` (256 МиБ) и `cache-secs` (60 с), чтобы сгладить короткие
провалы, не меняя URL. Умолчания снимаются с libmpv при старте worker'а и
восстанавливаются при выходе из режима. Ошибка установки свойства не фатальна
и только логируется.

Переход в экономичный режим:

- состояние `Reconnecting` с попыткой ≥ 2, либо `Buffering`, длящееся дольше
  трёх секунд;
- режим сбрасывается при `Started`/`Playing` после успешного старта и при
  ручном выборе новой станции.

### 4. Fallback по битрейту

При переходе в экономичный режим Session один раз на станцию ищет альтернативу:

1. **Сначала локальная выборка**: снимок в памяти (офлайн) или мировой топ
   каталога (онлайн); та же нормализованная строка имени, другой UUID,
   `bitrate > 0` и меньше текущего (если текущий битрейт неизвестен — любой
   поток с битрейтом), другой `url_resolved`, публичный адрес;
2. **Затем каталог**: один запрос `search` по имени (`limit = 20`,
   `hide_broken = true`), та же фильтрация; запрос не повторяется чаще одного
   раза на станцию за сессию;
3. найденная станция запускается обычным `start_station`: проверка
   `publishable`, история, click-tracking и MPRIS остаются прежними;
4. если альтернативы нет, работает текущий reconnect — ошибка не подменяется
   выдуманной станцией.

Успешная замена показывает тост «Экономный поток: {bitrate} kbps» и включает
индикатор `ECO` рядом с битрейтом в transport. `ECO` сбрасывается при выборе
другой станции. Внешние потоки `url:` не ищут альтернатив: у них нет записи в
каталоге.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Хранить весь кэш Radio Browser (512) на диск | Не переживает перезапуск в текущем виде, но 512 записей без координат хуже для карты; снимок 500 с координатами решает обе задачи |
| MessagePack | Нужен новый crate; JSON при 500 записях и так < 512 КиБ, читается глазами |
| Всегда загружать топ-1000 при старте | Трафик и задержка; снимок даёт мгновенный первый кадр, живой запрос идёт фоном |
| Повторять тот же URL бесконечно | Не помогает при нехватке полосы; остаётся только как последний шаг |
| Искать альтернативу на каждом кадре | Сеть и CPU в момент, когда они и так перегружены |
| Понижать битрейт через транскодирование | libmpv не транскодирует; это новый медиа-путь и нагрузка |

## Последствия

**Положительные:**

- глобус, маркеры и список стран работают без сети;
- снимок ограничен по размеру, времени и схеме;
- при плохой сети приложение пробует более лёгкий поток вместо пяти
  одинаковых ошибок;
- новых зависимостей и сетевых путей нет.

**Отрицательные / Риски:**

- офлайн-счётчики стран не равны полной базе — легенда обязана это объяснять;
- альтернатива ищется по имени: возможна станция-тёзка из другой страны,
  поэтому фильтр требует совпадения нормализованного имени;
- увеличение буфера повышает задержку старта в экономичном режиме;
- снимок раскрывает список прослушиваемых станций локальному пользователю —
  это те же данные, что уже лежат в `library.json`.
