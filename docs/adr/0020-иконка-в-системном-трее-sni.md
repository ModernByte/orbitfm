# ADR-0020: Иконка в системном трее (StatusNotifierItem на ksni)

**Статус:** Предложено  
**Дата:** 2026-10-23  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Правило проекта — «закрытие окна = Hide, процесс живёт» (ADR-0018), и у пользователя
должен остаться способ управлять радио, когда окно скрыто: показать окно, пауза/стоп,
переключить станцию, изменить громкость, выйти. Сейчас для этого есть только
CLI/IPC (`orbitfm toggle|play|stop|volume|quit`, ADR-0005), Noctalia-виджет (ADR-0007)
и медиа-клавиши через MPRIS (ADR-0006). Слот «Системный трей» в ROADMAP (Этап 5) не
реализован.

Проверено в целевом окружении (Linux, Wayland, niri + Noctalia 5.3.0):

- `org.kde.StatusNotifierWatcher` принадлежит Noctalia, `IsStatusNotifierHostRegistered = true`
  — хост трея есть и работает (зарегистрировано 6 items);
- контракт item'а по introspection: методы `Activate(ii)`, `ContextMenu(ii)`,
  `Scroll(is)`, `SecondaryActivate(ii)`; свойства `Category`, `IconName`,
  `IconPixmap a(iiay)`, `IconThemePath`, `Id`, `ItemIsMenu`, `Menu` (объектный путь
  `/MenuBar`), `Status`, `Title`, `ToolTip`, `WindowId`, `OverlayIcon*`,
  `AttentionIcon*`; сигналы `NewIcon`, `NewToolTip`, `NewStatus`, `NewTitle`,
  `NewOverlayIcon`, `NewAttentionIcon`; регистрация — `RegisterStatusNotifierItem`,
  контекстное меню — `com.canonical.dbusmenu`;
- `zbus` 5.19 уже присутствует в графе зависимостей транзитивно (через `playwire`),
  но **не** является прямой зависимостью, поэтому любая реализация трея — это новое
  решение и новая прямая зависимость, фиксируемая этим ADR.

## Решение

1. **Протокол — StatusNotifierItem (SNI/Freedesktop), а не XEmbed.** Целевое окружение
   (Noctalia, KDE-совместимые хосты) поддерживает SNI; XEmbed-трей на Wayland недоступен.

2. **Зависимость — `ksni` 0.3.7** (релиз 2026-10-20, `zbus ^5`, `default = ["tokio"]`,
   используется feature `blocking`). API, проверенное по исходникам crate:
   `blocking::TrayMethods::spawn()` / `disable_dbus_name()` / `assume_sni_available()`,
   `blocking::Handle::{update, shutdown, is_closed}`, трейты `Tray::{id, activate,
   secondary_activate, scroll, title, status, icon_name, icon_theme_path, icon_pixmap,
   tool_tip, menu, menu_about_to_show, watcher_offline, window_id}`,
   `menu::{StandardItem, CheckmarkItem, RadioGroup, SubMenu, Separator}` с
   `activate: Box<dyn Fn(&mut T) + Send>`, `Icon { width, height, data /* ARGB32,
   network byte order */ }`, `Status::{Passive, Active, NeedsAttention}`,
   `Error::WontShow`. `ksni` закрывает и item, и `com.canonical.dbusmenu` — своего
   dbusmenu-кода писать не нужно.

3. **Новый модуль `src/tray/`, вне UI и вне аудио.** Модуль не знает ни про egui, ни про
   `Station`: обмен идёт доменно-независимыми типами `TraySnapshot` (что показать) и
   `TrayCommand` (что сделать). App-оркестратор публикует снимок при изменениях
   воспроизведения/громкости/темы/видимости и исполняет команды через уже существующий
   dispatch (`process_media_commands`, `execute`), то есть трей — третий источник
   команд наравне с IPC и MPRIS, без нового протокола.

4. **Отдельный поток `orbitfm-tray`.** `blocking::spawn` и `Handle::update` внутри
   вызывают `block_on` на собственном current-thread runtime, поэтому их нельзя звать
   ни из наших async-потоков, ни из UI-потока с активным tokio-контекстом. Поток-владелец
   принимает снимки из канала и сам делает `update`, так что render-цикл никогда не
   блокируется dbus round-trip'ом.

5. **Меню и функции.** Подписи — английский (конвенция UI-строк):
   Show/Hide window · ─ · Play/Pause, Stop, Previous, Next, Radio Roulette · ─ ·
   Volume Up / Volume Down · ─ · Theme (RadioGroup: System / Dark / Light) · ─ · Quit.
   Левый клик по иконке (`Activate`) = toggle окна (тот же путь, что Noctalia-виджет),
   средний клик (`SecondaryActivate`) = показать и сфокусировать, колесо (`Scroll`) =
   громкость ±. Пункты Play/Pause и Theme отражают текущее состояние (`CheckmarkItem` /
   `RadioGroup`), Stop и Quit — разные действия: Quit завершает процесс, Stop только
   останавливает поток.

6. **Иконка.** `icon_pixmap` генерируется процедурно один раз при старте (орбитальный
   знак: круг + кольцо + точка — та же геометрия, что `widgets::logo_mark`) в размерах
   22/32/48, ARGB32 network byte order. Дополнительно заполняются `icon_name =
   "org.modernbyte.OrbitFM"` и `icon_theme_path` — если установленный каталог hicolor
   существует, хост возьмёт векторную иконку из упаковки (`packaging/linux/`), иначе —
   на наш pixmap. Новый бинарный ассет в репозиторий не добавляется.

7. **Feature-флаг и платформа.** `ksni` — optional-зависимость только для
   `cfg(target_os = "linux")`, `[features] default = ["tray"]`, `tray = ["dep:ksni"]`
   (AGENTS §4.3 — опциональная часть за фичем). На macOS/Windows — no-op-заглушка с тем
   же публичным API: код App не обрастает `cfg`-ветками, поведение не меняется.

8. **Деградация.** Если SNI-хоста нет (чистый Wayland-сессия без трея, CI, HEADLESS),
   `spawn()` возвращает `Error::Watcher(...)`/`Error::WontShow`; с
   `assume_sni_available(true)` они уходят в `Tray::watcher_offline`. Приложение пишет
   `warn!` и продолжает работать без трея — трей не может быть условием запуска. В
   sandbox (Flatpak) включается `disable_dbus_name(true)`; признак sandbox уточняется
   live-проверкой flatpak-сборки и не хардкодится.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| `tray-icon` 0.26.1 (+ `muda` 0.21) | default-фичи тянут `libappindicator + muda/gtk3 + dirs` — GLib-цикл событий и системные GTK-зависимости в AppImage/Flatpak; ksni-путь crate требует `muda-snapshot` и прослойку событий. Для SNI-окружения это лишний граф зависимостей ради кросс-платформенности, которой мы всё равно не проверяем |
| `system-tray` 0.8.9 | `zbus ^5` + `futures-lite`, но опциональные gtk/dbusmenu-gtk3-sys и отсутствие готового dbusmenu-объекта — больше кода на нашей стороне |
| Собственная обёртка над `zbus` (0 новых crate'ов) | Пришлось бы писать SNI-сервис и `com.canonical.dbusmenu` вручную (~600 строк dbus-кода) при наличии готовой поддерживаемой реализации |
| Только MPRIS + CLI, без трея | Не покрывает «показать окно» и выбор темы; пользователь явно запросил иконку с меню |
| Noctalia-виджет как единственный интерфейс | Работает только в Noctalia; трей — общий для любого SNI-хоста (KDE, Hyprland, Sway + waybar, GNOME с расширением) |
| XEmbed-трей (`libappindicator` по умолчанию) | Мёртвый путь на Wayland, противоречит «Linux First (Wayland)» |

## Последствия

**Положительные:**

- управление радио доступно при скрытом окне: toggle, play/pause, stop, prev/next,
  roulette, громкость, тема, выход;
- один источник истины для команд (существующий dispatch App-оркестратора), никаких
  изменений в IPC-протоколе ADR-0005;
- `zbus` 5 уже в графе (через playwire) — `ksni` не добавляет вторую мажорную версию
  dbus-стека;
- трей не блокирует UI и не влияет на 60 fps глобуса (отдельный поток + канал);
- чистая деградация при отсутствии хоста; optional-фича `tray` позволяет собрать
  минимальную версию.

**Отрицательные / Риски:**

- новая прямая зависимость `ksni` (Unlicense) и отдельный поток с собственным
  current-thread tokio-runtime — третье место, где живёт событийный цикл;
- `dbusmenu`-хосты по-разному реагируют на отсутствие `Category`/`ItemIsMenu` —
  поведение проверяется live в Noctalia, при необходимости значения дополняются;
- процедурная иконка проще векторной из упаковки: если установлен hicolor-пакет, хост
  может показать её, а не pixmap, — визуальное расхождение между Wayland-хостами;
- закрытое окно = скрытое окно (ADR-0018), поэтому «Quit» в трее оказывается единственным
  видимым способом завершить процесс без CLI, и он должен остаться явно неотличимым от Stop.
