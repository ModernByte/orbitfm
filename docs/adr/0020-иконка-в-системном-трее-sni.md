# ADR-0020: Иконка в системном трее (StatusNotifierItem на ksni)

**Статус:** Принято (2026-10-24)  
**Дата:** 2026-10-23  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Правило проекта — «закрытие окна = Hide, процесс живёт» (ADR-0018), и у пользователя
должен остаться способ управлять радио, когда окно скрыто: показать окно, пауза/стоп,
переключить станцию, изменить громкость, выйти. Сейчас для этого есть только
CLI/IPC (`orbitfm toggle|play|stop|volume|quit`, ADR-0005), Noctalia-виджет (ADR-0007)
и медиа-клавиши через MPRIS (ADR-0006). Слот «Системный трей» в ROADMAP (Этап 5) не
реализован.

Проверено в целевом окружении (Linux, Wayland, niri + Noctalia 5.3.0):

- `org.kde.StatusNotifierWatcher` принадлежит Noctalia, `IsStatusNotifierHostRegistered = true`
  — хост трея есть и работает (зарегистрировано 6 items);
- контракт item'а по introspection: методы `Activate(ii)`, `ContextMenu(ii)`,
  `Scroll(is)`, `SecondaryActivate(ii)`; свойства `Category`, `IconName`,
  `IconPixmap a(iiay)`, `IconThemePath`, `Id`, `ItemIsMenu`, `Menu` (объектный путь
  `/MenuBar`), `Status`, `Title`, `ToolTip`, `WindowId`, `OverlayIcon*`,
  `AttentionIcon*`; сигналы `NewIcon`, `NewToolTip`, `NewStatus`, `NewTitle`,
  `NewOverlayIcon`, `NewAttentionIcon`; регистрация — `RegisterStatusNotifierItem`,
  контекстное меню — `com.canonical.dbusmenu`;
- `zbus` 5.19 уже присутствует в графе зависимостей транзитивно (через `playwire` и
  `accesskit_unix`), но **не** является прямой зависимостью, поэтому любая реализация трея —
  это новое решение и новая прямая зависимость, фиксируемая этим ADR.

## Решение

1. **Протокол — StatusNotifierItem (SNI/Freedesktop), а не XEmbed.** Целевое окружение
   (Noctalia, KDE-совместимые хосты) поддерживает SNI; XEmbed-трей на Wayland недоступен.

2. **Зависимость — `ksni` 0.3.7** (релиз 2026-10-20, `zbus ^5`, `default = ["tokio"]`,
   используется feature `blocking`; edition 2021, `rust-version = 1.80`, лицензия Unlicense;
   фича `node` в нашем `Cargo.toml` не включается). Все технические утверждения этого пункта —
   по исходникам crate (`ksni-0.3.7/src/`, ссылки `файл:строка`):

   - **Вес зависимости.** `ksni` добавляет в граф ровно три новых crate'а — `arc-swap`,
     `crossbeam-queue`, `pastey` (`Cargo.lock:2087-2097`); остальные его зависимости
     (`zbus`, `serde`, `tokio`, `futures-util`) в графе уже есть. `zbus` при этом остаётся один —
     5.19.0 (`Cargo.lock:5240-5241`), тот же, что у `playwire` и `accesskit_unix`.
   - **Блокирующий API.** В `blocking` живут `TrayMethods`, `TrayServiceBuilder`, `Handle`,
     `ShutdownAwaiter`, плюс blanket-реализация `impl<T: Tray> TrayMethods for T`
     (blocking.rs:197); методы `TrayMethods::{spawn, disable_dbus_name,
     assume_sni_available}` (blocking.rs:18, :65, :83) и `Handle::{update, shutdown,
     is_closed}`. Никаких `blocking::Tray`, `blocking::Item`, `blocking::run()` и
     `spawn_with_path` в crate нет. `spawn_without_dbus_name` —
     `#[doc(hidden)] #[deprecated(since = "0.3.4")]` (blocking.rs:22-26), использовать
     запрещено: только `disable_dbus_name(true).spawn()`.
   - **Трейт `Tray`.** `pub trait Tray: Sized + Send + 'static` (lib.rs:71) — не object-safe
     (`dyn Tray` невозможен), `Default` не требуется. Единственный обязательный метод —
     `fn id(&self) -> String` (lib.rs:93); перечисляемые нами `activate`,
     `secondary_activate`, `scroll`, `title`, `status`, `icon_name`, `icon_theme_path`,
     `icon_pixmap`, `tool_tip`, `menu`, `menu_about_to_show`, `window_id`, `watcher_offline`
     имеют реализации по умолчанию. `watcher_offline(&self, reason: OfflineReason) -> bool`
     (lib.rs:251): аргумент — `#[non_exhaustive]`-перечисление `OfflineReason` (lib.rs:258),
     а возврат `false` закрывает соединение и выключает трей (service.rs:155-158, :164-167).
   - **Меню.** `Tray::menu(&self) -> Vec<MenuItem<Self>>` (lib.rs:221) — `Vec`, не `Option`
     и не boxed slice. `MenuItem<T>` — enum с вариантами `Standard(StandardItem<T>)`,
     `Separator`, `Checkmark(CheckmarkItem<T>)`, `SubMenu(SubMenu<T>)`,
     `RadioGroup(RadioGroup<T>)` (menu/mod.rs:81-87); отдельного типа `menu::Separator` не
     существует — разделитель это вариант `MenuItem::Separator` (menu/mod.rs:84).
     Колбэк у `StandardItem`/`CheckmarkItem`: `pub activate: Box<dyn Fn(&mut T) + Send>`
     (menu/mod.rs:148, :366), где `T` — сам тип трея, то есть `&mut Self`. У `RadioGroup`
     колбэка `activate` нет; реальная форма — `pub select: Box<dyn Fn(&mut T, usize) + Send>`,
     `pub selected: usize`, `pub options: Vec<RadioItem>` (menu/mod.rs:437-483), а активный
     пункт помечается `toggle_state = On` там, где `idx == selected` (menu/mod.rs:1034-1038).
     Все структуры меню реализуют `Default` (menu/mod.rs:169, :261, :388, :499, :550), поэтому
     принятый способ конструирования — struct-update `..Default::default()` и `.into()` до
     `MenuItem`.
   - **Типы.** `Icon { width: i32, height: i32, data: Vec<u8> }`, документированное
     представление — «ARGB32 format, network byte order» (tray.rs:150-156); каноническая
     конвертация rgba→argb — `pixel.rotate_right(1)` по чанкам из 4 байт (tray.rs:129-140,
     examples/custom_icon.rs:14-30). `ToolTip { icon_name, icon_pixmap: Vec<Icon>, title,
     description }` (tray.rs:106-117). `Status::{Passive, Active, NeedsAttention}`
     (tray.rs:60-73), `Category::{ApplicationStatus, Communications, SystemServices,
     Hardware}` (tray.rs:24-41), `Orientation::{Horizontal, Vertical}` (tray.rs:14-19).
   - **Ошибки.** `Error` — `#[non_exhaustive]` и ровно три варианта: `Dbus(zbus::Error)`,
     `Watcher(zbus::fdo::Error)`, `WontShow` (lib.rs:278-308). Варианта `Io` нет, значит
     любой `match` обязан иметь catch-all ветку.
   - `ksni` закрывает и item, и `com.canonical.dbusmenu` — своего dbusmenu-кода писать
     не нужно.

3. **Новый модуль `src/tray/`, вне UI и вне аудио.** Модуль не знает ни про egui, ни про
   `Station`: обмен идёт доменно-независимыми типами `TraySnapshot` (что показать) и
   `TrayCommand` (что сделать). Application Core (`Session`) публикует снимок при изменениях
   воспроизведения/громкости/темы/видимости и исполняет команды через уже существующий
   dispatch (`execute_media_command`, `execute`), то есть трей — третий источник
   команд наравне с IPC и MPRIS в том же `select!` припаркованного цикла `Session::park`
   (ADR-0018), без нового протокола.

4. **Отдельный поток `orbitfm-tray`.** `blocking::spawn` выполняет всю D-Bus-регистрацию
   синхронно на вызывающем потоке — `compat::block_on(service::run(..))`
   (blocking.rs:182-187) — и лишь затем создаёт собственный OS-поток, который крутит сервис
   дальше (blocking.rs:188-190). `compat::block_on` использует один **общий
   process-global** current-thread tokio-runtime в `LazyLock`-статике (compat.rs:24-35), а
   не отдельный runtime на поток. Отсюда три обязательных следствия:

   - в процессе может быть только один трей: блокирующий вход в рантайм —
     process-global (compat.rs:24-35);
   - поток-владелец обязан быть обычным `std::thread`: вызов `spawn`, `Handle::update` или
     `shutdown().wait()` из любого воркера нашего `rt-multi-thread` рантайма
     (`Cargo.toml:41-48`, `Builder::new_multi_thread` в `src/main.rs:71`) паникует
     «Cannot start a runtime from within a runtime» (текст паники — tokio 1.54.1,
     `runtime/context/runtime.rs:69`);
   - `Handle::update` = `compat::block_on(...)` (blocking.rs:207-208), то есть блокирующий
     вызов на потоке-вызывателе: он держит мьютекс трея (lib.rs:555-562) и ждёт, пока
     сервисный поток пересоберёт свойства/меню и разошлёт сигналы по D-Bus
     (service.rs:173-176). Поэтому из UI-потока его звать нельзя.

   Поток-владелец принимает снимки из канала и сам делает `update`, так что render-цикл
   никогда не блокируется dbus round-trip'ом.

5. **Меню и функции.** Подписи — английский (конвенция UI-строк):
   Show/Hide window · ─ · Play/Pause, Stop, Previous, Next, Radio Roulette · ─ ·
   Volume Up / Volume Down · ─ · Theme (RadioGroup: System / Dark / Light) · ─ · Quit.
   Разделители — вариант `MenuItem::Separator` (типа `menu::Separator` нет); Play/Pause —
   `CheckmarkItem` с `checked`, Theme — `RadioGroup` с `selected` (индекс активного пункта) и
   колбэком `select: Box<dyn Fn(&mut Self, usize) + Send>`, а не `activate`
   (menu/mod.rs:437-483); оба отражают текущее состояние. Левый клик по иконке (`Activate`) =
   toggle окна (тот же путь, что Noctalia-виджет), средний клик (`SecondaryActivate`) =
   показать и сфокусировать, колесо (`Scroll`) = громкость ±. Stop и Quit — разные действия:
   Quit завершает процесс, Stop только останавливает поток.

   **Ограничение по левому клику (реальное поведение ksni).** `ItemIsMenu` нельзя задать для
   конкретного экземпляра: свойство зеркалит associated-константу
   `Tray::MENU_ON_ACTIVATE` (lib.rs:78), которая фиксируется на этапе компиляции для типа
   (dbus_interface.rs:300-302). При `MENU_ON_ACTIVATE = true` метод `activate` не вызывается
   никогда (dbus_interface.rs:176-183), а D-Bus-метод `ContextMenu` всегда отвечает
   `UnknownMethod` (dbus_interface.rs:164-168). Значит схема «левый клик = `Activate`
   (toggle окна), меню по правому клику» достижима только при дефолтном
   `MENU_ON_ACTIVATE = false`, когда меню по правому клику показывает сам хост — кода на
   нашей стороне для этого нет.

   Справка (решением не является): в 0.3.7 есть `ksni::current_xdg_activation_token() ->
   Option<String>` (lib.rs:65-68) — Wayland XDG activation token, который хост обычно
   передаёт вокруг `activate`/`secondary_activate`/клика по пункту меню (lib.rs:55-57);
   наш текущий оконный путь (eframe 0.37 + winit 0.30.13, `Cargo.lock:5064-5065`) его не
   потребляет, решение о применении здесь не принимается.

6. **Иконка.** `icon_pixmap` генерируется процедурно один раз при старте (орбитальный
   знак: круг + кольцо + точка — та же геометрия, что `widgets::logo_mark`) в размерах
   22/32/48, ARGB32 network byte order (конвертация RGBA→ARGB — `pixel.rotate_right(1)` по
   чанкам из 4 байт, tray.rs:129-140). **Кэширование обязательно:** `icon_pixmap()`
   вызывается заново на каждом событии — `activate`, `secondary_activate` и `scroll` ведут
   полный пересчёт свойств (service.rs:577-595 → :291 → :615-619) и пересборку меню
   (service.rs:330) с рассылкой сигналов, а возвращаемый `Vec<Icon>` каждый вызов
   собирается заново. Поэтому пиксельный буфер строится однократно и хранится статически —
   `static ICONS: LazyLock<Vec<Icon>>` (тот же приём, что в doc-примере crate, tray.rs:129-140
   и examples/custom_icon.rs:14-30). Дополнительно заполняются `icon_name =
   "org.modernbyte.OrbitFM"` и `icon_theme_path` — если установленный каталог hicolor
   существует, хост возьмёт векторную иконку из упаковки (`packaging/linux/`), иначе —
   на наш pixmap. Новый бинарный ассет в репозиторий не добавляется.

7. **Feature-флаг и платформа.** `ksni` — optional-зависимость только для
   `cfg(target_os = "linux")`, `[features] default = ["tray"]`, `tray = ["dep:ksni"]`
   (AGENTS §4.3 — опциональная часть за фичем). На macOS/Windows — no-op-заглушка с тем
   же публичным API: код App не обрастает `cfg`-ветками, поведение не меняется.

8. **Деградация.** Если SNI-хоста нет (чистый Wayland-сессия без трея, CI, HEADLESS),
   `spawn()` возвращает `Err` — `Error::Watcher(...)` или `Error::WontShow`; `match` по
   `Error` обязан иметь catch-all ветку (`#[non_exhaustive]`, три варианта, lib.rs:278-308).
   Флаг `assume_sni_available(true)` работает не как «все ошибки уходят в
   `Tray::watcher_offline`», а именно так: проверка наличия хоста при нём пропускается
   (service.rs:118-125), то есть `WontShow` в `watcher_offline` не попадает; мягко через
   `watcher_offline` обрабатывается только `ServiceUnknown` при регистрации
   (service.rs:88-99), остальные ошибки регистрации `spawn()` по-прежнему возвращает как
   `Err` (tests/blocking.rs:178-196). Возврат `false` из `watcher_offline` закрывает
   соединение и выключает трей (service.rs:155-158, :164-167); если это произошло на старте
   при `assume_sni_available(true)`, `spawn()` вернёт `Ok` с уже мёртвым `Handle`
   (service.rs:96-99) — поэтому после старта состояние проверяется через `Handle::is_closed`.
   Приложение пишет `warn!` и продолжает работать без трея — трей не может быть условием
   запуска. В sandbox (Flatpak) включается `disable_dbus_name(true)` (deprecated
   `spawn_without_dbus_name` не используется); признак sandbox уточняется live-проверкой
   flatpak-сборки и не хардкодится.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| `tray-icon` 0.26.1 (+ `muda` 0.21) | default-фичи тянут `libappindicator + muda/gtk3 + dirs` — GLib-цикл событий и системные GTK-зависимости в AppImage/Flatpak. Для SNI-окружения это лишний граф зависимостей (путь `ksni` — три новых crate'а, см. п.2) ради кросс-платформенности, которой мы всё равно не проверяем |
| `system-tray` 0.8.9 | `zbus ^5` + `futures-lite`, но опциональные gtk/dbusmenu-gtk3-sys и отсутствие готового dbusmenu-объекта — больше кода на нашей стороне |
| Собственная обёртка над `zbus` (0 новых crate'ов) | Пришлось бы писать SNI-сервис и `com.canonical.dbusmenu` вручную (~600 строк dbus-кода) при наличии готовой поддерживаемой реализации |
| Только MPRIS + CLI, без трея | Не покрывает «показать окно» и выбор темы; пользователь явно запросил иконку с меню |
| Noctalia-виджет как единственный интерфейс | Работает только в Noctalia; трей — общий для любого SNI-хоста (KDE, Hyprland, Sway + waybar, GNOME с расширением) |
| XEmbed-трей (`libappindicator` по умолчанию) | Мёртвый путь на Wayland, противоречит «Linux First (Wayland)» |

## Последствия

**Положительные:**

- управление радио доступно при скрытом окне: toggle, play/pause, stop, prev/next,
  roulette, громкость, тема, выход;
- один источник истины для команд (существующий dispatch App-оркестратора), никаких
  изменений в IPC-протоколе ADR-0005;
- `zbus` 5.19.0 уже в графе и остаётся единственным (общая версия для `playwire` и
  `accesskit_unix`, `Cargo.lock:5240-5241`) — `ksni` не добавляет вторую мажорную версию
  dbus-стека, а три новых crate'а (`arc-swap`, `crossbeam-queue`, `pastey`) — вся цена
  зависимости;
- трей не блокирует UI и не влияет на 60 fps глобуса (отдельный поток + канал);
- чистая деградация при отсутствии хоста; optional-фича `tray` позволяет собрать
  минимальную версию.

**Отрицательные / Риски:**

- новая прямая зависимость `ksni` (Unlicense) и отдельный поток-владелец, который работает
  с общим process-global current-thread tokio-runtime (compat.rs:24-35) — третье место, где
  живёт событийный цикл;
- `dbusmenu`-хосты по-разному реагируют на отсутствие `Category`/`ItemIsMenu` —
  поведение проверяется live в Noctalia, при необходимости значения дополняются (учитывая,
  что `ItemIsMenu` задаётся только константой `MENU_ON_ACTIVATE` на тип, per-instance
  варианта нет);
- процедурная иконка проще векторной из упаковки: если установлен hicolor-пакет, хост
  может показать её, а не pixmap, — визуальное расхождение между Wayland-хостами;
- закрытое окно = скрытое окно (ADR-0018), поэтому «Quit» в трее оказывается единственным
  видимым способом завершить процесс без CLI, и он должен остаться явно неотличимым от Stop.

## Проверка реализации

Live-проверка на целевом окружении (Wayland, niri 26.04 + Noctalia 5.3.0 как
SNI-хост, 2026-10-24, debug-сборка этой ветки; запросы — `busctl --user`,
состояние приложения — `orbitfm status`, раскладка — `niri msg windows`):

- регистрация: `GetRegisteredItems` у `org.kde.StatusNotifierWatcher` до запуска —
  4 item'а, после — 5 (`org.kde.StatusNotifierItem-<pid>-1`), в логе
  `системный трей запущен`;
- свойства читаются хостом: `Category = ApplicationStatus`, `Id` и `IconName =
  org.modernbyte.OrbitFM`, `Title = OrbitFM`, `ItemIsMenu = false` (значит
  `Activate` вызывается), `Menu = /MenuBar`, `IconPixmap` — ровно 3 размера
  (22/32/48), `IconThemePath = ~/.local/share/icons/hicolor`, `ToolTip =
  ("org.modernbyte.OrbitFM", <пустой pixmap>, "OrbitFM", "Nothing playing")`;
- `com.canonical.dbusmenu.GetLayout` возвращает меню из п. 5 в том же порядке,
  состояние отражает снимок: у «Play/Pause» `toggle-state = 1` во время эфира и
  `0` на паузе, в `RadioGroup` темы `toggle-state = 1` стоит на активном пункте;
- левый клик (`Activate`) при открытом окне скрывает его: `niri msg windows` не
  возвращает ни одного окна OrbitFM, `status` отвечает `window hidden`, а
  `Status` item'а становится `Passive`;
- колесо (`Scroll vertical ±1`) в скрытом состоянии меняет громкость
  `0.70 → 0.80 → 0.70` — команда исполняется припаркованным `select!`, без окна;
- `orbitfm play <uuid>` в скрытом состоянии поднимает `Status` в `Active`, а
  `ToolTip.description` становится именем станции — снимок публикуется после
  каждого события парковки;
- пункты меню в скрытом состоянии исполняются: Play/Pause → `status paused`,
  Stop → `status stopped`, Volume Up → +0.10, Dark → `theme = dark` в
  `settings.json`, «Show window» → окно появляется через **≈986 мс**
  (сходится с ≈1.02 с из ADR-0018: перезапуск `eframe::run_native`);
- `SecondaryActivate` не ломает состояние (окно уже видно → `window visible`);
- Quit в меню завершает процесс, `GetRegisteredItems` снова 4 item'ов, в логе ни
  паник, ни предупреждений;
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings` — чисто, в том числе
  в `--no-default-features` (сборка без фичи `tray`); `cargo test` — 199 тестов,
  0 падений, 3 пропущено.

Уточнение к п. 3 по факту реализации: в `TraySnapshot` нет громкости — у SNI нет
витрины для неё (`Volume Up/Down` — действие, а не состояние), поэтому
изменение громкости само по себе ничего не публикует. Снимок меняется при
смене эфира, станции, темы и видимости окна; остальное — поведение меню и
колеса, а не витрины. Проверки flatpak/sandbox-пути (`disable_dbus_name`) в этом
списке нет: она требует отдельной сборки и остаётся открытой (п. 8).

Обновление (2026-10-24): первая строка меню — неактивная витрина
`Now playing: <станция>` / `Paused: <станция>` / `Nothing playing` (расширение
п. 5). Это отображение состояния, а не команда; остальные пункты и их порядок
не менялись.
