# ADR-0013: Избранное и история станций

**Статус:** Принято  
**Дата:** 2026-10-22  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

В ROADMAP после маркеров стоит пункт «Избранное и история». Сейчас станцию можно
запустить только из результатов последнего поиска, IPC `play <uuid>` или MPRIS;
любимые станции не сохраняются между запусками, а `Next`/`Previous` из MPRIS не
действуют из-за отсутствия истории. Приложение не имеет дискового хранилища:
радио-кэш и список результатов живут только в памяти.

Требуется локальное хранилище, которое:

- переживает перезапуск процесса;
- позволяет запускать сохранённую станцию без сети (значит, нужен не только UUID,
  но и `url_resolved` с метаданными);
- не блокирует GUI ощутимо и не ломает запуск при повреждённом файле;
- не добавляет IPC-команды и фоновые опросы без необходимости.

## Решение

1. **Новый модуль `library` (`src/library/`).** Он владеет снимками станций и
   персистентностью, зависит от `services::Station` как канонического доменного типа,
   но не знает о GUI, аудио и IPC. Application Core вызывает методы модуля.
2. **Расположение и формат.** Файл `$XDG_DATA_HOME/orbitfm/library.json`; если
   `XDG_DATA_HOME` не задан или относителен — `$HOME/.local/share/orbitfm/library.json`.
   Формат — JSON:
   `{ "favorites": [Station...], "history": [Station...] }`. `serde_json`
   переводится из dev-зависимостей в обычные.
3. **Атомарная запись.** JSON пишется в `library.json.tmp` в том же каталоге, затем
   `rename` поверх целевого файла. При ошибке rename старый файл остаётся нетронутым.
   Запись выполняется синхронно только по действию пользователя (переключение
   избранного, старт станции, очистка истории): файл мал, операции редки.
4. **Правила данных.** Избранное и история хранят снимок `Station` целиком, поэтому
   запуск не требует сети. Дубликаты определяются по `stationuuid`: повторное
   добавление в избранное переключает состояние, повторный старт перемещает станцию
   в начало истории. История ограничена 20 последними станциями; избранное — без
   жёсткого лимита. Порядок избранного — порядок добавления.
5. **Отказоустойчивость.** Отсутствие файла — пустая библиотека, не ошибка.
   Повреждённый JSON — ошибка загрузки: Application Core логирует предупреждение и
   использует пустую **эфемерную** библиотеку без пути; её сохранения — no-op, поэтому
   повреждённый файл не перезаписывается и доступен для ручного восстановления.
   Ошибки записи не прерывают воспроизведение и показываются в карточке.
6. **GUI.** В карточке появляются вкладки «Результаты», «Избранное (N)», «История (N)»
   и звёзды у текущей станции и строк списка. История пополняется при успешном
   `start_station` (клик, IPC `play`, маркер); MPRIS `Play` после `Stop` не считается
   новым запуском. Очистка истории — кнопкой в списке.
7. **Без новых IPC-команд.** Управление избранным и историей доступно только из GUI.
   `Next`/`Previous` MPRIS по-прежнему не переключают станции: история не является
   очередью воспроизведения, и семантика перехода требует отдельного решения.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| SQLite (`rusqlite`) | Тяжёлая зависимость и схема ради двух небольших списков |
| Хранить только UUID | Офлайн-запуск невозможен, нужен сетевой запрос при каждом открытии |
| TOML/бинарный формат | JSON проще для вложенных `Station` и ручной диагностики |
| Crate `dirs` для путей | Достаточно маленького XDG-резолвера на `std::env`, лишняя зависимость не нужна |
| Фоновая запись через канал | Усложняет порядок операций и обработку ошибок; файл мал |
| Использовать историю как очередь Next/Previous | Неоднозначная семантика (история — не плейлист) |

## Последствия

**Положительные:**

- Избранное и история переживают перезапуск и работают офлайн
- Границы модулей сохранены: `library` не зависит от GUI и аудио
- Повреждённый файл не уничтожается автоматически
- Нет новых IPC-команд и сетевых запросов

**Отрицательные / Риски:**

- Синхронная запись в GUI-потоке; при росте объёма данных потребуется вынести в фон
- Нет временных меток и сортировки избранного по алфавиту
- Нет синхронизации между экземплярами (гарантируется single-instance)
- `Next`/`Previous` остаются неактивными до отдельного решения о плейлисте
