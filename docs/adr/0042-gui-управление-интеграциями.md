# ADR-0042: GUI-управление интеграциями и AST-правка конфигов

**Статус:** Принято  
**Дата:** 2026-11-01  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич

## Контекст

ADR-0037 дал установщик `orbitfm integration install <target>`, но пользователь
всё равно работает в терминале. Для Waybar установщик кладёт скрипт и печатает
сниппет, который нужно вставить в `config.jsonc` руками; native-манифест
Chrome/Firefox ставится командой, а не кнопкой. Браузерные расширения при этом
требуют копирования JSON в `~/.config/…/NativeMessagingHosts/`.

Задача — перенести эти действия в окно настроек (ADR-0031), не ослабляя
ограничения:

- **regex-правка чужих конфигов запрещена**: она необратимо ломает комментарии,
  порядок ключей и форматирование;
- перед записью обязательна резервная копия;
- перезагрузка оболочки не должна использовать `killall`/`pkill`;
- установка идёт по одной цели с квитанцией (ADR-0037);
- новые сетевые пути, ослабление SSRF или allowlist native-host недопустимы.

## Решение

### 1. Категория «Интеграции» в настройках

`SettingsCategory::Integrations` добавляется после `Window`. Страница получает
список целей, сгруппированный по типу:

- **Бары и панели:** Waybar, Polybar, i3blocks, swaybar, i3status-rust, XFCE,
  Cinnamon, MATE, LXQt;
- **Окружения:** Plasma 6, GNOME, Omarchy/Quickshell;
- **Браузеры:** Chrome/Chromium-семейство, Firefox.

Для каждой цели показывается состояние (`не установлено`, `установлено`,
`доступно обновление`, `ошибка`), кнопка установки/удаления и кнопка
«Включить в конфиге» там, где применимо. Обнаружение — по наличию конфига
или исполняемого файла в `PATH` (та же логика, что в `Layout`, но без записи).

UI возвращает только `UiAction`; файловые операции выполняет presentation-слой,
как и остальные настройки (ADR-0031). Долгие операции не блокируют кадр:
установка идёт в `Session::runtime`, результат приходит кадром состояния.

### 2. Waybar: JSONC CST, а не регулярки

Waybar хранит конфиг в `config.jsonc` (допускается `config` и `config.json`).
Правка выполняется через `jsonc-parser` 0.34 с фичей `cst`:

1. файл читается как CST; комментарии и пробелы остаются узлами дерева;
2. в массиве `modules-right` добавляется строка `"custom/orbitfm"`, если её
   ещё нет;
3. в корневом объекте создаётся `custom/orbitfm` с `exec` на установленный
   `orbitfm-bar`, `interval: 2` (как в поставляемом сниппете), `exec-if` и
   `return-type: "json"`;
4. дерево сериализуется и **повторно парсится**; при ошибке запись
   отменяется, а старый файл остаётся нетронутым;
5. запись — `storage::write_atomic` в каталог конфига.

Перед первой правкой создаётся `config.jsonc.orbitfm.bak`. Если бэкап уже
существует, он не перезаписывается: первая копия остаётся оригиналом.

Сторона вставки и имя модуля фиксированы; произвольные ключи не редактируются.
Никакой regex по тексту конфига не применяется.

### 3. Перезагрузка без убийства процесса

- **Waybar:** сначала `waybar-msg cmd reload`; при ненулевом коде — сигнал
  `SIGUSR2` процессу Waybar через `libc::kill` (PID ищется по `/proc/*/comm`,
  без `killall`/`pkill`). Если оба способа недоступны, UI показывает просьбу
  перезапустить бар вручную.
- **Polybar:** документированный `polybar-msg cmd restart`.
- **Plasma/GNOME/Omarchy:** перезапуск не нужен — плагин/расширение
  подхватывается окружением; при необходимости показывается штатная команда.
- **Композиторы:** `hyprctl reload` только по явной кнопке; niri не имеет
  runtime-команды — показывается сниппет.

Ни один путь не вызывает `killall`, `pkill` и не завершает процесс принудительно.

### 4. Native host из GUI

Кнопки «Chrome/Chromium» и «Firefox» вызывают тот же `install_one`, что и CLI
(ADR-0038): генерируется `org.modernbyte.orbitfm.json`, путь к `orbitfm
native-host` абсолютный, манифест кладётся в обнаруженные каталоги браузеров.
Пользователь не копирует JSON. Кнопка показывает, какие браузеры найдены и что
после установки нужен перезапуск браузера. Квитанция и allowlist не меняются.

### 5. Безопасность и границы

- Все пути строятся из `$XDG_CONFIG_HOME`/`$HOME`; `ORBITFM_INTEGRATION_ROOT`
  остаётся тестовым переопределением.
- Запись возможна только в известный конфиг Waybar; путь не принимается из
  сети или IPC.
- Установщик не добавляет новых сетевых запросов и не скачивает расширения:
  ассеты встроены, ID фиксированы.
- Удаление по-прежнему идёт по квитанции, а не по «похожим» файлам.
- Ошибка установки показывается тостом с технической подробностью; частично
  записанный конфиг исключён атомарной записью и проверкой повторного парсинга.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Регулярные выражения по JSONC | Ломают комментарии/форматирование; запрещены задачей |
| `serde_json` с потерей комментариев | Тот же результат: конфиг пользователя необратимо меняется |
| Редактировать `hyprland.conf`/`config.kdl` из GUI | Нарушает ADR-0037; риск конфликтов и потери комментариев |
| `killall -SIGUSR2 waybar` | Запрещено в пользовательском пути |
| Скачивать расширения с сервера | Новый сетевой путь и цепочка доверия; ассеты уже встроены |

## Последствия

**Положительные:**

- включение Waybar-виджета — одна кнопка, комментарии и форматирование целы;
- native host ставится без ручного JSON;
- все операции обратимы бэкапом и квитанцией;
- GUI и CLI используют один установщик, поведение не расходится.

**Отрицательные / Риски:**

- новый crate `jsonc-parser` (MIT) требует обновления `Cargo.lock` и
  `flatpak-cargo-sources.json`;
- автоматическая перезагрузка Waybar зависит от версии `waybar-msg` и IPC;
- правка поддерживается только для Waybar; остальные цели ставят ассеты и
  показывают сниппет, пока для их формата нет CST-редактора;
- `/proc`-скан PID специфичен для Linux; на macOS/Windows кнопка показывает
  ручную подсказку.
