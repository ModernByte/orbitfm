# ADR-0055: Действие по истечении таймера сна

**Статус:** Принято  
**Дата:** 2026-11-06  
**Участники решения:** ModernByte Architecture, владелец продукта

## Контекст

Сейчас истечение таймера сна всегда означает одно: `stop_playback` и тост
`SleepExpired` (ADR-0046). Владелец запросил выбор действия: **Ничего / Сон /
Выключить**. «Ничего» — остановить эфир и остаться в системе; «Сон» —
перевести машину в suspend; «Выключить» — завершить работу.

Требования, вытекающие из задачи:

- действие выбирается в настройках и переживает перезапуск;
- значение по умолчанию — `Nothing` (сегодняшнее поведение);
- действие выполняется только после того, как все поверхности сняли отсчёт;
- ошибка действия не должна ронять процесс и не должна ретраиться;
- проверка на живой машине не должна случайно усыпить рабочую сессию.

## Решение

### 1. Конфигурация

`settings::SleepAction { Nothing, Suspend, PowerOff }` с `as_str`/`parse`
в kebab-case по образцу `NetworkProfile`:

| Значение | IPC/`settings.json` | Смысл |
|----------|---------------------|-------|
| `Nothing` | `nothing` | только остановить эфир |
| `Suspend` | `suspend` | остановить эфир, затем suspend |
| `PowerOff` | `power-off` | остановить эфир, затем выключение |

Ключ `sleep_action`, по умолчанию `nothing`. Неизвестное значение ⇒
`SettingsError::Parse` и фолбэк на `ephemeral()` (существующее поведение
`main.rs`) — не «тихо угадать».

### 2. Порядок при истечении

`Session::sleep_expiry` (тело уходит из `sleep.rs`):

1. `clear_sleep()` — таймер выключен, поверхности больше не считают;
2. **release inhibitor** — иначе собственный `Suspend` упрётся в наш
   `sleep/block` лок (ADR-0054);
3. снять фейд и `stop_playback()` (ADR-0056);
4. `sync_tray()` + `publish_status()` — все витрины снимают отсчёт до того,
   как окно может исчезнуть;
5. закрыть окно предупреждения, если оно открыто (ADR-0058);
6. выполнить действие.

### 3. Точные argv по ОС

**Linux.**

```
busctl --user call org.freedesktop.login1 /org/freedesktop/login1 \
  org.freedesktop.login1.Manager Suspend b true

busctl --user call org.freedesktop.login1 /org/freedesktop/login1 \
  org.freedesktop.login1.Manager PowerOff b true
```

Здесь `busctl` применим: возврата нет, fd не передаётся. `interactive=true`
— чтобы polkit мог спросить. На машине владельца `allow_active=yes` для
обоих методов. Фолбэк при отказе `busctl`:
`loginctl suspend` / `loginctl poweroff`.

**macOS.** `pmset sleepnow` / `osascript -e 'tell app "System Events" to shut
down'` — UNVERIFIED, закрывается live-протоколом; ошибка не фатальна.

**Windows.** `SetSuspendState(false, false, false)` и
`InitiateSystemShutdownExW` (+ feature `Win32_Security`); привилегия
`SeShutdownPrivilege` может отсутствовать — тогда `SleepActionFailed`.

Общее: argv фиксированы, shell не запускается; stderr читается для detail.

### 4. Политика отказа

- Ошибка действия не фатальна: `NoticeKey::SleepActionFailed` с detail из
  stderr, без ретраев. Эфир к этому моменту уже остановлен.
- `ORBITFM_POWER_DRY_RUN=1` — вместо spawn пишется `info!` с argv. Это
  read-only-диагностика: ни привилегий, ни реального сна.
- Если действие — `Nothing`, шаги 2 и 6 не отличаются от сегодняшнего
  поведения: лок снимается, эфир останавливается, тост `SleepExpired`.

### 5. Локализация

Новые строки: подпись настройки, три значения действия, `SleepActionFailed`.
Добавляются сразу во все 16 каталогов — гейт `assert_catalog_complete` не
позволяет частичную волну.

## Последствия

**Положительные:**

- ночной сценарий закрывается одним выбором: «дослушал — уснул — машина
  уснула»;
- отказ привилегий виден пользователю, а не проглатывается;
- dry-run делает ветку извлекаемой для проверки без риска.

**Отрицательные / риски:**

- `Suspend`/`PowerOff` требуют polkit-политики; на части систем
  `allow_active=no` — тогда останется тост об ошибке;
- macOS/Windows argv не проверены на живой ОС — статус «принято» не означает
  «проверено», это фиксируется в live-протоколе.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| `Hibernate`, `Restart`, `Logout` | разные привилегии на трёх ОС; «и т.д.» из запроса не обязывает |
| Ретраи действия | после неудачного suspend повтор может разбудить/усыпить неожиданно |
| `mode=delay` для собственного suspend | `InhibitDelayMaxSec=5`, гарантии нет |
| Выполнять действие до остановки эфира | окно предупреждения и трей успели бы показать устаревший отсчёт |
| Отдельная IPC-команда `poweroff` | расширение `sleep` покрывает сценарий; top-level команды не плодим |
