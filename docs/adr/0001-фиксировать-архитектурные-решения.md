# ADR-0001: Фиксировать архитектурные решения

**Статус:** Принято  
**Дата:** 2026-10-21  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Нужен лёгкий и долговечный способ фиксировать значимые архитектурные решения по OrbitFM, чтобы будущие участники (и мы сами через полгода) понимали *почему* был сделан тот или иной выбор.

## Решение

Используем Architecture Decision Records (ADR) в формате, предложенном Michael Nygard:

- Одно решение — один файл
- Последовательная нумерация (`0001-…`, `0002-…`)
- Хранение в `docs/adr/`
- Жизненный цикл статуса: Предложено → Принято → Устарело / Заменено

Каждый ADR содержит:
- Статус
- Дата
- Контекст
- Решение
- Последствия
- (опционально) Рассмотренные альтернативы

## Последствия

Положительные:
- Решения становятся полноценными артефактами, которые можно искать
- Ускоряется онбординг
- Меньше «устного знания»

Отрицательные:
- Небольшой дополнительный объём текста
- Требуется дисциплина в поддержке актуальности
