# ADR-0038: Браузерное расширение и native messaging host

**Статус:** Принято (2026-10-31)  
**Дата:** 2026-10-31  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич

## Контекст

ADR-0037 дал интеграциям единую поверхность: `status --json` схемы 1,
локализованные подписи `ui`, команды управления и установщик. Браузерная панель
не может пользоваться CLI напрямую: страница расширения не запускает процессы и
не имеет доступа к локальному сокету. Единственный поддерживаемый браузерами
канал к настольному приложению — **native messaging**: браузер запускает
объявленный хост, общается с ним по stdio и сам проверяет, какому расширению
разрешено это соединение.

Нужно решить семь задач:

1. транспорт и фрейминг сообщений между расширением и OrbitFM;
2. стабильную идентичность расширения, потому что native-манифест перечисляет
   точные ID и не допускает wildcard;
3. набор команд, которые панель вправе выполнять;
4. доставку состояния без опроса — через уже существующий `events` (ADR-0039);
5. установку в каталоги пользователя без правки чужих конфигов (ADR-0037);
6. модель угроз: что может страница, чужое расширение и локальный процесс;
7. честные границы поставки: распакованное расширение, подпись Firefox,
   Windows-реестр и непроверенные браузеры.

Ограничения те же, что у остальных интеграций: один GUI-процесс и один
экземпляр, три релизных артефакта, отсутствие новых сетевых портов и
User-Agent/сетевые правила Radio Browser не меняются.

## Решение

### 1. Транспорт — native messaging поверх stdio

Браузер запускает `orbitfm native-host` как дочерний процесс. Кадр — 4 байта
длины в native-endian, затем UTF-8 JSON. Нулевая длина и EOF означают конец
потока. Симметричный предел проекта — **1 МиБ на сообщение в обе стороны**;
входящий кадр длиннее лимита отклоняется без чтения payload, а ответ, который
после сериализации не помещается в лимит, заменяется короткой ошибкой. Это
строже лимитов Chrome и Firefox и не даёт браузеру или приложению раздувать
память.

Хост создаёт отдельный current-thread runtime, не поднимает GUI, не слушает
порт и не становится демоном: он живёт, пока жив порт расширения. Команды
уходят в тот же IPC-сокет, что у CLI (`send_to_existing`), поэтому второй
экземпляр приложения не появляется. Если OrbitFM не запущен, хост возвращает
`not-running`; **ни одна команда через браузер не выполняет холодный старт**,
даже `toggle` или `settings`, которые CLI вправе запускать.

### 2. Идентичность — фиксированные ID без wildcard

Native-манифест разрешает ровно одно расширение:

- Chromium: `allowed_origins: ["chrome-extension://lfhmfgjblkebbalfdlbmnalghhjplfbg/"]`;
- Firefox: `allowed_extensions: ["orbitfm@modernbyte"]`.

Браузер передаёт хосту аргумент с origin/ID вызывающего. Манифест всегда
указывает на wrapper, а wrapper не пробрасывает `$@`: `orbitfm native-host`
принимает только ноль аргументов. Хост не использует подсказку браузера для
авторизации — её всё равно нельзя проверить без native-манифеста, — а лишний
аргумент при прямом запуске отклоняется.

Chrome-ID выводится из публичного ключа, вшитого в `manifest.json`; приватный
ключ в репозитории не хранится. Firefox-ID задан в
`browser_specific_settings.gecko.id`. ID не меняются между установками и
обновлениями, иначе установленный native-манифест перестал бы совпадать с
расширением.

Хост сам не умеет проверить, кто его вызвал: это делает браузер по
native-манифесту. Поэтому манифест — часть контура безопасности, а не
установочная мелочь.

### 3. Команды — allowlist, а не весь IPC

Запрос имеет вид `{"id"?: <JSON>, "command": "<строка>"}`; неизвестные поля
запрещены. Команда разбирается тем же `IpcCommand::parse`, что и в CLI, затем
проверяется allowlist:

| Разрешено | Запрещено |
|-----------|-----------|
| `toggle`, `show`, `hide`, `panel`, `overlay` | `quit` |
| `status`, `status --json` | `play <uuid>` |
| `playpause`, `stop`, `next`, `previous`, `roulette` | `mode`, `mode <режим>` |
| `volume <0…1>`, `volume-up`, `volume-down` | неизвестная команда (`Raw`) |
| `theme system\|dark\|light`, `settings` | |

Причины запрета:

- `quit` — панель браузера не должна завершать процесс; выход остаётся за
  пользователем и CLI;
- `play` — расширение не получает произвольный запуск станции по UUID, то есть
  не может превратиться в канал навязывания потока;
- `mode` — компоновка окна принадлежит Core и hotkey/CLI, а не браузеру.

`overlay` и `panel` разрешены как идемпотентные команды показа/скрытия
существующих режимов (ADR-0021, ADR-0033); `settings` показывает окно
настроек, но только у уже работающего экземпляра.

Ответ — конверт `{"ok":true,"response":"…"}` или
`{"ok":false,"code":"…","error":"…"}`; `id` возвращается без изменений, если
был передан. Коды ошибок фиксированы в интерфейсе 14: `invalid-request`,
`invalid-command`, `forbidden`, `oversized`, `events-active`, `not-running`,
`timeout`, `subscription-rejected`, `ipc-error`, `invalid-frame`,
`stream-closed`.

### 4. Состояние — `events` через тот же порт

Popup не опрашивает `status --json`. Он один раз отправляет
`{"command":"events"}`, получает подтверждение `{"ok":true,"response":"events"}`
и далее принимает кадры `{"ok":true,"event":{…}}`, где `event` — ровно кадр
ADR-0039 (`snapshot`, `state`, `keepalive`). Поток завершается кадром
`{"ok":true,"event":null}`; ошибка чтения приходит как
`{"ok":false,"code":"stream-closed","stream":"closed"}`, битый кадр — как
`invalid-frame` с `"stream":"invalid"`.

На один процесс хоста допускается одна подписка `events`; повторная просьба
получает `events-active`. Команды управления можно слать в тот же порт, пока
поток открыт. Очередь вывода ограничена 64 сообщениями: медленный popup
притормаживает пересылку, а не копит память, а `watch`-канал ADR-0039
схлопывает промежуточные состояния.

### 5. Расширение — popup-only, без content scripts

Один общий WebExtension-код, две тонкие обёртки-манифеста:

- Manifest V3, `action.default_popup`, разрешение только `nativeMessaging`;
- нет content scripts, background/service worker, `host_permissions`,
  `externally_connectable` и `web_accessible_resources`;
- страница расширения не имеет доступа к веб-страницам, а веб-страницы не
  имеют доступа к порту native messaging;
- подписи кнопок берутся из `status.ui`, поэтому панель говорит на языке
  OrbitFM; при недоступном приложении остаются английские строки;
- громкость отправляется как `volume 0.74`, тема — как `theme dark`;
  видимость окна переключается `show`/`hide`, остальные кнопки — своими
  командами.

Popup закрывается вместе с фокусом; вместе с ним закрывается порт, хост
завершается, подписка `events` освобождает слот. Фонового опроса и скрытой
работы расширения нет.

### 6. Установщик — те же цели `integration`

`orbitfm integration install chrome` и `install firefox` (а также `all`)
раскладывают шесть файлов в
`$XDG_DATA_HOME/orbitfm/integrations/<цель>/`:

```text
extension/manifest.json
extension/popup.html
extension/popup.css
extension/popup.js
orbitfm-native-host      # 0755, exec "$ORBITFM" native-host
README.md
```

и пишут native-манифест `org.modernbyte.orbitfm.json` в каталоги только
обнаруженных браузеров:

| Цель | Каталоги native-манифеста |
|------|---------------------------|
| `chrome` | `$XDG_CONFIG_HOME/google-chrome/NativeMessagingHosts`, `chromium/…`, `BraveSoftware/Brave-Browser/…`, `microsoft-edge/…`, `vivaldi/…` |
| `firefox` | `~/.mozilla/native-messaging-hosts` |

Обнаружение — наличие каталога профиля или бинарника в `PATH`; если браузера
нет, файлы расширения всё равно устанавливаются, а манифест пропускается с
подсказкой повторить установку. Квитанция ADR-0037 расширена списком путей:
`uninstall` удаляет и native-манифесты, и файлы расширения, не трогая чужие
файлы. `ORBITFM_INTEGRATION_ROOT` ставит манифесты в тестовый корень и делает
прогон детерминированным.

Установщик не работает на не-Linux платформах: это та же граница, что у
остальных целей. Windows-манифесты через реестр в пакет не входят и не
обещаются. AppImage учитывается: если установка шла из образа, wrapper
запускает сам AppImage, а не временный mount, исчезающий после выхода.

### 7. Версия расширения — только числовая

Chrome и Firefox принимают в `manifest.json` версию из 1–4 числовых
компонентов. `CARGO_PKG_VERSION` вида `0.13.0-rc.2` для них невалиден, поэтому
ассеты расширения подставляют `@BROWSER_VERSION@` — версию без предрелизного
суффикса (`0.13.0`). Полная версия остаётся в квитанции и в `status.version`.
Это не косметика: без нормализации браузер отказывается загружать расширение
целиком.

### 8. Модель угроз

**Границы доверия.**

```text
веб-страница ──✕── popup расширения ──native messaging── браузер
                                                        │
                                                native-манифест (ID)
                                                        │
                                              orbitfm native-host
                                                        │ IPC-сокет 0600
                                                запущенный OrbitFM
```

Браузер — единственный, кто запускает хост и проверяет ID. Хост доверяет
манифесту и IPC-сокету; страница не имеет пути к порту; локальный процесс
пользователя, как и раньше, может напрямую пользоваться сокетом (SECURITY.md,
п. 2) — native host не расширяет его права.

| Угроза | Что мешает |
|--------|------------|
| Веб-страница шлёт команды в плеер | Нет content scripts, background и `externally_connectable`; popup не доступен странице |
| Чужое расширение обращается к хосту | Native-манифест разрешает ровно `chrome-extension://lfhm…/` или `orbitfm@modernbyte`; браузер не запускает хост для другого ID |
| Расширение пытается завершить процесс или включить произвольный поток | Allowlist: `quit`, `play`, `mode` запрещены даже при валидном запросе |
| Огромное или битое сообщение | Лимит 1 МиБ до чтения payload; строгий разбор `deny_unknown_fields`; oversized завершает хост, invalid-request — только запрос |
| Поток событий забивает память | `watch`-канал ADR-0039 схлопывает кадры, очередь вывода 64, медленный popup создаёт backpressure |
| Инъекция через путь или аргументы | Wrapper создаёт установщик, путь экранируется как shell-строка; `$@` браузера не пробрасывается, `native-host` не принимает аргументов |
| Выход за пределы каталога установки | Те же проверки путей и квитанции, что у ADR-0037; симлинк без `--force` не перезаписывается |
| Сетевой вход | Его нет: хост не слушает порт, ходит только в локальный IPC-сокет |
| Подмена расширения при обновлении | Не решается этим ADR: расширение распространяется распакованным и не подписано магазином |

**Принятые остаточные риски.**

1. **Публичный ключ задаёт ID, но не целостность.** Любой, кто может положить
   файлы расширения на диск, может изменить popup; фиксированный ID лишь
   делает манифест стабильным. Защита — права пользовательского каталога и
   осознанная загрузка распакованного расширения.
2. **Хост не видит ID вызывающего.** Он полагается на проверку браузера по
   native-манифесту; при ошибке в манифесте или политике браузера граница
   держится только allowlist'ом команд.
3. **Firefox-дополнение временное.** Постоянная установка требует подписи
   Mozilla; в репозитории она не выполняется. Пользователь загружает
   `manifest.json` через `about:debugging`, и после перезапуска браузера
   дополнение исчезает.
4. **Живая приёмка покрывает Chrome for Testing и Firefox, но не Brave, Edge и
   Vivaldi.** У них общий код и одинаковый native-манифест, однако поведение
   конкретной сборки не проверялось.
5. **Chromium с `--user-data-dir` читает native-манифесты не из XDG-каталога.**
   В этом режиме браузер ищет их в `<user-data-dir>/NativeMessagingHosts`;
   установщик пишет в стандартный профиль. Пользователь нестандартного профиля
   должен установить манифест туда сам — это описано в вики.
6. **Windows и macOS вне поставки установщика.** Native host как бинарник
   платформенно-нейтрален, но манифесты через реестр Windows и раскладка
   macOS не реализованы и не заявлены.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Локальный HTTP/WebSocket-сервер для расширения | Новый порт, CORS, авторизация и поверхность атаки; нарушает «один сокет, один экземпляр» |
| Content script + мост через страницу | Даёт веб-страницам путь к плееру и требует `externally_connectable`; резко расширяет поверхность атаки |
| Прямой вызов `orbitfm` из расширения | Браузер не запускает произвольные процессы со страницы расширения; native messaging — единственный штатный канал |
| Отдельное расширение под каждый браузер | Три копии popup и логики; несовместимости confined to manifests |
| Только Chrome Web Store / подписанный XPI | Требует аккаунтов, ревью и ключей, которых у проекта нет; исключило бы локальную установку из AppImage |
| Отдавать состояние через опрос `status --json` | Задержка и лишние процессы; `events` уже даёт snapshot и изменения без опроса |
| Разрешить весь IPC-протокол | Расширение получило бы `quit`, `play` и `mode`; компрометация popup стоила бы слишком дорого |
| Отдельный демон/служба native host | Второй процесс, жизненный цикл и обновление; хост должен жить ровно столько, сколько живёт порт |

## Последствия

**Положительные:**

- браузерная панель показывает Now Playing без опроса и без второго GUI;
- тот же `status`/`events`/IPC, что у CLI и плагинов, — одна логика состояния;
- allowlist не даёт панели завершить процесс или запустить произвольный поток;
- установка и удаление идут через общие квитанции, чужие конфиги не меняются;
- нет сетевого входа, фонового демона и постоянного процесса.

**Отрицательные / Риски:**

- фиксированный Chrome-ID навсегда связывает манифест с публичным ключом;
  смена ключа потребует переустановки native-манифеста;
- распакованное расширение и временное дополнение Firefox — не магазинная
  поставка: пользователь должен включить режим разработчика или повторить
  загрузку после перезапуска;
- native messaging добавляет вторую точку разбора недоверенного JSON; она
  покрыта тестами, но остаётся новым кодом;
- поведение Chromium-семейства кроме Chrome for Testing не проверено живьём;
- нестандартный `--user-data-dir` требует ручной установки манифеста.

## Реализация

- 0.15.0-rc.2: `src/native_host.rs` (фрейминг, allowlist, конверт, события,
  лимиты), маршрут `native-host` в `src/main.rs`;
- `src/integration/{mod,assets}.rs`: цели `chrome`/`firefox`, раскладка
  расширения, native-манифесты, детект браузеров, квитанции, wrapper;
- `integrations/browser/{popup.html,popup.css,popup.js,orbitfm-native-host}`,
  `integrations/chrome/manifest.json`, `integrations/firefox/manifest.json`,
  README целей;
- нормализация версии `@BROWSER_VERSION@` и разбор конверта `events` в popup —
  обе находки живой приёмки 2026-10-31;
- документация: `docs/interfaces/14-native-host.md`,
  `docs/modules/17-browser-companion.md`,
  `docs/wiki/12-Браузерное-расширение.md`.

Живая приёмка 2026-10-31 (Linux x86_64, niri/Wayland):

- Chrome for Testing 153 через CDP `Extensions.loadUnpacked`: реальный popup
  получил `snapshot` от запущенного экземпляра, показал «остановлено»,
  «Ничего не играет», громкость 75 % и русские подписи; громкость 74 %
  дошла до приложения и вернулась в popup, после чего восстановлена 75 %;
- Firefox 159 через WebDriver BiDi `webExtension.install` (временное
  дополнение): тот же popup, тот же snapshot и тот же round-trip громкости;
- установщик в подставном `HOME`: Chrome — 6 файлов расширения + 2
  native-манифеста для google-chrome и chromium, Firefox — 6 + 1; JSON
  манифестов точный, ID фиксированные, wrapper исполняемый, `uninstall`
  удаляет всё по квитанции;
- протокол хоста проверен отдельным клиентом: `status --json`, `events`,
  `forbidden` для `quit`/`play`/`mode`, `not-running`, oversized и битый кадр;
- `node --check integrations/browser/popup.js` — без ошибок.

Границы доказательности: Brave, Edge, Vivaldi и Firefox с постоянной
подписью не запускались; Windows-реестр и macOS-манифесты не реализованы;
Chrome/Chromium с нестандартным `--user-data-dir` требует ручного манифеста.
Это «проверено в runtime» для Chrome for Testing и Firefox на Linux и
«собрано/проверено статически» для остальных заявленных браузеров.

## Ревизии

- 2026-10-31 (0.16.0-rc.1): попап получил полный паритет с выпадающей панелью
  Noctalia — карточку now playing, транспорт с `status.can`, громкость,
  вкладки «Поиск | Избранное | История», мини-визуализатор и футер «Play this
  page». Allowlist расширен командами `search`, `library`, `favorite`,
  `play-result`, `play-library`, `play-url`; `quit`, `play`, `mode` и `Raw`
  остаются запрещёнными. Играть можно только строку последней выдачи поиска,
  элемент библиотеки или явный URL — произвольного `play <uuid>` у расширения
  нет. Манифесты получают `activeTab` и `scripting` для скана активной вкладки
  по клику; `host_permissions`, content scripts и фоновых скриптов по-прежнему
  нет. Состояние поиска живёт в `Session::companion` и публикуется кадром
  `search` (ADR-0039, ревизия 0.16). Новые файлы установщика не появились:
  состав целей `chrome`/`firefox` прежний, шесть файлов.
