# ADR-0002: Выбор GUI-стека

**Статус:** Принято  
**Дата:** 2026-10-21  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

OrbitFM требует:

- Кроссплатформенный native UI (Linux First, затем Windows и macOS)
- Поддержку прозрачного окна (overlay-режим)
- Возможность встроить кастомный 3D-рендер (глобус) непосредственно в UI
- Минимальные накладные расходы и быструю итерацию
- Хорошую поддержку Wayland

Рассматривались основные варианты для Rust-экосистемы.

## Решение

Выбираем стек:

- **eframe** + **egui** — основной GUI-фреймворк
- **egui-wgpu** — бэкенд рендеринга + механизм `PaintCallback` / `CallbackTrait` для кастомного 3D-пасса

### Обоснование (по официальной документации)

1. **eframe** — официальный фреймворк для написания приложений на egui. Поддерживает native (Linux, macOS, Windows) и web. Источник: docs.rs/eframe, github.com/emilk/egui.
2. **egui** — immediate-mode GUI. Низкие накладные расходы, отличная производительность, простой API.
3. **egui-wgpu** — официальные биндинги. Позволяет выполнять произвольный wgpu-код внутри UI через `Callback` / `PaintCallback`. Это единственный чистый путь отрисовать 3D-глобус прямо в текстуру egui без внешних окон и без конфликтов с другими 3D-движками.
4. Поддержка прозрачности: `NativeOptions` / `ViewportBuilder::with_transparent(true)` + `App::clear_color`. На Linux (особенно Wayland) работает; на Windows/macOS требуется дополнительное тестирование (известны ограничения wgpu-бэкенда).

### Альтернативы, которые были отклонены

| Вариант              | Причина отклонения |
|----------------------|--------------------|
| iced                 | Менее зрелый для кастомного 3D-рендера, слабее immediate-mode подход |
| gtk-rs / relm4       | Сильная привязка к GNOME/GTK, хуже кроссплатформенность и кастомный рендер |
| tauri + webview      | Избыточный вес, web-стек внутри, хуже контроль над 3D и прозрачностью |
| bevy + bevy_egui     | Слишком тяжёлый игровой движок для радиоплеера |
| three-d + отдельное окно | Конфликт с egui, два контекста рендеринга, сложнее overlay |

## Последствия

**Положительные:**
- Единый процесс UI + 3D
- Чистая интеграция кастомного рендера через официальный API
- Хорошая поддержка Linux/Wayland
- Быстрая разработка UI

**Отрицательные / Риски:**
- Прозрачность окна с wgpu-бэкендом имеет известные ограничения (особенно Windows). Возможно, потребуется fallback на glow-бэкенд для overlay-режима.
- egui находится в активной разработке — возможны breaking changes между минорными версиями. Нужно фиксировать версии и следить за changelog.
- Для полноценного PBR и сложных шейдеров придётся писать собственный wgpu-пайплайн.
