# ADR-0025: Безопасная загрузка и декодирование favicon

**Статус:** Принято, ред. 3 (2026-10-31) — opt-in `artwork_allow_http` закрывает
цену HTTPS-only покрытия, фоновый вердикт яруса 2 закрывает остаточный риск (б)
ред. 2; ранее (ред. 2) — сетевая политика цели в два яруса (SSRF), перепроверка
каждого хоппа редиректа, HTTPS-модель целостности, жёсткий потолок кэша и
ограниченная backpressure; ранее (ред. 1) — только форматы и лимиты декодера  
**Дата:** 2026-10-24  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

OrbitFM загружает favicon станций по URL из каталога Radio Browser. Это
пользовательский контент (UGC): URL и содержимое иконки не контролируются
проектом. Иконки загружаются автоматически при появлении станции в списке
(`src/app.rs`, `FaviconCache::texture`) и декодируются в фоне.

OrbitFM — клиентское приложение без бэкенда, загрузки файлов пользователем,
файлового хранилища и веб-вью. Поэтому часть стандартного чек-листа по
безопасности изображений к нему неприменима:

| Мера из общего чек-листа | Применимость в OrbitFM |
|--------------------------|-------------------------|
| Перекодирование и удаление EXIF/IPTC/XMP | Применяется де-факто: оригинальные байты не сохраняются, декодер отдаёт только RGBA-пиксели |
| Случайные имена файлов, защита от path traversal | Неприменимо: файлы на диск не пишутся, URL не используется как путь |
| Отдельный домен/CDN, CSP, `nosniff` | Неприменимо: нет браузера и отдачи контента |
| ClamAV, sandbox-контейнер, non-root | Неприменимо: нет серверной обработки; декодирование идёт в процессе клиента |
| Запрет SVG и GIF | Применяется: эти форматы не подключены в `image` |
| Лимиты размера, разрешения, magic numbers | Применяется: границы декодера |

Остаётся реальный вектор: вредоносный или повреждённый файл, эксплуатирующий
декодер, decompression bomb, огромный ответ или подмена типа содержимого.
Декодер `image` написан на Rust, но паника или чрезмерная аллокация всё равно
могут вывести из строя фоновую загрузку.

Ревизия 2 добавляет второй, ранее отрицанный вектор. Redaction 1 прямо снимала
с себя SSRF («защита от запросов к приватным адресам не реализуется»), и два
независимых аудита 0.12/0.13 показали, что это не отложенная, а отсутствующая
мера: `favicon` станции — URL из UGC-каталога, он подставляется в запрос
**автоматически**, без участия пользователя, а приложение работает на машине,
где рядом живут loopback-сервисы, CGNAT-адреса облачных метаданных
(`169.254.169.254`) и внутренняя сеть владельца. Злоупотребление — не чтение
ответа (его никто не показывает), а сам факт адресного запроса: сканирование
внутренних портов, обращение к контроллерам локальных сервисов, DNS rebinding.
Тем же путём приватный literal уходил наружу — в MPRIS `artUrl` и SMTC, где его
читает фетчер обложек оболочки (ADR-0011, ADR-0026).

## Решение

1. **Форматы.** Декодируются только PNG, JPEG и WebP по фактической сигнатуре
   файла (`ImageReader::with_guessed_format`), а не по расширению или
   `Content-Type`. SVG, GIF и ICO отклоняются. Из `image` удаляется фича `ico`,
   добавляется `webp`.
2. **Лимит файла.** Тело ответа читается потоково и обрывается при превышении
   512 КиБ; `Content-Length` больше лимита отклоняется до чтения. Тот же лимит
   повторно проверяется в `decode_favicon` — на случай прямого вызова.
3. **Лимит разрешения.** До декодирования читаются размеры из заголовка; сторона
   больше 512 px отклоняется. Декодер дополнительно ограничен
   `Limits { max_image_width: 512, max_image_height: 512, max_alloc: 8 МиБ }`,
   что закрывает decompression bomb.
4. **HTTP.** Принимаются только `http`/`https`; таймаут 6 с; не более 3
   редиректов. Если `Content-Type` присутствует, он должен быть одним из
   `image/png`, `image/jpeg`, `image/webp` или `application/octet-stream`;
   `text/html`, `image/svg+xml`, `image/gif` и прочее отклоняются. Отсутствие
   заголовка допускается — решает проверка сигнатуры.
   *С ред. 2:* редиректы больше не доверяются `Policy::limited(3)` — политика
   перепроверяется на каждом хоппе вручную (п. 10), общий бюджет ответа — wall-clock
   6 с поверх всего цикла, а `http`-ссылка авто-повторяется как `https` (п. 11).
5. **Изоляция паники.** Декодирование в фоновой задаче обёрнуто в
   `catch_unwind`: паника декодера не должна навсегда занимать слот `in_flight`
   и блокировать очередь. *С ред. 2:* страховка расширена на весь путь задачи —
   `FetchGuard` освобождает слот при любом выходе (паника, `?`, ранний возврат,
   отказ политики), а не только при панике декодера.
6. **Хранение.** Оригинальные байты не сохраняются. В кэше остаются только
   декодированные RGBA-текстуры 64×64 в памяти (не более 256 записей); EXIF,
   IPTC, XMP и любые «хвосты» файла теряются при декодировании. *С ред. 2:* 256 —
   жёсткий инвариант, а не ориентир: вставку невозможно превысить, очередь
   вторым независимым лимитом больше не существует (п. 13).
7. **Отказ безопасен.** Любая ошибка загрузки, типа или декодирования помечает
   favicon как `Failed`; UI показывает инициал станции. Повторных запросов нет.
   *С ред. 2:* каждый отказ логируется одной строкой `tracing::debug!` с
   ограниченным перечнем причин (`warn!` для транспортных ошибок) — раньше ни
   одна ветка отказа в лог не попадала, и «инициалы вместо иконки» были
   неразличимы с SSRF-политикой, таймаутом и мусорным ответом.

8. **Политика цели в два яруса** (`src/services/ssrf.rs` +
   `src/services/artwork.rs`, `src/services/` — слой исходящей сети по AGENTS.md
   §4.2; `ui` и `media` сеть не делают). Ярусы разделены, потому что вызывающие
   контексты разные:

   | Ярус | Контракт | DNS | Потребитель |
   |------|----------|-----|-------------|
   | 1 — синтаксический | чистая функция над `Url`, без сети | нет | публикация метаданных (главный поток, `Session::park` внутри `block_on`) и фетчер до всякого резолва |
   | 2 — разрешённый | async-вердикт по адресу | свой таймаут 3 с | только фетчер, на каждом хоппе |

   Ярус 1 обязан существовать отдельно: `sync_media()` исполняется на главном
   потоке и внутри `runtime.block_on` в `Session::park`, поэтому резолв там
   означал бы стопор UI.

9. **Классификатор адреса** (`is_public_destination`) — deny-by-default таблица
   диапазонов: для IPv4 — `0.0.0.0/8`, весь `127/8`, RFC 1918, `169.254/16`
   (link-local и метаданные облаков), `100.64/10` CGNAT (в `is_private` **не
   входит**), `192.0.0.0/24`, три документационных `/24` (`192.0.2.0`,
   `198.51.100.0`, `203.0.113.0`), `198.18/15`, `224/4`,
   `240/4`; для IPv6 — `::1`, `::`, `ff00::/12`, `fe80::/10`, `fc00::/7` ULA,
   `::ffff:0:0/96` и `2002::/16` с рекурсивной классификацией вложенного v4
   (один уровень), `2001::/32` Teredo целиком, `2001:db8::/32`, `0000::/96`,
   `100::/64`. Классификация идёт по
   **типизированному `Url::host()`**: парсер WHATWG канонизирует `0x7f.0.0.1`,
   `127.1`, `0177.0.0.1`, `2130706433` в `Host::Ipv4` бесплатно, поэтому ни
   `idna`, ни `ipnet` не нужны. Отклоняются также: одноярлыковые хосты
   (`http://router/` резолвится search-domain'ами во внутреннюю сеть),
   `localhost`/`*.localhost`/`*.local`/`*.internal`/`*.home.arpa`/`*.localdomain`
   — сравнение по **границе ярлыка**, чтобы `artwork-local.example` не попал
   под запрет, любой userinfo (`http://localhost@good.example/`) и порт 0.
   Корневая точка DNS-записи (`router.`, `LOCALHOST.`) снимается перед
   сравнением: иначе одноярлыковый хост и `localhost` обходили бы запрет
   законной записью зоны.
   *С ред. 2 (уточнение к формулировке плана):* отдельного правила «не-ASCII в
   имени» нет и быть не может — тот же парсер применяет IDNA-маппинг до того,
   как ярлык попадает в политику, и возвращает punycode (`exämple.com` →
   `xn--exmple-cua.com`), а идеографическая точка (`127。0。0。1`) разворачивается
   в обычный IPv4-literal и отбивается адресом. Голиф-обход поэтому не уходит в
   резолвер в виде UTF-8; решающим остаётся класс разрешённого адреса (ярус 2),
   а не видимость написания имени.

10. **Перепроверка каждого хоппа.** `Policy::none()`, `MAX_ARTWORK_REDIRECTS = 3`,
    и на каждом хоппе: ярус 1 → резолв хоста → **all-or-nothing** (приватный
    адрес хотя бы в одном ответе — отказ) → запрос клиентом, припинованным через
    `resolve_to_addrs` → 2xx проверяется на MIME и ≤512 КиБ, 3xx склеивается с
    `Location` и проходит ярусы заново. `Policy::custom` отклонён: у
    `Attempt::url()` только `Url` без резолва, поэтому `evil.com → 127.0.0.1` и
    редирект на rebinding-хост им не ловятся. Понижать `https → http` запрещено
    всегда; `Location` с userinfo, не-http(s)-схемой или чужим хостом-ловушкой
    отклоняется.
    `resolve_to_addrs` — билдер-time, поэтому клиент живёт в bounded-карте
    `host:port → Client` (потолок 16, TTL 60 с, LRU): у фавиконок сильная
    кластеризация по CDN-хостам, так что переиспользование соединений даже
    растёт. Alternativa — переписать URL на IP-literal с подменным заголовком
    `Host` — отклонена: ломает SNI и проверку имени сертификата.

11. **HTTPS как модель целостности, а не приватности.** http-vs-https — не
    вопрос SSRF (публичная цель остаётся публичной), вопрос доверия байтам,
    которые уходят в `image`: on-path атакующий на 80 порту подменяет содержимое
    валидной ссылкой. Поэтому загрузка HTTPS-only с беззвучной авто-повторной
    попыткой `http:// → https://` (семантика `https_only(true)`), без новой
    строки i18n и без UI-ручки; genuinely-http-only станции показывают инициалы.
    *С ред. 3:* явный opt-in `artwork_allow_http` (default `false`) реализован.
    Это одна настройка `settings.json`, тумблер «Разрешить HTTP-обложки» в
    категории «Внешний вид» (2 поля × 10 каталогов = 20 переводов) и
    `AtomicBool` в политике фетчера: включение действует на летящие и новые
    запросы без перезапуска, а уже помеченные `Failed` favicon возвращаются в
    очередь (`FaviconCache::retry_failed`), иначе тумблер не давал бы видимого
    результата до перезапуска. Смысл настройки не меняется: HTTP допустим только
    как **конечная** цель по явному выбору владельца, понижение `https → http` в
    редиректе запрещено при любом значении, а подмена байтов по дороге остаётся
    принятым риском этого выбора.

12. **Публикация метаданных гейтится ярусом 1 синхронно и ярусом 2 асинхронно**
    (SEC-04). `artUrl` MPRIS, Now Playing и SMTC получают `favicon`, а поле
    `url` — `url_resolved` станции только после яруса 1; при отказе публикуется
    пусто (`artwork_url: ""`), никогда не проксируется и не переписывается.
    Иначе приватный literal утекал наружу DE-фетчеру, который сам ходит по
    этому адресу. *С ред. 3:* прохождение яруса 1 — необходимое, но больше не
    достаточное условие: `Session::publish_gate` (`src/session/publish_gate.rs`)
    держит bounded-карту вердиктов яруса 2 (`MAX_VERDICTS = 64`, TTL 60 с) и
    решает по правилу stale-while-revalidate:
    * свежий публичный вердикт → URL публикуется;
    * свежий отказ → не публикуется;
    * вердикта нет → URL не публикуется, в кэш кладётся «в ожидании», в фон
      уходит `services::public_verdict` (резолв с таймаутом 3 с + all-or-nothing
      классификация адресов); после ответа пробуждается GUI, и кадр публикует
      URL — обычно со следующего кадра, без действий пользователя;
    * вердикт истёк → публикуется прежнее решение, а обновление идёт в фоне:
      обложка не мигает на каждом TTL.
    Вердикт запрашивается только после яруса 1 — отклонённый синтаксически URL
    не порождает ни DNS-запроса, ни записи в кэше. `sync_media()` остаётся
    синхронным: он читает готовый вердикт и никогда не резолвит на главном
    потоке (иначе `Session::park` внутри `block_on` встал бы на DNS). Цена —
    первый кадр новой станции может опубликовать пустой `artUrl`; выигрыш —
    домен, резолвящийся во внутреннюю сеть, больше не проходит в `artUrl`.

13. **Потолок кэша — инвариант, backpressure — ограниченная (SEC-01).**
    Три свойства держатся после каждого публичного вызова `FaviconCache` и
    доказаны тестами: `entries.len() <= MAX_CACHED`, `in_flight <= MAX_IN_FLIGHT`
    и `queued == count(Queued)`. Механика:
    * вставка при полном кэше **отказывается** (`texture()` → `None`), а не
      превышает потолок; `None` для UI означает то же, что и раньше — инициалы
      и репейнт через `is_busy()`;
    * отдельной неограниченной очереди заявок нет: `Queued` живёт в той же карте
      записей, поэтому вторая, отдельно нарушаемая коллекция больше не
      существует;
    * результаты идут в `mpsc::channel(MAX_IN_FLIGHT)`, задачи шлют `try_send`
      и не могут зависнуть при закрытом окне; буферизованных результатов
      физически не бывает больше числа слотов;
    * запись несёт номер поколения, поэтому поздний результат вытесненной
      загрузки отвергается и слот освобождается ровно один раз; проверка
      записи и поколения выполняется **до** `ctx.load_texture`, так что чужой
      результат не аллоцирует текстуру;
    * слот страхует `FetchGuard`: `Drop` отправляет исход на любом выходе —
      паника декодера, `?`, ранний возврат, отказ политики.
    Счётчики `CacheStats { entries, served, failed, evicted }` и одна строка
    `tracing::debug!` на причину отказа закрывают наблюдаемость (PERF-01):
    до ред. 2 ни одна ветка отказа в лог не попадала.

## Последствия

**Положительные:**
- Устранены основные клиентские риски: decoder DoS, decompression bomb,
  неограниченный ответ, исполняемые форматы (SVG/GIF) и метаданные.
- Оригинальный файл никогда не покидает память и не попадает на диск.
- Ошибка одной иконки не блокирует очередь загрузок.
- *С ред. 2:* адресная поверхность закрыта — ни loopback, ни RFC 1918, ни
  link-local и облачные метаданные, ни CGNAT, ни ULA не получают соединения;
  приватный literal не публикуется в MPRIS/SMTC/Now Playing.
- *С ред. 2:* «инициалы вместо иконки» стали различимы в логе по причине, а
  потолок кэша перестал быть советным.
- *С ред. 3:* приватный по резолву хост больше не публикуется в `artUrl`,
  `Now Playing` и SMTC; вердикт яруса 2 считается фоном, поэтому главный поток
  и `park()` не блокируются, а готовое решение живёт 60 с и не пересчитывается
  каждый кадр.

**Отрицательные / Риски:**
- Иконки в ICO, GIF и SVG больше не отображаются — вместо них инициал станции.
  Это осознанный компромисс в пользу меньшей поверхности декодеров.
- Изображения больше 512 px по стороне или 512 КиБ отклоняются, даже если
  визуально корректны.
- *С ред. 2:* HTTPS-only сужает покрытие: станции, чей favicon живёт только на
  80 порту, показывают инициалы. *С ред. 3:* это больше не константа: владелец
  может включить HTTP явным тумблером; доля потерь замерена на живом каталоге
  (из 62 отказов rc.2 только 4 объяснялись схемой и транспортом, остальные —
  MIME, размер и не-2xx, которые случились бы и на `http`).
- *С ред. 3:* включённый opt-in возвращает риск подмены байтов на пути к
  декодеру и снижает ценность HTTPS-модели для выбравшего её станции; это
  осознанный выбор пользователя, а не политика по умолчанию. Подсказка строки
  говорит об этом прямо.
- *С ред. 3:* первый кадр станции может не содержать `artUrl` — вердикт яруса 2
  приходит фоном; для DE-фетчера это выглядит как «обложки ещё нет», а не как
  отказ. Смена адреса при неизменном названии станции на время обновления
  вердикта публикует прежнее решение (SWR), поэтому старый URL может побыть
  видимым до истечения TTL+резолва.
- Принятые остаточные риски ред. 3. (а) Припинованный клиент живёт до
  `CLIENT_TTL` = 60 с — окно, в котором хост мог переехать на приватный адрес;
  мы не владеем резолвером, и это цена переиспользования соединений. (б) Закрыт
  в ред. 3: домен, резолвящийся во внутреннюю сеть, не попадает в `artUrl` —
  публикация ждёт вердикта яруса 2. (в) Не-дефолтные порты разрешены сознательно
  (решение владельца): угроза SSRF определяется классом адреса, а не портом, а
  денист портов обходится (`10.0.0.5:9999`) и ломает покрытие каталога.
- Встроенный антивирус не используется; защита опирается на allowlist форматов
  и лимиты декодера.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Доверять `image` с лимитами по умолчанию (512 МиБ) | Слишком высокий потолок для 64×64 иконки |
| Определять формат по расширению или `Content-Type` | Клиентские заголовки подделываются; сигнатура надёжнее |
| Оставить ICO ради покрытия favicon | Расширяет поверхность декодеров; PNG/JPEG/WebP покрывают основные случаи |
| Перекодировать через внешний сервис/CDN | У проекта нет бэкенда и хранилища |
| Декодировать в отдельном процессе-песочнице | Непропорциональная сложность для локального клиента |
| *С ред. 2:* `redirect::Policy::limited(3)` | Внутри редиректа нет резолва: `evil.com → 127.0.0.1` и rebinding-хост не ловятся |
| *С ред. 2:* `redirect::Policy::custom` с проверкой `Attempt::url()` | То же: у `Attempt` только `Url`, адрес цели неизвестен |
| *С ред. 2:* переписать URL на IP-literal с подменным заголовком `Host` | Ломает SNI и проверку имени сертификата |
| *С ред. 2:* резолвить имя при публикации метаданных | `sync_media` исполняется на главном потоке и внутри `block_on` в парке — DNS остановил бы UI |
| *С ред. 2:* проксировать или переписывать приватный `artUrl` перед публикацией | Мы не владеем DE-фетчером; переписанная строка — новая ложь в контракте, а прокси — второй сетевой путь |
| *С ред. 3:* запретить публикацию без готового вердикта навсегда (fail-closed без фона) | DE никогда не увидел бы обложку: вердикт неоткуда взять, а `sync_media` не может ждать |
| *С ред. 3:* пересчитывать вердикт каждый кадр | Десятки DNS-запросов в секунду на неизменный адрес; кэш с TTL и SWR даёт тот же результат без сети |
| *С ред. 3:* держать вердикты в неограниченной карте | Публикация идёт от UGC-каталога; bounded-кэш 64 записи с вытеснением самого старого не даёт расти памяти |
| *С ред. 3:* отдавать вердикт синхронно через `block_in_place`/отдельный поток с ожиданием в кадре | Кадр UI встаёт на резолв до 3 с; фон + пробуждение сохраняют отзывчивость |
