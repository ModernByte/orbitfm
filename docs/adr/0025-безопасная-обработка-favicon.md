# ADR-0025: Безопасная загрузка и декодирование favicon

**Статус:** Принято  
**Дата:** 2026-10-24  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

OrbitFM загружает favicon станций по URL из каталога Radio Browser. Это
пользовательский контент (UGC): URL и содержимое иконки не контролируются
проектом. Иконки загружаются автоматически при появлении станции в списке
(`src/app.rs`, `FaviconCache::texture`) и декодируются в фоне.

OrbitFM — клиентское приложение без бэкенда, загрузки файлов пользователем,
файлового хранилища и веб-вью. Поэтому часть стандартного чек-листа по
безопасности изображений к нему неприменима:

| Мера из общего чек-листа | Применимость в OrbitFM |
|--------------------------|-------------------------|
| Перекодирование и удаление EXIF/IPTC/XMP | Применяется де-факто: оригинальные байты не сохраняются, декодер отдаёт только RGBA-пиксели |
| Случайные имена файлов, защита от path traversal | Неприменимо: файлы на диск не пишутся, URL не используется как путь |
| Отдельный домен/CDN, CSP, `nosniff` | Неприменимо: нет браузера и отдачи контента |
| ClamAV, sandbox-контейнер, non-root | Неприменимо: нет серверной обработки; декодирование идёт в процессе клиента |
| Запрет SVG и GIF | Применяется: эти форматы не подключены в `image` |
| Лимиты размера, разрешения, magic numbers | Применяется: границы декодера |

Остаётся реальный вектор: вредоносный или повреждённый файл, эксплуатирующий
декодер, decompression bomb, огромный ответ или подмена типа содержимого.
Декодер `image` написан на Rust, но паника или чрезмерная аллокация всё равно
могут вывести из строя фоновую загрузку.

## Решение

1. **Форматы.** Декодируются только PNG, JPEG и WebP по фактической сигнатуре
   файла (`ImageReader::with_guessed_format`), а не по расширению или
   `Content-Type`. SVG, GIF и ICO отклоняются. Из `image` удаляется фича `ico`,
   добавляется `webp`.
2. **Лимит файла.** Тело ответа читается потоково и обрывается при превышении
   512 КиБ; `Content-Length` больше лимита отклоняется до чтения. Тот же лимит
   повторно проверяется в `decode_favicon` — на случай прямого вызова.
3. **Лимит разрешения.** До декодирования читаются размеры из заголовка; сторона
   больше 512 px отклоняется. Декодер дополнительно ограничен
   `Limits { max_image_width: 512, max_image_height: 512, max_alloc: 8 МиБ }`,
   что закрывает decompression bomb.
4. **HTTP.** Принимаются только `http`/`https`; таймаут 6 с; не более 3
   редиректов. Если `Content-Type` присутствует, он должен быть одним из
   `image/png`, `image/jpeg`, `image/webp` или `application/octet-stream`;
   `text/html`, `image/svg+xml`, `image/gif` и прочее отклоняются. Отсутствие
   заголовка допускается — решает проверка сигнатуры.
5. **Изоляция паники.** Декодирование в фоновой задаче обёрнуто в
   `catch_unwind`: паника декодера не должна навсегда занимать слот `in_flight`
   и блокировать очередь.
6. **Хранение.** Оригинальные байты не сохраняются. В кэше остаются только
   декодированные RGBA-текстуры 64×64 в памяти (не более 256 записей); EXIF,
   IPTC, XMP и любые «хвосты» файла теряются при декодировании.
7. **Отказ безопасен.** Любая ошибка загрузки, типа или декодирования помечает
   favicon как `Failed`; UI показывает инициал станции. Повторных запросов нет.

## Последствия

**Положительные:**
- Устранены основные клиентские риски: decoder DoS, decompression bomb,
  неограниченный ответ, исполняемые форматы (SVG/GIF) и метаданные.
- Оригинальный файл никогда не покидает память и не попадает на диск.
- Ошибка одной иконки не блокирует очередь загрузок.

**Отрицательные / Риски:**
- Иконки в ICO, GIF и SVG больше не отображаются — вместо них инициал станции.
  Это осознанный компромисс в пользу меньшей поверхности декодеров.
- Изображения больше 512 px по стороне или 512 КиБ отклоняются, даже если
  визуально корректны.
- Защита от SSRF/запросов к приватным адресам в этом ADR не реализуется:
  favicon-URL по-прежнему может указывать на внутренний хост. Это отдельное
  решение, если понадобится.
- Встроенный антивирус не используется; защита опирается на allowlist форматов
  и лимиты декодера.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Доверять `image` с лимитами по умолчанию (512 МиБ) | Слишком высокий потолок для 64×64 иконки |
| Определять формат по расширению или `Content-Type` | Клиентские заголовки подделываются; сигнатура надёжнее |
| Оставить ICO ради покрытия favicon | Расширяет поверхность декодеров; PNG/JPEG/WebP покрывают основные случаи |
| Перекодировать через внешний сервис/CDN | У проекта нет бэкенда и хранилища |
| Декодировать в отдельном процессе-песочнице | Непропорциональная сложность для локального клиента |
