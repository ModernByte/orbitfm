# ADR-0014: Темы и кастомизация интерфейса

**Статус:** Принято  
**Дата:** 2026-10-22  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Сейчас оформление OrbitFM зашито в код: тёмная карточка, акцент `#6CB0FF`
(`ACCENT`), приглушённый текст и маркеры используют константы `app.rs` и
`render/markers.rs`. Пользователь не может выбрать светлую тему или другой
акцент, а настройки не сохраняются между запусками.

ROADMAP Этапа 7 включает пункт «Темы и кастомизация». Требуется решение, которое:

- переиспользует возможности egui и не тянет новую UI-библиотеку;
- не ломает прозрачность overlay-режима;
- сохраняет выбор между запусками и не мешает при повреждённом файле;
- не добавляет IPC-команды и сетевые запросы.

## Решение

1. **Новый модуль `settings` (`src/settings/`).** Он хранит только пользовательские
   предпочтения оформления (`ThemeMode`, `AccentColor`) и не зависит от egui,
   доменных модулей и GUI. Application Core применяет настройки.
2. **Расположение и формат.** Файл `$XDG_CONFIG_HOME/orbitfm/settings.json`; если
   переменная не задана или относительна — `$HOME/.config/orbitfm/settings.json`.
   Формат — JSON:
   `{ "theme": "system" | "dark" | "light", "accent": "blue" | "green" | "amber" | "violet" | "rose" | "cyan" }`.
   Недостающие поля заменяются значениями по умолчанию (`system`, `blue`).
3. **Атомарная запись.** Как и у библиотеки: `settings.json.tmp` + `rename`.
   Запись синхронная и выполняется только при изменении настройки.
4. **Темы.** Используется `egui::ThemePreference` (`System`/`Dark`/`Light`) и
   `Context::set_theme`. Для обеих тем настраиваются одинаковые прозрачные
   `panel_fill`/`window_fill`, поэтому overlay-режим работает в любой теме.
   `System` следует системной теме, которую eframe передаёт в `RawInput`.
5. **Акцент.** Набор из шести предпетов вместо произвольного цвета: акцент
   применяется к выделению вкладок, ссылкам, подписи страны, маркерам станций и
   подсветке важных элементов. Собственный цвет через color picker отложен:
   перетаскивание пикера писало бы файл несколько раз в секунду.
6. **Палитра.** Application Core выбирает цвета карточки, приглушённого текста,
   ошибок и подложек в зависимости от активной темы (`Context::theme`). Константы
   `ACCENT`, `MUTED_TEXT`, `ERROR_TEXT` заменяются вычисляемой палитрой.
7. **GUI.** В карточке появляется сворачиваемый блок «Оформление»: выбор темы
   (Системная/Тёмная/Светлая) и акцентные образцы. Изменения применяются сразу и
   сохраняются; ошибка записи показывается в карточке и не прерывает
   воспроизведение. Новых IPC-команд нет.
8. **Отказоустойчивость.** Отсутствие файла — настройки по умолчанию, не ошибка.
   Повреждённый JSON — предупреждение и эфемерное хранилище без пути: файл не
   перезаписывается до исправления вручную.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Произвольный цвет через color picker | Запись на каждое движение пикера; нужен debounce и отдельное состояние |
| Внешние файлы тем (TOML/JSON + hot reload) | Больше scope: схема, валидация, документация формата, риски несовместимости |
| Только `Visuals::light()` без своей палитры | Карточка и маркеры остались бы тёмными/несогласованными |
| Хранить настройки в `library.json` | Смешение пользовательских данных и конфигурации; XDG разделяет каталоги |
| Настройки через IPC | Не требуются: управление доступно из GUI, single-instance |
| Новая UI-библиотека | egui уже предоставляет темы и стили |

## Последствия

**Положительные:**

- Светлая и тёмная темы, следование системной теме и шесть акцентов
- Настройки переживают перезапуск; overlay остаётся прозрачным
- Модуль `settings` не зависит от GUI, egui и домена
- Нет новых IPC-команд, зависимостей и сетевых обращений

**Отрицательные / Риски:**

- Светлая палитра требует отдельной проверки контраста на глобусе и в карточке
- Акцент ограничен предпетами; произвольный цвет — отдельное решение
- `System` зависит от того, передаёт ли оконный менеджер системную тему
- При ошибке записи выбор живёт только до завершения процесса
