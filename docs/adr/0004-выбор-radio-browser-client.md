# ADR-0004: Выбор клиента Radio Browser

**Статус:** Принято  
**Дата:** 2026-10-21  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

OrbitFM получает список радиостанций из сообщества Radio Browser. Нужен надёжный способ:

- Находить живые серверы API
- Выполнять поиск и получение станций
- Обрабатывать падения зеркал
- Соблюдать правила использования API

## Решение

Реализуем собственный тонкий клиент на `reqwest` + DNS-discovery.

### Обязательные правила (из официальной документации api.radio-browser.info)

1. **Server Discovery**  
   Перед первым запросом выполнять DNS-lookup имени `all.api.radio-browser.info`.  
   Полученный список серверов рандомизировать и использовать с failover.

2. **User-Agent**  
   Каждый запрос обязан содержать говорящий User-Agent:  
   `OrbitFM/1.0 (ModernByte; Linux; Rust)`

3. **Рекомендуемые действия**  
   - Использовать поле `url_resolved` для воспроизведения  
   - Отправлять `/json/url` (click) при старте воспроизведения станции  
   - Не использовать устаревшие поля `id` и `country` (вместо них — `stationuuid` и `countrycode`)

4. **Протокол**  
   HTTPS, JSON-эндпоинты (`/json/stations/search` и др.)

### Альтернативы

| Вариант                    | Причина отклонения |
|----------------------------|--------------------|
| Готовый crate `radiobrowser` | Существует, но мы предпочитаем полный контроль над discovery, retry и User-Agent |
| Прямой хардкод одного зеркала | Нарушает официальные рекомендации, снижает отказоустойчивость |

## Последствия

**Положительные:**
- Полный контроль над политикой повторов и выбором зеркала
- Соответствие официальным требованиям API
- Лёгкая замена транспорта при необходимости

**Отрицательные / Риски:**
- Нужно самостоятельно реализовать DNS-discovery и health-check
- API может менять список серверов — discovery должен быть динамическим
