# ADR-0006: Медиа-контроли (MPRIS / системные кнопки)

**Статус:** Принято  
**Дата:** 2026-10-21  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Пользователь должен иметь возможность управлять воспроизведением через:

- Медиа-клавиши клавиатуры
- Системные виджеты (GNOME, KDE, Noctalia и т.д.)
- MPRIS-клиенты (`playerctl` и др.)

На Linux это MPRIS v2.  
На Windows — System Media Transport Controls (SMTC).  
На macOS — Now Playing / MPNowPlayingInfoCenter.

## Решение

Используем кроссплатформенную библиотеку **playwire** (предпочтительно) или **souvlaki** как fallback.

### Почему playwire

- Активно поддерживается
- Единый API для Linux (MPRIS через zbus), Windows (SMTC) и macOS
- Исправляет известные недостатки souvlaki (trackid, shuffle/repeat, capabilities и др.)

Если playwire окажется недостаточно зрелым на момент реализации — допустим переход на souvlaki или комбинацию `mpris-server` + платформенные бэкенды.

### Минимальный набор возможностей MPRIS

- Identity / DesktopEntry
- PlaybackStatus (Playing / Paused / Stopped)
- Metadata (title, artist/station, artUrl)
- Play / Pause / Stop / PlayPause
- Volume
- CanPlay, CanPause, CanGoNext (по возможности)

### Альтернативы

| Вариант              | Причина отклонения / заметка |
|----------------------|------------------------------|
| mpris-player         | Unmaintained (рекомендуют mpris-server) |
| Только zbus + ручной MPRIS | Много кода, плохая кроссплатформенность |
| souvlaki             | Рабочий, но имеет ряд недочётов; оставлен как запасной вариант |

## Последствия

**Положительные:**
- Единый код для трёх платформ
- Нормальная интеграция с системными контролами

**Отрицательные / Риски:**
- Нужно внимательно тестировать каждую платформу
- На Linux зависимость от D-Bus (zbus)
