# ADR-0049: Локальная статистика прослушивания

**Статус:** Принято  
**Дата:** 2026-11-03  
**Участники решения:** ModernByte Architecture

## Контекст

До 0.19.0-rc.1 приложение знает о прослушанном ровно столько, сколько
помнит история: `library.json` хранит последние `HISTORY_LIMIT = 20` станций
без меток времени и без длительности. Из этого нельзя ответить на вопросы
«сколько я слушаю», «какие станции за месяц», «какие страны и жанры
интересны». Аудит `docs/audit/OrbitFM-future-features.md` §2.5 относит
локальную статистику к приоритету B и волне 2; ADR-0046 зафиксировал
принципы ритуалов слушания, но счётчики сознательно отложил.

Одновременно действует приватное обещание README §(г): телеметрии нет, и её
появление требует отдельного архитектурного решения и явного включения
пользователем. Статистика обязана остаться строго на устройстве — иначе она
противоречит и аудиту («без аккаунта, без отправки на сервер»), и README.

Отдельная сложность: `library.json` и его экспорт схемы 1 — переносимый
контракт между desktop и Android Companion (ADR-0045, ADR-0046). Смешивать с
ним приватные счётчики нельзя: импорт/экспорт библиотеки не должен молча
переносить цифры прослушивания.

## Решение

### 1. Что считается

Считается **только время в состоянии `Playing`**, приписанное активной
станции — той же, что показывают `status`, MPRIS и панель (ADR-0046).

- Пауза, загрузка, реконнект, ошибка, стоп — не считаются.
- Громкость не важна: станция на нулевой громкости считается прослушанной,
  потому что намерение слушать было.
- Станция, запущенная из браузерного расширения, CLI, GNOME-расширения или
  бар-скрипта, считается так же, как запущенная мышью: источник команды не
  имеет значения.
- Время, сыгранное до внедрения счётчиков, не восстанавливается: история не
  содержит длительности.
- Внешний поток (ADR-0025, `play-url`) без `stationuuid` каталога получает
  запись с синтетическим ключом — см. §3.

### 2. Где хранится

Отдельный файл `$XDG_DATA_HOME/orbitfm/stats.json` (**схема 1**) рядом с
`library.json` и `settings.json`. Библиотека и её экспорт не меняются.

Файл повреждён или не читается — статистика начинается с нуля, а
существовавший файл остаётся нетронутым до первой успешной записи (тот же
подход, что у `StationLibrary`). Ошибка показаывается тостом; воспроизведение
от неё не зависит.

### 3. Модель данных

Счётчики хранятся по станциям; сводки по странам, тегам и дням считаются при
чтении и в файл не пишутся.

```json
{
  "schema": 1,
  "updated_at": 1762156800,
  "stations": [
    {
      "uuid": "c685c086-b716-4edd-b313-d4a7baf1084c",
      "name": "Radio Swiss Pop",
      "countrycode": "CH",
      "tags": "pop,rock",
      "seconds": 5400,
      "sessions": 12,
      "last_at": 1762150000
    }
  ],
  "days": { "2026-11-03": 1800 }
}
```

- `stations` — не больше `STATION_LIMIT = 500` записей; при переполнении
  выбывает запись с наименьшим `seconds`.
- `name`, `countrycode`, `tags` пишутся при первой встрече станции и
  обновляются, если каталог дал более полные данные; `tags` усекаются до 128
  байт по границе тега, чтобы файл не разрастался.
- `days` — глобальные секунды по локальным датам `YYYY-MM-DD`, не больше
  `DAY_LIMIT = 730` записей; старые даты выбрасываются первыми. Это то, что
  позже даст «карту года» без смены схемы.
- Внешний поток без каталожного UUID: `uuid` = `external:<sha256(.url)[0..16]>`,
  адрес в файл не пишется — только имя из метаданных потока или `url` без
  схемы, если имени нет.

`session` — число запусков станции, а не число секунд: оно позволяет
отличить «слушал фоном один вечер» от «включал десять раз по минуте».

### 4. Когда пишется на диск

Счётчики живут в `Session` и копятся в памяти. На диск идут:

- каждые `FLUSH_SECS = 30` накопленного времени;
- переход из `Playing` в любое другое состояние (пауза, стоп, ошибка);
- смена станции;
- истечение таймера сна, `stats clear`, выключение `stats_enabled`;
- завершение процесса.

Запись атомарная: временный файл + `rename`, как у библиотеки. Пока станция
играет и счётчик не изменился, записи нет.

### 5. Настройка

`settings::stats_enabled: bool` по умолчанию `true` — статистика локальна, как
история, и не отправляется наружу. Значение `false`:

- накопление и запись останавливаются, текущий накопитель сбрасывается;
- существующий `stats.json` не удаляется и не перезаписывается;
- раздел UI показывает ноль и предложение включить учёт.

Старые `settings.json` без поля читаются как `true` (`#[serde(default)]`).

### 6. IPC и CLI

- `stats` — человекочитаемая сводка: суммарное время, топ-5 станций, топ-5
  стран, топ-5 тегов.
- `stats --json` — схема 1: `{ schema, app, version, enabled, total_seconds,
  stations[], countries[], tags[], days }` со всеми подписями, уже
  посчитанными приложением.
- `stats clear` — сбрасывает счётчики (файл становится пустой схемой 1),
  историю и избранное не трогает.
- Команды обслуживают **уже запущенный** экземпляр, как `sleep`: новый
  процесс они не стартуют. Без запущенного экземпляра — ошибка.
- В белый список браузерного native host (ADR-0038) не входят: попапу
  статистика не нужна.
- `status --json` остаётся как есть. Схема не растёт, интеграции не платят
  парсингом за данные, которые не используют.

### 7. Интерфейс

Окно настроек (ADR-0031) получает категорию **«Статистика»** между «Окном» и
«О станции»:

- суммарные минуты и минуты за последние 7 и 30 дней;
- топ-10 станций, топ-10 стран, топ-10 тегов — строки `controls::row` с
  полоской-долей;
- тумблер учёта (`stats_enabled`) и кнопка «Очистить» с подтверждением.

Отрисовка — отдельный модуль `src/ui/stats_view.rs`; `settings_panel.rs`
добавляет вариант перечисления и один вызов, чтобы не раздувать файл.
Подписи категорий и строки раздела входят во все 16 языков и `System` через
`i18n::labels`; ошибки записи используют существующий тост
`NoticeKey::SettingNotSaved`.

### 8. Экспорт

Вне объёма этой реализации. Статистика не попадает в `library-export` схемы 1
и не переносится на Android. Позже — аддитивная схема и только по явному
желанию пользователя (audit §2.5 «export opt-in»), с собственным ADR.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| SQLite-таблица счётчиков | Новая тяжёлая зависимость ради нескольких десятков тысяч пар ключ–секунды |
| Счётчики внутри `library.json` | Смешало бы переносимый контракт ADR-0046 с приватными данными и утащило их в экспорт |
| Запись на диск каждый `tick()` | Ровный износ файлов при нулевой пользе: потеряны будут максимум секунды |
| Только сводки по странам и тегам | Теряется ответ «сколько я слушал эту станцию» и путь к «карте года» |
| Хранить бакеты по дням для каждой станции | 365 × 500 записей против 730 глобальных: файл растёт без продуктовой задачи |
| Телеметрия на сервер ModernByte | Противоречит README §(г) и аудиту; потребовало бы аккаунта и согласия |
| Считать время по `volume != 0` | Нулевая громкость — часто «слушать фоном без помех соседям», а не отказ слушать |

## Последствия

**Положительные:**

- появляются ответы на «что и сколько я слушаю» без сети и аккаунта;
- приватное обещание README сохраняется: адресов запросов статистики не
  существует, код не содержит таких путей;
- библиотека и её схема не затронуты, Android-паритет не сломан;
- `days` закладывает основу «карты года» без смены схемы;
- пользователь видит, где живут его цифры, и может их выключить или стереть.

**Отрицательные / Риски:**

- счётчики не переживают перезапуск процесса в середине эфира: максимум
  теряется `FLUSH_SECS` секунд;
- `days` считается по локальной дате — перевод часов и перелёт через
  полуночь переносят секунды между бакетами;
- статистика не синхронизируется между устройствами и не переживает чистку
  каталога данных — это осознанно;
- станции, переименованные каталогом, сохраняют имя из первой записи до
  обновления метаданных;
- раздел настроек — ещё одна категория: вики и ADR-0031 обязаны быть
  обновлены в том же релизе.
