# ADR-0018: Скрытие окна сжатием до 1×1 на Wayland

**Статус:** Предложено  
**Дата:** 2026-10-23  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

`orbitfm_srs.md` (п. про жизненный цикл окна) и правило AGENTS «Single-instance» требуют:
закрытие окна (кнопка [X], `Super+Q` в композиторе) **не** завершает процесс — окно
скрывается, аудиосессия продолжает играть; полный выход — только отдельный `Quit`.

Текущая реализация (`src/app.rs::logic`, `set_window_visible`) делает
`ViewportCommand::CancelClose` + `ViewportCommand::Visible(false)` + `Minimized(false)`.
На Wayland это не работает:

- winit 0.30.13, бэкенд wayland: `set_visible` — документированный no-op
  («Not possible on Wayland»), `is_visible()` возвращает `None`,
  `set_minimized(false)` игнорируется;
- eframe 0.37 транслирует `egui::ViewportCommand::Visible(v)` прямо в
  `window.set_visible(v)` (`egui-winit-0.37.0/src/lib.rs:2013`), то есть наследует no-op;
- niri 26.04 не предоставляет действия «minimize» вообще, поэтому путь
  «спрятать в минимизированное состояние» недоступен в целевом окружении;
- practically: после «скрытия» окно остаётся в раскладке композитора (занимает
  колонку/плавающий слой) и продолжает перехватывать ввод, будучи полностью
  прозрачным (`App::clear_color` → альфа 0). Пользователь видит «Super+Q ничего
  не делает».

Дополнительно в UI не было явной кнопки закрытия (`src/ui/hud.rs`), только пункт
«Hide window» в попапе шестерёнки.

## Решение

1. **Скрытие = сжатие поверхности до 1×1 px.** `set_window_visible(false)` последовательно
   посылает `ViewportCommand::MinInnerSize([1., 1.])`, затем `ViewportCommand::InnerSize([1., 1.])`,
   затем `ViewportCommand::Visible(false)` — последние два ничего не ломают на Wayland
   и сохраняют корректное поведение на X11/Windows, где `Visible` работает.
   Поверхность и так полностью прозрачна (`clear_color` α = 0), поэтому «окно-в-1-пиксель»
   визуально неотличимо от отсутствия окна и не перехватывает заметный ввод.

2. **Показ = восстановление геометрии.** Перед скрытием в `AppState` запоминается
   `restore_size: Vec2` (фактический размер окна), при показе посылается
   `InnerSize(restore_size)` (по умолчанию `920×660`, как в `ViewportBuilder`),
   затем `MinInnerSize([720., 480.])`, `Visible(true)`, `Focused(true)`.
   Порядок важен: сначала снять нижний лимит, потом задавать размер, иначе запрос
   размера будет отклонён min-size ограничением.

3. **Единая точка для всех источников.** Закрытие по WM-запросу
   (`close_requested` → `CancelClose` + скрытие), IPC `toggle`/`hide`/`show`
   (Noctalia-виджет) и кнопка **×** в HUD вызывают одну и ту же
   `set_window_visible`. Никакой отдельной логики закрытия в UI-модулях не появляется:
   `hud.rs` возвращает `UiAction::Hide`, побочный эффект остаётся в App-оркестраторе
   (ADR-0015, границы `src/ui/`).

4. **Кнопка × = hide, Quit = выход.** В правой части HUD добавляются `×`
   (скрытие окна; подпись «Hide window (audio keeps playing)») и `?` (карточка
   управления). Пункт «Quit» остаётся только в попапе шестерёнки и в трее
   (ADR-0020). В Noctalia-оверлее × не обязателен: повторный клик по виджету
   уже делает `toggle`.

5. **Поведение не зависит от композитора.** Правило окна niri
   (`wm-configs/orbitfm-niri.kdl`: `open-floating`, фиксированные 920×660) не меняется:
   сжатие — рантайм-запрос к уже созданному окну, а не изменение правила.
   Для tiled-состояния композитор может проигнорировать запрос размера — это
   зафиксировано как ограничение, а не как ошибка приложения.

## Проверка на живом окружении (niri 26.04, Wayland)

Механизм из п. 1 **не выполняет своё требование** на целевом окружении — окно
остаётся в раскладке:

- `orbitfm hide` → `niri msg windows` по-прежнему сообщает `Window size: 952 x 1034`,
  колонка не схлопывается, а снимок `grim` показывает пустую живую поверхность,
  которая перехватывает курсор;
- winit 0.30.13 (`platform_impl/linux/wayland/window/mod.rs`): `set_visible` —
  документированный no-op («Not possible on Wayland»), `is_visible()` возвращает
  `None`, `set_minimized(false)` игнорируется («Unminimizing is ignored on Wayland»),
  `request_inner_size` — только клиентская просьба;
- в niri 26.04 нет minimize-действия (`niri msg action --help`), а для tiled-окон
  запрос клиента на изменение размера отбрасывается.

Отсюда следует, что честное «close = hide» на Wayland возможно только через
**уничтожение вьюпорта и пересоздание окна при показе** (строка таблицы
«Альтернативы», ранее отклонённая): `run_native` возвращается по закрытии окна,
процесс с аудио, IPC и MPRIS живёт, показ перезапускает цикл UI. Это меняет
жизненный цикл приложения, поэтому ADR остаётся в статусе «Предложено» до
принятия решения о механизме.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| `ViewportCommand::Visible(false)` как единственное средство | На Wayland no-op (winit), окно остаётся в раскладке и ловит ввод |
| `Minimized(true)` | В niri нет minimize-действия; winit wayland игнорирует `set_minimized(false)`, состояние не восстановить |
| Уничтожение вьюпорта и пересоздание окна при показе | Теряются wgpu-ресурсы глобуса и состояние камеры, пересоздание surface на Wayland — заметно более тяжёлая и менее надёжная операция |
| Реальные decorations + системная кнопка закрытия | Конфликтует с безрамочным оверлей-дизайном «Orbit Desk» и с `with_decorations(false)` в overlay-режиме |
| Закрытие = завершение процесса | Прямо противоречит SRS и правилу «Single-instance»: радио не должно умирать от [X] |
| Перемещение окна за пределы экрана (`Position`) | Композиторы (niri) нормализуют позицию плавающих окон; «призрак» в раскладке остаётся |

## Последствия

**Положительные:**

- `Super+Q`, × и IPC `toggle` ведут себя как обещано SRS: окно исчезает, процесс
  и воспроизведение продолжают жить (на композиторах, уважающих запрос размера:
  X11, Windows, плавающие окна niri);
- одно поведение на X11/Wayland/Windows без платформенных веток в UI-коде;
- никаких новых зависимостей и никаких изменений в протоколе IPC;
- размер окна восстанавливается точно (в т.ч. если пользователь его изменил до скрытия).

**Отрицательные / Риски:**

- «скрытое» окно формально существует (1×1), то есть остаётся в списке окон композитора;
  в niri это видно в `niri windows`, но не занимает места в раскладке;
- если композитор проигнорирует запрос размера (например, окно в tiled-состоянии),
  скрытие не уберёт окно из раскладки — **подтверждено live-проверкой на niri**,
  см. раздел «Проверка на живом окружении»;
- 1×1 поверхность всё ещё аллоцирует буферы обмена; размер минимален, но не нулевой.
