# ADR-0019: Синтетический аудиовизуализатор (24 столбца-огибающая)

**Статус:** Принято  
**Дата:** 2026-10-23  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

`docs/ui/visual-spec.md` §3.3 требует заменить текущий FFT-оверлей на cava-like
набор вертикальных столбцов (16 / 24 / 32, рекомендуемый default 24) с внутренним
градиентом по высоте: снизу салатовый, в середине жёлто-оранжевый, сверху красный.
Текущая реализация (ADR-0010) рисует один горизонтальный «strip» на 96 точек поверх
глобуса (`SpectrumOverlay::paint`, `src/render/spectrum.rs:78-156`) плюс
псевдо-полосы из пяти значений в транспорт-панели (`spectrum_levels`,
`src/ui/transport.rs:227-237`).

Ограничение ADR-0010 остаётся в силе и проверено: mpv 2.5 (libmpv2 6.0) не даёт
клиентского PCM-колбэка, `ao=pcm` заменяет вывод, `af`-фильтры отдают только
**агрегированные** метрики. `SpectrumFrame` (`src/audio/mod.rs:44-62`) несёт шесть
скаляров: `centroid_hz`, `spread_hz`, `rolloff_hz`, `flatness` (0..1), `flux`
(сырое значение FFmpeg), `rms_db`. Бинного спектра в данных нет, поэтому «настоящие»
полосы по бинам возможны только через PCM-tap и новый ADR.

## Решение

1. **Полосы-огибающая, а не спектр по бинам.** Новые столбцы вычисляются из тех же
   шести агрегатов: гауссова огибающая в лог-шкале частот с центром в `centroid_hz` и
   шириной от `spread_hz`, общий уровень от `rms_db` (нормализация в существующих
   константах `MIN_RMS_DB = -60`, `RMS_RANGE_DB = 60`), «живость» и детализация от
   `flux` и `flatness`. Формулировка в UI и документации — «оценка спектральной
   огибающей», не «FFT-спектр».

2. **Новый модельный модуль `src/render/visualizer.rs`.** `VisualizerModel` хранит
   `levels: Box<[f32]>` и `peaks: Box<[f32]>` фиксированной длины (аллокация только в
   `new`), методы `band_targets(&SpectrumFrame, bars) -> Box<[f32]>` и
   `advance(&mut self, targets: &[f32], dt: f32)`. Сглаживание асимметричное:
   attack ~30 мс, decay 80–150 мс (peak-hold с плавным спадом). При `frame == None`
   или состоянии, отличном от Playing, — idle «дыхание» 2–3 px, а не нулевая линия.
   Модель не знает ни про egui, ни про аудио-движок: вход — `Option<&SpectrumFrame>` и
   `dt`, выход — `&[f32]` уровней 0..1.

3. **Количество столбцов настраивается.** `Settings::viz_bars` ∈ {16, 24, 32},
   default 24; enum `Copy` с `#[serde(default)]`, старые конфиги остаются валидными.
   Выбор — в попапе шестерёнки HUD.

4. **Отрисовка — в транспорт-панели, справа.** Старый strip над глобусом удаляется
   вместе с `SpectrumOverlay::paint` и 96-точечной огибающей; `update` и `pulse`
   **сохраняются**, потому что питают Fresnel-обод глобуса (ADR-0015, Фаза 5).
   `src/ui/widgets.rs::viz_bars` рисует столбцы высотой ~40–56 px; градиент внутри
   каждого столбца — три опорные зоны §3.3 ТЗ (`#22C55E/#4ADE80` → `#FBBF24/#FB923C`
   → `#EF4444/#F87171`). В egui 0.37 `LinearGradient` применим только к штрихам,
   поэтому столбец собирается из 6–8 тонких горизонтальных сегментов с интерполяцией
   цвета (чистая функция `bar_gradient_stops()` + тест). Псевдо-полосы
   `spectrum_levels`/`draw_mini_spectrum` и чип «FFT» из `src/ui/transport.rs`
   удаляются, переключатель остаётся один — «Visualizer» (`UiAction::ToggleSpectrum`).

5. **Такты без изменений.** Опрос метрик ~50 мс (`SPECTRUM_POLL_INTERVAL`) и repaint
   ~33 мс при видимом визуализаторе (`src/app.rs::logic`) сохраняются; новых потоков
   и новых зависимостей нет.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| PCM-tap и настоящий бинный FFT (cava-like) | Требует перехвата PCM, которого нет в libmpv 2.5 (ADR-0010); отдельный ADR и пересмотр ADR-0003 — отложено в ROADMAP |
| Оставить старый 96-точечный strip, перекрасив градиент | Не соответствует §3.3 (дискретные столбцы, количество настраивается) и перекрывает глобус |
| `showspectrum` из libavfilter + показ как изображения | Нет доступа к кадрам без видео-конвейера и VO (отклонено ещё ADR-0010) |
| Рендер баров на wgpu-пассе | Избыточно для 24 примитивов; ломает правило «оверлеи рисуются через egui::Painter» (ADR-0002, orbitfm-gui) |
| Анимация, не зависящая от данных (случайные бары) | Прямо противоречит правилу «ничего не выдумывать» и обманывает пользователя о звуке |

## Последствия

**Положительные:**

- UI достигает ТЗ `docs/ui/visual-spec.md` §3.3: дискретные столбцы с вертикальным
  green→yellow→red градиентом, в правой части нижней панели, рядом с громкостью;
- глобус освобождается от технического strip, доминанта сцены не размывается;
- ноль новых зависимостей, ноль изменений в аудио-тракте и в IPC-протоколе;
- модель вынесена в чистый модуль и покрыта тестами (монотонность по RMS, порядок по
  частоте, конечность, idle-диапазон, отсутствие аллокаций на кадр);
- количество столбцов доступно пользователю, а не зашито.

**Отрицательные / Риски:**

- столбцы — **оценка огибающей**: две станции с одинаковым centroid/RMS дадут похожую
  картину, различить гармонику внутри полосы невозможно; это честным образом
  зафиксировано в подписи переключателя и в этом ADR;
- `flatness` и `flux` — агрегаты, их влияние на «детализацию» эмпирическое, параметры
  сглаживания (30 мс attack / 80–150 мс decay) подбираются live-проверкой;
- при выключенном визуализаторе Fresnel-обод глобуса продолжает работать по
  сглаженным `level`/`flux`, то есть удаляемый код не был единственным потребителем
  `SpectrumFrame`.
