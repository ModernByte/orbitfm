# ADR-0066: Порядок загрузки каталога

**Статус:** Принято 2026-11-13  
**Дата:** 2026-11-13  
**Участники решения:** ModernByte Architecture, владелец продукта  

## Контекст

Владелец (2026-11-13): при выборе страны первую пачку станций брать **по
рейтингу**, остальное — по требованию, а порядок загрузки (рейтинг / качество /
стиль / жанр / музыкальные или разговорные) продумать и, возможно, вынести в
настройки.

Что есть сейчас:

- `RadioBrowserClient::search` **всегда** передаёт `order=votes&reverse=true`
  (`src/services/radio_browser.rs`, интерфейс 02). Выбор порядка недоступен.
- Панель умеет **локально** сортировать загруженные строки
  (`station_filter::StationSort`: Popularity / Bitrate / Name), но выбор не
  переживает перезапуск и не влияет на то, что каталог отдаёт первым: пока
  пользователь не включит сортировку Bitrate вручную, первая страница всё равно
  «по рейтингу».
- Порядок `order` в Radio Browser ограничен официальным списком (проверено по
  документации `/json/stations/search`): `name`, `url`, `homepage`, `favicon`,
  `tags`, `country`, `state`, `language`, `votes`, `codec`, `bitrate`,
  `lastcheckok`, `lastchecktime`, `clicktimestamp`, `clickcount`, `clicktrend`,
  `changetimestamp`, `random`. Сортировки по «стилю» и «контенту» в API нет.

Ограничения: Linux First, официальный API, локализация на всех языках
(ADR-0030), профиль сети `Metered` режет битрейт (ADR-0048).

## Решение

### 1. `CatalogOrder` — единая настройка порядка

Вводится `CatalogOrder` (в `src/settings`), сериализуется `kebab-case`,
аддитивно к схеме `settings.json`:

| Вариант | `order` Radio Browser | Подпись UI |
|---|---|---|
| `Rating` (`#[default]`) | `votes` | По рейтингу |
| `Popularity` | `clickcount` | По популярности |
| `Trend` | `clicktrend` | По тренду |
| `Quality` | `bitrate` | По качеству |
| `Name` | `name` | По имени |
| `Random` | `random` | Случайно |

Всегда добавляется `reverse=true` (кроме `random`, где порядок не определён).
`Quality` по `reverse=true` означает «выше битрейт — выше в списке».

### 2. Одна точка правды: список, карта и веер

- `settings.catalog_order` применяется к запросу **списка** и к слою **карты**
  (ADR-0065) — то есть «первая пачка списка» и «первые маркеры» согласованы.
- Локальный `StationSort` панели **сливается** с `CatalogOrder`: контрол в
  панели и настройка меняют одно и то же поле. Отдельной второй сортировки не
  остаётся.
- Смена порядка **перезапускает контекстный запрос с `offset = 0`** и слой
  карты, иначе уже загруженные страницы упорядочены по старому порядку, и
  «первая пачка» перестаёт быть первой.
- Кластер веера (ADR-0065 § 3) тоже читает `CatalogOrder` для порядка станций.

### 3. Случайный порядок отключает пагинацию

`Random` не даёт стабильной выдачи при смене `offset`: сервер вернёт другой
набор. Поэтому после первой страницы `has_more = false`, кнопка «Загрузить ещё»
скрыта, подпись — «N случайных». Выборка живёт до явного обновления (повторный
выбор страны / смена режима).

### 4. Жанр и стиль — фильтр, а не порядок

Radio Browser не сортирует по тегам. «По стилю / жанру» остаётся **фильтром**:
`tag` на сервере или локальный предикат панели (жанровые чипы); при
необходимости тем же предикатом сужается слой карты. В UI жанр **не**
подписывается как пункт `CatalogOrder`.

### 5. «Музыкальные / разговорные» — вне объёма

У Radio Browser **нет признака контента** (проверено по документации
`/json/stations/search`): разделение возможно только эвристикой по тегам
(`talk`, `news`, `speech`, `podcast`, `audiobook` против музыкальных), которая
будет врать (`music+news`, «talk radio» без тега `talk`). Это откладывается
отдельным решением с явной пометкой «приблизительно» и не блокирует ни слой
карты, ни кластеры, ни порядок загрузки.

### 6. Где живёт настройка

Категория «Каталог» в окне настроек (девятая): порядок загрузки и — при
необходимости — размер первой страницы. Локальный контрол сортировки в панели
остаётся как быстрый доступ к тому же полю.

## Последствия

**Положительные:**

- Первая пачка списка и первые маркеры соответствуют выбранному порядку;
- выбор переживает перезапуск (единая настройка вместо локального состояния
  панели);
- «по рейтингу по умолчанию» сохраняет сегодняшнее поведение;
- честная семантика: жанр — фильтр, контент — не выдумываем.

**Отрицательные / риски:**

- Смена порядка стоит нового сетевого запроса (сброс на `offset = 0`);
- `Random` ломает привычную пагинацию — объясняется подписью;
- `Quality` на профиле `Metered` ограничен сверху `bitrateMax` (ADR-0048):
  «качество» там означает «до потолка профиля»;
- новая категория настроек и строки на 16 языках (ADR-0030);
- `clicktrend`/`clickcount` зависят от данных Radio Browser и могут быть
  шумными — это данные каталога, а не ошибка клиента.

## Альтернативы

| Вариант | Причина отклонения |
|---|---|
| Оставить локальную сортировку панели без сервера | «Первая пачка» не управляется: каталог всё равно отдаёт `order=votes` |
| Сортировать «по стилю/жанру» | Order по тегу не существует в API; это фильтр |
| Разделять music/talk по тегам | Признака контента нет; эвристика вводит в заблуждение без явной пометки |
| Не персистить порядок | Владелец просил настройку; локальное состояние не переживает запуск |
| Отдельный порядок для карты и списка | Два источника правды, «первые маркеры» и «первая пачка» разъедутся |
