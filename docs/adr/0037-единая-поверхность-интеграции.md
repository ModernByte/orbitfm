# ADR-0037: Единая поверхность интеграции — JSON-статус, CLI-команды и установщик

**Статус:** Принято (2026-10-28, ред. 2026-10-31) — добавлен поток событий
`events` (ADR-0039) к единой поверхности интеграции  
**Дата:** 2026-10-28  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Интеграций с окружением становится много: плагин Noctalia v5 (ADR-0007,
ADR-0033), трей SNI на Linux (ADR-0020), меню-бар macOS (ADR-0026), а по плану —
плазмоид KDE Plasma 6, расширение GNOME Shell, плагин Omarchy/Quickshell,
виджеты Waybar/Polybar/i3blocks/swaybar/i3status-rust, сниппеты XFCE/Cinnamon/
MATE/LXQt и расширения Chromium/Firefox. Все они решают одну задачу: показать
«сейчас играет» и дать кнопки play/pause, next/previous, рулетку, громкость,
тему, панель и настройки.

Сегодня каждая интеграция вынуждена либо разбирать текстовый `status`,
рассчитанный на человека, либо дублировать каталог подписей на 11 языках
(`src/i18n/catalog.rs`), либо дёргать окно через `toggle` — состояние «что
открыто» при этом живёт в плагине, а не в Application Core. Текстовый формат
хрупок: у него нет ни версии, ни обязательства совместимости.

Одновременно действуют жёсткие ограничения:

- приложение остаётся одним GUI-процессом и одним экземпляром (ADR-0005):
  плагины и расширения — клиенты CLI/IPC, а не второй GUI;
- релиз состоит ровно из трёх артефактов (AppImage, MSI, DMG) плюс
  `SHA256SUMS`; прикладывать zip с плагинами к релизу нельзя;
- бар-виджеты живут в чужих конфигурациях: установщик не имеет права править
  Waybar/Polybar/i3/Quickshell-конфиги молча;
- на macOS `status` обязан отражать `mark_hidden`, а не только закрытие
  root-вьюпорта (ADR-0026);
- новые интеграции не добавляют сетевых запросов и не трогают Radio Browser.

## Решение

1. **Машиночитаемый статус — `status --json` (схема 1).** Новый IPC-глагол
   `StatusJson` возвращает одну строку компактного JSON:

   ```json
   {
     "schema": 1,
     "app": "orbitfm",
     "version": "0.13.0-rc.1",
     "state": "playing",
     "station": {
       "uuid": "…", "name": "…", "country": "…", "countrycode": "de",
       "tags": "…", "favicon": "https://…", "homepage": "https://…",
       "bitrate": 128, "codec": "MP3"
     },
     "volume": 0.42,
     "window": { "visible": true, "mode": "focus" },
     "theme": "dark",
     "language": "ru",
     "can": { "previous": true, "next": true },
     "ui": {
       "play_pause": "Пуск/Пауза", "stop": "Стоп", "previous": "Предыдущая",
       "next": "Следующая", "radio_roulette": "Радиорулетка",
       "settings": "Настройки", "show_window": "Показать окно",
       "hide_window": "Скрыть окно", "nothing_playing": "Ничего не играет",
       "volume_up": "Громче", "volume_down": "Тише"
     }
   }
   ```

   `state` использует существующий `PlaybackState::as_str`; `station` равен
   `null` для `stopped`/`error`; `window.visible` на macOS отражает
   `mark_hidden`; `can` описывает доступность skip-команд; `ui` — подписи из
   `i18n::catalog` (`TrayText`), чтобы QML/JS не дублировали каталог.
   Текстовый `status` остаётся байт-в-байт прежним для человека и скриптов.

2. **Правило совместимости.** `schema` растёт только при удалении или
   переименовании полей; добавление полей схему не меняет. Клиенты обязаны
   игнорировать неизвестные поля и не падать на `station: null`, пустом
   `ui`-поле и незнакомом `state`.

3. **Новые команды — тот же Application Core, никакой второй логики.** IPC
   получает глаголы `playpause`, `next`, `previous`, `roulette`,
   `volume-up`, `volume-down`, `theme <system|dark|light>`, `settings` и
   `status --json`. Все они вызывают существующие методы `Session`
   (`toggle_playback`, `play_relative`, `start_roulette`, `nudge_volume`,
   `set_theme`, `open_settings`) и используют тот же IPC-сервер, сокет и
   single-instance (ADR-0005). `theme` разбирается wire-типом `ThemeArg`, в
   доменный `ThemeMode` его переводит Core — направление зависимости
   Core → инфраструктура сохраняется.

4. **Cold-start разрешён не всем командам.** Экземпляр запускают только
   `toggle`, `show`, `panel`, `overlay`, `mode <режим>` и `settings` — это
   действия, которые обязаны показать окно. Команды управления
   (`playpause`, `next`, `previous`, `roulette`, `volume-up`, `volume-down`,
   `theme`, `stop`, `volume`, `hide`, `status`, `status --json`) при
   незапущенном приложении возвращают `OrbitFM не запущен` и код 1:
   бар-виджет или расширение браузера не должны поднимать GUI-процесс ради
   переключения трека.

5. **Установщик интеграций — часть бинарника, а не релизного архива.**
   `orbitfm integration status|install|uninstall <target> [--force]` ставит
   QML/JS/скрипты из каталога `integrations/<target>/`, встроенного в бинарник
   через `include_str!`/`include_bytes!`. Установка идёт в пользовательские
   каталоги без root; каждая установка пишет квитанцию
   `$XDG_DATA_HOME/orbitfm/integrations/<target>.json` со списком файлов и
   признаком `asset|generated`. `uninstall` удаляет только файлы из квитанции;
   изменённый пользователем файл без `--force` не удаляется. Установщик
   никогда не правит чужие конфиги: он печатает готовый сниппет и точный путь
   скрипта. `integration install all` ставит применимые для текущей ОС пакеты,
   но не включает виджеты в оболочках автоматически.

6. **Три релизных артефакта сохраняются.** Ассеты интеграций встраиваются в
   бинарник; zip расширений и отдельные пакеты плагинов к релизу не
   прикладываются. Установщик — единственная точка материализации ассетов на
   диске пользователя.

7. **Браузеры — отдельное решение.** Native messaging, allowlist и модели
   угроз для расширений Chromium/Firefox фиксирует ADR-0038; этот ADR задаёт
   только общую поверхность (JSON-статус, команды, установщик), которой
   расширения пользуются через CLI или stdio-помощника.

8. **Поток событий — та же поверхность (ред. 2026-10-31).** Опрос
   `status --json` остаётся, но интеграциям, которым нужна реакция на смену
   трека, паузу или громкость, добавляется подписка `events` по тому же
   IPC-сокету (ADR-0039). Первый кадр — `snapshot`, далее полные кадры
   `state`, на простое — `keepalive`; конверт NDJSON версионируется полем
   `ev`, а `status` внутри — той же схемой 1. `events` не поднимает GUI и не
   входит в cold-start allowlist; подписки ограничены отдельным бюджетом,
   чтобы не вытеснять управляющие команды. Контракт зафиксирован в
   `docs/interfaces/13-events.md`.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Локальный HTTP/WebSocket-сервер для плагинов | Новый сетевой вход, порт, CORS и вопросы авторизации; нарушает «один сокет, один экземпляр» и увеличивает поверхность атаки |
| D-Bus API | На macOS и Windows D-Bus нет; пришлось бы держать два контракта. IPC уже кроссплатформен |
| Плагины разбирают текстовый `status` | Нет версии и обязательств совместимости; подписи и станции с переводами строк ломают разбор |
| Дублировать каталог подписей в каждом плагине | 11 языков × N интеграций; рассинхронизация гарантирована |
| Отдавать плагинам готовые HTML/форматированные строки | Привязывает вид оболочки к приложению; каждая оболочка рисует по-своему |
| Прикладывать zip плагинов к релизу | Нарушает правило трёх артефактов; zip распаковывают вручную и версии расходятся |
| Установщик правит конфиги баров | Чужие конфиги — зона пользователя; ошибка установщика ломает рабочий стол |

## Последствия

**Положительные:**

- у всех интеграций один стабильный контракт: JSON со схемой, локализованные
  подписи, явные `can`-флаги;
- плагины перестают хранить состояние «что открыто»: `panel`/`overlay`/`mode`
  идемпотентны и живут в Core (ADR-0033);
- команды управления не поднимают GUI — бар-виджет при закрытом приложении
  показывает «не запущено», а не запускает процесс;
- установщик покрыт квитанциями и `--force`, не требует root и не трогает
  конфиги оболочек;
- релиз остаётся тремя артефактами.

**Отрицательные / Риски:**

- JSON-схема — новый публичный контракт: любое переименование теперь требует
  `schema: 2` и синхронного обновления всех интеграций;
- `ui`-подписи фиксируют набор строк трея как публичный API; новые языки
  обязаны заполнять все поля `TrayText`;
- установщик живёт в бинарнике и обязан быть идемпотентным; ошибки в путях
  XDG/macOS ломают `integration status`;
- встроенные ассеты увеличивают размер бинарника (текст QML/JS невелик,
  единственный бинарный ассет — PNG-значок расширения);
- интеграции, не покрытые CI (Plasma, GNOME, Omarchy), проверяются только
  сборкой и ручной матрицей;
- `settings` и `panel` в cold-start показывают окно — это осознанное
  исключение из правила «управление не запускает GUI».

## Реализация

- 0.13.0-rc.1: `IpcCommand::{StatusJson, PlayPause, Next, Previous, Roulette,
  Theme, Settings, VolumeUp, VolumeDown}`, `ThemeArg`, `Session::status_json`
  (`STATUS_SCHEMA = 1`), локализованный `StatusUi` из `i18n::catalog`;
  текстовый `format_status` не изменён. Cold-start allowlist — в
  `src/main.rs`.
- 0.14.0-rc.1: `orbitfm events` и `StatusFeed` (ADR-0039,
  `docs/interfaces/13-events.md`), `src/integration/` — `Target`,
  `install`/`uninstall`/`status`, квитанции, `--force`,
  `ORBITFM_INTEGRATION_ROOT` для тестов; ассеты Plasma 6, GNOME 45–51,
  Omarchy, Quickshell, Waybar, Polybar, i3blocks, swaybar, i3status-rust и
  generic-сниппетов.
- 0.15.0-rc.1: расширения браузеров и native messaging — ADR-0038, интерфейс
  14, модуль 17; цели `chrome`/`firefox` в том же установщике, живая приёмка
  Chrome for Testing и Firefox 2026-10-31.
