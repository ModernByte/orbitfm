# ADR-0009: Каталог паттернов проектирования

**Статус:** Принято  
**Дата:** 2026-10-22  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Без явного списка допустимых паттернов агенты и разработчики склонны либо изобретать тяжёлые enterprise-решения, либо писать связный код без понятных границ. Нужен единый справочник, привязанный к модулям OrbitFM.

## Решение

1. Вести каталог в `docs/patterns/00-overview.md`.
2. Скилл `orbitfm-patterns` обязателен при проектировании и рефакторинге структуры кода.
3. Новые повторяющиеся структурные решения добавляются в каталог только после ADR (или обновления этого ADR / нового ADR).
4. Запрещены без отдельного ADR: Event Sourcing, DI-контейнеры, тяжёлый Unit of Work, глобальные singleton-кучи.

## Последствия

**Положительные:**
- Единый язык для команды и агентов
- Меньше случайной сложности
- Явная связь паттерн ↔ модуль ↔ interface

**Отрицательные:**
- Каталог нужно поддерживать при эволюции архитектуры
