# ADR-0047: TUI на ratatui — терминальный IPC-клиент

**Статус:** Принято (2026-11-03); ревизия 2 — визуализаторы, компоновки и
`spectrum`-кадры; реализация не начата  
**Дата:** 2026-11-03  
**Участники решения:** ModernByte Architecture

## Контекст

Desktop OrbitFM закрывает визуальный сценарий: 3D-глобус, Orbital Desk,
стекло и motion. Android Companion (ADR-0045) закрывает карман. Между ними
остаётся устойчивая ниша терминала:

- SSH на домашний box, VPS или машину без рабочего стола;
- tmux/screen рядом с другими terminal-native инструментами;
- минимальный WM, tty и recovery-сценарии;
- слабый GPU или удалённый X11, где wgpu избыточен;
- сценарии «скрипт + человек», где CLI уже есть, но нужен обозреватель станций.

К 0.18.0-rc.1 у desktop уже есть почти всё, что нужно такому клиенту:
single-instance IPC (ADR-0005), поток `events` с `snapshot`/`state`/`search`
(ADR-0039), companion-команды `search`, `library`, `favorite`, `play-result`,
`play-library`, ритуалы `next`/`previous`/`sleep` (ADR-0046) и переносимая
библиотека схемы 1 (ADR-0046, интерфейс 15).

Аудит `docs/audit/OrbitFM-tui-ratatui.md` предлагает отдельный TUI на
ratatui и два варианта: remote control к существующему ядру или standalone
плеер. Нужно выбрать архитектуру до написания кода и не нарушить инварианты
проекта: один процесс с аудио, один источник библиотеки, никакого второго
libmpv и MPRIS-агента.

## Решение

### 1. Роль продукта

`orbitfm-tui` — **терминальный клиент к уже работающему ядру**, а не второй
плеер. Он показывает состояние эфира, ищет станции, управляет избранным и
историей и отправляет команды через публичный IPC-контракт. Аудио, MPRIS,
трей, каталог Radio Browser и `library.json` остаются за `orbitfm`.

TUI не заменяет Orbital Desk и не подменяет Android-приоритет. Это
parallel track для terminal-native аудитории.

### 2. Границы и размещение

- Отдельный бинарник `orbitfm-tui` и отдельный crate
  `crates/orbitfm-tui/` в Cargo workspace. Корневой пакет `orbitfm`
  остаётся desktop-приложением и не получает зависимость на ratatui.
- TUI не содержит аудио-движка, не создаёт MPRIS-агента, не открывает
  сетевой сервер и не читает `library.json` напрямую.
- TUI не вызывает Radio Browser и не дублирует SSRF/User-Agent политику:
  поиск идёт через `search` ядра, результаты приходят кадром `search`.
- TUI не импортирует `file://`, не скачивает favicon и не открывает
  homepage. В v1 команда `play-url` в TUI не выставляется.

### 3. Адаптер ядра

Между UI и IPC вводится граница `CoreClient`. UI не знает, как именно
доставляется команда.

Версия v1 — `CliCoreClient`:

- долгоживущий дочерний процесс `orbitfm events` читает NDJSON-поток;
- каждая команда — отдельный запуск установленного `orbitfm` с аргументами;
- путь к бинарнику берётся из `ORBITFM_BIN`, иначе ищется `orbitfm` в `PATH`;
- stdout/stderr дочерних процессов перехватываются, чтобы не ломать кадр TUI;
- команды выполняются в отдельном worker-потоке, поэтому медленный `play`
  с резолвом каталога не блокирует ввод и перерисовку.

Прямой клиент Unix-сокета/named pipe — будущая реализация того же
`CoreClient`, если появится общий library-крейт IPC. Дублировать выбор пути
сокета, проверку каталога, framing и таймауты в TUI v1 запрещено: CLI уже
является публичным контрактом.

### 4. MVP

Экраны: **Now Playing**, **Search**, **Favorites**, **History**, **Help**.
Поверх них — строка статуса, подтверждение `Q` и ввод таймера сна.
Визуализатор — отдельный модуль любого экрана (см. §9), а не шестой экран.

Клавиши v1 — vim-friendly:

| Клавиша | Действие |
|---------|----------|
| `j`/`k`, `↓`/`↑` | перемещение по списку |
| `g`/`G` | начало/конец списка |
| `Enter` | играть выбранную станцию |
| `p`/`Space` | play/pause |
| `s` | stop |
| `[`/`]` | previous/next |
| `r` | радиорулетка |
| `+`/`-` | громкость шагом протокола |
| `/` | поиск |
| `f` | экран избранного |
| `h` | экран истории |
| `a` | переключить избранное выбранной станции |
| `t` | задать таймер сна, `T` — снять |
| `v` | следующий визуализатор |
| `V` | визуализатор вкл/выкл |
| `l` | следующий пресет компоновки |
| `m` | менеджер модулей и пресетов |
| `M` | motion: full → reduced → off |
| `Ctrl+R` | сброс компоновки к `desk` |
| `?` | помощь |
| `q` | выйти из TUI, эфир продолжает играть |
| `Q` | подтвердить и выполнить `quit` ядра |
| `R` | переподключиться к ядру |

`q` никогда не останавливает эфир. `Q` показывает подтверждение и только
после `y` отправляет `orbitfm quit`; при ошибке TUI остаётся открытым и
показывает причину.

### 5. Данные

- Состояние — только из `events`: первый `snapshot`, затем полные `state`;
  `keepalive` считается признаком жизни, `search` коррелируется по `id`.
- Избранное и история — команда `library`. Ответ ограничен 20 записями на
  список; это осознанный потолок companion-контракта. Полный список
  избранного в v1 не показывается; расширение протокола (пагинация или
  `library --all`) — отдельное аддитивное решение, а не чтение файла.
- Запуск из выдачи — `play-result <uuid>`; если ядро уже заменило последнюю
  выдачу чужим поиском, TUI повторяет попытку через `play <uuid>`.
- Запуск из избранного/истории — `play-library <uuid>` без обращения к
  каталогу.
- Избранное — `favorite <uuid>`; ответ `favorite true|false` обновляет
  индикатор. После изменения списки перезапрашиваются.
- Таймер сна — `sleep <1..=720>` и `sleep clear`; остаток берётся из
  `status.sleep`, обратный отсчёт рисуется локально между кадрами.
- Переподключение после EOF — с backoff 1/2/4/… до 30 с, с новым `snapshot`.
  Во время разрыва TUI показывает баннер и не притворяется, что эфир жив.
- Кадры `spectrum` — только по опциональной подписке
  `events --spectrum` (§9.3). Без них визуализатор работает в procedural-
  режиме и явно сообщает об этом в статусе.

### 6. Headless-ядро

TUI v1 требует уже запущенный `orbitfm`. `events` не входит в cold-start
allowlist и не поднимает GUI; TUI тоже не запускает ядро, потому что
`orbitfm` стартует через `run_window` и требует дисплея.

Для сценария «чистый SSH без графической сессии» нужен отдельный трек
**headless core** (`--headless` или `ORBITFM_HEADLESS=1`: IPC + audio без
egui-окна). Это изменение жизненного цикла процесса, а не деталь TUI,
поэтому оно проектируется отдельным ADR и не входит в TUI v1. До него TUI
честно полезен в tmux на машине с уже работающим desktop-ядром.

### 7. Безопасность

- Только локальный пользователь: TUI использует тот же сокет/pipe, что CLI.
- Аргументы передаются в `Command` без shell; никакой интерполяции строк.
- Все строки от ядра перед выводом в терминал проходят локальную очистку
  C0/C1/DEL/ESC и bidi-переопределений, даже если ядро уже санитизировало
  их. Это защита от terminal escape injection на последнем рубеже.
- Запрос поиска ограничен 128 символами, как в IPC.
- TUI не слушает сеть, не ходит в каталог и не читает файлы библиотеки.
- `Q` требует явного подтверждения; `q` и Ctrl-C завершают только TUI.

### 8. Поставка и совместимость

- TUI распространяется как исходная сборка
  (`cargo install --path crates/orbitfm-tui`); пятый релизный артефакт не
  добавляется без отдельного решения владельца.
- Версия TUI независима (`0.1.0`), совместимость определяется конвертом
  `ev: 1` и `status.schema: 1`. Целевое ядро — `>= 0.18.0-rc.1`.
- Неизвестные поля и типы кадров игнорируются; `schema`/`ev` другой версии
  или чужой `app` — понятная ошибка совместимости без частичного управления.
- `sleep` при отсутствии поля/команды скрывается, остальные экраны работают.
- TUI v1 — английские служебные подписи; строки `status.ui` не смешиваются
  с ними. Локализация TUI — отдельный этап после стабилизации UX.

### 9. Визуализаторы и компоновки

#### 9.1. Визуализаторы — часть TUI v1

TUI обязан иметь аудиовизуализаторы, а не только списки. Проектируются шесть
режимов; v1 реализует четыре, остальные — T6:

| id | Название | Полотно | Идея |
|----|----------|---------|------|
| `bars` | Orbital Bars | half blocks | гравитация, peak-hold и синтетическая огибающая desktop-визуализатора |
| `ring` | Orbit Ring | Braille/точки | полярное кольцо: bass — радиус, mid — вращение, high — мерцание |
| `scope` | Braille Scope | Braille 2×4 | осциллограмма/Lissajous: level — амплитуда, centroid — частота |
| `pulse` | Core Pulse | block gauge | минимальный индикатор для узкого экрана и `motion=off` |
| `stars` | Signal Constellation | Braille/точки | звёздное поле, flux — варп; T6 |
| `heat` | Spectrogram Heat | half blocks | спектрограмма во времени; T6 |

Отрисовка подчиняется общим правилам:

- 16-цветный fallback, `NO_COLOR`, `glyphs = "unicode" | "ascii"`;
- тик ≤ 15 FPS, `motion = full | reduced | off`; скрытый модуль не тикает;
- запрет полнокадровых инверсий и вспышек чаще 3 Hz;
- высота сцены < 3 строк — визуализатор скрывается;
- эфир остановлен — медленное «дыхание», ошибка — статичный `!`.

#### 9.2. Компоновки и модули

Пресеты: `desk` (default), `focus`, `library`, `minimal`, `dashboard`.
Адаптивность: `< 80` колонок — одна зона, `80–119` — две, `≥ 120` —
`dashboard`; минимум 60×18.

Модули `now_playing`, `visualizer`, `search`, `results`, `favorites`,
`history`, `status`, `help` включаются независимо. Управление: `v`/`V` —
визуализатор, `l` — пресет, `m` — менеджер модулей, `M` — motion,
`Ctrl+R` — сброс. Настройки хранятся в
`$XDG_CONFIG_HOME/orbitfm/tui.toml` (fallback `~/.config`), пишутся
атомарно с debounce 500 мс. Конфиг TUI не пересекается с настройками core
и не читает `library.json`.

#### 9.3. `spectrum`-кадры

Reactive-визуализаторы используют опциональную подписку
`orbitfm events --spectrum`. Кадр аддитивен к `ev: 1`:

```json
{"ev":1,"type":"spectrum","seq":42,"level":0.63,
 "centroid_hz":1720.0,"spread_hz":1600.0,"flatness":0.42,
 "flux":0.0018,"bands":{"bass":0.70,"mid":0.55,"high":0.30}}
```

- Только при `playing`, не чаще 30 Hz, latest-wins, без очереди;
  `keepalive` не сбрасывается.
- Подписчик без флага кадров не получает; поведение `events` по умолчанию
  не меняется.
- Ядро уже вычисляет `SpectrumFrame` (ADR-0010/0019); публикация не меняет
  FFT-граф, аудио-поток и не создаёт второй движок.
- Флаг появляется в ядре позже 0.18.0-rc.1. До этого TUI работает в
  procedural и пишет `visualizer: procedural`; выдавать локальную анимацию
  за реальный спектр запрещено.
- Неизвестные типы кадров и поля игнорируются; `ev` другой версии —
  ошибка совместимости.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| TUI как feature в бинарнике `orbitfm` | Тянет ratatui/crossterm в desktop-сборку, усложняет запуск и терминальный lifecycle; отдельный бинарь чище |
| Standalone-плеер со своим libmpv | Второй аудио-движок, второй MPRIS-агент, расхождение библиотеки и устройств вывода |
| Прямой клиент сокета в v1 | Требует library-крейта или дублирования выбора пути, framing и таймаутов; CLI уже стабильный контракт |
| Клиентский Radio Browser в TUI | Дублирует discovery, User-Agent и SSRF-политику; расходятся результаты поиска |
| Чтение `library.json` напрямую | Файл не публичный контракт, возможны гонки с ядром и обход core-инвариантов |
| Экспорт библиотеки во временный файл для полного списка | Лишняя запись пользовательских данных и гонки; потолок `library` 20 записей принят для v1 |
| Опрос `status --json` вместо `events` | Лишние процессы и задержки; поток уже существует и покрывает поиск |
| Автозапуск GUI из TUI | На SSH/tty нет дисплея; холодный старт должен решаться headless-режимом |
| Spectrum-кадры в общем потоке без флага | 30 Hz на всех подписчиков — лишний трафик и изменение семантики `events`; подписка должна быть опциональной |
| FFT-визуализатор внутри TUI | У TUI нет аудио-данных и второго движка; источник метрик — только core |
| Процедурная анимация под видом реального спектра | Вводит пользователя в заблуждение; procedural явно маркируется в статусе |
| Фиксированный экран вместо модулей | Не отвечает сценариям btop-подобной настройки; модули и пресеты дешевле, чем отдельные экраны |
| Пятый релизный артефакт сразу | Расширяет матрицу поставки без решения владельца; начнём с `cargo install` |

## Последствия

**Положительные:**

- терминальный доступ к тому же эфиру и библиотеке без второго процесса;
- desktop-код не получает ratatui-зависимость;
- контракт TUI опирается на уже принятые IPC/events/library-export;
- `q`/`Q` разделяют «закрыть клиент» и «остановить ядро»;
- визуализаторы и btop-подобные модули дают TUI собственное лицо и
  используют уже существующие метрики эфира;
- spectrum-подписка опциональна: старые клиенты не платят за неё.

**Отрицательные / Риски:**

- без запущенного ядра TUI бесполезен; чистый SSH ждёт headless-трек;
- CLI-адаптер зависит от `orbitfm` в `PATH` и добавляет запуск процесса на
  команду; worker-поток скрывает задержку от UI;
- `library` отдаёт только 20 избранных; полный список — будущее расширение;
- TUI v1 не локализован и не поддерживает мышь, favicon и настройки;
- визуализаторы добавляют UI-код, тики и риск перегрева CPU; лечится
  `motion=off`, скрытием модуля и лимитом FPS;
- reactive-режим зависит от будущего флага `events --spectrum` в ядре; до
  него TUI показывает только procedural-анимацию;
- появляется ещё один клиент, который нужно держать в синхроне с `ev: 1` и
  `status.schema: 1`;
- `Q` может остановить эфир, запущенный другим клиентом; поэтому только
  после подтверждения.
