# ADR-0067: Каналы релизов и автообновление

**Статус:** Принято (2026-11-21)  
**Дата:** 2026-11-21  
**Участники решения:** ModernByte Architecture

## Контекст

OrbitFM поставляет четыре артефакта (AppImage, MSI, два DMG, `.plasmoid`) и
распространяет их через GitHub Releases. Обновление сейчас **полностью ручное**:
пользователь узнаёт о новой версии сам и скачивает артефакт со страницы релиза.
`install-appimage.sh` умеет поставить конкретный файл, но не умеет ни проверить,
ни найти, ни применить более новый.

Между тем релизный ряд устроен так, что **все публикуемые версии — предрелизы**
(`vX.Y.Z-rc.N`), а финальная `vX.Y.Z` появляется реже. Разным аудиториям нужны
разные потоки:

- обычному пользователю — только финальные (`vX.Y.Z`);
- тестировщику и владельцу — предрелизы (`vX.Y.Z-rc.N`) первыми.

Кроме разовой команды нужен **фоновый планировщик**: проверить по таймеру,
уведомить, при разрешении — установить. Ни одна из этих возможностей не должна
поднимать GUI (cold-start-команда, ADR-0037), ломать эфир или требовать root.
Финальный порог честности — ADR-0052: нельзя заявлять автоустановку там, где
она не проверена.

## Решение

### 1. Два канала

| Канал | Что это | Теги |
|-------|---------|------|
| `stable` (default) | публичный | `vX.Y.Z` без суффикса, релиз не `prerelease` |
| `dev` | разработка | `vX.Y.Z-rc.N`, релиз помечен `prerelease` |

Канал хранится в `settings.json` (`update_channel`) и меняется командой
`orbitfm update channel <stable|dev>`. Канал — **фильтр**, а не отдельный
репозиторий: источник один (GitHub Releases репозитория `ModernByte/orbitfm`).

### 2. Версия

- Текущая версия — `CARGO_PKG_VERSION` (или `ORBITFM_VERSION` при сборке).
- Сравнение — `semver` 1.0. Крейт уже присутствует в графе транзитивно, поэтому
  прямая зависимость не добавляет новых пакетов.
- Обновление доступно, если максимальная версия канала строго больше текущей.
  `vX.Y.Z-rc.N < vX.Y.Z` по semver; `rc.2 > rc.1`.

### 3. Обнаружение

`GET https://api.github.com/repos/ModernByte/orbitfm/releases?per_page=30` с
заголовками `User-Agent: OrbitFM/1.0 (ModernByte; <OS>; Rust)`,
`Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`.

- черновики (`draft`) игнорируются;
- канал определяется флагом `prerelease`;
- тег парсится как semver после снятия префикса `v`;
- выбирается максимум по semver внутри канала;
- переносятся `tag_name`, `name`, `body` (примечания), `published_at`,
  `html_url`, список `assets` (`name`, `browser_download_url`, `size`).

Ассет платформы: Linux — `*-x86_64.AppImage`; Windows — `*.msi`; macOS —
`*.dmg` (по `arch`). Дополнительно запрашивается `SHA256SUMS`, если он есть в
релизе.

### 4. Возможности

Команда `update` (cold-start, GUI не поднимает):

| Команда | Поведение |
|---------|-----------|
| `orbitfm update --check` | проверить сеть и напечатать человекочитаемо |
| `orbitfm update --check --json` | машиночитаемый снимок (схема 1) |
| `orbitfm update` | то же, что `--check` |
| `orbitfm update channel <stable\|dev>` | сменить канал и сохранить |
| `orbitfm update install` | скачать и применить (где поддерживается) |

JSON-снимок (схема 1, только добавление; `status.schema` остаётся 1):

```json
{"schema":1,
 "channel":"stable","current":"0.23.0","latest":"0.24.0",
 "available":true,"checked_at":"2026-11-21T10:00:00Z",
 "release_url":"https://github.com/ModernByte/orbitfm/releases/tag/v0.24.0",
 "published_at":"2026-11-20T09:00:00Z",
 "notes":"...",
 "asset":{"name":"OrbitFM-0.24.0-x86_64.AppImage","size":12345678,
          "url":"https://...","sha256":"..."}}
```

`status --json` дополняется **аддитивно** объектом
`update: {channel, current, latest, available}` из последнего результата, без
сетевого запроса в обработчике `status`.

### 5. Планировщик (демон обновлений)

- Внутрипроцессная tokio-задача в `Session`: при старте — проверка с задержкой
  (не мешает запуску), далее по интервалу.
- Интервал — `update_check`: `off` | `daily` | `weekly` (default `daily`).
  `off` выключает и сеть, и уведомления.
- Совпадение с сетевым профилем (ADR-0048): в `offline-first` проверка не
  выполняется; в `metered` — только ежедневный минимум (никакой загрузки
  артефактов).
- При доступном обновлении — уведомление (существующая система `Notice`) и
  поле в `status`. Повтор не спамит: уведомляем при смене `latest`.
- Автоустановка — только если `update_auto_install = true` и платформа
  поддерживает (см. §6). Иначе — только уведомление.
- Альтернатива без GUI: пользовательский systemd-timer вызывает
  `orbitfm update --check`; команда не входит в cold-start allowlist GUI и не
  поднимает окно.

### 6. Установка по платформам

| Платформа | Автоустановка | Механика |
|-----------|---------------|----------|
| Linux AppImage | **да** | скачать ассет и `SHA256SUMS`, сверить SHA-256, записать во временный файл рядом, `chmod 0755`, атомарный `rename` поверх `~/.local/bin/orbitfm`; повторный запуск — новая версия |
| Windows MSI | нет | уведомление + URL релиза; MSI требует установщика и привилегий |
| macOS DMG | нет | уведомление + URL релиза; подпись/нотаризация вне этого ADR |
| `cargo install` / dev-сборка | нет | уведомление; обновление — задачей разработчика |

Детект «это AppImage»: переменная `APPIMAGE` (её ставит рантайм AppImage) или
совпадение пути с установленным `~/.local/bin/orbitfm`. Иначе — честное
«автоустановка недоступна».

### 7. Безопасность

- Только HTTPS. Хосты ассетов — allowlist: `github.com`,
  `objects.githubusercontent.com`, `api.github.com`; иной хост — отказ.
- Обязательный `User-Agent`.
- Автоустановка выполняется **только** после сверки SHA-256 из `SHA256SUMS`
  того же релиза; при отсутствии суммы — отказ от автоустановки.
- Аргументы — `Command` без shell; root не требуется; только пользовательские
  пути.
- Сетевой сбой, несовпадение суммы, отказ API — не фатальны для эфира:
  уведомление и повтор по расписанию.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Отдельный репозиторий на канал | Двойная публикация, расхождение артефактов, лишняя поддержка |
| `stable` и `dev` как разные origin (GitHub + зеркало) | Не нужно: фильтра `prerelease` достаточно |
| Свой сервер обновлений | Лишняя инфраструктура и точка отказа |
| Автоустановка MSI/DMG | Требует привилегий/подписи/нотаризации; не проверено — нарушало бы ADR-0052 |
| Подпись артефактов (minisign/GPG) сейчас | Нет ключевой инфраструктуры; SHA256SUMS — необходимый минимум, подпись — отдельный ADR |
| Опрос Releases на каждый `status` | Сеть в горячем пути; недопустимо |
| Обновление через `git pull` + `cargo build` | Не для конечного пользователя |
| Root-демон обновлений | Противоречит «без root» и single-instance |

## Последствия

**Положительные:** пользователь узнаёт об обновлении сам; dev-аудитория получает
предрелизы первыми; AppImage обновляется под ключ; ноль root и ноль влияния на
эфир; `status`/`update --json` дают интеграциям машинный ответ.

**Отрицательные / Риски:** GitHub — единая точка и лимит 60 запросов/час без
токена (лечится интервалом и кэшем); SHA-256 из того же релиза не защищает от
компрометации самого релиза (нужна подпись — будущее); на Windows/macOS только
уведомление; замена AppImage не работает, если файл запущен из нестандартного
пути.
