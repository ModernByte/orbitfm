# ADR-0053: Окно настроек как отдельное окно

**Статус:** Принято  
**Дата:** 2026-11-06  
**Участники решения:** ModernByte Architecture, владелец продукта

## Контекст

С 0.9 настройки — самописная модалка внутри окна стола: скрим на весь
`viewport` и `egui::Area` с `Order::Foreground` (`src/app.rs`), геометрия
`SETTINGS_MODAL = (760, 544)` с clamp по вьюпорту (`src/ui/layout.rs`), а
глобус блокируется через `blocks_point`.

Владелец воспроизвёл реальный сценарий: кнопка «Settings» в браузерном
расширении показывает панель или стол, поверх которых ложится модалка —
«это полная фигня». Ожидается обычное окно настроек: одно, самостоятельное,
закрывается вместе с завершением сервиса, не тащит за собой стол.

Дополнительные требования:

- окно обязано открываться и тогда, когда стол спрятан (процесс припаркован);
- варианты размера выбираются автоматически по категории, без настройки;
- правила WM должны матчить окно настроек по заголовку, как уже матчатся
  капсулы (ADR-0021 п. 4);
- закрытие окна настроек не должно показывать стол.

## Решение

### 1. Носитель «стол виден»: immediate-вьюпорт

`draw_settings` остаётся единственной функцией вёрстки. Её вызов оборачивается
в `egui::Context::show_viewport_immediate(SETTINGS_VIEWPORT_ID, builder, |ui,
class| …)` прямо из `OrbitApp::draw`.

- На desktop `embed_viewports = false`, поэтому потомок — настоящее окно.
- Если бэкенд не умеет мультивьюпортность, приходит
  `ViewportClass::EmbeddedWindow`: в этом же колбэке рисуется прежняя модалка,
  пишется `warn!`, приложение не ломается.
- Наружу из потомка возвращается `Vec<UiAction>` через `&mut`-перехват. Именно
  поэтому выбран immediate, а не deferred: `&mut Session` не помещается в
  `FnOnce + Send + Sync + 'static`, а второй источник состояния мимо `Session`
  запрещён.
- удаляются: scrim-`Area`, `settings_rect` и его clamp, позиция `settings` из
  `blocks_point`, крестик в шапке панели, обработка Esc внутри потомка. Esc в
  столе больше не закрывает настройки.

### 2. Носитель «стол скрыт»: корневое окно настроек

Без UI-пасса immediate-потомок родиться не может: `run_session` при hide
закрывает root-вьюпорт и уходит в `park()`. Сценарий владельца — ровно этот.

- `ParkOutcome::Settings` — новый вариант; матчится одним местом в `main.rs`.
- `session::window::RootSurface { Desk(WindowMode), Settings(SettingsSize) }`.
  Это не новый `WindowMode`: `mode` — публичное поле статуса и IPC-контракта.
- `run_window` для `RootSurface::Settings` строит обычное декорированное окно
  с заголовком `OrbitFM · Settings · <вариант>`.
- `OrbitApp::new` в этом surface не создаёт `GlobeRenderer` и не печатает
  `AdapterReport`: глобусу в окне настроек нечего делать.
- `open_settings(origin)` перестаёт вызывать `show()`: если UI-пасс есть —
  открывается потомок; если процесс припаркован — ставится
  `UiIntent::Settings`.
- Закрытие корня-настроек ⇒ `end_window()` ⇒ `park()`; стол не показывается.
- `session.quit()` закрывает настройки вместе с процессом.

Инвариант `Session::settings_open` сохраняется и остаётся единственным
признаком «настройки открыты» для статуса и горячих клавиш.

### 3. Размеры и заголовки

`SettingsSize::{Compact, Medium, Wide}` живёт в `session/window.rs`.

| Вариант | Размер | Минимум | Категории |
|---------|--------|---------|-----------|
| Compact | 420×560 | 360×480 | Language, About |
| Medium | 760×544 | 560×420 | Appearance, Audio, Motion, Window (сегодняшняя модалка) |
| Wide | 1040×720 | 760×480 | Integrations, Stats |

- Выбор — чистая функция `for_open(category, mode)`; ручной настройки размера
  нет (решение владельца).
- Заголовок несёт вариант (`OrbitFM · Settings · Compact/Medium/Wide`),
  потому что правила WM матчатся по `title` (прецедент — `OVERLAY_TITLE`,
  `PANEL_TITLE`, ADR-0021 п. 4).
- Геометрия не персистится: на Wayland размер задаёт правило WM, иначе
  появился бы второй источник правды.
- Переход из Compact в Wide — это пересоздание потомка с новым заголовком, а
  не resize: у `show_viewport_immediate` размер задаётся builder'ом.

### 4. Жизненный цикл

| Событие | Поведение |
|---------|-----------|
| `settings` из IPC при открытом столе | immediate-потомок поверх стола |
| `settings` при спрятанном столе | `ParkOutcome::Settings`, отдельный `run_native` |
| закрытие потомка | настройки закрыты, стол остаётся |
| закрытие корня-настроек | `end_window` → `park`, стол не показывается |
| `quit` | закрываются и настройки, и процесс |
| смена `WindowMode` при открытых настройках | режим меняется, настройки закрываются (как раньше) |

## Последствия

**Положительные:**

- сценарий «Settings из расширения» даёт одно окно и не показывает стол;
- окно настроек живёт в WM как обычное окно: правила, фокус, закрытие;
- одна функция вёрстки на оба носителя — расхождений UI нет;
- `Session` остаётся единственным владельцем состояния.

**Отрицательные / риски:**

- два прогона `eframe::run_native` в одном процессе уже легальны
  (ADR-0018/0021), но первый кадр корня-настроек обязан пережить отсутствие
  `GlobeRenderer`; проверяется live;
- на бэкенде без мультивьюпортности настройки останутся модалкой — это
  осознанный fallback, а не скрытый дефект;
- заголовок стал частью контракта WM: переименование обязано менять сниппеты
  и тест зеркала.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Deferred-вьюпорт с `Arc<RwLock<…>>` | второй источник истины мимо `Session`; `&mut Session` не проходит через `'static` |
| Отдельный процесс настроек | нарушает single-instance и ADR-0018 |
| Нативное окно ОС (GTK/Qt) | вторая UI-технология и вторая тема |
| Оставить модалку, но прятать стол | не решает сценарий владельца: стол уже показан |
| Персистить геометрию в `Settings` | на Wayland два источника правды: правило WM и файл |

## Уточнение (2026-11-10): app-id дочернего вьюпорта

Дефект 0.21.0-rc.2/rc.3: билдер окна настроек собирался без `app_id`, и на
Wayland дочернее окно получало `app_id = null`. egui не наследует app-id от
родителя — `ViewportBuilder::app_id` по умолчанию `None`
(`egui-0.37.0/src/viewport.rs:295`), а `egui-winit` ставит Wayland-имя окна
только когда `app_id` задан явно (`egui-winit-0.37.0/src/lib.rs:2378–2381`).
Правила niri матчат пару
`match app-id="org.modernbyte.OrbitFM" title=r"^OrbitFM · Settings · ...$"`,
поэтому размер не применялся и окно оставалось тайлом; в Hyprland не
срабатывали и классовые строки `float`/`center`/`stayfocused`, потому что
класс окна тоже был пустым. В парковке (`RootSurface::Settings`) дефекта не
было: там окно создаёт `main.rs::run_window`, который `with_app_id(APP_ID)`
ставит всегда.

Решение: `settings_viewport_builder(size)` (и такой же
`warning_viewport_builder()` для ADR-0058) выставляет `with_app_id(crate::APP_ID)`
— то же значение, что у корневого прогона и `.desktop`-файла. Заголовок с
вариантом размера остаётся вторым матчером, а не единственным: он различает
три размера, а app-id — принадлежность окна приложению.

Измерено на живой сессии niri 26.04 (`niri msg --json windows`,
отладочная сборка `0.21.0-rc.3` + этот патч):
окно настроек — `app_id="org.modernbyte.OrbitFM"`,
`OrbitFM · Settings · Medium`, floating, 760×544; окно предупреждения — тот же
app-id, `OrbitFM · Sleep Warning`, floating, 420×320.

Регрессия закрыта юнит-тестом
`child_viewports_carry_app_id_and_titles_for_window_rules` (`src/app.rs`): он
проверяет app-id, заголовок, размеры, минимумы, `decorations` и
`transparent` у обоих дочерних билдеров.
