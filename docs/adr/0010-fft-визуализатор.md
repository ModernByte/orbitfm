# ADR-0010: Экспериментальный FFT-визуализатор

**Статус:** Принято  
**Дата:** 2026-10-22  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

Этап 6 включает экспериментальный FFT-визуализатор. Исходная формулировка в SRS
предполагала получение PCM через `audio-filter` mpv с выводом в pipe; это же
допущение упомянуто в ADR-0003 как перспективная возможность. При проверке
выяснилось, что у mpv нет tee-механизма для аудиовыхода:

- драйвер `ao=pcm` записывает декодированный поток в файл или FIFO, но **заменяет**
  штатный вывод, то есть воспроизведение пришлось бы реализовывать самостоятельно;
- второй декодер (mpv/ffmpeg) дублирует сетевой поток, рассинхронизируется с плеером
  и добавляет второй процесс;
- libmpv не предоставляет колбэк с PCM-сэмплами для клиента.

При этом mpv умеет отдавать метаданные аудиофильтров через свойство
`af-metadata/<filter-label>`. Встроенный фильтр libavfilter `aspectralstats`
вычисляет FFT-метрики кадра, а `astats` — уровень сигнала. Оба фильтра прозрачны
для звука и не меняют маршрут воспроизведения.

## Решение

1. Визуализатор работает на **агрегированных FFT-метриках** libavfilter:
   `aspectralstats` (centroid, spread, rolloff, flatness, flux) и `astats`
   (RMS level).
2. Фильтры подключаются к уже работающему mpv через свойство `af` по запросу
   пользователя и снимаются при выключении. PCM не перехватывается, второй
   декодер не создаётся.
3. Аудио-поток `orbitfm-audio` опрашивает `af-metadata/spectrum` примерно раз в
   50 мс и публикует `SpectrumFrame`. GUI сглаживает значения и рисует
   спектральную огибающую средствами egui.
4. Визуализатор выключен по умолчанию и считается экспериментальным. Если сборка
   mpv не содержит нужных фильтров, включение возвращает `AudioError::Spectrum`,
   а воспроизведение продолжается без визуализации.
5. Классические полосы FFT (спектр по бинам) в этой реализации **не**
   предоставляются. Для них потребуется отдельное решение по PCM-tap и новый ADR.

> **Развитие (ADR-0019).** Горизонтальный огибающий strip заменён синтетическими
> вертикальными столбцами (16/24/32), которые считаются из тех же шести агрегатов.
> PCM-перехват по-прежнему недоступен, поэтому статус «не спектр по бинам» сохраняется.
>
> **Развитие (ADR-0027).** Три полосы — Bass/Mid/High — стали доступны без
> PCM-перехвата: `acrossover` делит копию потока, `astats` снимает RMS по
> каналам, `pan` возвращает исходный сигнал. Это три огибающие, а не спектр
> по бинам; пер-биновый спектр по-прежнему требует PCM-tap и нового ADR.

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| `ao=pcm` + собственная реализация вывода (например, cpal) | Меняет аудиотракт и громкость, дублирует ответственность libmpv, высокий риск регрессий; требует пересмотра ADR-0003 |
| Второй процесс mpv/ffmpeg только для анализа | Двойная нагрузка на сеть и станцию, рассинхронизация, лишний процесс |
| Готовый спектр через `showspectrum`/скриншоты | Нет доступа к кадрам без видео-конвейера и VO; тяжело и хрупко |
| Отказаться от визуализатора | Противоречит Этапу 6 |

## Последствия

**Положительные:**

- Аудиотракт остаётся прежним: libmpv декодирует и выводит звук как раньше
- Нет новых зависимостей и второго процесса
- Отказ фильтра не ломает воспроизведение
- Визуализация управляется реальными FFT-метриками, а не синтетикой

**Отрицательные / Риски:**

- Нет покадрового спектра по полосам; огибающая строится по агрегатам
- Доступность `aspectralstats` зависит от сборки libavfilter (проверено на
  FFmpeg 12.1 / mpv 0.41)
- Опрос метаданных добавляет ~20 обращений к mpv в секунду при включённом
  визуализаторе
- Экспериментальный статус: возможны визуальные артефакты при реконнекте
