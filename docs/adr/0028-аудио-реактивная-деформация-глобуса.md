# ADR-0028: Аудио-реактивная деформация глобуса

**Статус:** Принято  
**Дата:** 2026-10-24  
**Участники решения:** ModernByte Architecture, Юрий Анатольевич  

## Контекст

ADR-0023 давал глобусу геометрический пульс `1 + 0.005 · pulse`, аудио-модуляцию
Fresnel-обода и авто-вращение после четырёх секунд простоя. Пульс снят
2026-10-24: он читался как волна от краёв к центру. Авто-вращение остаётся.
Этого недостаточно для «живой» планеты: нужна деформация в такт эфиру, разные
характеры движения под разные жанры и мягкий возврат в дыхание после Stop.

Требования из концепции:

- движения Strictly из аудиосигнала, без случайного screensaver;
- деформация малая — несколько процентов, а не «желейный шар»;
- камера и orbit пользователя приоритетнее любого музыкального движения;
- после Stop — плавный возврат в idle-дыхание за 300–500 мс;
- Bass / Mid / High, RMS, flux/onset, centroid и фаза бита;
- режимы Soft Pulse, Groove Sway, Bass Drop, Ambient Drift, Sparkle Twitch,
  Beat March; Auto по умолчанию;
- перевороты по умолчанию выключены, с кулдауном 8–20 с и длительностью
  0,6–1,2 с;
- настройки Motion reactivity (Off/Low/Normal/High), стиль, перевороты и
  Reduce motion;
- Overlay и Listening не должны получать Full-реактивность; Noctalia-виджет
  глобуса не имеет и остаётся без изменений;
- производительность: анализ не в UI-потоке, сглаженные uniform'ы, без
  лишних 60 fps.

Ограничения текущего кода:

- глобус — UV-сфера 64×32 с текстурой; вершины заданы в `src/render/globe.rs`;
- попадание луча и проекция маркеров/контуров стран считаются для сферы
  радиуса 1 (`GlobeCamera::screen_to_sphere`, `project_on_sphere`);
- маркеры и страны рисуются 2D-средствами egui поверх wgpu-сцены;
- камера живёт в `Session` и переживает скрытие окна; сглаженный `SpectrumOverlay`
  живёт в `OrbitApp` и пересоздаётся при показе;
- новых зависимостей для эффекта не требуется.

## Решение

1. **Анализ полос — отдельное решение ADR-0027.** `SpectrumFrame` получает
   `bands: Option<BandLevels>`; при недоступности полос движение работает на
   полном RMS и flux. Это не дублируется в этом ADR.

2. **Новый чистый модуль `src/render/motion.rs`.** Он не рисует и не знает
   про egui/wgpu. Вход — `SpectrumTarget`, настройки, `dt` и признак
   взаимодействия с камерой; выход — `GlobeMotion`:

   ```rust
   struct GlobeMotion {
       deform: GlobeDeform,   // squash по осям
       ripple: f32,           // амплитуда 0..0.004
       ripple_phase: f32,
       yaw_sway: f32,         // рад, только когда камера свободна
       roll: f32,             // рад, только переворот
       flash: f32,            // 0..0.15, без стробоскопа
       style: MotionStyle,
       intensity: f32,        // 0..1 для отладки и HUD
   }
   ```

   `MotionMixer` владеет историей энергии, onset-детектором, пружиной и
   состоянием стиля. Он живёт в `OrbitApp` рядом с `SpectrumOverlay`: это
   presentation-состояние одного показа, ему не нужно переживать закрытие окна.
   Настройки и `GlobeCamera` остаются в `Session`.

3. **Spring-squash с сохранением объёма.** Целевое растяжение задаётся
   нормированным басом:

   ```text
   target = 1 − amount · bass_env
   v += (k · (target − s) − c · v) · dt
   s += v · dt
   s = clamp(s, 1 − max, 1 + max)
   scale_y = s
   scale_xz = 1 / sqrt(scale_y)
   ```

   `scale_xz` компенсирует объём: планета сжимается по вертикали и
   расширяется по горизонтали, а не «раздувается». Пружина интегрируется
   полунеявно с фиксированным шагом не больше 1/240 с; `dt` ограничивается
   сверху, чтобы сон окна не выбросил планету в крайнее положение.

   Пределы по реактивности:

   | Реактивность | Максимум squash | Ripple |
   |--------------|-----------------|--------|
   | Low | 1,0 % | 0,15 % |
   | Normal | 2,0 % | 0,25 % |
   | High | 3,5 % | 0,40 % |
   | Off | 0 | 0 |

   Это «несколько процентов» только на High; Normal остаётся спокойным.
   Старый аудио-пульс ADR-0023 удалён; `deform` — единственный источник
   аудио-движения геометрии. Fresnel-обод статичен, пока его не усиливает
   `flash` (п. 9).

4. **Idle-дыхание и возврат после Stop.** Без аудио цель squash — медленная
   синусоида 0,12 Гц с амплитудой 0,35 % (Low/Normal; на High — 0,5 %).
   При Stop/паузе/пропаже спектра амплитуда уходит к idle-дыханию с
   экспоненциальной постоянной `RELEASE_TAU = 0,10 с`: через 300 мс остаётся
   около 5 %, через 500 мс — меньше 1 % от рабочей амплитуды. Это выполняет
   требование 300–500 мс и не даёт «щелчка» геометрии.

5. **Onset и фаза бита.** Детектор работает на нормированной энергии баса
   и flux:

   - история 2,1 с (43 кадра по 50 мс);
   - базовая линия — медиана последней секунды без последних 200 мс;
   - onset, если `bass_env > baseline + max(0,04; 0,35 · σ)` или flux
     превышает адаптивный порог;
   - рефрактерный интервал 150 мс;
   - уверенность (`confidence`) растёт на сильных onset и затухает;
   - фаза бита — накопитель 0..1, который сбрасывается на onset; период
     оценивается медианой последних 4 интервалов и ограничивается
     60–180 BPM;
   - при неуверенности фаза не применяется, стили остаются на дыхании.

   Никакого random: все решения — функции сигнала и времени.

6. **Шесть характеров и Auto.** Стиль — не жёсткий жанровый классификатор,
   а набор весов движения. Общие параметры: squash, sway, ripple, flash,
   склонность к перевороту.

   | Стиль | Триггер/характер | Основное движение |
   |-------|------------------|-------------------|
   | Soft Pulse | низкий уровень, мало flux | дыхание + мягкий bass squash |
   | Groove Sway | устойчивые onset, сильная середина | покачивание yaw ±0,015 рад в фазе бита |
   | Bass Drop | бас доминирует, сильный onset | глубокий squash, короткий ripple, лёгкий flash |
   | Ambient Drift | низкий flux, высокий flatness | очень медленный дрейф и ripple |
   | Sparkle Twitch | высокий centroid, много flux | мелкая высокочастотная рябь, без качки |
   | Beat March | регулярные интервалы, высокая уверенность | шаг на каждый бит, умеренный squash |

   Auto выбирает стиль по средним за 2–3 с и переключается с гистерезисом:
   минимальное удержание 3 с, кроссфейд параметров 0,8–1,5 с. Это исключает
   «дребезг» стилей на живом радио.

7. **Приоритет камеры.** `GlobeCamera::advance` получает `yaw_sway` и
   `pulse`; roll-анимацией переворота владеет сама камера, а фактический
   `roll` кадра презентация кладёт в `GlobeMotion.roll` для painter'ов:

   - при перетаскивании, зуме, клике или `fly_to` музыкальные `yaw_sway`
     и `roll` гасятся за 150–250 мс, а squash/ripple ослабляются до 35 %;
   - после отпускания sway возвращается плавно, не рывком;
   - авто-вращение ADR-0023 остаётся базовым слоем, музыка не отменяет его;
   - перевороты разрешены только при простое не меньше 2 с, без `fly_to`,
     без drag и только если камера не в крайнем pitch.

   Пользовательский orbit всегда выигрывает: музыка не может «отобрать»
   управление или изменить цель `fly_to`.

8. **Перевороты — это roll камеры, а не поворот модели.** В
   `GlobeCamera::view_proj` добавляется поворот вокруг оси взгляда:
   `projection · rotation_z(roll) · view`. Все маркеры, контуры стран и
   hit-test используют ту же `view_proj`/обратную матрицу, поэтому
   согласованы автоматически. Это дешевле и надёжнее, чем отдельная
   модельная матрица для меша, маркеров, стран и raycast.

   Параметры: по умолчанию выключено; длительность 0,6–1,2 с; кулдаун 12 с
   (допустимый диапазон 8–20 с); не больше одного переворота подряд; только
   на сильном onset; в Overlay/Listening и при Reduce motion запрещено.

9. **GPU-контракт.** `CameraUniform` расширяется двумя `vec4`:

   ```text
   motion:  x = scale_y − 1, y = scale_xz − 1,
            z = ripple_amp,   w = ripple_phase
   motion2: x = flash,       y = style_id,
            z = beat_phase,   w = time
   ```

   Вершинный шейдер применяет анизотропный масштаб к позиции, добавляет
   малую радиальную рябь (2–3 лепестка по долготе, затухание к полюсам) и
   передаёт flash во фрагментный шейдер для усиления Fresnel-кромки.
   Нормаль для освещения пересчитывается обратной транспонированной
   диагональю масштаба; нормаль ряби не считается — при амплитуде ≤0,4 %
   это не заметно и дешевле.

10. **Согласованность маркеров, стран и кликов.** Squash — линейное
    преобразование сферы, поэтому оно применяется и на CPU через общий
    `GlobeDeform`:

    - маркер: единичная точка → `deform.to_world()` → проекция;
    - контур страны: точки колец → `deform.to_world()` → проекция;
    - hit-test: луч переводится в пространство единичной сферы обратным
      масштабом, пересекается с единичной сферой, результат возвращается
      как единичная точка для `GeoService`;
    - ripple в hit-test не входит: его вклад ≤0,4 % радиуса (около пикселя
      при обычном зуме), и это осознанная граница.

    При `MotionReactivity::Off` `GlobeDeform` — единичное преобразование,
    существующие тесты и поведение не меняются.

11. **Настройки.** В `Settings` добавляются поля с `serde(default)`:

    ```rust
    pub motion: MotionReactivity,      // Off | Low | Normal | High
    pub motion_style: MotionStyle,     // Auto | шесть стилей
    pub allow_flips: bool,             // default false
    pub reduce_motion: bool,           // default false
    ```

    `MotionReactivity::Normal` и `MotionStyle::Auto` — значения по умолчанию.
    Эффективная реактивность зависит от режима окна: Focus — как в
    настройках; Overlay — не выше Low; Listening — Off (у капсулы остаётся
    только кольцо Listening). `reduce_motion` принудительно выключает
    squash/ripple/sway/flips, но не отключает сам эфир; статичный
    Fresnel-обод остаётся.

12. **UI настроек.** В меню шестерёнки HUD появляется секция Motion:
    сегменты Off/Low/Normal/High, выбор стиля, переключатель Allow flips
    (недоступен при Off/Reduce motion) и Reduce motion. Overlay/Listening
    настроек не показывают: у них нет HUD-меню. Изменения сохраняются сразу,
    как тема и акцент; при изменении реактивности Session включает анализ,
    если он нужен движению, даже когда cava-визуализатор выключен.

13. **Перерисовка.** При активном движении достаточно 30 fps; при
    перевороте — обычная частота кадров на 0,6–1,2 с; при idle-дыхании —
    около 15 fps; при Off/Reduce motion дополнительных кадров нет. Анализ
    остаётся в аудиопотоке с шагом 50 мс. Окно, скрытое по ADR-0018, не
    рисует и не крутит motion.

14. **Деградация.** Если полосы недоступны (ADR-0027), миксер работает на
    полном RMS и flux: доступны Soft Pulse, Groove Sway и Ambient Drift;
    Bass Drop/Beat March/Sparkle Twitch требуют полос и в Auto не выбираются.
    Если аудио-анализ отключён или эфир остановлен — idle-дыхание.

## Уточнение реализации (2026-10-24)

Сверка после live-приёмки Phase 4:

- фактический `GlobeMotion` кроме полей из п. 2 несёт `pulse`, `beat_phase`,
  `time` и `intensity`; `roll` — выход презентации (фактический угол кадра),
  а не вход камеры; контракт зафиксирован в `docs/interfaces/04-render.md`;
- переворот запускается фронтом `pulse ≥ 0,6` при `allow_flips`, простое
  ≥ 2 с, `priority ≤ 0,5` и pitch не у края ±85°; длительность 0,9 с,
  кулдаун 12 с, направление чередуется; drag/`fly_to`/снятие разрешения
  отменяют анимацию, остаточный roll затухает с τ 80 мс;
- `with_camera_priority` ослабляет squash и ripple до 35 % на полном
  приоритете; `yaw_sway` гасится тем же коэффициентом;
- live-прогон на niri 26.04 не выявил расхождений маркеров, стран, callout и
  hit-test; перевороты по умолчанию выключены и в live не включались, их
  матрица и отмена покрыты unit-тестами;
- Reduce motion, Overlay ≤ Low и Listening Off реализованы эффективной
  реактивностью Session; авто-вращение ADR-0023 при Reduce motion
  сохраняется (подпись настройки ограничивает только squash/ripple/sway).

## Последствия

**Положительные:**

- планета реагирует на реальный эфир, а не на случайный шум;
- деформация мала и ограничена, камера пользователя имеет приоритет;
- squash согласован с маркерами, странами и кликами на CPU;
- перевороты не требуют второй модельной матрицы и не ломают hit-test;
- новые настройки аддитивны, `settings.json` остаётся совместимым;
- новых зависимостей нет; GPU-нагрузка — только вершинный шейдер.

**Отрицательные / Риски:**

- ripple не участвует в hit-test: при максимальной амплитуде возможна
  визуальная погрешность около пикселя у кромки;
- музыкальная качка и перевороты могут укачивать; поэтому Reduce motion,
  Off, ограничения Overlay/Listening и выключенные по умолчанию перевороты
  обязательны;
- onset-детектор эвристический: на шумных станциях возможны ложные
  срабатывания; уверенность и гистерезис снижают их, но не устраняют;
- анализ и микшер добавляют состояние и тесты; сложность `motion.rs`
  сопоставима с визуализатором;
- при смене стиля возможен визуальный скачок, если кроссфейд не успевает;
  минимальное удержание 3 с и плавные параметры обязательны;
- `CameraUniform` растёт на 32 байта, шейдер и тесты нужно синхронизировать;
- полный per-bin спектр по-прежнему недоступен (ADR-0010/0027).

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Деформировать меш на CPU и загружать vertex buffer каждый кадр | Лишняя нагрузка и аллокации; GPU-вершины дешевле |
| Деформировать только шейдер, не трогая маркеры/страны/hit-test | Маркеры и клики «плавают» над поверхностью при squash 2–3,5 % |
| Крутить модель глобуса для переворотов | Нужна общая модельная матрица для меша, маркеров, стран и raycast; camera roll эквивалентен и проще |
| Случайное процедурное движение | Противоречит требованию «строго из аудиосигнала» |
| Вести камеру по музыке как основную | Отбирает управление у пользователя и укачивает |
| Всегда 60 fps для плавности | Лишняя нагрузка; 30 fps достаточно для сглаженных форм |
| Новый crate для beat detection | Адаптивный onset на нескольких числах не требует зависимости |
| Полный FFT по бинам для каждого стиля | ADR-0010/0027: это отдельное решение; трёх полос достаточно |
