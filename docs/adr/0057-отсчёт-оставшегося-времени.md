# ADR-0057: Отсчёт оставшегося времени таймера сна

**Статус:** Принято  
**Дата:** 2026-11-06  
**Участники решения:** ModernByte Architecture, владелец продукта

## Контекст

Сейчас таймер сна показывает только выбранные минуты («45 min») и одно
one-shot пробуждение окна к дедлайну (`sleep_repaint_after`, `park.rs`).
Пользователь не видит, сколько осталось, а окно просыпается один раз — в
последний момент.

Владелец потребовал: иконка часов показывает оставшееся время, раз в минуту
до последней минуты и раз в секунду в последнюю минуту. Требование
сформулировано как часть «ритуала сна», а не как отдельная настройка.

Ограничения:

- «интервальных таймеров нет» — принцип парковки (ADR-0018, ADR-0020):
  пробуждения только под ближайшее событие;
- в парковке нет UI-пасса: репейнт окна и тик сессии — разные вещи;
- `status --json` — публичный контракт, поле `remaining_secs` уже существует.

## Решение

### 1. Модель времени

`SleepTimer` получает:

- `next_display_change(now)` — ближайший момент, когда меняется отображаемая
  строка: остаток > 60 с → до целой минуты; ≤ 60 с → до целой секунды;
- `display_seconds(now)` — сколько показывать: округление вверх до целой
  секунды, чтобы «0:01» не мелькало дважды;
- `next_event(now)` = min(deadline, fade_start, warning_start,
  display-change).

`poll_sleep` переименовывается в `poll_sleep_events` с порядком
fade → warning → expiry (ADR-0055/0056/0058). `sleep_deadline` удаляется:
единственный потребитель — ветка парковки, она переходит на `next_event`.

### 2. Одно пробуждение вместо интервального таймера

Ветка `sleep_until` в `wait_on` (`src/session/park.rs`) переиспользуется:
ей передаётся `next_event`, а не дедлайн. После каждого события модель
пересчитывает следующий момент. Нового потока и периодического таймера нет.

Родительский репейнт (`src/app.rs`) меняет `sleep_repaint_after` на
`next_display_change`: в последнюю минуту это ~60 кадров, до неё — один кадр в
минуту. В `docs/interfaces/13-events.md` §5 фиксируется «до +60 кадров в
последнюю минуту».

### 3. Поверхности

- **Кнопка часов** (`ui::icons::sleep_status_button`) при активном таймере
  рисует моноширинный текст фиксированной ширины под максимум `12:00:00`
  вместо глифа. Ширина фиксирована, чтобы цифры не дёргали соседние кнопки
  каждый тик. При неактивном таймере остаётся `Icon::Clock`.
- **Подсказка** кнопки: «Таймер сна · осталось 12:34».
- **Трей**: `TraySnapshot.sleep_remaining_secs` + `tray::text::sleep_label`
  → «Sleep timer · 12:34». Пункты подменю остаются длительностями: это выбор,
  а не статус.
- **`status --json`**: `sleep.remaining_secs` получает документированную
  гранулярность (≤ 1 мин, ≤ 1 с в последнюю минуту); `inhibited`, `action`,
  `warning`, `fade_seconds` добавляются туда же (схема 1).

### 4. Форматирование

`i18n::sleep_remaining_label(language, secs)` рядом с `sleep_option_label`:
`M:SS` / `H:MM:SS`; потолок `MAX_SLEEP_MINUTES = 720` ⇒ `12:00:00`. Новых
строк каталога не требует — только цифры и двоеточия.

## Последствия

**Положительные:**

- пользователь видит остаток, не открывая настройки;
- в последнюю минуту отсчёт секундный, до неё — минутный: нет лишних кадров;
- модель времени остаётся чистой и тестируемой без egui и ОС.

**Отрицательные / риски:**

- в последнюю минуту окно просыпается раз в секунду — на слабой машине это
  заметнее, чем один кадр в минуту;
- фиксированная ширина текста должна совпасть с максимумом `12:00:00` во всех
  шрифтах, иначе соседние кнопки всё же сдвинутся;
- `status --json` чаще меняется в последнюю минуту — подписчики `events`
  получают больше кадров (задокументировано).

## Альтернативы

| Вариант | Причина отклонения |
|---------|--------------------|
| Периодический таймер 1/с всегда | нарушает «никаких интервальных таймеров», лишние кадры |
| Тикать только в UI-пассе | в парковке отсчёт бы замирал, трей и статус врали бы |
| Показывать остаток только в подсказке | владелец просил именно иконку |
| Отдельная настройка частоты | избыточно; каденция следует из смысла |
