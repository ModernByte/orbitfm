# Описание релиза: шаблон и правила

**Раздел для разработчиков** · [Хаб документации](../README.md) · [ADR-индекс](adr-index.md)

Текст GitHub Release собирается автоматически из двух файлов: русского текста в
[CHANGELOG](../CHANGELOG.md) и английского перевода в `docs/releases/en/<версия>.md`.
Первый абзац — единственное, что надёжно видно в превью ссылки (Open Graph / карточки
чатов), поэтому он обязан быть самодостаточным.

Связано: `.github/workflows/release.yml` (сборка тела релиза), `packaging/check-docs.sh`
(гейт наличия английского текста), `docs/CHANGELOG.md`.

## Где что лежит

| Файл | Язык | Роль |
|------|------|------|
| `docs/CHANGELOG.md`, секция `## [X.Y.Z] - YYYY-MM-DD` | русский | источник русского блока и первый абзац превью |
| `docs/releases/en/X.Y.Z.md` | английский | английский блок; без него релиз не публикуется |
| `release-notes.md` | оба | собирается workflow, в репозиторий не коммитится |

Имя файла — версия без префикса `v`, ровно как в `Cargo.toml`.

## 1. Правила первого абзаца (превью)

| Правило | Деталь |
|---------|--------|
| **Длина** | 1–2 предложения, **≈120–200 символов** (с пробелами). Не больше ~240 — иначе обрезка в карточках |
| **Содержание** | Что изменилось для пользователя + тип релиза (MINOR / PATCH / MAJOR). Без списка файлов и без «см. ниже» |
| **Язык** | Русский в CHANGELOG, английский в `docs/releases/en`; ключевые термины можно оставить: GPU, IPC, DMG |
| **Без** | Длинных скобок, перечней через «;», обрыва на полуслове, внутренних ADR-номеров в первой строке |
| **С** | Законченная мысль. Читатель, не открывший релиз, понимает суть |

### Плохо (как на превью v0.22.0-rc.1)

> MINOR: глобус рисует дискретная GPU, если она есть; прокрутка и перетаскивание считаются из геометрии сцены (постоянный шаг видимого размера и 1:1 с с...

Обрыв, канцелярит, превью бесполезно.

### Хорошо

> MINOR: глобус предпочитает дискретную GPU; жест орбиты и зум привязаны к видимому размеру сцены — одинаковый жест даёт предсказуемую скорость на любом окне.

## 2. Полная структура текста релиза

```markdown
## [0.22.0-rc.2] - 2026-11-XX

MINOR: глобус предпочитает дискретную GPU; жест орбиты и зум привязаны к видимому размеру сцены — предсказуемая скорость на любом размере окна.

### Добавлено
- …

### Изменено
- …

### Исправлено
- …

### Упаковка / CI
- …

### Документация
- …
```

**Порядок блоков** (пустые секции не включать):

1. **Первый абзац** — summary для превью (обязателен, без заголовка `###`).
2. `### Добавлено` — только user-visible или важные API/IPC.
3. `### Изменено` — поведение, совместимость.
4. `### Исправлено` — баги (краш, регресс).
5. `### Упаковка / CI` — AppImage, DMG, MSI, подписи, аудиты dylib.
6. `### Документация` — руководство, ADR, README.
7. `### Внутреннее` (опционально, в конце) — рефакторинг без эффекта для пользователя.

Английский файл повторяет ту же структуру и порядок блоков; заголовки секций —
`### Added`, `### Changed`, `### Fixed`, `### Packaging / CI`, `### Documentation`,
`### Internal`. Секции не переводятся построчно один в один, но факты обязаны совпадать.

## 3. Как workflow собирает тело

1. Берёт всё после `## [X.Y.Z]` до следующего `## [` из `docs/CHANGELOG.md` —
   это русский блок.
2. Требует непустой `docs/releases/en/X.Y.Z.md`; без него job падает.
3. Пишет `release-notes.md`: русский блок, разделитель `---`, заголовок `## English`,
   английский блок и языконейтральный подвал со ссылками на руководство.
4. Публикует релиз с именем `OrbitFM vX.Y.Z` (workflow) и признаком pre-release
   для тегов с `-rc.`.

Поэтому в CHANGELOG не нужно дублировать английский текст, а в английском файле —
ссылку на руководство: подвал добавляется автоматически.

## 4. Шаблоны по типу релиза

### PATCH (только фиксы)

```text
PATCH: на macOS приложение снова запускается без системного Python — убрана цепочка VapourSynth из бандла libmpv.
```

### MINOR (фичи + совместимость)

```text
MINOR: таймер сна и экспорт избранного; IPC получил команды sleep и library-export без ломания старых клиентов.
```

### MAJOR (ломающие изменения — редко для rc)

```text
MAJOR: схема IPC 2 и новый формат library.json; клиентам шеллов нужна обновлённая интеграция.
```

### Только упаковка

```text
PATCH: Windows MSI подписан; контрольные суммы SHA256SUMS публикуются вместе с установщиками.
```

## 5. Чеклист перед тегом

- [ ] Версия в `Cargo.toml` и в заголовке CHANGELOG совпадает
- [ ] Секция `## [X.Y.Z]` существует — иначе release job падает
- [ ] `docs/releases/en/X.Y.Z.md` существует и непустой
- [ ] Первый абзац ≤ ~200 символов, без обрыва, на обоих языках
- [ ] Нет спойлера «подробности ниже» вместо сути
- [ ] Breaking changes названы явно в первом абзаце, если есть
- [ ] `packaging/check-docs.sh` зелёный
- [ ] Имя релиза на GitHub: `OrbitFM vX.Y.Z` (уже задаёт workflow)
