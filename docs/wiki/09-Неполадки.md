# Неполадки

← [Домой](Home)

Каталог разобран в формате **симптом → почему → что сделать**. Всё ниже — про ветку `main` после
OrbitFM 0.21.0-rc.4; если поведение вашей сборки отличается, сначала сверьте версию.

## Четыре команды, которые отвечают на половину вопросов

```bash
pgrep -ax orbitfm     # жив ли процесс
orbitfm status        # состояние, станция, громкость, окно, режим
orbitfm status --json # то же машинно-читаемым JSON
ls -l "$XDG_RUNTIME_DIR/orbitfm.sock"
```

`orbitfm status` отвечает набором строк; после `#` — возможные значения, которых в реальном выводе нет:

```text
status playing            # stopped | playing | paused | buffering | reconnecting | error
stationuuid 960cf833-…
name SomaFM Groove Salad (128k MP3)
volume 0.85
window visible            # visible | hidden
mode focus                # focus | overlay | listening | panel
```

Строки `stationuuid` и `name` исчезают, когда состояние `stopped` или `error`. Если процесс не
запущен, `toggle`, `show`, `settings`, `panel`, `overlay` и `mode <режим>` поднимут новый экземпляр, а любая
другая команда (включая `playpause`, `next`, `previous`, `roulette`, `volume-up`, `volume-down`, `theme`, `stats`, `alias`
и `status`) напечатает `OrbitFM не запущен` и вернёт код 1 — управляющие команды не запускают GUI молча.

## 1. Запуск и графика

| Симптом | Почему | Что сделать |
|---|---|---|
| «не удалось запустить GUI» | Окно рисуется через wgpu: не работает графический стек или сессия | Проверьте, что сессия Wayland/X11 вообще поднимает окна; попробуйте запуск под X11 (XWayland) |
| Фон чёрный или серый вместо полупрозрачного «стекла» | На Windows и macOS у прозрачности wgpu есть известные ограничения | На Linux (Wayland) прозрачность работает; на Windows/macOS это известное поведение, на функциональность не влияет |
| Повторный запуск не создаёт новое окно | OrbitFM один процесс: второй запуск отдаёт команду существующему | Это норма; нужно поднять новый процесс — сначала `orbitfm quit` |
| Закрыл окно крестиком, а музыка играет | Закрытие окна = hide, не выход | `orbitfm show` или клик по [виджету панели](Интеграции-панели); выйти полностью — `orbitfm quit` |
| macOS: `Cmd-W` прячет окно, `Cmd-Q` завершает | Так и задумано: крестик и `Cmd-W` — скрытие с живым Now Playing, выход только через `Cmd-Q`, меню и `orbitfm quit` | Управление скрытым окном — меню в строке меню, медиа-клавиши, `orbitfm show` |
| macOS: «Нельзя открыть программу… не поддерживается этим компьютером Mac» | DMG собран под другую архитектуру (arm64 на Intel Mac) или система старше 13.0 | `uname -m`: `arm64` — [Apple Silicon](Установка-macOS-Apple-Silicon), `x86_64` — [Intel](Установка-macOS-Intel); нужен свой DMG и macOS 13+ |
| macOS: окно есть, а глобуса нет — он чёрный или отсутствует | не инициализировался рендер либо адаптер не потянул лимиты; живой приёмки на Intel UHD Graphics 617 пока не выполнено | снять `orbitfm-render.log` (раздел 9) и приложить к issue — по этой строке видно, какой адаптер выбран |
| macOS: приложение упало сразу, окна не было | dyld не собрал граф зависимостей бандла | `orbitfm --version` из терминала; при abort или «Symbol not found» приложите вывод целиком — этот класс дефектов ловит гейт сборки `smoke-launch.sh` |
| `bash: orbitfm: команда не найдена` | Бинарник не в `PATH` | Симлинк в `~/.local/bin/orbitfm`, проверить `echo $PATH`; см. [Установка](01-Установка) |
| AppImage: `Permission denied` или ругань на FUSE | Файл не исполняемый, либо `libfuse` нет/заблокирован | Запустите интеграцию без root и без `chmod` самого AppImage: `bash install-appimage.sh ./OrbitFM-…AppImage` (скрипт из релиза или `packaging/linux/`); вручную — `chmod +x OrbitFM-…AppImage`, при необходимости `APPIMAGE_EXTRACT_AND_RUN=1 ./OrbitFM-…AppImage` |
| Мастер первого запуска не появился | Он показывается только в чистом профиле: нет `settings.json` и не отмечен `onboarding_done`; при существующем конфиге мастер не запускается | При остановленном процессе переименуйте `~/.config/orbitfm/settings.json` и запустите снова; см. [Первый запуск](02-Первый-запуск) |
| Кнопка «Настроить окно» в мастере сообщила об ошибке | Hyprland не ответил на `hyprctl keyword` (не тот композитор, IPC недоступен, переменные сеанса не проброшены) | Скопируйте сниппет из окна мастера и добавьте его в `hyprland.conf` вручную, либо поставьте цель `orbitfm integration install hyprland` — она кладёт `~/.config/hypr/orbitfm.conf` и применяет правила сеансу; правило без правки файлов работает только на живой сессии Hyprland |
| Правила окна исчезли после перезапуска Hyprland | Мастер ставит правила только на текущую сессию и не правит конфиги | `orbitfm integration install hyprland` положит `~/.config/hypr/orbitfm.conf`; строку `source = ~/.config/hypr/orbitfm.conf` в свой `hyprland.conf` добавляете сами. Для niri — `orbitfm integration install niri`, он же допишет единственную строку `include` |

## 2. Звук и libmpv

| Симптом | Почему | Что сделать |
|---|---|---|
| Старт падает с «не удалось инициализировать аудио-ядро», звука нет | Нативной сборке нужна системная `libmpv` | Debian/Ubuntu — `libmpv-dev`, Fedora — `mpv-libs-devel`, Arch — `mpv`. AppImage, MSI и DMG носят `libmpv` с собой |
| Играет, потом тишина, в статусе `reconnecting` | Поток обрывается, OrbitFM переподключается | Подождите: статус сам перейдёт в `playing`; `error` означает, что попытки исчерпаны и воспроизведение остановлено |
| «Playback failed» на конкретной станции | Обычно сам вещатель: выключенный или битый сервер, гео-блокировка, переезд потока | Проверьте соседнюю станцию или «Радиорулетку»: если играет всё, кроме одной — проблема на стороне вещателя; если адрес каталога устарел, поможет ручная ссылка — `orbitfm alias` (раздел 3) |
| Громкость на ползунке меняется, а после перезапуска «слетает» | Слайдер при перетаскивании меняет только звук и запоминает значение: в файл оно пишется на отпускании, клике или клавиатурном шаге | Отпустите ползунок до конца и проверьте `volume` в `orbitfm status` |

## 3. Станции и Radio Browser

Каталог станций — внешний Radio Browser: сначала OrbitFM находит серверы через DNS
(`all.api.radio-browser.info`), затем перебирает зеркала при сетевых ошибках и ответах `5xx` /
`429` / `408`. Жёстко привязанного к одному сервера в коде нет.

| Симптом | Почему | Что сделать |
|---|---|---|
| «Станции не найдены» | Чаще всего сеть или DNS, либо пустой/слишком узкий запрос | Если снимок уже был, список может заполниться из него; иначе проверьте сеть и разрешение имён (`getent hosts all.api.radio-browser.info`), измените запрос, попробуйте позже |
| Глобус рисуется, но стран и станций в списке нет | Границы стран вшиты и рисуются без сети; список берётся из Radio Browser, а если сети нет — из локального офлайн-снимка. Снимка ещё не было | Ответ API не пришёл, и снимка на диске нет: проверьте сеть/DNS; после первого успешного запуска снимок появится сам (`~/.local/share/orbitfm/cache/stations-snapshot.json`) |
| В легенде карты стоит «снимок», счётчики стран маленькие | OrbitFM показывает офлайн-снимок: это не вся база, а до 500 сохранённых станций | Это штатная деградация без сети; когда Radio Browser ответит, карта и счётчики заменятся живыми. Подробнее — [Варианты использования](08-Варианты-использования) |
| Список страны/жанра/поиска пуст, хотя сеть есть | Живой ответ не пришёл или запрос слишком узкий; офлайн-снимок покрывает только сохранённые станции | Повторите запрос, проверьте DNS; снимок не заменяет полный каталог, а страхует от пустого экрана |
| Станции находятся, но не стартуют по клику | Ответ `error` от аудио-ядра | См. раздел 2; сначала `orbitfm status` |
| Станция из избранного, истории или списка перестала играть, а соседние играют | Перегорел каталожный `url_resolved`: вещатель переехал на другой хост, сменил порт или убрал `.mp3` из пути; запись в Radio Browser чинят днями, а то и не чинят | Подставить станции рабочий адрес вручную: `orbitfm alias <uuid> <url>`. Станция остаётся собой — те же `stationuuid`, избранное, история и минуты статистики. Проверить — `orbitfm alias <uuid>` и `orbitfm alias list`, снять — `orbitfm alias <uuid> remove`; пока ссылка ручная, строка станции и карточка текущей станции показывают пометку «ручная ссылка · хост». Команды `alias` браузерному расширению недоступны |
| Станция с пометкой «ручная ссылка» снова даёт `error` | Алиасный адрес тоже перегорает; каталожную ссылку приложение молча не возвращает, иначе смысл ручной ссылки теряется | Проверить адрес у вещателя и поставить новый тем же `alias <uuid> <url>`; вернуть игру по каталогу — `orbitfm alias <uuid> remove` (текущий эфир дослушивается по алиасу, следующий запуск пойдёт по `url_resolved`) |
| Рядом с битрейтом появилась метка `ECO` | Включился экономичный режим: сеть не тянет поток, libmpv получил больший буфер и OrbitFM нашёл ту же станцию с меньшим битрейтом | Это ожидаемое поведение при плохой сети. Выберите другую станцию — метка снимется; при возврате связи проще выбрать исходную станцию вручную |
| Звук после `ECO` тише или хуже | Экономный поток сознательно с меньшим битрейтом | Выберите станцию с большим битрейтом или подождите, пока сеть восстановится; автопереключения обратно нет |
| Вместо обложки — абстрактный рисунок, а не логотип | Favicon отсутствует или не прошёл проверку адреса; `FaviconCache` рисует детерминированную процедурную обложку из жанра, страны и голосов | Штатное поведение: звук и метаданные не затронуты. Логотип появится, если favicon пройдёт проверку; «Разрешить HTTP-обложки» помогает станциям с HTTP-only иконкой |
| Вместо обложки — инициалы названия | Процедурная обложка ещё не посчитана или текстура вытеснена из кэша (256 записей, LRU) | Прокрутите список — обложка пересоздастся; причина отказа favicon видна в `RUST_LOG=debug` |
| Обложка пропала у станции, которая играла с картинкой | Картинка живёт в кэше до 256 записей и 8 одновременных загрузок; при большой прокрутке старые обложки вытесняются | Прокрутите список назад — обложка загрузится заново |
| В профиле «Экономия» меньше станций и иконок | Профиль сети добавляет `bitrateMax=128` в запросы каталога, уменьшает мировой снимок до 250 станций и держит не больше двух загрузок иконок | Это ожидаемо; верните «Безлимит» командой `orbitfm network unlimited` или в настройках категории «Звук» |
| В профиле «Сначала офлайн» карта пустая или старая | Фоновый мировой запрос отключён; карта и обложки берутся из офлайн-снимка, а новые иконки не запрашиваются | Запустите поиск или станцию — действия пользователя по-прежнему ходят в сеть; для живой карты включите «Безлимит» |

### Импорт внешних потоков

`orbitfm play-url` разбирает `.m3u`/`.pls`, прямую ссылку и HTML-страницу с аудио.
Ошибка возвращается одной строкой, без стека и кода; вот что означают сообщения:

| Сообщение | Почему | Что сделать |
|---|---|---|
| `поддерживаются только http:// и https://` | Схема `file:`, `ftp:` и подобные запрещены | Дайте адрес `http://` или `https://` |
| `HLS-потоки (.m3u8) не поддерживаются` | HLS требует отдельного движка; `.m3u8`, `application/vnd.apple.mpegurl` и тело `#EXT-X-` отклоняются | Возьмите прямой аудиопоток (MP3/AAC/OGG) или плейлист `.m3u`/`.pls` со ссылкой на него |
| `страница или плейлист больше 1 МиБ` | Тело читается с жёстким кэпом 1 МиБ | Укажите прямую ссылку на поток вместо тяжёлой страницы |
| `аудиопоток не найден` | На странице нет `og:audio`, `<audio src>` или `<source src>` с подходящим адресом | Откройте страницу в браузере и скопируйте ссылку на аудио |
| `плейлист не содержит воспроизводимых ссылок` | В `.m3u`/`.pls` только комментарии, локальные пути или битые записи | Проверьте файл; нужна хотя бы одна `http(s)`-ссылка |
| `слишком много редиректов` / `слишком много уровней плейлиста` / `цикл в плейлисте или странице` | Защита от бесконечных переадресаций и самоссылающихся плейлистов | Дайте конечный адрес потока |
| `превышен таймаут импорта` | Весь разбор ограничен 8 секундами | Повторите позже или проверьте доступность сервера |
| `HTTP 404`, `HTTP 403` … | Сервер ответил ошибкой | Проверьте ссылку; гео-блокировка и авторизация не обходятся |
| `сеть: …` | DNS, TLS или соединение | Проверьте сеть; адреса локальной сети при явном импорте разрешены |

Импорт запускается только вручную — командой или кнопкой «Play this page» в попапе;
сам по себе OrbitFM внешние адреса не запрашивает. Станция получает идентификатор
`url:…` и дальше ведёт себя как обычная: история, избранное, MPRIS.

### Ручная ссылка станции

`orbitfm alias <uuid> <url>` подменяет адрес эфира станции каталога:
станция остаётся собой — тот же `stationuuid`, имя, страна, теги, место в избранном
и истории, накопленные минуты статистики, — а играет по адресу, который указали вы.
Подмена одна и применяется при любом запуске: из списков, избранного, истории,
очереди `next`/`previous`, рулетки, `orbitfm play <uuid>`, MPRIS и попапа браузера.
Отклонённый адрес отвечает `error <сообщение>`, а файл не меняется; вот что означают
сообщения:

| Сообщение | Почему | Что сделать |
|---|---|---|
| `алиас отклонён: приватный или служебный адрес` | Ярус 1 не пропускает адреса локальной сети, loopback, link-local и multicast: послаблений, которые есть у явного `play-url`, у алиаса нет | Возьмите публичный адрес эфира |
| `алиас отклонён: схема не http/https` | Принимаются только `http` и `https` | Дайте ссылку `http://` или `https://` |
| `алиас отклонён: одноярлыковый хост` / `локальный или служебный домен` | `http://radio/stream` и `localhost` отбивает та же проверка публичности | Укажите полное доменное имя потока |
| `алиас отклонён: адрес не разобран` / `хост не указан` / `порт 0` / `userinfo в ссылке` | Ссылка скопирована криво: не URL вовсе, без хоста, с нулевым портом или с логином-паролем | Скопируйте адрес целиком, от `http://` или `https://`, без учётных данных |
| `алиас отклонён: адрес длиннее 2048 байт` | Длина адреса ограничена 2048 байтами | Оставьте только прямую ссылку на поток, без длинного хвоста параметров |
| `алиас отклонён: внешнему потоку алиас не нужен` | `stationuuid` начинается с `url:` — это синтетическая станция `play-url`, её адрес и есть она | Почините ссылку повторным `orbitfm play-url <адрес>` |
| `алиас отклонён: stationuuid пустой` / `адрес пустой` | Один из аргументов пришёлся пустым (например, `orbitfm alias "" https://…`) | Укажите и UUID станции, и адрес; UUID берётся из строки `stationuuid` в `orbitfm status` или из `library.json` |
| `алиас отклонён: алиасов уже 200: снимите ненужный — alias <uuid> remove` | Потолок в 200 записей; вытеснения нет — молча потерять починенную станцию хуже отказа | Снимите ненужные `orbitfm alias <uuid> remove`, затем ставьте новый |
| `некорректный аргумент команды: alias: ожидается stationuuid или list` / `stationuuid не содержит пробелов` / `лишний аргумент: …` | Команда не разобралась: UUID не указан, в нём пробел, или аргументов больше, чем нужно (служебные слова `list` и `remove` различаются по позиции) | Форма одна из четырёх: `alias <uuid>`, `alias <uuid> <url>`, `alias <uuid> remove`, `alias list`; адрес пробелов не содержит |

Ответ `alias none` — не ошибка: у станции нет ручной ссылки (так же отвечает
`alias list` на пустом списке). Снятие несуществовавшего алиаса идемпотентно:
`ok alias removed`, а `library.json` не переписывается. Алиас можно поставить и
станции, которой сейчас нет в избранном, истории или выдаче: она может вернуться
в каталог позже, и ссылка её уже будет ждать.

Проверить, что подмена на месте, проще всего по пометке «ручная ссылка · хост» в
строке станции и в карточке текущей станции: расхождение каталога и эфира обязано
быть видно. Полный адрес в интерфейсе не показывается — только хост. Метки `ECO`
у такой станции не будет: экономная подмена меняет `stationuuid`, поэтому для
алиасных станций лёгкий поток не ищется. Если умер и алиасный адрес — это обычная
ошибка воспроизведения (раздел 2): каталожную ссылку приложение молча не
возвращает, нужен новый `alias <uuid> <url>` либо `alias <uuid> remove`.

Алиасы живут полем `aliases` в `library.json` и остаются только на вашей машине: в
`library-export`/`library-import` (схема 1) и в `status --json` их нет, браузерному
native host команда `alias` запрещена целиком. Команды `alias`
обслуживает запущенный экземпляр, сам GUI они не поднимают.

## 4. Окно, режимы и правила WM

Размеры: Focus **1100×800** (минимум 720×480, заголовок `OrbitFM`), Overlay **500×620** (360×480,
`OrbitFM · Overlay`), Listening **420×152** (360×120, `OrbitFM · Listening`), Panel **400×640**
(360×480, `OrbitFM · Panel`), настройки **420×560 / 760×544 / 1040×720** (`OrbitFM · Settings ·
Compact|Medium|Wide`), предупреждение таймера сна **420×320** (`OrbitFM · Sleep Warning`).

Правила матчат пару «`app-id` + заголовок», и app-id у всех окон один — `org.modernbyte.OrbitFM`.

| Симптом | Почему | Что сделать |
|---|---|---|
| Overlay/Listening/Panel растянулись на весь тайл | Не подключены правила окон тайлового WM | Поставьте цель установщика: `orbitfm integration install niri` (файл правил + одна строка `include` с копией `config.kdl.orbitfm.bak`) или `orbitfm integration install hyprland` (файл `~/.config/hypr/orbitfm.conf`; строку `source =` добавляете сами); кнопкой — на странице «Настройки → Интеграции». См. [Панели и виджеты](Интеграции-панели) и [Режимы окна](03-Режимы-окна) |
| Окно появляется в центре экрана, а не под панелью | Niri центрирует плавающие окна | В правилах niri якорь `top-right` и `y=48`; отступ `x` под свою раскладку бара подбирается вручную |
| Правило не срабатывает | Не совпал `title`: у каждого режима свой заголовок, и это служебная строка, которая не переводится | `NIRI_SOCKET=<сокет> niri msg windows` — поля `Tile size`, `Window size`, `Workspace-view position`; сравните фактический размер с ожидаемым |
| Настройки или окно предупреждения растянуты на весь тайл | У окна пустой `App ID` — так было в 0.21.0-rc.2/rc.3: дочерние окна рождались без класса, и правило с заголовком не находило их | Обновите сборку до **0.21.0-rc.4** или новее и переустановите цель `niri`/`hyprland`; проверка — `niri msg windows`, поле `App ID` должно быть `org.modernbyte.OrbitFM` |
| Hyprland ругается на конфиг после обновления | `windowrulev2` помечен устаревшим в 0.53+ (работает в 0.52 и совместимом режиме) | Мигрируйте на `windowrule { … }`, сверившись с документацией Hyprland |
| Переключил режим — окно всё ещё скрыто | Скрытое окно тоже имеет режим: он применится следующим показом | `orbitfm show`; в статусе строка `mode` идёт после `window` |

### Интеграции и правка конфигов

Страница «Настройки → Интеграции» использует CST-правку без регулярных выражений: комментарии и
форматирование Waybar сохраняются, а первая копия файла остаётся рядом с суффиксом `.orbitfm.bak`.
Из чужих конфигов правится ровно два места: `modules-right` Waybar по кнопке «Включить в конфиге»
и одна строка `include "./cfg/orbitfm.kdl"` в `~/.config/niri/config.kdl` при установке цели `niri`
(перед первой правкой — копия `config.kdl.orbitfm.bak`). Остальные цели раскладывают только
свои файлы, а `hyprland.conf` установщик не редактирует.
Никаких `killall`/`pkill`: перезагрузка идёт через IPC, сигнал или D-Bus, иначе показывается
ручная подсказка. Подробности — [Интеграции](06-Интеграции).

| Симптом | Почему | Что сделать |
|---|---|---|
| «Включить в конфиге» не сработало | Waybar-конфиг не найден, не разобрался как JSONC, в нём нет `modules-right`, или файл — символическая ссылка (правка не поддерживается) | Строка состояния показывает путь и причину; почините конфиг вручную, бэкап не тронут. При симлинке отредактируйте целевой файл сами |
| Модуль добавлен, но в баре его нет | Waybar не перечитал конфиг автоматически | Нажмите «Перезагрузить»; если IPC недоступен, перезапустите Waybar штатным для вашей сессии способом (без `killall`/`pkill`) |
| Правка конфига потеряла комментарии | Этого быть не должно: правка идёт через CST | Восстановите `.orbitfm.bak` и сообщите об ошибке — потеря комментариев считается дефектом |
| Хочу откатить правку | Рядом лежит первая копия исходного файла | Переименуйте `config.jsonc.orbitfm.bak` обратно; бэкап создаётся один раз и не перезаписывается следующими правками |
| Chrome/Firefox не видит native host | Манифест установлен в каталог профиля, а браузер читает такие манифесты при старте; для Firefox дополнительно важен ID расширения | Перезапустите браузер; установка из GUI прописывает абсолютный путь к `orbitfm`, поэтому `PATH` тут не нужен |
| Расширение установлено, но не подключается | Не совпал ID расширения или манифест указывает на удалённый бинарник | Переустановите native host из «Настроек → Интеграции» и проверьте расширение из релиза |

## 5. Язык, шрифты и флаги

| Симптом | Почему | Что сделать |
|---|---|---|
| Флаги стран не рисуются | Встроенный сабсет закрывает только региональные индикаторы; если флагов нет совсем — повреждена сборка или шрифт не загрузился | Обновите OrbitFM; полный системный **Noto Color Emoji** (если найден) даёт ещё и остальные эмодзи, но для флагов он больше не обязателен |

| Арабский интерфейс не зеркалится | egui 0.37 шейпит арабский текст, но не делает bidi-зеркалирование; мастер первого запуска разворачивает шаги справа налево вручную | Осознанное ограничение пре-релиза; текст читается, порядок колонок настроек остаётся слева направо |
| Интерфейс на английском, хотя нужен русский | В режиме «Системный» читаются `LC_ALL` → `LC_MESSAGES` → `LANG`; `C`/`POSIX` и неизвестная локаль дают английский | Выберите язык явно в «Настройки → Язык» — применяется сразу, перезапуск не нужен; см. [Настройки и язык](04-Настройки-и-язык) |
| Названия станций, стран и жанров не перевелись | Они приходят из Radio Browser и остаются как есть, как и служебные строки (CLI, протокол IPC, заголовки окон) | Штатное поведение |

## 6. Трей и MPRIS

| Симптом | Почему | Что сделать |
|---|---|---|
| Иконки трея нет | На Linux трей работает по StatusNotifierItem и требует хоста SNI: Noctalia, KDE, Hyprland, Sway/waybar; в GNOME — расширение вроде AppIndicator/StatusNotifier | Без хоста иконки не будет — штатная деградация, управляйте через `orbitfm …`; подробности в [Трей и MPRIS](07-Трей-и-MPRIS) |
| Иконка исчезает после остановки музыки при скрытом окне | Так вела себя сборка до 0.16.0-rc.2: при `stopped` элемент SNI уходил в `Passive`, и Noctalia v5 скрывал его | Обновите OrbitFM: с 0.16.0-rc.2 статус всегда `Active`, пока жив процесс |
| Трея нет на Windows | Модуль трея там намеренно no-op | На Windows управляйте через SMTC и CLI |
| На macOS нет иконки в строке меню | AppKit не создал `TrayIcon`; плеер в этом случае пишет `warn!` в лог и работает без трея | Проверьте `RUST_LOG=debug`, управляйте через `orbitfm …` и Now Playing; иконка появится после перезапуска, если бэкенд восстановится |
| На macOS медиа-клавиши и Control Center не видят плеер | Так было до 0.13.0-rc.1: скрытое окно парковало run loop, и `MPRemoteCommandCenter` не доставлял команды | Обновите OrbitFM; в 0.13 скрытие — `orderOut` при живом run loop. Live-приёмка на живом Mac ещё впереди, поэтому о расхождении сообщите в issue |
| В меню трея «Ничего не играет» | Процесс жив, но воспроизведение не запущено или поток не загрузился | Запустите станцию из окна или «Радиорулетку» в меню трея, проверьте `orbitfm status` |
| Плеер не виден в `playerctl` и виджетах | MPRIS-имя — `org.mpris.MediaPlayer2.OrbitFM`; его нет только если процесс не запущен | `pgrep -ax orbitfm`, затем `playerctl -l` и `playerctl -p OrbitFM status` |
| Управление из SMTC (Windows) / Now Playing (macOS) работает странно | SMTC проверялся только сборкой и тестами; Now Playing в 0.13 переписан на живой run loop, но live-проверок на живом Mac ещё не было | Пользуйтесь CLI/IPC (`orbitfm next`, `status --json`); о расхождении сообщите в issue |

## 7. Настройки, библиотека и файлы

```text
$XDG_CONFIG_HOME/orbitfm/settings.json              (обычно ~/.config/orbitfm/settings.json)
$XDG_DATA_HOME/orbitfm/library.json                 (обычно ~/.local/share/orbitfm/library.json; избранное, история и ручные ссылки — поле aliases)
$XDG_DATA_HOME/orbitfm/stats.json                   (локальная статистика прослушивания)
$XDG_DATA_HOME/orbitfm/cache/stations-snapshot.json (офлайн-снимок; обычно ~/.local/share/...)
IPC: $XDG_RUNTIME_DIR/orbitfm.sock (Linux), \\.\pipe\orbitfm-<хеш профиля> (Windows), $TMPDIR/orbitfm-<uid>/orbitfm.sock (macOS)
```

| Симптом | Почему | Что сделать |
|---|---|---|
| Предупреждение о повреждённых настройках, всё вернулось к умолчаниям | При повреждённом `settings.json` программа предупреждает и проводит сессию со значениями по умолчанию, **не перезаписывая** файл | Починить или удалить файл вручную и перезапустить; удаление также вернёт мастер первого запуска |
| Мастер первого запуска появился снова | Он показывается только когда `settings.json` нет; значит, файл переименовали, удалили или профиль новый | Завершите мастер или нажмите «Пропустить» — отметка `onboarding_done` сохранится |
| Не сохранились тема, язык, громкость | Сессия могла работать на значениях по умолчанию (строка выше) | Проверьте содержимое `settings.json` после `orbitfm quit` |
| Нужно начать с чистого листа | Конфиг и библиотека — обычные JSON-файлы | При остановленном процессе переименовать: `orbitfm quit`, затем `mv ~/.config/orbitfm/settings.json ~/.config/orbitfm/settings.json.bak` и то же для `library.json` |
| Пропало избранное и история | Библиотека отдельна от настроек: избранное и история живут в `library.json` | Восстановить `.bak`-файл; оформление при этом не затрагивается |
| Офлайн-снимок не обновляется или его нужно удалить | Снимок пишется только после живого ответа каталога и не чаще раза в сутки; повреждённый файл просто игнорируется | «Настройки → О программе → Очистить офлайн-снимок»; новый появится после следующего успешного ответа Radio Browser |
| Снимок пуст после очистки | Очистка отключает запись до конца сеанса и стирает файл | Перезапустите OrbitFM или дождитесь следующего успешного ответа каталога в новом сеансе |
| Таймер сна не сработал | Таймер живёт в сессии и сбрасывается при `orbitfm quit`; после перезапуска его нужно поставить заново | Проверьте `orbitfm status --json` → `sleep`; поставьте таймер снова `orbitfm sleep <минуты>` |
| `library-import` отказал | Файл больше 2 МиБ/5000 станций, не JSON схемы 1, нет прав на чтение или импорт запущен без работающего плеера | Проверьте размер и `schema` файла, права и что OrbitFM запущен; импорт не требует остановки эфира |
| `library-import` вернул `skipped` больше нуля | Станции с локальными адресами (`play-url` → `source = stream`, например `http://127.0.0.1:…`) экспортируются как есть, но импорт пропускает всё, что не проходит проверку публичных URL | Это не ошибка переноса: такие станции нужно добавить заново командой `orbitfm play-url <адрес>`; для библиотеки только с публичными станциями повторный импорт даёт нули |
| `library-export` не создал файл | Нет прав на запись в каталог, путь указывает на каталог, либо плеер не запущен | Укажите существующий каталог с правом записи и запущенный OrbitFM; экспорт пишет файл атомарно с правами `0600` |
| Уведомление «Статистика прослушивания не читается — счётчики начались с нуля» | `stats.json` не разобрался: файл обрезан, правился вручную, содержит неизвестную `schema` либо вообще не читается. Счётчики начинаются с нуля, и этот файл **не трогается** до первой успешной записи; на воспроизведение это не влияет | Уведомление показывается один раз за запуск. Если файл нужен — `orbitfm quit`, затем почините или уберите `~/.local/share/orbitfm/stats.json` и запустите снова. Если не нужен — просто продолжайте слушать: первая успешная запись заменит его обычным порядком |
| Статистика пуста или не растёт | Учёт выключен (`stats_enabled = false` — тумблер «Учитывать прослушанное» в «Настройках → Статистика»), либо эфир не в состоянии `playing`: пауза, буферизация, реконнект, ошибка и стоп секунд не добавляют | Проверьте `orbitfm stats` — строка `stats enabled false` означает выключенный учёт; включите тумблер и убедитесь, что `orbitfm status` даёт `status playing`. Выключение учёта файл не удаляет: прежние счётчики остаются |
| Прошлые минуты не вернуть после «Очистить» или `stats clear` | «Очистить» и `orbitfm stats clear` пишут на диск пустую схему 1 (команда идемпотентна и отвечает `ok stats cleared` даже при нулевых счётчиках), а история длительности нигде не хранится | Это не потеря данных, а штатное поведение. Перед экспериментом копируйте файл: `orbitfm quit`, затем `cp ~/.local/share/orbitfm/stats.json ~/.local/share/orbitfm/stats.json.bak` |
| Тост «Настройка не сохранена» при накоплении статистики (в детали — текст ошибки) | Запись `stats.json` не удалась (нет прав на каталог данных, диск переполнен, файл принадлежит другому пользователю). Счётчики остаются в памяти и пробуют записаться снова при следующем удобном случае | Исправьте права на `~/.local/share/orbitfm/` — например `chmod u+rwX ~/.local/share/orbitfm`; выход процесса тоже пытается записать накопленное, поэтому после починки лучше перезапустить OrbitFM |

## 9. Как собрать логи

OrbitFM пишет логи в **stderr**, уровень задаётся переменной `RUST_LOG` (tracing-subscriber
env-filter, по умолчанию `orbitfm=info`); цвета ANSI включаются только когда stderr — терминал.

Ключевой момент: **логи пишет тот процесс, который запустил GUI.** Команда `orbitfm …` из терминала —
это клиент, логи существующего процесса она не покажет. Чтобы собрать их:

```bash
orbitfm quit
RUST_LOG=debug orbitfm show 2> ~/orbitfm.log
```

Воспроизведите проблему и прикрепите `~/orbitfm.log`. Если GUI поднимает плагин или автозапуск —
перенаправьте stderr в файл там, иначе логи этого сеанса потеряны.

### macOS: лог выбранного GPU

При первом кадре приложение пишет в stderr одну строку `orbitfm render: …` — тот ли это
видеоадаптер, который выбрал wgpu, его драйвер и лимиты. Это единственный способ увидеть,
чем рисуется глобус на конкретной машине, и именно она нужна для приёмки Intel:

```bash
orbitfm quit
orbitfm 2>&1 | tee orbitfm-render.log
```

Закройте окно (или `orbitfm quit` из другого терминала) и приложите
`orbitfm-render.log` целиком. Строка — диагностика, а не интерфейс: её формат может
меняться между релизами, поэтому сшить её по полям из issue нельзя, только целиком.
Формат вывода и чем обеспечена матрица поддержки macOS —
[ADR-0052](https://github.com/ModernByte/orbitfm/blob/main/docs/adr/0052-матрица-поддержки-macos.md).

## 10. Что приложить к issue

Шаблон «Ошибка (Bug)» из `.github/ISSUE_TEMPLATE/bug.yml` просит:

1. **Кратко** — что пошло не так.
2. **Шаги воспроизведения** — нумерованный список.
3. **Ожидаемое поведение**.
4. **Фактическое поведение**.
5. **Платформу** — например `Linux (Niri 25.x) / Windows / macOS`.
6. **Версию / коммит** — вывод `orbitfm --version` или git SHA.
7. **Логи / стек** — файл из раздела 9; если проблема в графике на macOS, отдельно
   `orbitfm-render.log` из того же раздела.

Полезно добавить рядом вывод `orbitfm status`, наличие системной `libmpv` (для нативной сборки),
имя композитора и версию Noctalia/Hyprland, если речь об окне или виджете.
Issue-трекер: <https://github.com/ModernByte/orbitfm/issues>.

| Ожидание | Факт |
|---|---|
| Глобальные горячие клавиши на всю систему | Их нет в текущей версии; работают медиа-клавиши через MPRIS/SMTC/Now Playing и `orbitfm …` |
| Запись эфира и плейлисты | Не реализованы; таймер сна есть — разовый, `orbitfm sleep <минуты>` |
| Пакеты в AUR, Flathub, Homebrew | Их нет: Linux-путь — AppImage или сборка из исходников |
| Синхронизация, аккаунт, телеметрия | Настройки, библиотека и статистика прослушивания хранятся локально в `settings.json`, `library.json` и `stats.json` и никуда не отправляются; наружу уходят только запросы каталогу Radio Browser (включая click-tracking), к потоку выбранной станции и к адресу обложки — подробности в разделе «Безопасность и приватность» README |
| Перенос ручных ссылок между машинами | Алиасы — поле `aliases` локального `library.json`; в `library-export` и `library-import` (схема 1) их нет, поэтому на другой машине ручную ссылку ставят заново — `orbitfm alias <uuid> <url>`. Отдельного решения о переносе нет |
| Обложки по `http` | По умолчанию не грузятся намеренно: plain HTTP позволил бы по дороге подменить байты, уходящие в декодер. Владелец может включить их тумблером «Разрешить HTTP-обложки» в настройках — тогда такие станции получают иконку, а подмена по пути становится принятым риском выбора |
| Трей на Windows | Модуль намеренно no-op; на macOS меню-бар есть с 0.13.0-rc.1 |
| Управление плеером из виджета Noctalia | Виджет — одна кнопка показать/скрыть панель, остальное в окне и трее |
| SMTC (Windows) и Now Playing (macOS) как проверенное | SMTC проверялся только сборкой; Now Playing переписан на живой run loop в 0.13.0-rc.1, но live-приёмки на живом Mac ещё не было |
| Обещание плавности на Intel UHD Graphics 617 | Его нет: x86_64-сборка собирается, линтится и тестируется на Intel-раннере и проходит запуск в CI, но первый кадр на этой GPU ещё не снимался — см. `orbitfm-render.log` выше и матрицу в ADR-0052 |
| Запоминание режима окна между запусками | Не запоминается, новый запуск стартует с компоновки по умолчанию |
| Растянуть капсулу Overlay/Listening или панель Panel вручную | Компактные режимы — фиксированные компоновки: размер по умолчанию и минимум заданы режимом, а позицию и размер на тайловом WM — правила окон (раздел 4) |
