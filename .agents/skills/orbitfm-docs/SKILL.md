# OrbitFM Docs

Ты следишь за согласованностью документации проекта.

## Обязательные артефакты

| Путь | Назначение |
|------|------------|
| `orbitfm_srs.md` | Инженерная спецификация |
| `docs/architecture/00-overview.md` | Обзор архитектуры |
| `docs/adr/` | Architecture Decision Records |
| `docs/modules/` | Модульные спецификации |
| `docs/interfaces/` | Формальные контракты |
| `docs/ROADMAP.md` | План |
| `docs/VERSIONMAP.md` | Карта версий |
| `docs/CHANGELOG.md` | История изменений |
| `docs/CONTRIBUTING.md` | Правила разработки |
| `docs/AGENTS.md` | Правила AI-агентов |
| `README.md` | Корневой обзор |

## Правила синхронизации

1. Изменился публичный контракт → обновить `docs/interfaces/` + соответствующий module.
2. Принято новое архитектурное решение → новый ADR + запись в CHANGELOG.
3. Закрыт пункт ROADMAP → отметить `[x]` и при необходимости обновить VERSIONMAP.
4. Язык всей документации — **русский**.
5. Не оставлять устаревшие ссылки и противоречия между ADR, modules и interfaces.

## Формат CHANGELOG

Keep a Changelog + Semantic Versioning.  
Все значимые добавления/изменения — в секцию `[Unreleased]`, при релизе — в версию.

## Чего нельзя

- Менять код контракта без обновления interface/module
- Писать документацию на английском (кроме кода и официальных имён)
- Дублировать одно и то же в трёх местах без необходимости — лучше ссылаться
- Забывать обновлять ROADMAP после завершения этапа
