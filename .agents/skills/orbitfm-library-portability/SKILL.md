# OrbitFM Library Portability

Ты обеспечиваешь **перенос избранного и истории** между установками и
клиентами (desktop ↔ Android), без облачного аккаунта OrbitFM. Схема 1 уже
реализована в desktop на уровне CLI/IPC; Android-клиент ещё не написан.

## Источники

1. `docs/interfaces/15-library-export.md` — единственный контракт схемы 1
2. `docs/adr/0046-ритуалы-слушания.md` — решение об export/import и слиянии
3. `docs/adr/0045-android-companion.md` — роль Android и общие правила
4. `docs/modules/09-library.md`, `docs/interfaces/08-library.md`
5. ADR-0013 (favorites/history), ADR-0025 (публичные URL)
6. `orbitfm-core`; `orbitfm-android` для мобильного клиента

## Маршрутизация

- **Когда:** схема библиотеки, экспорт/импорт, Settings → Data, импорт на
  Android, совместимость версий формата.
- **Обязательные спутники:** `orbitfm-core` + `orbitfm-rust`/`orbitfm-ipc` по
  слою; `orbitfm-android` для мобильного импорта; `orbitfm-architect` +
  `orbitfm-docs` при изменении схемы.
- **Не подменяет:** `orbitfm-listening-ux` (сценарии слушания) и
  `orbitfm-product` (приоритеты).
- **Правила:** `docs/AGENTS.md` §2.2; при конфликте скилла и принятого ADR
  действует ADR.

| Часть | Статус |

## Схема 1

```json
{
  "schema": 1,
  "app": "orbitfm",
  "exported_at": 1762137600,
  "favorites": [],
  "history": []
}
```

- `schema` обязателен при импорте; поддерживается только `1`, иначе понятная
  ошибка без частичного импорта.
- `app` — пусто или `"orbitfm"`; чужое значение отклоняется.
- `exported_at` — информационное Unix-время, на слияние не влияет.
- `favorites`/`history` — списки станций; история новые записи первыми.
- Станция использует те же поля, что `library.json`/`status`: `stationuuid`,
  `name`, `url`, `url_resolved`, `homepage`, `favicon`, `tags`, `countrycode`,
  `language`, `votes`, `country`, `state`, `bitrate`, `codec`, `geo_lat`,
  `geo_long`, `source`.
- `stationuuid` — обязательный ключ слияния; пустой UUID отбрасывается.
- `url` и `url_resolved` — публичный `http(s)` без userinfo; пустое поле
  заполняется вторым до проверки.
- `homepage`/`favicon` — необязательные публичные `http(s)`; при провале
  проверки становятся `null`, станция сохраняется.
- `geo_lat`/`geo_long` — оба в допустимых диапазонах или оба `null`.
- `source` — `radio` или `stream`; отсутствие читается как `radio`.

Полная спецификация полей, ошибок и тестов — интерфейс 15. Не дублируй её
здесь при изменении: обновляй контракт.

## Desktop

- CLI/IPC: `library-export <path>` и `library-import <path>`; путь — остаток
  строки, относительный разрешается от текущего каталога процесса.
- Экспорт сериализует текущее избранное и историю, санитизирует строки и
  пишет атомарно. На Unix файл получает права `0600`.
- Импорт — **только слияние**, не замена: дубликат UUID сохраняет локальную
  запись, новые добавляются; история нормализуется и обрезается до
  `HISTORY_LIMIT` (20).
- Файл сохраняется только при наличии добавлений.
- Browser native host команды не получает — `forbidden`.
- GUI-кнопок в 0.18.0-rc.1 нет; появление file picker — отдельная задача UX.

## Android

- Импорт через SAF, только схема 1; неизвестная версия — понятная ошибка.
- Слияние по `stationuuid`; локальная запись побеждает.
- Битые и запрещённые URL пропускаются со счётчиком «N пропущено».
- После импорта станции не запускаются автоматически.
- Перед play — полный SSRF/publishable pipeline, как для URL Radio Browser.
- Импорт не пишет вне data dir приложения и не исполняет поля как код.

## Версионирование

- Новые поля добавляются без смены `schema`; удаление/переименование/смена
  семантики — `schema: 2`, ADR/interface и оба клиента одновременно.
- Desktop `library.json` не является публичным контрактом; Android работает
  только с форматом интерфейса 15.
- Экспорт не содержит облачный аккаунт, серверную синхронизацию или
  неограниченную историю.

## Клиенты

| Клиент | Роль |
|--------|------|
| Desktop | канонический редактор библиотеки + export/import |
| Android | импорт, локальные правки, экспорт |
| TUI | read-only `library`/`play-library`; файл не читает |

## Проверки

- roundtrip export → import без потерь и дублей;
- повторный импорт публичного файла даёт нули;
- локальные `stream`-станции экспортируются, но импортом пропускаются в
  `skipped` из-за публичной URL-политики;
- `schema: 2`, чужой `app`, файл > 2 МиБ и > 5000 станций отклоняются;
- приватные/link-local/`file://`/userinfo URL пропускаются;
- координаты вне диапазона обнуляются, строки санитизируются;
- на Unix права файла `0600`, временный файл убран.

## Чего нельзя

- «Синхронизация через наш сервер» под видом export.
- Импорт без поля `schema`.
- Импорт с заменой библиотеки вместо слияния.
- Неограниченная history в экспорте.
- Чтение `library.json` на Android или в TUI.
- Ослабление URL-политики ради импорта локальных потоков.
