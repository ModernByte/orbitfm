# OrbitFM Listening UX

Ты добавляешь функции **повседневного слушания**, а не новый 3D-эффект и не
новый шелл. База sleep/очереди и переноса библиотеки реализована в
0.18.0-rc.1; быстрый доступ к таймеру и профиль сети — в 0.19.0-rc.1; локальная
статистика — в 0.19.0-rc.2; URL-алиасы — в 0.20.0-rc.1 (ADR-0050).

## Маршрутизация

- **Когда:** sleep timer, `next`/`previous` и края очереди, network profile,
  локальная статистика, URL-алиасы, паритет этих сценариев с Android.
- **Обязательные спутники:** `orbitfm-core` + слой реализации
  (`orbitfm-rust`, `orbitfm-gui`, `orbitfm-ipc`); `orbitfm-android` для
  мобильного паритета; `orbitfm-library-portability` при экспорте;
  `orbitfm-architect` + `orbitfm-docs` при смене контракта.
- **Не подменяет:** продуктовое планирование (`orbitfm-product`), аудио-ядро
  (`orbitfm-audio`) и интеграции шеллов (`orbitfm-integration`).
- **Правила:** `docs/AGENTS.md` §2.2; при конфликте скилла и принятого ADR
  действует ADR.

## Sleep timer

- Единый ряд `settings::SLEEP_CHOICES = [0, 15, 30, 45, 60, 90]`, где `0` —
  выключен. UI показывает те же подписи через `i18n::sleep_option_label`.
- IPC принимает любое целое `1..=720`: `sleep <minutes>` заменяет дедлайн,
  `sleep clear` снимает; без активного таймера `clear` — no-op.
- По истечении — **stop**, не pause: эфир освобождает сеть и аудио-устройство.
  Fade-out в v1 не делается. Уведомление — `NoticeKey::SleepExpired`.
- Дедлайн живёт в `Session`, переживает закрытие окна, проверяется в `tick()`
  и в `park()`; выход процесса его не переживает.
- `status --json` схемы 1: аддитивное `sleep: { minutes, remaining_secs } | null`.
- Быстрый доступ: часы в шапках HUD/Overlay/Listening и панели, подменю трея
  (SNI `RadioGroup`, macOS `CheckMenuItem`), popup браузерного companion,
  подменю GNOME. Noctalia открывает панель, отдельная кнопка не нужна.
- Android: sleep timer — v1.5 must / v1 should, если успевает; действие в
  notification.

## Очередь и Next / Previous

Видимая очередь — та же, что показывает активная вкладка панели: избранное,
история или результаты поиска с действующим фильтром.

- `queue_wrap = true` (по умолчанию): `next` после последней станции идёт к
  первой, `previous` с первой — к последней.
- `queue_wrap = false`: шаг за край — no-op; кнопки, MPRIS
  `CanGoNext/CanGoPrevious` и поля `can` в `status --json` гаснут по позиции.
- Если текущей станции нет в видимой очереди, оба шага ведут к первой/последней.
- Семантика зафиксирована в интерфейсах 05/10; отдельных IPC-команд нет.
- Расширенные контексты из аудита (страна/жанр, «назад по history stack») —
  будущее развитие, не повод ломать текущую семантику.
- Roulette — отдельный сценарий; он не подменяет явный `next`.

## Network profile

| Профиль | Поведение |
|---------|-----------|
| Unlimited | полный каталог, снимок 1000 станций, 8 favicon-запросов |
| Metered | `bitrateMax=128` в discovery, снимок 250 станций, 2 favicon-запроса; эфир и библиотека без cap |
| Offline-first | snapshot first (ADR-0043), фоновый мир и новые favicon не стартуют, сеть по действию пользователя |

- Desktop реализован (ADR-0048): `settings.network_profile`, IPC `network`,
  `status --json.network`, карточка «Сеть» в категории «Аудио»; смена профиля
  сразу влияет на мир, discovery и `FaviconCache`.
- Отмена летящего мира при `offline-first` — `Session::cancel_world_fetch`
  (отбрасывание приёмника), без поколений.
- Android читает OS metered flag и ручной override вместе с ADR-0045.
- Не отключать SSRF/publishable checks и не ломать адаптивный битрейт ADR-0043
  «облегчённым» режимом.

## Локальная статистика

Реализовано в 0.19.0-rc.2 (ADR-0049): контракт — `docs/interfaces/17-stats.md`,
модуль — `docs/modules/20-stats.md`, накопление — `src/session/stats.rs`,
хранилище — `src/stats/mod.rs`, раздел настроек — `src/ui/stats_view.rs`.

- Считываются только целые секунды `Playing` активной станции; пауза, буферизация,
  реконнект, ошибка и стоп — нет, громкость не важна. `sessions` растёт на каждом
  запуске станции (`start_station`); источник команды — мышь, CLI, MPRIS, попап — не
  имеет значения.
- Файл `$XDG_DATA_HOME/orbitfm/stats.json`, схема 1: `schema`, `updated_at`,
  `stations[]`, `days` по UTC-суткам. Запись атомарная (`stats.json.tmp` → `rename`);
  отсутствующий файл — пустая статистика, а не ошибка. Пределы: `STATION_LIMIT = 500`
  станций, `DAY_LIMIT = 730` суток, теги — `TAGS_BYTE_LIMIT = 128` байт по границе
  тега.
- Сброс на диск: порог `FLUSH_SECS = 30` накопленных секунд, уход из `Playing`, смена
  станции, выключение `stats_enabled`, `stats clear` и выход процесса. В `park()`
  накопление продолжается (`Parked::Stats`) — закрытое окно счётчикам не мешает.
- `stats_enabled` (интерфейс 09) по умолчанию `true`; выключение останавливает
  накопление и запись, но файл не удаляет. Стирает счётчики только очистка —
  идемпотентная, поэтому `stats clear` при нулях тоже успешен.
- Внешний поток (ADR-0025, ADR-0040) — отдельная станция с ключом
  `external:<fnv1a64(url)>` (16 шестнадцатеричных разрядов) из `stats::station_key`;
  адрес в файл не пишется, только имя потока.
- IPC (интерфейс 05): `stats` — строки `stats total <seconds>`, `stats enabled
  <true|false>` и топ-5 `stats station|country|tag`; `stats --json` — схема 1 с
  топ-10 станций/стран/тегов, окнами 7 и 30 суток, ≤30 последних дат и локализованным
  блоком `ui`; `stats clear` — `ok stats cleared`. Неизвестный аргумент отклоняется на
  разборе. Команды обслуживает живой экземпляр и не поднимает GUI. `status`,
  `status --json` и поток `events` статистики не содержат — схема не менялась.
- UI: категория «Статистика» (`SettingsCategory::Stats`, иконка часов, шестая из
  восьми) — итоги «всего / 7 дней / 30 дней», тумблер учёта, «Очистить» со вторым
  кликом и три топ-10 списка с полосой доли относительно лидера. Снимок
  пересобирается не чаще `STATS_REFRESH = 1 с` и только пока раздел открыт.
- Приватность: без сервера, скрытой телеметрии и аккаунта; браузерный native host
  `stats`, `stats --json` и `stats clear` запрещает (ADR-0038). В экспорт библиотеки
  (интерфейс 15) счётчики не попадают — экспорт возможен только по отдельному ADR.
- Ошибки файла: неразбираемый `stats.json` даёт пустую статистику, исходник не
  трогается до первой успешной записи, `NoticeKey::StatsDamaged` показывается один раз
  за запуск; ошибка записи — `NoticeKey::SettingNotSaved`, счётчики остаются в памяти.
- Подписи раздела — группа `settings` каталога i18n (`stats*`) на всех 16 языках и
  `stats_damaged` в `notices`; `ui`-блок ответа `stats --json` берёт те же строки
  (интерфейс 12).
- Из идей аудита не сделано: «карта года» на глобусе, экспорт, статистика на Android.

## URL-алиасы

Реализовано в 0.20.0-rc.1 (ADR-0050, интерфейс `docs/interfaces/18-aliases.md`):

- Алиас `stationuuid → url` живёт полем `aliases` в `library.json`; схема файла
  не менялась, старые читатели получают пустой список.
- Единственная точка подмены — `StationLibrary::launch_url`
  (`src/library/mod.rs`), куда обращаются `Session::start_station`, publish
  gate и `sync_media`; станция не переписывается, статистика, история и
  click-трекинг остаются по `stationuuid`.
- Адрес проходит ярус 1 SSRF наравне с каталожным (`ALIAS_URL_LIMIT = 2048`);
  алиасная станция вне экономного подбора `ECO`.
- Команды `alias <uuid> [url|remove]` и `alias list` (интерфейс 05); браузерный
  native host их запрещает (ADR-0038). Экспорт библиотеки и `status --json`
  алиасы не содержат.
- UI: пометка «ручная ссылка» (хост-`label`) в строке списка и карточке
  станции — часть контракта, а не украшение.

## Чего нельзя

- Считать stats облачным product analytics без продукта и consent.
- Отдавать `stats`, `stats --json` и `stats clear` браузерному native host:
  счётчики приватные, белого списка ADR-0038 для них нет.
- Молча тащить статистику в `status --json` или в экспорт библиотеки
  (интерфейс 15): схема 1 не росла, экспорт — только через отдельный ADR.
- Удалять `stats.json` выключением `stats_enabled`: настройка останавливает
  накопление и запись, стирает счётчики только очистка.
- Ломать adaptive bitrate ADR-0043 противоречивыми «профилями».
- Добавлять next как «ещё один roulette» без контекста списка.
- Ослаблять SSRF/publishable policy в metered или offline-режиме.
- Менять схему `status`/IPC без ADR, интерфейса и CHANGELOG.
