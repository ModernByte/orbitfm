# OrbitFM Rust

Ты пишешь и ревьюишь Rust-код проекта OrbitFM (ModernByte).

Всегда учитывай `orbitfm-core` и границы модулей из `orbitfm-architect`.

## Базовые требования

- **Edition:** 2024
- **Форматирование:** `rustfmt` (стандартные настройки проекта)
- **Линтинг:** `clippy` (включая разумный уровень pedantic) + `cargo deny`
- **Асинхронность:** `tokio` (structured concurrency, избегай `spawn` без необходимости)
- **Ошибки:** `thiserror` для доменных ошибок, `anyhow` — только на границах приложения (main, CLI)

## Именование

| Элемент | Стиль |
|---------|-------|
| Модули, файлы, функции, переменные | `snake_case` |
| Типы, трейты, enum-варианты | `PascalCase` |
| Константы, статические | `SCREAMING_SNAKE_CASE` |
| Крейты / feature-флаги | `kebab-case` / `snake_case` |

## Структура модулей

- Один логический модуль = один каталог или файл в соответствии с `docs/modules/`.
- Публичный API модуля должен соответствовать `docs/interfaces/`.
- `pub use` — только для стабильного фасада модуля.
- Не делай `pub` всё подряд. Минимизируй публичную поверхность.

## Ошибки

```rust
#[derive(Debug, thiserror::Error)]
pub enum AudioError {
    #[error("не удалось инициализировать libmpv: {0}")]
    Init(String),
    #[error("ошибка воспроизведения: {0}")]
    Playback(String),
    // ...
}
```

- Все публичные fallible-функции возвращают `Result<T, ModuleError>`.
- Не используй `unwrap()` / `expect()` в библиотечном коде (только в `main`, тестах и явно безопасных местах с комментарием).
- Сообщения ошибок — на русском или английском, но единообразно внутри модуля.

## Async

- Предпочитай `async fn` + `.await`.
- Не блокируй runtime (`std::thread::sleep`, тяжёлый синхронный FFI без `spawn_blocking`).
- Для libmpv (не thread-safe в общем случае) — выделенный поток или очередь команд + `spawn_blocking` / канал.
- Каналы: `tokio::sync::mpsc`, `broadcast`, `watch` — по смыслу.

## FFI (libmpv и др.)

- Весь `unsafe` изолируй в минимальные функции/модули.
- Каждый `unsafe`-блок сопровождай комментарием **почему это безопасно**.
- Не храни сырые указатели дольше необходимого.
- RAII-обёртки (`Drop`) обязательны для `mpv_handle` и подобных ресурсов.
- Проверяй коды возврата C API и мапь их в `ModuleError`.

## Зависимости (Cargo.toml)

- Добавляй зависимость только если она реально нужна.
- Архитектурно значимые зависимости — через ADR.
- Фиксируй версии разумно (не `*`).
- Feature-флаги: `mpris`, `fft`, `noctalia` и т.п. — чтобы можно было собирать облегчённые варианты.

## Тесты

- Unit-тесты рядом с кодом (`#[cfg(test)]`).
- Интеграционные — в `tests/`.
- Для FFI и сети — моки / feature-флаги, чтобы CI не требовал libmpv и сеть обязательно.
- Имена тестов — говорящие: `reconnects_after_network_drop`.

## Обязательные проверки перед коммитом

```bash
cargo fmt --check
cargo clippy -- -D warnings
cargo test
cargo deny check   # если настроен
```

## Документация в коде

- Все публичные элементы — `///` комментарии.
- Примеры в doc-тестах — только если они реально компилируются и полезны.
- Внутренние инварианты — `// Safety:` или `// Invariant:`.

## Чего делать нельзя

- `unwrap()` в production-пути без крайней необходимости
- Глобальное мутабельное состояние без синхронизации
- Циклические зависимости между модулями
- Тянуть GUI-типы в domain-модули (audio, geo, radio)
- Игнорировать `Result` (`let _ = ...`)
- Писать «магические» числа без именованных констант

## Связь с другими скиллами

- Границы модулей и ADR → `orbitfm-architect`
- Конкретная подсистема → профильный скилл (`orbitfm-audio`, `orbitfm-gui` и т.д.)
- Общие правила проекта → `orbitfm-core`
